## State machine / hooks used

There is no reducer anywhere in the unit. All shared state lives in a single `MenuStore` class instance per `Menu.Root`, created exactly once via `useRefWithInit` (`packages/react/src/menu/root/MenuRoot.tsx:651-666`, call site `packages/react/src/menu/root/MenuRoot.tsx:132-147`). `MenuStore` extends the generic `ReactStore` from `@base-ui/utils/store` (`packages/react/src/menu/store/MenuStore.ts:2`, class at `packages/react/src/menu/store/MenuStore.ts:114`); its state is the shared popup state plus menu-specific members (`packages/react/src/menu/store/MenuStore.ts:19-38`), seeded from `createInitialPopupStoreState` (`packages/react/src/menu/store/MenuStore.ts:211`). The popup-generic open lifecycle — `open`, `mounted`, `transitionStatus`, `activeTriggerElement`, the trigger registry — is owned by the shared popups layer via `useOpenStateTransitions` (`packages/react/src/menu/root/MenuRoot.tsx:196-203`), which is also where `forceUnmount` (surfaced through `actionsRef.unmount`, `packages/react/src/menu/root/MenuRoot.tsx:448-452`) comes from. behavior.md → "Cross-cutting behavior → One shared state machine."

**Selectors encode the parent-type polymorphism.** The store's selector table (`packages/react/src/menu/store/MenuStore.ts:51-101`) is where "root menu vs submenu vs menubar child vs context menu" branching is centralized, so no component needs its own conditionals: `disabled` folds in a menubar parent's `disabled` (`packages/react/src/menu/store/MenuStore.ts:53-56`), `modal` is only meaningful for root/context-menu parents and defaults to `true` (`packages/react/src/menu/store/MenuStore.ts:57-59`), and `rootId`, `floatingTreeRoot`, and `keyboardEventRelay` are inherited from the parent menu's store for submenus (`packages/react/src/menu/store/MenuStore.ts:65-71`, `packages/react/src/menu/store/MenuStore.ts:77-83`, `packages/react/src/menu/store/MenuStore.ts:90-100`). The constructor's `observe('parent', …)` subscription (`packages/react/src/menu/store/MenuStore.ts:126-162`) keeps those inherited values live as the parent store changes and shares the parent's `allowMouseUpTriggerRef` (`packages/react/src/menu/store/MenuStore.ts:153`) — the mechanism behind behavior.md → "Shared `onOpenChange` reason taxonomy" and "Shared harness" event flow across nesting levels.

**One mutation gate.** Every open/close request in the unit — trigger clicks, hover timers, item presses, dismissals, imperative handles — funnels into `store.setOpen`, which merely emits a `setOpen` event on the floating root context (`packages/react/src/menu/store/MenuStore.ts:165-167`). `MenuRoot` subscribes to that event in a layout effect (deliberately not passive, so imperative `MenuHandle.open()` calls in the same commit are not dropped — `packages/react/src/menu/root/MenuRoot.tsx:425-442`) and routes them through its single `setOpen` transition (`packages/react/src/menu/root/MenuRoot.tsx:308-413`):

1. Stale-close and no-op guards — a close is dropped when the store is already closed (read directly, not the render-captured value, because relayed tree events can arrive before re-render: `packages/react/src/menu/root/MenuRoot.tsx:317-319`); a same-state same-reason same-trigger request is deduped (`packages/react/src/menu/root/MenuRoot.tsx:321-327`).
2. `attachPreventUnmountOnClose` decorates the details so consumers can opt out of unmount-on-close (`packages/react/src/menu/root/MenuRoot.tsx:329-331`), and a triggerless close defaults `eventDetails.trigger` to the active trigger so exit animations and focus return have a target (`packages/react/src/menu/root/MenuRoot.tsx:335-337`).
3. Veto point: `onOpenChange` runs before any state changes and `details.cancel()` aborts (`packages/react/src/menu/root/MenuRoot.tsx:339-343`) — behavior.md → `parts/root.md` → "State model (controlled/uncontrolled, defaults, transitions)".
4. The floating root context's `dispatchOpenChange` commits the open flip (`packages/react/src/menu/root/MenuRoot.tsx:345`), followed by touch-device guards: a touch click that was opened via a focus event is shielded from an immediate close for 300 ms (`packages/react/src/menu/root/MenuRoot.tsx:360-368`), and a touch close inside that window is swallowed (`packages/react/src/menu/root/MenuRoot.tsx:347-355`) — behavior.md → `parts/root.md` → "Edge cases".
5. `instantType` derivation: keyboard/AT activations produce `detail === 0` clicks and map to `'click'`; Escape/null-reason closes map to `'dismiss'`; menubar focus/hover/navigation/sibling reasons map to `'group'` (`packages/react/src/menu/root/MenuRoot.tsx:370-405`). Everything lands in one `store.update` (`packages/react/src/menu/root/MenuRoot.tsx:411`) — required so React 17 synchronous flushes can't separate `instantType` from the mount that must observe it (inline comment at `packages/react/src/menu/root/MenuRoot.tsx:407-410`). This is the mechanism behind the `[data-instant]` matrix in behavior.md → `parts/popup.md` → "State model".
6. Initially-open submenus seed their `instantType` from the parent during the first render only (`packages/react/src/menu/root/MenuRoot.tsx:122-130`) and clear it once the enter phase settles or the open flips (`packages/react/src/menu/root/MenuRoot.tsx:211-251`) — the "inherited instantType seed cleared across interruptions" claim in behavior.md → `parts/popup.md` → "State model".

**Root-level hook composition** (all in `packages/react/src/menu/root/MenuRoot.tsx` unless noted):

- `store.useControlledProp('openProp'/'triggerIdProp')` (`packages/react/src/menu/root/MenuRoot.tsx:149-150`) — controlled/uncontrolled resolution for `open` is delegated to the store's controlled-prop machinery; `useContextCallback` wires `onOpenChangeComplete` (`packages/react/src/menu/root/MenuRoot.tsx:152`).
- `useOpenInteractionType` (`packages/react/src/menu/root/MenuRoot.tsx:185`) — supplies the `openMethod` state that the scroll-lock and keyboard-vs-touch decisions read (`packages/react/src/menu/positioner/MenuPositioner.tsx:69`, `packages/react/src/menu/root/MenuRoot.tsx:360-375`).
- `useSyncedValues` (`packages/react/src/menu/root/MenuRoot.tsx:187-193`) — mirrors prop changes (`disabled`, `highlightItemOnHover`, `modal`, `rootId`) into the store.
- `useImplicitActiveTrigger` (`packages/react/src/menu/root/MenuRoot.tsx:195`) — single-trigger menus get their trigger marked active automatically.
- `useAnimationsFinished(store.context.popupRef)` (`packages/react/src/menu/root/MenuRoot.tsx:205`) — used to sequence the seeded-`instantType` clear.
- `useSyncedFloatingRootContext` (`packages/react/src/menu/root/MenuRoot.tsx:415-421`) — the only place a menu wires its floating root context; open changes are relayed through the `setOpen` event rather than a direct callback (inline comment at `packages/react/src/menu/root/MenuRoot.tsx:658-660`).
- `useDismiss` (`packages/react/src/menu/root/MenuRoot.tsx:467-478`) — Escape bubbling is driven by `closeParentOnEsc` (`packages/react/src/menu/root/MenuRoot.tsx:469`; behavior.md → `parts/root.md` → "Keyboard interactions" level-by-level Escape); `outsidePress` is suppressed until a 500 ms grace period elapses for context-menu-opened menus (`packages/react/src/menu/root/MenuRoot.tsx:170-171`, `packages/react/src/menu/root/MenuRoot.tsx:294-300`).
- `useListNavigation` (`packages/react/src/menu/root/MenuRoot.tsx:492-506`) and `useTypeahead` (`packages/react/src/menu/root/MenuRoot.tsx:515-527`) — the composite-list highlight engine (arrows/Home/End, `loopFocus`, orientation/RTL, hover-highlight) and label typeahead; together with the Space-suppression below they produce behavior.md → "Shared keyboard model".
- Trigger/popup/item prop blobs are computed once at the Root (`packages/react/src/menu/root/MenuRoot.tsx:529-626`) — `activeTriggerProps`/`inactiveTriggerProps` from `mergeProps` over typeahead/listNavigation/dismiss references plus `aria-haspopup`/`aria-expanded`; `popupProps` merges `FOCUSABLE_POPUP_PROPS`, role/aria wiring, hover-enable side effects (`packages/react/src/menu/root/MenuRoot.tsx:581-591`), the menubar `keyboardEventRelay` forward (`packages/react/src/menu/root/MenuRoot.tsx:592-600`), and the three floating hooks' floating props; `itemProps = listNavigation.item` (`packages/react/src/menu/root/MenuRoot.tsx:618`). `usePopupInteractionProps` publishes them into the store (`packages/react/src/menu/root/MenuRoot.tsx:620-626`) so parts read props as data (see Context section).
- Timeout hygiene is entirely via `useTimeout` (`packages/react/src/menu/root/MenuRoot.tsx:171`, `packages/react/src/menu/root/MenuRoot.tsx:173`): the 500 ms outside-press grace (`packages/react/src/menu/root/MenuRoot.tsx:297-299`), the 300 ms touch-close shield (`packages/react/src/menu/root/MenuRoot.tsx:360-368`), the trigger's 200 ms mouseup arm (`packages/react/src/menu/trigger/MenuTrigger.tsx:235`), `PATIENT_CLICK_THRESHOLD` stickiness (`packages/react/src/menu/trigger/MenuTrigger.tsx:366`), and the positioner's `closeDelay` (`packages/react/src/menu/positioner/MenuPositioner.tsx:201-206`). Async handlers (`setOpen`, the document-mouseup closer, submenu-trigger registration, radio-group `setValue`) are wrapped in `useStableCallback` (`packages/react/src/menu/root/MenuRoot.tsx:308`, `packages/react/src/menu/trigger/MenuTrigger.tsx:127`, `packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx:68`, `packages/react/src/menu/radio-group/MenuRadioGroup.tsx:42`).

**Trigger hook composition** (`packages/react/src/menu/trigger/MenuTrigger.tsx`): the store comes from the root context or, for detached triggers, from `usePopupHandleStore(handle)` with the inert null-store fallback (`packages/react/src/menu/trigger/MenuTrigger.tsx:66-73`); throwing without either is the behavior.md → `parts/trigger.md` → "Public API surface" error. Interaction layers merge in `props` (`packages/react/src/menu/trigger/MenuTrigger.tsx:221-247`): `useButton` (`packages/react/src/menu/trigger/MenuTrigger.tsx:113-116`), `useClick` with `mousedown` semantics (`packages/react/src/menu/trigger/MenuTrigger.tsx:187-193`), `useHoverReferenceInteraction` with `safePolygon` and hover `delay`/`closeDelay` (`packages/react/src/menu/trigger/MenuTrigger.tsx:166-180`), `useFocus` only when a menubar parent has a submenu open (`packages/react/src/menu/trigger/MenuTrigger.tsx:163-164`, `packages/react/src/menu/trigger/MenuTrigger.tsx:195-197`), and `useMixedToggleClickHandler` for menubar mixed mouse/keyboard input (`packages/react/src/menu/trigger/MenuTrigger.tsx:199-203`). Hover-open stickiness is a local hook, `useStickIfOpen` (`packages/react/src/menu/trigger/MenuTrigger.tsx:358-376`): after a hover-open, clicks within `PATIENT_CLICK_THRESHOLD` are ignored as close toggles. The drag-release contract (mousedown on trigger → release elsewhere must not activate an item and should close, behavior.md → `parts/root.md` → "Events") is implemented by arming `allowMouseUpTriggerRef` on mousedown (`packages/react/src/menu/trigger/MenuTrigger.tsx:229-241`), a once-only document `mouseup` listener that emits `close` with `cancelOpen` unless the release landed on the trigger, the positioner, or any popup of the same root (`packages/react/src/menu/trigger/MenuTrigger.tsx:127-161`), and the item-side counterpart in `useMenuItemCommonProps` (below). Per-trigger data (`payload`, `closeDelay`, parent descriptor, floating node ids, menubar keyboard relay) is pushed into the store by `useTriggerDataForwarding` (`packages/react/src/menu/trigger/MenuTrigger.tsx:93-106`).

**SubmenuTrigger** (`packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx`) reuses the item machinery for a different parent: it registers with the parent's composite list (`packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx:54`), reads `itemProps`/`highlighted` from the *parent menu's* store (`packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx:117-118`), and its `itemMetadata.setActive` writes the highlight into the parent store on hover (`packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx:120-130`). `useMenuItem` is called with the parent's `typingRef` so typeahead suppression spans the whole level (`packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx:132-142`). Hover-open is gated on the parent's `allowMouseEnter` once a delay is configured (`packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx:146-160`, `shouldOpen` at line 153) and includes `guardStaleOpen` for Chrome's dropped-mouseleave bug (inline comment, `packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx:157-159`). Click behavior inverts with `openOnHover`: toggle only when hover-open is off, ignore mouse entirely when on (`packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx:162-168`). The VoiceOver `aria-expanded` removal is a render-time prop override (`packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx:23`, `packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx:177-183`, applied at `packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx:193-198`) — behavior.md → `parts/submenu-trigger.md` → "Accessibility (roles, aria-*, id linking)". Its `registerTrigger` wrapper also claims `activeTriggerElement` for initially-open submenus (`packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx:65-87`, registration effect at `packages/react/src/menu/submenu-trigger/MenuSubmenuTrigger.tsx:89-95`).

**Items** share one hook pair. `useMenuItem` (`packages/react/src/menu/item/useMenuItem.ts:14-76`) = `useButton` with `focusableWhenDisabled: true` and `composite: true` (`packages/react/src/menu/item/useMenuItem.ts:29-34` — the mechanism behind behavior.md → "Shared keyboard model" disabled-but-focusable) + `useMenuItemCommonProps` (`packages/react/src/menu/item/useMenuItem.ts:36-45`) + merged refs (`packages/react/src/menu/item/useMenuItem.ts:67`). `useMenuItemCommonProps` (`packages/react/src/menu/item/useMenuItemCommonProps.ts:59-135`) carries: `role="menuitem"` and roving `tabIndex` (`packages/react/src/menu/item/useMenuItemCommonProps.ts:62-63`); Space `preventDefault` while a typeahead session is live via the shared `typingRef` (`packages/react/src/menu/item/useMenuItemCommonProps.ts:64-68`); the `itemhover` emit that lets sibling branches close each other (`packages/react/src/menu/item/useMenuItemCommonProps.ts:69-80`, consumed by the positioner listener below); the click→`close` emit honoring `closeOnClick` (`packages/react/src/menu/item/useMenuItemCommonProps.ts:81-85` — `preventBaseUIHandler()` veto support comes from the shared event-details layer, behavior.md → `parts/group-item-link.md` → "Events"); and the drag-release `onMouseUp` that synthesizes a click with `detail: 1` when the pointer-up lands after a trigger mousedown (`packages/react/src/menu/item/useMenuItemCommonProps.ts:106-118` — the `detail: 1` marker keeps `MenuRoot`'s `isKeyboardClick` heuristic honest, `packages/react/src/menu/root/MenuRoot.tsx:370-375`). Each item type adds its own state and role on top: `MenuItem` (`packages/react/src/menu/item/MenuItem.tsx:43-63`), `MenuCheckboxItem` with `useControlled` and a cancelable `onCheckedChange` (`packages/react/src/menu/checkbox-item/MenuCheckboxItem.tsx:53-58`, `packages/react/src/menu/checkbox-item/MenuCheckboxItem.tsx:80-92`), `MenuRadioItem` deriving `checked` from the group (`packages/react/src/menu/radio-item/MenuRadioItem.tsx:48-56`, `packages/react/src/menu/radio-item/MenuRadioItem.tsx:78-84`), and `MenuLinkItem` reusing the same common props on an `<a>` with non-native button semantics (`packages/react/src/menu/link-item/MenuLinkItem.tsx:47-65`).

**Indicator lifecycle** (both indicators are structurally identical): `useTransitionStatus(item.checked)` mounts the indicator with the checked state (`packages/react/src/menu/checkbox-item-indicator/MenuCheckboxItemIndicator.tsx:26`), `useOpenChangeComplete({ batch: true, enabled: !item.checked, … })` defers `setMounted(false)` until exit animations finish (`packages/react/src/menu/checkbox-item-indicator/MenuCheckboxItemIndicator.tsx:28-38`), and rendering is gated by `enabled: keepMounted || mounted` (`packages/react/src/menu/checkbox-item-indicator/MenuCheckboxItemIndicator.tsx:55`) — the mechanism behind behavior.md → `parts/checkbox-item.md` → "Edge cases" (batched single-commit removal, `keepMounted`, `data-ending-style`).

## DOM/portal strategy and why

- **Root renders no element.** It returns the provider, the optional `PopupHandleAttachment` for handle-backed detached triggers, and children (`packages/react/src/menu/root/MenuRoot.tsx:636-641`); only when it is the top of a floating tree (root or context-menu parent) does it wrap content in `FloatingTree` so nested menus share dismissal/navigation context (`packages/react/src/menu/root/MenuRoot.tsx:643-648`) — the structural side of behavior.md → "Uniform DOM shell."
- **Portal** is a thin wrapper over `FloatingPortal` (`packages/react/src/menu/portal/MenuPortal.tsx:37`) with `keepMounted` gating `shouldRender` (`packages/react/src/menu/portal/MenuPortal.tsx:22-27`). The hidden `aria-owns` owner's role is computed from the React-tree `parent` (not the store's, which a detached trigger overwrites — inline comment at `packages/react/src/menu/portal/MenuPortal.tsx:29-32`): `group` only under role-constrained parents (`packages/react/src/menu/portal/MenuPortal.tsx:32`) — behavior.md → "ARIA model across the tree."
- **Positioner** requires the Portal context (throw at `packages/react/src/menu/portal/MenuPortalContext.ts:6-12`), resolves side/align defaults per parent type — `inline-end`/`start` for submenus, orientation-dependent for menubars, context-menu overrides for anchor/offsets (`packages/react/src/menu/positioner/MenuPositioner.tsx:88-107`) — and delegates geometry to `useAnchorPositioning` (`packages/react/src/menu/positioner/MenuPositioner.tsx:111-136`). The rendered element goes through the shared `usePositioner` wrapper with `hidden: !mounted` and `inert: !open` (`packages/react/src/menu/positioner/MenuPositioner.tsx:277-284`), which is exactly behavior.md → `parts/positioner.md` → "DOM structure & portal behavior" (keepMounted stays in DOM but inaccessible). It hosts three non-obvious residents: an `InternalBackdrop` for modal state with a cutout hole for the menubar content element or the root trigger (`packages/react/src/menu/positioner/MenuPositioner.tsx:286-311`); the `FloatingNode` that registers this menu in the floating tree (`packages/react/src/menu/positioner/MenuPositioner.tsx:313`); and `CompositeList` over the store's `itemDomElements`/`itemLabels` refs (`packages/react/src/menu/positioner/MenuPositioner.tsx:314-319`, refs owned at `packages/react/src/menu/store/MenuStore.ts:44-45`) — items self-register via `useCompositeListItem({ guess: true, label })` (`packages/react/src/menu/item/MenuItem.tsx:33`), which is what keeps the composite list order in sync with render order without a manifest.
- **Cross-level coordination lives in the positioner's event listeners**, not in Root: `menuopenchange` emissions implement sibling-open closes (a sibling menu opened under the same parent → `setOpen(false, siblingOpen)`, `packages/react/src/menu/positioner/MenuPositioner.tsx:138-158`) and parent-close propagation with the parent's own reason (`packages/react/src/menu/positioner/MenuPositioner.tsx:160-179`); `itemhover` closes unrelated branches honoring `closeDelay` (`packages/react/src/menu/positioner/MenuPositioner.tsx:190-220`); every open flip is re-broadcast so children and siblings observe it (`packages/react/src/menu/positioner/MenuPositioner.tsx:222-231`). The `siblingOpen`/`sibling-open` reason claims in behavior.md → "Shared `onOpenChange` reason taxonomy" and → `parts/positioner.md` → "Events" are produced here. The positioner also owns trigger-change instant handling (`packages/react/src/menu/positioner/MenuPositioner.tsx:233-256`) and the modal scroll lock (`packages/react/src/menu/positioner/MenuPositioner.tsx:267-275`, modal computation at `packages/react/src/menu/positioner/MenuPositioner.tsx:267-268`).
- **Popup** is a `div` rendered inside `FloatingFocusManager` (`packages/react/src/menu/popup/MenuPopup.tsx:122-142`) whose options encode the per-parent focus contract of behavior.md → "Focus returns to the opener": `returnFocus` is derived from parent type, active trigger, and open reason unless `finalFocus` overrides it (`packages/react/src/menu/popup/MenuPopup.tsx:114-120`); `initialFocus` is disabled for submenus (first item is focused via list navigation instead, `packages/react/src/menu/popup/MenuPopup.tsx:129`); the root menu passes focus-guard refs and the trigger focus target (`packages/react/src/menu/popup/MenuPopup.tsx:132-138`). Popup props come from the store (`packages/react/src/menu/popup/MenuPopup.tsx:38`), the hover-close interaction is enabled only while `hoverEnabled` (`packages/react/src/menu/popup/MenuPopup.tsx:79-82`), and the element is stamped with `data-rootownerid` (`packages/react/src/menu/popup/MenuPopup.tsx:110`) — see the untested-surface section for that marker's consumer.
- **Trigger DOM**: a native `<button>` by default (`nativeButton = true`, `packages/react/src/menu/trigger/MenuTrigger.tsx:56`) rendered via `useRenderElement` (`packages/react/src/menu/trigger/MenuTrigger.tsx:249-255`); inside a menubar it renders as a `CompositeItem` instead so the menubar's own composite list owns it (`packages/react/src/menu/trigger/MenuTrigger.tsx:257-270`). When open, the trigger renders flanked by two `FocusGuard` siblings inside keyed fragments — the keys keep the element's DOM node stable as guards mount/unmount (`packages/react/src/menu/trigger/MenuTrigger.tsx:272-291`).
- **Viewport** contains no transition machinery of its own: it selects `side` from the positioner and delegates to the shared `usePopupViewport` (`packages/react/src/menu/viewport/MenuViewport.tsx:28-32`), which owns the `data-current`/`data-previous` remount and activation-direction behavior documented in behavior.md → `parts/arrow-backdrop-portal-viewport.md`.
- **Arrow** and **Backdrop** are pure leaves: Arrow merges the positioner's `arrowRef` and computed `arrowStyles` (`packages/react/src/menu/arrow/MenuArrow.tsx:33-42`); Backdrop is a `role="presentation"` div, `hidden` while unmounted, with hover-open menus getting `pointerEvents: 'none'` and always `userSelect`/`-webkit-user-select: none` (`packages/react/src/menu/backdrop/MenuBackdrop.tsx:42-53`).
- **`findRootOwnerId`** (`packages/react/src/menu/utils/findRootOwnerId.ts:3-13`) walks ancestors for the `data-rootownerid` marker; it is the DOM-level ownership test the trigger's document-mouseup handler uses to ignore releases inside any popup of the same root (`packages/react/src/menu/trigger/MenuTrigger.tsx:145`) — what makes multi-trigger/multi-menu drag-release safe without a React-level registry lookup.
- **Public surface assembly**: `index.parts.ts` aliases every part into the `Menu` namespace, re-exports `Separator` from the separator unit (`packages/react/src/menu/index.parts.ts:19`), and exports the handle API (`packages/react/src/menu/index.parts.ts:21`); types are re-exported individually in `packages/react/src/menu/index.ts:1-21`. `MenuHandle` extends the shared `BasePopupHandle` with the inert null store as its initial attachment (`packages/react/src/menu/store/MenuHandle.ts:12-18`), so `open(triggerId)`/`close()`/`isOpen` no-op safely before a root mounts (`packages/react/src/menu/store/MenuHandle.ts:28-46`).

## Anything in source not explained by any test

Flagged explicitly for the golden-fixture stage and the backward-looking audit; verified against this unit's test files (and, where noted, repo-wide) rather than assumed:

1. **`data-rootownerid` popup marker and its consumer.** The attribute (`packages/react/src/menu/popup/MenuPopup.tsx:110`), the `findRootOwnerId` walk (`packages/react/src/menu/utils/findRootOwnerId.ts:3-13`), and the same-root guard in the trigger mouseup handler (`packages/react/src/menu/trigger/MenuTrigger.tsx:145`) are referenced by no test file in the entire repo (grep for `rootownerid` across `*.test.tsx` returns nothing), and behavior.md never mentions the attribute. The *behavior* (drag-release close semantics) is covered per behavior.md → `parts/root.md` → "Events", but the ownership-marker mechanism — and therefore the multi-menu boundary condition it guards — is untested.
2. **Context-menu mouseup guards on items.** `useMenuItemCommonProps`' `onMouseUp` suppresses activation for the right-click gesture that opened a context menu (cursor-drift check and non-macOS button-2 suppression, `packages/react/src/menu/item/useMenuItemCommonProps.ts:86-104`). No test in the repo references `initialCursorPoint`, and this unit's tests never render a context-menu parent — an untested seam owned jointly with `library: context-menu`.
3. **Backdrop `userSelect` and `hidden`.** `MenuBackdrop.test.tsx` asserts only the `pointerEvents: 'none'` hover rule (matching behavior.md → `parts/arrow-backdrop-portal-viewport.md`); the always-on `userSelect: 'none'`/`WebkitUserSelect: 'none'` inline styles and the `hidden: !mounted` attribute (`packages/react/src/menu/backdrop/MenuBackdrop.tsx:44-49`) are asserted by no menu test and appear nowhere in behavior.md.
4. **Viewport `data-instant`.** `MenuViewport` forwards `instantType` into its state (`packages/react/src/menu/viewport/MenuViewport.tsx:34-38`) and `MenuViewportDataAttributes.ts` declares `data-instant`, but `MenuViewport.test.tsx` contains no `instant` assertions (behavior.md's `data-instant` coverage is popup-scoped in `parts/popup.md`).
5. **`getDisabledMountTransitionStyles` on the popup.** The helper call (`packages/react/src/menu/popup/MenuPopup.tsx:108`) suppresses mount transitions under a suspended/initially-hidden popup; no test file references the helper and no test asserts its resulting styles — its effect is currently observable only through the `BASE_UI_ANIMATIONS_DISABLED` harness toggles, not as a contract.
6. **Menu-side `keyboardEventRelay` path.** The popup's keydown relay (`packages/react/src/menu/root/MenuRoot.tsx:592-600`), its store selector inheritance for submenus (`packages/react/src/menu/store/MenuStore.ts:90-100`), and the trigger's registration of `compositeRootContext.relayKeyboardEvent` (`packages/react/src/menu/trigger/MenuTrigger.tsx:104`) are exercised by no menu test — the only `relayKeyboardEvent` references in tests live in the toolbar suites, i.e. the other end of the wire. Behavior.md → `parts/root.md` (detached-trigger/menubar sections) does not cover this plumbing.
7. **`MenuStore` parent-observer mechanics.** The constructor's `observe('parent', …)` subscription and cross-store propagation (`packages/react/src/menu/store/MenuStore.ts:126-162`) have no direct test; their *effects* (inherited `rootId`, shared `allowMouseUpTriggerRef`) are visible in detached-trigger/hover tests, but the propagation contract itself — including the unsubscribe-on-parent-change dance — is unobserved.
8. **CSS variable name constants.** `packages/react/src/menu/positioner/MenuPositionerCssVars.ts:1-37` (available width/height, anchor size, transform origin, positioner size) and `packages/react/src/menu/viewport/MenuViewportCssVars.ts` are exported style hooks referenced by no test and by no behavior.md section; whether the runtime actually emits all of them for menus is verifiable only in the golden-fixture stage.
9. **Type-only spec files are not tests.** Two of the unit's listed "source" files are compile-time assertions with no runtime behavior: `packages/react/src/menu/link-item/MenuLinkItem.spec.tsx:1-10` (LinkItem's `render` callback exposes native `href`) and `packages/react/src/menu/positioner/MenuPositioner.spec.tsx:1-4` (`keepMounted` is type-excluded on `Menu.Positioner` — only `Menu.Portal` accepts it).
