## State model (controlled/uncontrolled, defaults, transitions)

- Provider keeps a store whose state exposes `toasts`; the internal context hook `useToastProviderContext()` (imported from `./ToastProviderContext`) gives access to `store.state.toasts` `packages/react/src/toast/provider/ToastProvider.test.tsx:7` `packages/react/src/toast/provider/ToastProvider.test.tsx:66-78`.
- Each entry in `store.state.toasts` carries at least `id` and a boolean `limited` flag, read directly off the toast objects `packages/react/src/toast/provider/ToastProvider.test.tsx:71-76`.
- When `limit` is reached, the older toast is marked `limited: true` while the newer toast stays `limited: false`: after adding `first` then `second` with `limit: 1`, the observed state was `[{ id: 'second', limited: false }, { id: 'first', limited: true }]` `packages/react/src/toast/provider/ToastProvider.test.tsx:92-99`. This also proves insertion order in the store: the most recently added toast (`second`) occupies the first array slot at that observation point `packages/react/src/toast/provider/ToastProvider.test.tsx:96-99`.
- The Provider `timeout` prop drives auto-close timing: with `timeout: 1000`, a toast added during the same commit fired `onClose` after 1000ms — not called at t=999ms, called exactly once by t=1001ms `packages/react/src/toast/provider/ToastProvider.test.tsx:39-47`.
- Provider prop sync is committed-render-scoped: a `startTransition` update that changed `timeout` 5000→1000 alongside a suspending child never applied; a toast added after the abandoned render still closed on the previously committed 5000ms timeout (not called at t≈1001ms, called once at t≈5001ms) `packages/react/src/toast/provider/ToastProvider.test.tsx:102-168`.
- Positioner defaults when the toast carries no `positionerProps`: `data-side="top"` and `data-align="center"` `packages/react/src/toast/positioner/ToastPositioner.test.tsx:99-103`.
- Precedence: element-level Positioner props override the toast's `positionerProps` (`side="left"` on the element beats `positionerProps.side="bottom"`), while props not set on the element still fall back to the toast's `positionerProps` (`data-align="end"` comes from the toast) `packages/react/src/toast/positioner/ToastPositioner.test.tsx:106-132`.
- `--toast-index` transition: the newest toast gets `--toast-index: 0` and older toasts get increasing indices (`oldest` = 1 when two toasts are open) `packages/react/src/toast/positioner/ToastPositioner.test.tsx:160-161`.
- On close, the closing toast is excluded from the visible stack but keeps a real index (0, not -1) while animating out, and remaining toasts re-index (`oldest` drops from 1 to 0) `packages/react/src/toast/positioner/ToastPositioner.test.tsx:163-168`.
- External-manager mode is proven imperative/controlled: tests call `manager.add(...)` and `manager.close('newest')` directly against the `toastManager` instance `packages/react/src/toast/positioner/ToastPositioner.test.tsx:150-155` `packages/react/src/toast/positioner/ToastPositioner.test.tsx:163`.
- Per-toast `timeout: 0` is exercised `packages/react/src/toast/provider/ToastProvider.test.tsx:58-59`, but its semantics (disabling auto-close) are not asserted. UNVERIFIED — inferred from `packages/react/src/toast/provider/ToastProvider.test.tsx:58-59`, no test asserts this.

## Edge cases (rapid interactions, unmount, nesting)

- Same-commit prop + toast sync: a toast added from a descendant `useIsoLayoutEffect` in the same render pass that changes Provider `timeout` uses the updated timeout (fires at ~1000ms, not ~5000ms) `packages/react/src/toast/provider/ToastProvider.test.tsx:14-48`.
- Same-commit limit sync: two toasts added back-to-back in one layout effect observe the freshly-set `limit: 1`, with the older toast flagged `limited: true` `packages/react/src/toast/provider/ToastProvider.test.tsx:50-100`.
- Abandoned render isolation: a transition render that suspends (child throws a never-resolving promise inside `React.Suspense`) does not sync its prop changes; the toast added afterwards uses the last committed timeout `packages/react/src/toast/provider/ToastProvider.test.tsx:102-168`.
- Provider nested in `React.Suspense` is an exercised configuration `packages/react/src/toast/provider/ToastProvider.test.tsx:144-149`.
- Close-while-animating: a closing toast keeps a real `--toast-index` (0) instead of collapsing to -1 so it can animate out, while visible toasts re-index `packages/react/src/toast/positioner/ToastPositioner.test.tsx:139-169`.
- Out-of-context usage: rendering a Positioner with no Provider rejects with the descriptive `Base UI:`-prefixed error; the test spies on `console.error`, silences it, and restores it in a `finally` `packages/react/src/toast/positioner/ToastPositioner.test.tsx:172-182`.
- Unmount behavior of Provider/Portal/Positioner is not covered by this batch — no test asserts it.
