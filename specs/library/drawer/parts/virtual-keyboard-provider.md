# Virtual keyboard provider — Behavior Spec (part)

Covers behavior mined from `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx` (3709 lines; component source intentionally not consulted). ## Public API surface (props, parts, subcomponents)

- `Drawer.VirtualKeyboardProvider` is a Drawer part rendered inside `Drawer.Root`, wrapping the drawer content tree (typically `Drawer.Portal` → `Drawer.Viewport` → `Drawer.Popup` → fields). Every usage in the tests passes it **zero props**; no props are exercised by any test `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:158-181`.
- It works with both non-modal (`modal={false}`) and modal drawers (most tests use `modal={false}`; the page-restore and autoFocus tests use the default modal behavior) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:159`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2638-2650`.
- It exposes a React context consumed via `useDrawerVirtualKeyboardContext()` (imported in the test from `./DrawerVirtualKeyboardContext`). The context object exposes at least `onTouchStart` and `onTouchEnd` handler props that a consumer may attach to arbitrary elements; both are optional (the test accesses them with `?.`) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:6`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:52-63`.
- All keyboard behavior is **opt-in**: an identical drawer setup without `Drawer.VirtualKeyboardProvider` produces no scroll slack, no `scrollPaddingBottom`, and no scrolling when the visual viewport shrinks `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:692-737`.
- Several tests use `Drawer.Popup initialFocus={false}` to prevent the popup from stealing focus so the keyboard-target capture can be tested deterministically `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2396`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3417`.

## State model (controlled/uncontrolled, defaults, transitions)

All state is internal; no controlled props or callbacks are proven. The observable state model:

- **Keyboard inset value**: derived from the visual viewport. Formula proven: `inset = innerHeight − min(innerHeight, visualViewport.offsetTop + visualViewport.height)` — with innerHeight 800, `offsetTop` 40, height 500, the viewport element gets `--drawer-keyboard-inset: 260px` `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2810-2819`. With no offset this is `800 − 500 = 300px` `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:569-579`. When the keyboard is not open the variable is `'0px'` `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:585-587`.
- **Open threshold**: a visual-viewport reduction smaller than 60px (`KEYBOARD_RESIZE_THRESHOLD`, per the test comment) is treated as browser-chrome movement, not the software keyboard: with innerHeight 800 and viewport height 750 (50px reduction) the inset stays `'0px'`, no slack is added, and `overflowAnchor` is never touched `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2767-2778`.
- **Pinch-zoom kill switch**: while `visualViewport.scale ≠ 1` (test uses 1.5) both the inset/slack computation and tap-to-focus interception are disabled: no slack, no `scrollPaddingBottom`, no scrolling `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:862-877`, and taps on inputs are left fully native (no preventDefault, no focus) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3242-3259`.
- **Tracked keyboard target**: the currently focused keyboard-eligible element. Transitions proven:
  - Set on `focusin` of an eligible field (input, textarea, contentEditable, or the control labelled by a tapped/focused `label`) — including fields inside shadow roots `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:595-633`.
  - Kept when focus moves directly to another keyboard input: a synthetic bubble-phase `focusout` from input A with `relatedTarget` = input B (and no following `focusin`) leaves the inset at `300px` — the comment states focus must re-align to the new target, not clear the inset, to avoid flicker to `0px` between fields `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:672-684`.
  - Cleared on blur of the field: inset returns to `'0px'` `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:581-587`.
  - Cleared when a tapped input redirects focus to a non-keyboard element (consumer `focusin` handler calls `other.focus()`): the button keeps focus and the inset is `'0px'` — the provider reconciles when focus lands on a non-keyboard element `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2153-2179`.
  - Cleared when a tapped input blurs itself from `onFocus` (consumer opens its own picker): the `focusout` arrives before `.focus()` returns, focus ends on `body`, and no `focusin` follows — that `focusout` alone must drop the target, so the frame-scheduled alignment never applies the inset/slack to the abandoned field (inset `'0px'`, `paddingBottom` restored, `scrollPaddingBottom` cleared after 3 animation frames) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2253-2281`.
  - Cleared when the tracked field is no longer contained in the viewport (removal simulated by mocking `viewport.contains` to return false for the input): a subsequent viewport resize (500 → 490) resets the inset to `'0px'` and restores the scroller `paddingBottom` `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3389-3397`.
- **Adjusted scroll container**: exactly one scroll container holds slack at a time. When focus moves to a field in a different scroll container, the new container gains slack and the previous one has its inline `paddingBottom` restored (to `'10px'`) and its `overflowAnchor` inline style removed (`''`) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3143-3160`.
- **Gesture tracking (tap vs scroll)**: a `touchstart` records the touch target and start point; `touchend` yields a tap only if no `touchcancel` intervened and the finger moved ≤ the move threshold (10px, `INPUT_TAP_MOVE_THRESHOLD` per test comment). Moving 80px before lifting → no preventDefault, no focus; moving 5px → tap (preventDefault + focus) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3039-3071`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1369-1425`.
- **Alignment scheduler**: after a new target is captured, a frame-scheduled alignment pass measures geometry and may defer; delayed realign passes follow. `pointerdown` on the scroller cancels both the pending frame alignment and the delayed passes `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2102-2119`. The scheduler defers scrolling until measured geometry stops changing, but has a bounded give-up: when geometry oscillates on every read (never settles), exactly one alignment `scrollTo` is still issued (after 65 advanced frames) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2361-2377`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2444-2451`.
- UNVERIFIED — inferred from `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:217-218`, no test asserts this: in normal (non-reduced-motion) motion the alignment scroll is animated/smooth; only the reduced-motion `behavior: 'auto'` form is directly asserted `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1874-1882`.

## Keyboard interactions

No physical-keyboard key handling is proven anywhere in this file — "keyboard" here means the on-screen (virtual) keyboard. Proven virtual-keyboard interactions:

- **Viewport tracking**: the provider reacts to `visualViewport` `'resize'` events (the test mock emits `'resize'` for both height and scale changes) and `'scroll'` events (offset/height changes) to recompute the inset and re-evaluate alignment `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:109-123`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:226-230`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2810-2819`.
- **If `window.visualViewport` is unavailable** (set to `undefined`), focusing an input and running animation frames produces no alignment and the inset stays `'0px'` — handled gracefully `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3676-3702`.
- **Tap-to-focus**: on a qualifying tap (see gesture state above) over a keyboard-eligible element, the provider calls `element.focus({ preventScroll: true })` and `preventDefault()`s the `touchend` `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:939-945`.
- **Re-summon keyboard on already-focused input**: if the tapped input is already focused but the keyboard viewport is closed (mock viewport height 800), the provider calls `input.blur()` exactly once, then `focus({ preventScroll: true })` `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1583-1599`. If the input is already focused and the keyboard viewport is open (mock height 500), the tap is left native (no preventDefault, no focus call) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1519-1539`. Plain focus changes while the keyboard is closed never trigger the blur/refocus cycle (`second.blur()` never called; `second.focus` called exactly once — the test's own call) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2604-2618`.
- **Tap-less focus change while keyboard open** (e.g. iOS next-field arrow): focusing a second input applies a synchronous geometry override — by the time a bubble-phase `focusout` listener on `document` fires, `second.style.transform` already contains `translateY`; afterwards the inline `transform` and `opacity` are cleaned back to `''`, `blur()` is not called, and the new field keeps focus `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1644-1661`. The new field is also centered inside the scrollable body (scroll position moves so the field center matches the visible-band center) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1764-1775`.
- **Alignment scrolling**: the focused field is centered in the visible band: `inputCenter ≈ (scrollRect.top + min(scrollRect.bottom, keyboardViewportHeight)) / 2`, and the scroll container is scrolled to `scrollTop = fieldCenter − visibleCenter` (e.g. `scrollTo({ top: 270, ... })` for the test geometry) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:241-247`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2561-2568`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1874-1882`.
- **Reduced motion**: when `matchMedia('(prefers-reduced-motion: reduce)')` matches, the alignment scroll is issued as `{ top: 270, behavior: 'auto' }`, is not re-issued while progressing (scrollTop moved to 100 mid-flight, 150ms later still one call), and is not restarted once settled (scrollTop 270) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1788-1793`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1874-1896`.
- **Stall recovery**: if the scroll never actually moves (mock `scrollTo` that does nothing, standing in for a smooth scroll canceled by WebKit's native reveal resolution), delayed realign passes re-issue the alignment — `scrollTo` called ≥ 2 times, last with `top: 270` `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1982-2001`.
- **Realign on tap while keyboard already open elsewhere**: with the keyboard open for a footer field outside the scroller, tapping a `textarea` inside the scroller focuses it and the frame pass centers against the *squeezed* geometry (`scrollTop` 430); when the scroller then expands (bottom 380 → 480, no viewport event fires), the delayed realign passes re-center against the expanded geometry using `visibleCenter = (scrollRect.top + min(scrollRect.bottom, keyboardViewportHeight)) / 2` `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2531-2568`.

## Focus management

- **Focus capture** works through shadow roots: an `input` appended to an open shadow root inside the popup is captured on focus; the inset is applied `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:614-628`.
- **Tap focus targets** (all focus with `{ preventScroll: true }` unless noted):
  - Text inputs `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:939-945`.
  - Textareas (they get alignment/slack via their scroll ancestor, never on themselves) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:444-449`.
  - `contentEditable` elements `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2901-2914`.
  - Nested non-focusable elements inside a `contentEditable` resolve focus to the **editing host** (the editor `div` receives focus) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2943-2960`.
  - A tapped `<label htmlFor>` focuses the **labelled control** (`input.focus({ preventScroll: true })`) and re-dispatches the click on the label `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2855-2872`.
- **Blur/refocus cycle**: only for tapping an already-focused input while the keyboard viewport is closed (`blur()` once, then `focus({ preventScroll: true })`) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1597-1599`.
- **Consumer focus redirects** (validation / auto-advance / custom pickers) are reconciled: focus redirected away on `focusin` leaves the button focused with inset `'0px'` `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2157-2179`; self-blur on `focusin` ends with no focus on the input, inset `'0px'`, slack restored `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2258-2281`.
- **Initially focused input** (modal drawer, `autoFocus`, viewport already reduced): the input keeps focus, the inset is `300px`, and `window.scrollTo` is never called — the initial capture must not attempt a page restore `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3426-3432`.
- The tap-focus call must not scroll the page (`preventScroll: true` — test title "without page scroll") and must not mutate the touched element's inline styles (`opacity`, `transform`, `transition` all unchanged) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:945`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:952-954`.

## Events (names, payload shape, bubbling, preventDefault semantics)

No custom events with payloads are emitted by the provider. Proven event handling:

- **`visualViewport` events**: `'resize'` (height and scale changes) and `'scroll'` (offset/height changes) drive inset computation and realignment; the test mock emits exactly these `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:109-123`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:569-572`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2810-2819`.
- **`window` `'scroll'` (modal only)**: while a modal drawer has the keyboard open, a page scroll (simulated by setting `window.scrollY = 120` and dispatching a `scroll` event on `window` — "WebKit's native reveal scroll escaping the scroll lock") triggers `window.scrollTo({ left: 0, top: 0, behavior: 'instant' })` — the object form with `'instant'` so a global `scroll-behavior: smooth` cannot animate the restore `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2662-2668`. For a non-modal drawer the same simulation calls `window.scrollTo` zero times `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2714-2717`.
- **Touch events** (on the touch target's tree):
  - `touchstart`: begins tap/swipe tracking; a tap candidate requires it. With `data-base-ui-swipe-ignore` on the touched element, the drawer's swipe state does not start (see below) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1297-1308`.
  - `touchmove`: moving the touch > 10px from the start point marks the gesture as a scroll — subsequent `touchend` is not intercepted (no preventDefault, no focus); ≤ 10px still yields a tap `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3039-3071`.
  - `touchcancel`: aborts the tracked tap — a following `touchend` is not prevented and no focus occurs `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1399-1420`.
  - `touchend`: when the provider handles the tap it calls `preventDefault()` (asserted via `touchEnd.defaultPrevented === true`) and focuses `{ preventScroll: true }` `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:944-945`. When it declines the tap the event is left native (`defaultPrevented === false`): picker inputs `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1006-1007`, lift over a neighboring interactive element `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1059-1061`, disabled inputs `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1169-1171`, already-focused input with keyboard open `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1538-1539`, pinch-zoomed `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3258-3259`.
- **Synthetic click re-dispatch**: preventing `touchend` suppresses the native compatibility click, so the provider re-dispatches a `click` on the touched element with the touch's `clientX`/`clientY` and `detail: 1` (input: coords 12/34 `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:946-951`; label: coords 24/48 `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2869-2872`). No synthetic click is dispatched when the tap is declined (disabled input, disabled label→control) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1171`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1265`.
- **`focusin` / `focusout`** (document-level, capture phase per test comments): drive target capture and release; `focusout`'s `relatedTarget` decides whether the inset is kept (moving to another keyboard input) or cleared `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1642-1643`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2154-2157`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:676-684`.
- **`pointerdown`** (bubbling, on the scroll container): cancels pending frame alignment and delayed realign passes so a user scroll is never yanked back `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2102-2119`.

**Lift-point resolution** (how the provider decides what a tap hit): the lift coordinates come from `touchend` `changedTouches` first, falling back to `touches` when `changedTouches` is empty; the element is resolved via hit-testing at that point, probing nearby points when the exact point misses (a mock that only resolves the input 16px below the lift point still finds it — "hit-slop probe"), falling back to the touchstart target when `elementFromPoint` returns `null`, and using a MouseEvent-based lookup when `window.PointerEvent` is undefined `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:2989-3008`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3544-3556`, `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3580-3600`. The lift point wins over the native touch target (finger lifting over a neighboring button leaves the tap native and dispatches no synthetic click on the input) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1041-1061`, and the hit-slop probe must not steal a tap that lands exactly on an interactive element (button) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3191-3210`.

## Edge cases (rapid interactions, unmount, nesting)

- **No `touchstart` before `touchend`**: the touchend is not prevented and no focus occurs — tap tracking requires a preceding touchstart `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1351-1362`.
- **`touchcancel` then `touchend`**: the late touchend is ignored (not prevented, no focus) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1399-1420`.
- **Tap vs scroll**: 80px move → gesture is a scroll (no focus); 5px move → still a tap (preventDefault + focus) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3039-3071`.
- **Drawer closed but kept mounted** (`preventUnmountOnClose`, popup has `data-closed`): taps handled through the directly wired context handlers (`onTouchStart`/`onTouchEnd` from `useDrawerVirtualKeyboardContext()`) are inert — the input does not receive focus after touchstart/touchmove/touchend `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3444-3486`.
- **Nested drawer open**: the parent popup carries `data-nested-drawer-open=""`; while a nested `Drawer.Root` is open, tap-to-focus in the parent is suppressed (touchend not prevented, no focus) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:1458-1482`.
- **Drawer close restores styling**: with slack applied (and overflowAnchor `'none'`), setting `open={false}` restores `paddingBottom` to `'20px'`, clears `scrollPaddingBottom`, and restores `overflowAnchor: 'auto'` while the popup is still mounted during close `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:810-827`.
- **Previously adjusted scroll container removed from the DOM** (`isConnected` false): its slack is still restored (`paddingBottom` back to `'10px'`, `overflowAnchor` `''`) before the new container is adjusted `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3323-3340`.
- **Focused field removed**: keyboard state is dropped when the tracked field is no longer contained in the viewport (inset `'0px'`, slack restored on the next viewport resize) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3389-3397`.
- **Lift point outside the drawer**: if hit-testing resolves to an element outside the drawer, nothing is focused (neither the inside nor the outside input) `packages/react/src/drawer/virtual-keyboard-provider/DrawerVirtualKeyboardProvider.test.tsx:3513-3523`.
