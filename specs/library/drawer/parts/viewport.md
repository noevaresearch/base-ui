## Public API surface (props, parts, subcomponents)

- `Drawer.Viewport` renders a single `HTMLDivElement` (conformance asserts `refInstanceof: window.HTMLDivElement`). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:17-26`
- It is a generic element: conformance runs the full suite — prop spreading/forwarding, ref forwarding, render prop, and `className` — with no skips. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:17-26` (helper suite listing: `packages/react/test/describeConformance.tsx:44-49`)
- It accepts `data-testid`, `ref`, `style`, and arbitrary element props (used throughout, e.g. `style={{ position: 'fixed', inset: 0, pointerEvents: 'none' }}`). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1366`
- The viewport must be rendered inside `Drawer.Portal` within a `Drawer.Root` (the conformance wrapper and every test do so). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:19-25`
- Composes with: `Drawer.Root` (open/snap state source), `Drawer.Portal` (mount target), `Drawer.Backdrop` (receives swipe-state attributes), `Drawer.Popup` (receives movement CSS variables and ending attributes), `Drawer.Content`, `Drawer.Close`, `Drawer.Provider`/`Drawer.Indent` (progress publication). It owns no subcomponents of its own — no test renders any `Drawer.Viewport.X` part. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:211-249`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4519-4543`

- Internal context consumed by test fixtures (proving the integration surface): `useDialogRootContext().useState('open')`, `useDrawerRootContext().onNestedSwipeProgressChange`, `useDrawerProviderContext().visualStateStore.set({ swipeProgress, frontmostHeight })`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:10-12`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4676`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4733-4735`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4822-4826`

## State model (controlled/uncontrolled, defaults, transitions)

Open state:

- `onOpenChange(nextOpen: boolean, details)` is called with `false` and a details object containing `reason: 'swipe'` when a touch swipe dismisses the drawer. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:958-961`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2165-2168`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2236-2239`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2307-2310`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2378-2381`
- The open-change details object also exposes `preventUnmountOnClose()`; when used, the popup stays mounted in a closed state (popup carries `data-closed`). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4298-4330`

Snap points:

- `snapPoints` accepts mixed string/number values: `['100px', '200px']`, `['200px', '100px']` (order matters for resolution — the taller point may be declared first), `[300, 100]`, `['100px', 1]` (1 = full), `['50%']`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1851`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1363`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3230`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4045`
- `defaultSnapPoint` selects the initial snap point (e.g. `"100px"`). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3666`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3762`
- `snapPoint` is controlled; changing it via re-render re-publishes resting progress. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4614`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4663`
- `onSnapPointChange(nextSnapPoint, details)` fires on release/settle with the resolved snap point (`'100px'`, `'200px'`) or `null` when the release would close the drawer. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3299-3300`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3379`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3640`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3740`
- The details object exposes `cancel()`; canceling the `null` (close) transition suppresses swipe dismissal entirely: `onOpenChange` is never called and no ending attributes are written (a `MutationObserver` on `data-ending-style`/`data-swipe-dismiss` records zero mutations). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3650-3658`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3740-3744`
- Snap-point resolution requires a measurable popup: when the popup's `offsetHeight` is 0, swipe-to-dismiss is suppressed (`onOpenChange` not called even after a 40px drag). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3971-4040`
- When snap points cannot be resolved at all (here: `snapPoints={['50%']}` with mocked popup height 200 and unmocked viewport height), the gesture falls back to regular dismissal — a 140px downward swipe calls `onOpenChange(false, …)`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4042-4106`
- Tests resolve exact dimensions via `offsetHeight`/`offsetWidth` mocks (helper `setHeight` defines `offsetHeight` as a configurable property); the viewport height (mocked to 400) and popup height (mocked to 200/300) are both involved in snap-point math. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:40-44`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3234-3235`

Swipe/session state (transient, per gesture):

- While a drag is active, the `Drawer.Backdrop` has `data-swiping=""`; it is removed on pointer up. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3020-3076`
- The popup carries `--drawer-swipe-movement-x` / `--drawer-swipe-movement-y` (px strings, e.g. `'30px'`, `'-10px'`) that track the live drag; they reset to `'0px'` on reopen of a kept-mounted drawer. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2628`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1947-1948`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4721`
- The popup exposes `--drawer-snap-point-offset` (`'0px'` initially when snap points resolve); consumers position the sheet with e.g. `translateY(calc(var(--drawer-snap-point-offset) + var(--drawer-swipe-movement-y)))`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1394-1396`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1376-1378`
- Nested drawers: while a child drawer swipe exceeds the movement threshold, the parent popup gets `data-nested-drawer-swiping=""` and a nonzero `--drawer-swipe-progress`; both revert (`'0'`, attribute removed) when the swipe is reversed before release, when release settles on a snap point, or after an unattributed gesture ends. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1080-1102`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1171-1185`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3442-3454`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3547-3550`
- Nested swipe progress is settable from the root context: calling `onNestedSwipeProgressChange(0.5)` sets `--drawer-swipe-progress: 0.5` on the parent popup. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4733-4735`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4785-4788`
- Provider publication: during a drag, `Drawer.Indent` receives `--drawer-swipe-progress` (movement/popupHeight; 39px drag on a 100px popup → ≈0.39, because the first move only re-anchors the drag origin) and `--drawer-height` (the popup's height, e.g. `'100px'`); both clear to `'0'`/`''` when the drag returns to origin. The same state is reachable via `visualStateStore.set({ swipeProgress, frontmostHeight })`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4552-4588`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1925`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4823-4826`
- Backdrop resting progress with snap points: a modal, open drawer with `snapPoints` renders `--drawer-swipe-progress: '1'` on the backdrop at rest, and a press/release inside `Drawer.Content` that never starts a swipe leaves it at `'1'` (the release handler still runs but reports no deltas). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3944`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3947-3948`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3968`. UNVERIFIED — inferred from `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4614-4665`: in a `modal={false}` controlled-snapPoint test, a snap-point change writes `--drawer-swipe-progress: '0'` on the backdrop; no test pins the unified semantic of this variable across backdrop vs popup/indent consumers.
- Ending attributes: when a release settles on a snap point (including unattributed and sequential modes) the popup does NOT receive `data-ending-style` or `data-swipe-dismiss`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3301-3302`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3547-3548`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3641-3642`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3831` (What sets them on a real dismiss is only proven negatively here.)
- Reopening a kept-mounted, previously swiped drawer clears stale state during layout: `--drawer-swipe-movement-y` is reset to `'0px'` and `data-swipe-dismiss` is removed before descendant passive effects run. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4671-4726`

## DOM structure & portal behavior

- The viewport is a plain `div` rendered inside `Drawer.Portal`; it may contain `Drawer.Popup` (with optional `Drawer.Content`, `Drawer.Close`) and the portal may also contain `Drawer.Backdrop` as a sibling of the viewport. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:19-25`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:371-381`
- Shadow DOM: `Drawer.Portal` accepts `container={shadowRoot}`; the viewport, popup, and backdrop mount into the shadow root, and swipe hit testing consults the shadow root's own `elementFromPoint` — a document-level hit test returning an in-popup element is not sufficient to start a swipe when the shadow-root lookup yields a non-swipeable (e.g. `data-base-ui-swipe-ignore`) element. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:251-315` (skipIf(isJSDOM) real-hit-testing variant: `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:317-367`)
- Hit testing is coordinate-based: every swipe test stubs `document.elementFromPoint` to control which element the pointer is "over", which the viewport uses to map raw pointer/touch events to the actual target. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:89-90`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:287-288`
- Events whose composed path has no element (e.g. `composedPath()` returning `[window]`) fall back to the viewport as the target, and swiping still works. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4433-4467`
- Descendants portaled outside the drawer's portal container (via `ReactDOM.createPortal` to another `document.body` node) are still recognized as drawer content for scroll arbitration: their `touchmove` is not prevented. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:592-641`
- A nested `Combobox` popup (its own portal/positioner/listbox) inside the drawer content is left alone: touch gestures on its scrollable list do not start a drawer swipe, do not call `onOpenChange`, and the listbox stays visible. Chromium-only (`it.skipIf(isJSDOM)`). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:643-739`
- The popup must be mounted for swipe input to have any effect: a viewport without a popup swallows a full down/move/up gesture and never calls `onOpenChange`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4180-4222`
- A closed but still-mounted drawer (closed via `Drawer.Close` with `preventUnmountOnClose()`) ignores pointer swipes: no `data-swiping`, no `onOpenChange`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4293-4352`

## Events (names, payload shape, bubbling, preventDefault semantics)

Pointer (mouse) drag path — all on the viewport element, hit-test mapped:

- `pointerdown` (mouse, `buttons: 1`) with the hit-test target inside the popup begins drag tracking. If the document selection's endpoints are popup elements, the selection is cleared (`removeAllRanges()` called once); selections anchored outside the popup are preserved (`rangeCount` stays 1, text intact). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:55-106`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4354-4390`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:108-156`
- Touch (`touchstart`) never clears the selection. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:158-209`
- Non-touch (mouse/pen) swipes do not start from `Drawer.Content` or its descendants: a mouse `pointerdown` on a div inside `Drawer.Content` (hit-test target) never sets `data-swiping`, and a press on `Drawer.Content` itself never starts a swipe even though the release handler runs. Mouse drags do start when the hit-test target is the popup itself (no `Content` boundary). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:803-841`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3947-3948`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3949-3968`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3040-3061`
- Pen input is treated as non-touch: a pen `pointerdown` on a button inside `Drawer.Content` sets no `data-swiping`, and the subsequent `touchstart`/`touchmove` sequence does not start a swipe nor prevent the touchmove. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:964-1031`
- The first `pointermove` only re-anchors the drag origin (moving to the same coordinates is a no-op for movement). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1925-1932`
- `data-swiping=""` appears on the backdrop once movement starts (after a move, not on down) and is removed on `pointerup`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3040-3072`
- `pointercancel` cancels the drag (backdrop `data-swiping` removed). A touch-type pointer `pointercancel`/`pointerdown` pair is ignored entirely (compatibility events for touch do not drive the pointer path). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3114-3124`
- A full touch-type compatibility pointer sequence (`pointerdown/move/move/up/cancel` with `pointerType: 'touch'` and real displacement) is ignored: no `data-swiping`, no `onOpenChange` — touch is handled via touch events, not pointer events. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4469-4517`
- Releasing the primary mouse button mid-gesture ends the drag: a `pointermove` with `buttons: 2` (right button) or `buttons: 0` stops swiping (backdrop `data-swiping` removed). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4108-4178`
- Overshoot damping: with snap points, dragging past the fully-open edge replaces the raw frozen transform with square-root-damped movement — a 100px upward overshoot yields `--drawer-swipe-movement-y: '-10px'`. Duplicate-coordinate moves (cursor pinned at the screen edge) and horizontal jitter while vertically pinned must not reinstate the raw (undamped) transform or change the damped offset. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1895-1984`
- `touchstart` with an empty `touches` list is ignored. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3130-3144`
- Two-finger `touchmove` (pinch-zoom) is left to the browser: no preventDefault, no `data-swiping`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4907-4937`

Touch swipe-to-dismiss:

- Touch swipes start from interactive elements (a `<button>` inside the popup) once the hit-test maps to it. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:211-249`
- `data-base-ui-swipe-ignore` on an element blocks swipe start from it: a full touch gesture over such an element produces no `data-swiping` and no `onOpenChange`. The legacy attribute `data-swipe-ignore` does NOT block swipes (swiping proceeds). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:536-590`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:741-801`
- A tap (touchstart + touchend + click, no movement) on a non-ignored, non-interactive element fires the element's `onClick` exactly once, never calls `onOpenChange`, and sets no `data-swiping`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:480-534`
- Starting a touch outside the popup and moving into it does not jump the sheet: `--drawer-swipe-movement-y` stays `0` while the finger is outside, even though `data-swiping` is set. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:843-891`
- Starting outside and swiping far enough inside dismisses: `onOpenChange(false, { reason: 'swipe' })`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:893-962`
- Scroll arbitration (the core touchmove policy; `fireEvent`/`dispatchEvent` return `false` when the event was preventDefault'ed, `true` otherwise):
  - At a scroll container's dismiss-blocking edge (top for down drawers, bottom for up drawers), an in-axis `touchmove` is prevented AND does not reach React `onTouchMove` handlers on the target or ancestors. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1191-1237`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1239-1289`
  - Scrolling away from the blocking edge is allowed: at scroll top moving the finger up (content scrolls down) is not prevented and the container's `onTouchMove` fires once. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1801-1847`
  - A scrollable ancestor that wraps (rather than sits inside) the popup is honored: touchmove over popup content is prevented when that ancestor sits at its top edge. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1291-1345`
  - With no scroll container at all, touchmove is prevented and the swipe engages. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1426-1471`
  - A scrollable container away from its dismiss edge keeps the gesture for native scrolling first: an in-axis touchmove is prevented but `data-swiping` is not set; once the container reaches the dismiss edge (`scrollTop` → 0), the next in-axis move starts the swipe (`data-swiping` set). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2032-2098`
  - Swipe-to-dismiss completes from all four scroll-edge configurations: top-edge scroll down, bottom-edge scroll up, left-edge horizontal scroll right (right drawer), right-edge horizontal scroll left (left drawer) — each ends with `onOpenChange(false, { reason: 'swipe' })`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2100-2169`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2171-2240`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2242-2311`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2313-2382`
  - Cross-axis scrolling inside a perpendicular drawer wins: a horizontal swipe-dismiss attempt from mid-scroll in a vertical container is allowed (slop-passing drawer-axis move claims it: `data-swiping` set after a 20px horizontal move). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2384-2434`
  - Axis-attribution slop: below the slop the first `touchmove` is never prevented (3px move on the drawer axis is dispatched; iOS comment: preventing the first cancelable touchmove cancels native scrolling for the whole gesture). Past the slop on the drawer axis (12px move) the gesture is claimed (touchmove prevented). Threshold proven between 3px and 12px (nested threshold data shows 5px unclaimed / 20px claimed). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2436-2485`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2487-2533`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1082-1102`
  - A non-cancelable `touchmove` before the claim means the browser committed to native scroll: the gesture is yielded, and even a decisive drawer-axis move afterwards is not claimed (not prevented). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2535-2590`
  - Once claimed, a drag returning inside the slop is NOT re-arbitrated (still prevented) and keeps tracking the finger — `--drawer-swipe-movement-x` goes negative past the origin. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2592-2648`
  - Once claimed, non-cancelable moves still drive the drag (movement grows 50→100→150px) and later cancelable moves are still prevented. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2650-2715`
  - Minor cross-axis jitter (4px/3px) does not lock out the drawer axis: a later 28px drawer-axis move claims the gesture. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2717-2776`
  - Mixed-axis scroll containers (overflow both ways, one axis exhausted) are not hijacked: a mostly-cross-axis diagonal move produces no `data-swiping`. Chromium-only. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2778-2834`
  - Single-axis overflow containers never block cross-axis scrolling in any drawer orientation (right/left drawers with vertical-only overflow; down/up drawers with horizontal-only overflow): moves are dispatched and no `data-swiping`. All Chromium-only. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2836-2880`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2882-2926`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2928-2972`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:2974-3018`
  - Native form controls are exempt: `touchmove` over `<input type="range">` and over a `Slider` thumb input is dispatched (not prevented) and no swipe starts. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1473-1512`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1514-1560`
  - Active text selections suppress swipe start: with an active selection on `<input>`, `<textarea>`, `contentEditable`, or a plain span (selection-handle adjustment gesture), `touchstart` + `touchmove` produce no `data-swiping` and are not prevented. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1562-1614`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1616-1668`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1670-1735`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1737-1799`
  - An expanded touch selection whose anchor is outside the popup but focus inside it does not start a swipe either (mocked `document.getSelection` with `anchorNode` outside / `focusNode` in popup → no `data-swiping`). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4392-4431`
  - Opposite-direction guards: a down drawer with snap points will not start an up-swipe from a scroll container at its bottom; a right drawer will not start a left-swipe from a container at its right scroll edge (move dispatched, no `data-swiping`). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1849-1893`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1986-2030`
  - A scroll container without overflow still gets its `touchmove` prevented (prevents page-scroll chaining), while non-cancelable moves pass through untouched. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4939-4980`
  - A stationary touch (touchmove at identical coordinates) in overflowing content is not claimed (not prevented). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:5032-5062`
  - A claimed scroll-edge swipe keeps moving through non-cancelable events AND stops them from reaching ancestor React `onTouchMove` handlers; subsequent cancelable moves are still prevented. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4982-5030`
  - Page-scroll edge: with `body` itself a scroll container (Chromium-only), swiping up away from the page scroll edge (body at scrollTop 0) still starts a swipe. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1347-1424`

Release resolution & velocity (uses `firePointer` with pinned `timeStamp`; see harness notes):

- Regular dismissal with snap points: horizontal drawers (`swipeDirection="left"`) with snap points configured still use plain swipe dismissal — dragging 180→40px calls `onOpenChange(false, …)`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3146-3215`

## Edge cases (rapid interactions, unmount, nesting)

- Unmount mid-swipe: unmounting the whole drawer while a touch swipe is active removes `data-swiping` from the (now detached) backdrop during cleanup. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:369-410`
- Popup unmount mid-swipe: if the popup is removed while dragging, subsequent moves still show `data-swiping` but the final `pointerup` clears it and never calls `onOpenChange`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4224-4291`
- Kept-mounted closed drawer: pointer swipes are ignored while closed (`data-closed` present on popup; no `data-swiping`, no `onOpenChange`). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4293-4352`
- Reopen resets stale swipe state during layout, before descendant passive effects: `--drawer-swipe-movement-y` forced to `'50px'` and `data-swipe-dismiss` set while closed are cleared (`'0px'`, attribute removed) synchronously with the reopen. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4671-4726`
- Nested drawers: `data-nested-drawer-swiping` is not set on the parent popup until movement passes the threshold (5px move: unset; 20px move: set); both viewports lack `data-nested-dialog-open` during this flow. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1033-1106`
- Nested swipe reversed before release: moving back to the origin clears `data-nested-drawer-swiping` and resets the parent popup's `--drawer-swipe-progress` to `'0'`. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:1108-1189`
- Nested state after unattributed snap-point gesture: parent is marked with nonzero progress during the drag; on `pointerup` progress returns to `'0'` and the attribute is removed. Same clearing after an attributed drag that settles on a snap point (child popup gets no `data-ending-style`/`data-swipe-dismiss`). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3384-3458`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3460-3557`
- Child drawer closing clears the parent popup's nested progress during layout (before descendant passive effects): `--drawer-swipe-progress` set to `0.5` via `onNestedSwipeProgressChange` is reset to `'0'` when the child unmounts/closes. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4728-4811`
- Viewport teardown clears provider and backdrop state during layout teardown (before passive effects): an `Indent` showing `--drawer-swipe-progress: 0.5` / `--drawer-height: 100px` and a backdrop with `data-swiping` are all cleared when the viewport is removed. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4813-4905`
- Resting snap progress is republished before descendant passive effects when the controlled `snapPoint` changes (a `setProperty('--drawer-swipe-progress','0')` on the backdrop is observed to happen before the passive-effect flush). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4594-4669`
- `document.elementFromPoint` returning different elements on successive calls (scroll arbitration target rotation) is handled: the swipe claims based on the relevant target. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:446-451`
- Non-measurable popup (`offsetHeight` 0) blocks snap-point dismissal entirely. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3971-4040`
- All-invalid snap points (`['50%']` unresolvable in the test env) fall back to regular dismissal. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:4042-4106`
- Canceled snap-point close: `onSnapPointChange(null, details)` still fires, but `details.cancel()` prevents both the dismissal and any ending-attribute writes (verified with a `MutationObserver` attribute log that stays empty). `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3648-3748`
- Many release-resolution tests run under `vi.useFakeTimers()` (with `firePointer` pinning event `timeStamp`s), indicating settle/animation scheduling uses timers; `timeStamp` pinning exists so gesture-velocity logic is clock-independent. `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3221-3306`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3461-3557`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3563-3646`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3661-3748`, `packages/react/src/drawer/viewport/DrawerViewport.test.tsx:3754-3923`
