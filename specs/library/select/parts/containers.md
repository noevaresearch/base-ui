## State model (controlled/uncontrolled, defaults, transitions)

- Controlled `open` renders the popup content; a closed select starts with `aria-expanded="false"` on the trigger (`packages/react/src/select/popup/SelectPopup.test.tsx:102-105`).
- Uncontrolled open via `defaultOpen` also mounts the positioned popup and lets the component close itself (`packages/react/src/select/positioner/SelectPositioner.test.tsx:288` is `defaultOpen`; the scroll-resize helper uses `open={undefined} defaultOpen` when `uncontrolledOpen` is set: `packages/react/src/select/popup/SelectPopup.test.tsx:1157-1160`, `packages/react/src/select/popup/SelectPopup.test.tsx:1652-1660`).
- `onOpenChange` is invoked on user open: in the rtl fixture the popup appears after clicking the combobox even though `open` is fully controlled by `React.useState` fed by `onOpenChange={setOpen}` (`packages/react/src/select/popup/SelectPopup.test.tsx:649-655`, `packages/react/src/select/popup/SelectPopup.test.tsx:700-712`). The payload shape passed to `onOpenChange`: UNVERIFIED — inferred from `packages/react/src/select/popup/SelectPopup.test.tsx:655`, no test asserts the arguments.
- Transitions proven to close the select: Escape key (`packages/react/src/select/popup/SelectPopup.test.tsx:555-556`, `packages/react/src/select/positioner/SelectPositioner.test.tsx:301-306`), clicking an item (`packages/react/src/select/popup/SelectPopup.test.tsx:561-562`), clicking an item via `element.click()` in the finalFocus tests (`packages/react/src/select/popup/SelectPopup.test.tsx:1699-1706`), and a window `resize` event when the popup is item-aligned (`packages/react/src/select/popup/SelectPopup.test.tsx:1662-1671`).
- `defaultValue` seeds the selected item, which is the item used for trigger alignment and the item focused on keyboard open (`packages/react/src/select/popup/SelectPopup.test.tsx:204-217`, `packages/react/src/select/popup/SelectPopup.test.tsx:50-59`).
- `multiple` changes the listbox's `aria-multiselectable` (see Accessibility); no multi-select interaction is asserted in this batch.
- No test in this batch asserts value-change state (`onValueChange`) or the controlled `value` prop.

## Keyboard interactions

- Enter on a focused trigger opens the select: after `user.keyboard('{Enter}')` a `listbox` is present (`packages/react/src/select/popup/SelectPopup.test.tsx:73-74`).
- Keyboard open moves focus onto the selected item: with `defaultValue="a"`, after Enter the option named `a` has focus (`packages/react/src/select/popup/SelectPopup.test.tsx:73-77`).
- ArrowRight is swallowed by the popup while the popup owns focus: when the trigger lives inside a `Toolbar.Root`, pressing ArrowRight with focus inside the popup does not invoke the toolbar's `onKeyDown` and does not move focus to the next `Toolbar.Button` (`packages/react/src/select/popup/SelectPopup.test.tsx:80-87`). The test also notes Enter is *not* a composite key, so the open keystroke legitimately reaches the toolbar (comment only; the assertion covers ArrowRight: `packages/react/src/select/popup/SelectPopup.test.tsx:79-87`).
- Escape closes the select: after `user.keyboard('{Escape}')` the trigger's `aria-expanded` becomes `false` (`packages/react/src/select/popup/SelectPopup.test.tsx:555-556`), and in the positioner test the kept-mounted positioner becomes `hidden` after Escape (`packages/react/src/select/positioner/SelectPositioner.test.tsx:301-306`).
- No other keys (arrows navigation, typing/typeahead, Home/End, Tab) are asserted in this batch.

## Focus management

- Default close-focus is the trigger: open via `trigger.click()`, close via item click, and the trigger ends up with focus (`packages/react/src/select/popup/SelectPopup.test.tsx:1694-1707`).
- `finalFocus={refObject}` moves focus to the referenced element on close instead of the trigger (`packages/react/src/select/popup/SelectPopup.test.tsx:1709-1749`).
- `finalFocus` as a function returning an element focuses that element on close (`packages/react/src/select/popup/SelectPopup.test.tsx:1751-1787`).
- `finalFocus={false}` disables the focus move: after close the trigger does *not* have focus (no assertion about where focus went) (`packages/react/src/select/popup/SelectPopup.test.tsx:1789-1822`).
- `finalFocus={() => true}` restores default behavior — the trigger is focused on close (`packages/react/src/select/popup/SelectPopup.test.tsx:1824-1857`).
- `finalFocus={() => null}` also falls back to default behavior — the trigger is focused on close (`packages/react/src/select/popup/SelectPopup.test.tsx:1859-1892`).
- On keyboard open, focus lands on the selected item inside the popup (`packages/react/src/select/popup/SelectPopup.test.tsx:73-77`).

## Accessibility (roles, aria-*, id linking)

- The trigger has `role="combobox"` (`packages/react/src/select/popup/SelectPopup.test.tsx:102`).
- Closed state: trigger has `aria-expanded="false"` and no `aria-controls` (`packages/react/src/select/popup/SelectPopup.test.tsx:104-105`, `packages/react/src/select/popup/SelectPopup.test.tsx:139-140`).
- `aria-haspopup="listbox"` is present both closed (`packages/react/src/select/popup/SelectPopup.test.tsx:141`) and open (`packages/react/src/select/popup/SelectPopup.test.tsx:117`, `packages/react/src/select/popup/SelectPopup.test.tsx:157`).
- Without a `Select.List`, the popup element itself is the listbox: `popup === screen.findByRole('listbox')`, it gets a non-empty generated `id`, `aria-multiselectable="true"` under `multiple`, and the trigger's `aria-controls` points at the popup's id once open (`packages/react/src/select/popup/SelectPopup.test.tsx:109-116`).
- With a `Select.List` inside the popup, the list is the listbox instead: `list === findByRole('listbox')`, the list carries `aria-multiselectable` and a non-empty `id`, the popup demotes to `role="presentation"` and has no `aria-multiselectable`, and the trigger's `aria-controls` points at the list id and not the popup id (`packages/react/src/select/popup/SelectPopup.test.tsx:145-157`).
- `aria-controls` appears only while open (closed assertions show it absent: `packages/react/src/select/popup/SelectPopup.test.tsx:104`, `packages/react/src/select/popup/SelectPopup.test.tsx:139`).
- The positioner exposes a `data-side` attribute; in item-aligned mode its value is `"none"` (`packages/react/src/select/popup/SelectPopup.test.tsx:224-226`, `packages/react/src/select/positioner/SelectPositioner.test.tsx` has no data-side assertion — all data-side assertions live in the popup test, e.g. `packages/react/src/select/popup/SelectPopup.test.tsx:284-289`).

## DOM structure & portal behavior

- Composition proven by the conformance wrappers: `Root > Portal > Positioner > Popup > List > Item` (`packages/react/src/select/list/SelectList.test.tsx:10-20`), and `Root > Portal > Positioner > Popup` (`packages/react/src/select/popup/SelectPopup.test.tsx:14-22`).
- `Select.Portal` renders its child inside the React tree of `Select.Root` and forwards a ref to an `HTMLDivElement` container (`packages/react/src/select/portal/SelectPortal.test.tsx:9-14`).
- `Select.Positioner` and `Select.Popup` can also be rendered inline (without `Select.Portal`) — the toolbar test nests `Positioner > Popup` directly under `Select.Root`, and the closed-scroll test renders `Positioner` inline under `Root` (`packages/react/src/select/popup/SelectPopup.test.tsx:56-61`, `packages/react/src/select/popup/SelectPopup.test.tsx:1042-1061`).
- `Select.Popup` requires the `Select.Positioner` context; rendering it without one rejects with a descriptive error (`packages/react/src/select/popup/SelectPopup.test.tsx:25-41`).
- While open (non-item-aligned mode) the positioner carries a non-empty inline `transform` (`packages/react/src/select/positioner/SelectPositioner.test.tsx:298-299`) of the form `translate(Xpx, Ypx)` with offsets applied along the side/align axes (`packages/react/src/select/positioner/SelectPositioner.test.tsx:56-58`, `packages/react/src/select/positioner/SelectPositioner.test.tsx:180-182`).
- In item-aligned mode (`alignItemWithTrigger` default active) the positioner is anchored with inline `top`/`bottom`/`height` styles instead: bottom-anchored uses `bottom: 0px` with empty `top` (`packages/react/src/select/popup/SelectPopup.test.tsx:1255-1258`), top-anchored uses `top: 0px` with empty `bottom` (`packages/react/src/select/popup/SelectPopup.test.tsx:1340-1343`), and short popups are top-anchored (`packages/react/src/select/popup/SelectPopup.test.tsx:920-924`).
- After Escape closes an opened select, the positioner element remains in the DOM but is `hidden`, reset to `position: fixed` with `transform: ''`, `top: 0px`, `left: 0px` — i.e. parked at the viewport origin until repositioned (`packages/react/src/select/positioner/SelectPositioner.test.tsx:304-317`).
- The positioner exposes a `--anchor-width` CSS custom property seeded from the `anchor` element's width (a 240px-wide custom anchor yields `--anchor-width: 240px`) (`packages/react/src/select/popup/SelectPopup.test.tsx:733-736`); the docs-style fixture consumes it as `min-width: var(--anchor-width)` (`packages/react/src/select/popup/SelectPopup.test.tsx:602-609`).
- The popup exposes a `--transform-origin` CSS custom property; when the positioner has no measurable height it is `50% 50%` (`packages/react/src/select/popup/SelectPopup.test.tsx:1480-1486`).
- User-set transform-related inline styles on the popup survive measurement: `transform`, `scale`, and `translate` set in a ref callback are still present after a microtask (`packages/react/src/select/popup/SelectPopup.test.tsx:160-193`).
- Parts are real DOM elements with forwarded refs: List/Popup/Positioner/Portal all resolve refs to `HTMLDivElement` instances (`packages/react/src/select/list/SelectList.test.tsx:9`, `packages/react/src/select/popup/SelectPopup.test.tsx:13`, `packages/react/src/select/positioner/SelectPositioner.test.tsx:18`, `packages/react/src/select/portal/SelectPortal.test.tsx:10`).

## Events (names, payload shape, bubbling, preventDefault semantics)

- Window `resize` (dispatched as `new UIEvent('resize')`) closes an item-aligned select: after placement, firing resize removes the `listbox` from the document (`packages/react/src/select/popup/SelectPopup.test.tsx:1652-1672`).
- `scroll` events drive the aligned-popup resize behavior, and the listener targets the scroll container element:
  - Scrolling the `Select.List` grows a bottom-anchored popup by the scrolled distance and snaps `list.scrollTop` back to `0` (`packages/react/src/select/popup/SelectPopup.test.tsx:1274-1282`); sub-pixel scroll (`0.5`) is consumed into `+0.5px` of height (`packages/react/src/select/popup/SelectPopup.test.tsx:1298-1304`).
  - A `scroll` event dispatched on the popup element is ignored while the `Select.List` owns scrolling (height unchanged), even though the event bubbles and the popup has its own scroll geometry; a subsequent scroll on the list does resize (`packages/react/src/select/popup/SelectPopup.test.tsx:1535-1570`).
  - When the popup itself is the scroll container, scrolling the popup grows the positioner and resets the popup's `scrollTop` to `0` (`packages/react/src/select/popup/SelectPopup.test.tsx:1572-1650`).
- Keydown propagation: ArrowRight keydowns with focus inside the popup do not reach an ancestor `Toolbar.Root`'s `onKeyDown` (`packages/react/src/select/popup/SelectPopup.test.tsx:84-87`).
- No test in this batch asserts an `onOpenChange` (or any Select custom event) payload object, event `details` shape, or `preventDefault` semantics — those are N/A for this batch beyond the behaviors above.

## Edge cases (rapid interactions, unmount, nesting)

- Reopen cycles keep alignment correct: open (no selection yet → first item's text vertically centered on the trigger value), Escape-close, re-open (still first item), click the selected item (closes), re-open (now the selected item is the alignment target) (`packages/react/src/select/popup/SelectPopup.test.tsx:552-565`).
- Kept-mounted positioner must not retain stale coordinates while closed: after Escape it is `hidden`, `position: fixed`, `transform` empty, parked at `top: 0px; left: 0px` to avoid viewport overflow on next open (`packages/react/src/select/positioner/SelectPositioner.test.tsx:286-318`).
- A stray `scroll` on the list before the popup is ever placed must be inert: positioner inline `height`/`top`/`bottom` unchanged and the kept-mounted `ScrollUpArrow` does not get `data-visible` (`packages/react/src/select/popup/SelectPopup.test.tsx:1036-1082`).
- Once a top-anchored popup saturates the available height, further scrolls stop resizing (height clamps at the available height, e.g. `380px`) (`packages/react/src/select/popup/SelectPopup.test.tsx:1354-1384`).
- A top-anchored popup already filling the viewport stops taking over scrolling: scroll positions (including sub-pixel `99.5`) are left to the list instead of being snapped back (`packages/react/src/select/popup/SelectPopup.test.tsx:1386-1420`).
- `max-height`-constrained popups stop growing entirely once placed (`packages/react/src/select/popup/SelectPopup.test.tsx:1422-1444`), while `max-height: 0` is treated as unconstrained (popup still grows by the scrolled distance) (`packages/react/src/select/popup/SelectPopup.test.tsx:1446-1468`).
- When the viewport collapses below the popup's margins, no non-positive height is applied (height unchanged) (`packages/react/src/select/popup/SelectPopup.test.tsx:1489-1513`).
- Browser zoom (`documentElement.style.zoom = '0.9'`) does not disable item alignment (`packages/react/src/select/popup/SelectPopup.test.tsx:195-230`) and scroll-driven height correction survives zoom with fractional pixel heights (`225.538px → 226px` while preserving `scrollTop = 14`) (`packages/react/src/select/popup/SelectPopup.test.tsx:740-823`).
- A 1px-off `maxScrollTop` still classifies a short popup as top-positioned (`top` set, `bottom` empty) (`packages/react/src/select/popup/SelectPopup.test.tsx:825-930`).
- An aligned height fractionally below the popup's `minHeight` does not disable item alignment (`data-side="none"` retained) (`packages/react/src/select/popup/SelectPopup.test.tsx:932-1034`).
- Pinch-zoom (`visualViewport.scale = 1.5`) is ignored outside WebKit: item alignment stays active (`packages/react/src/select/popup/SelectPopup.test.tsx:1515-1533`).
- Nesting inside a `Toolbar.Root` (trigger composed via `Toolbar.Button render={<Select.Trigger/>}`, popup rendered inline so it sits inside the toolbar's DOM subtree) does not leak ArrowRight to the toolbar's composite navigation (`packages/react/src/select/popup/SelectPopup.test.tsx:43-88`).
- `sideOffset`/`alignOffset` callback data reflects collision-resolved (flipped) logical/physical values: `side="left"` reads `data.side === 'right'`, `side="right" align="start"` reads `data.align === 'end'`, and `side="inline-start"` reads `data.side === 'inline-end'` in an LTR document (`packages/react/src/select/positioner/SelectPositioner.test.tsx:83-158`, `packages/react/src/select/positioner/SelectPositioner.test.tsx:207-282`).
