# Select — Trigger & Value: behavior mined from tests

Scope: behavior proven only by `packages/react/src/select/trigger/SelectTrigger.test.tsx` and `packages/react/src/select/value/SelectValue.test.tsx` (plus the shared test harness under `packages/react/test/`). Nothing here is inferred from component source.

## Public API surface (props, parts, subcomponents)

- `<Select.Trigger />` is rendered standalone in tests and forwards a ref to an instance of `window.HTMLButtonElement`; the conformance suite is configured with `refInstanceof: window.HTMLButtonElement` and `button: true`, mounted inside an open `<Select.Root>` (`packages/react/src/select/trigger/SelectTrigger.test.tsx:9-15`).
- `<Select.Value />` forwards a ref to an instance of `window.HTMLSpanElement`, mounted inside an open `<Select.Root>` (`packages/react/src/select/value/SelectValue.test.tsx:10-15`).
- Rendering `<Select.Trigger />` outside `<Select.Root>` rejects with the error `Base UI: SelectRootContext is missing. Select parts must be placed within <Select.Root>.` (`packages/react/src/select/trigger/SelectTrigger.test.tsx:17-27`).
- Root-level props exercised by these tests: `value`, `defaultValue`, `onOpenChange`, `open`, `defaultOpen`, `multiple`, `required`, `name`, `items` (object and array formats), `itemToStringLabel`, `itemToStringValue`, `onValueChange` (`packages/react/src/select/trigger/SelectTrigger.test.tsx:39-49`, `packages/react/src/select/value/SelectValue.test.tsx:67-99`, `packages/react/src/select/value/SelectValue.test.tsx:337-341`, `packages/react/src/select/value/SelectValue.test.tsx:369`).
- `Select.Value` props exercised: `children` (node, string, or render function), `placeholder` (string or ReactNode), plus pass-through test attributes (`packages/react/src/select/value/SelectValue.test.tsx:18-45`, `packages/react/src/select/value/SelectValue.test.tsx:613-762`).
- `items` accepts an object map of `value -> label` (`packages/react/src/select/value/SelectValue.test.tsx:60-64`) or an array of `{ value, label }` objects (`packages/react/src/select/value/SelectValue.test.tsx:177-181`); labels may be ReactNodes in both formats (`packages/react/src/select/value/SelectValue.test.tsx:143-156`, `packages/react/src/select/value/SelectValue.test.tsx:260-273`).
- `itemToStringLabel` / `itemToStringValue` accept functions used for object-valued items; `itemToStringLabel` output is displayed by `Select.Value` (`packages/react/src/select/value/SelectValue.test.tsx:330-360`) and `itemToStringValue` output feeds the stringified value (see hidden-input and placeholder tests, `packages/react/src/select/value/SelectValue.test.tsx:337-341`, `packages/react/src/select/trigger/SelectTrigger.test.tsx:184-210`).
- Surrounding parts used in the fixtures: `Select.Portal`, `Select.Positioner`, `Select.Popup`, `Select.Item` (`packages/react/src/select/trigger/SelectTrigger.test.tsx:43-50`, `packages/react/src/select/value/SelectValue.test.tsx:30-36`).

## State model (controlled/uncontrolled, defaults, transitions)

- Controlled `value` + `onValueChange`: external state changes update the rendered `Select.Value` text synchronously after the state-setting click (no `waitFor` needed) — `'sans'` → `'Serif'` → `'Monospace'` for items object (`packages/react/src/select/value/SelectValue.test.tsx:117-125`) and the same for items array (`packages/react/src/select/value/SelectValue.test.tsx:234-242`), and `'1'` → `'2'` → back to `null` (`packages/react/src/select/value/SelectValue.test.tsx:452-464`).
- Uncontrolled defaults: `defaultValue="b"` / `defaultValue="a"` (string), `defaultValue={shippingMethods[0]}` (object), `defaultValue={['a']}` (array in multiple mode) are all used to seed state without a `value` prop (`packages/react/src/select/trigger/SelectTrigger.test.tsx:107`, `packages/react/src/select/trigger/SelectTrigger.test.tsx:194`, `packages/react/src/select/trigger/SelectTrigger.test.tsx:249`).
- Open state: `defaultOpen` seeds an open popup (`packages/react/src/select/trigger/SelectTrigger.test.tsx:39`, `packages/react/src/select/trigger/SelectTrigger.test.tsx:79`); `open` is used in the conformance wrappers (`packages/react/src/select/trigger/SelectTrigger.test.tsx:13`, `packages/react/src/select/value/SelectValue.test.tsx:13`). Default (no props) is closed — clicking the trigger is required before the listbox exists (`packages/react/src/select/trigger/SelectTrigger.test.tsx:282-284`).
- Value of `null` is a distinct "no selection" state: `value={null}` puts both Trigger and Value into placeholder state (`packages/react/src/select/trigger/SelectTrigger.test.tsx:160-182`) and shows the `placeholder` text (`packages/react/src/select/value/SelectValue.test.tsx:624-632`).
- A stringified value of `''` also counts as placeholder state: with `itemToStringValue={(item) => item.id}` where the selected item's `id` is `''`, both parts have `data-placeholder` while the label text is still displayed (`'Default'`) (`packages/react/src/select/trigger/SelectTrigger.test.tsx:184-210`).
- An items entry whose `value` is `null` is treated as the null-selection label: with `items=[{ label: 'Select font', value: null }]` and no selection, `data-placeholder` is set and the text `'Select font'` is displayed (`packages/react/src/select/trigger/SelectTrigger.test.tsx:212-229`); with `items=[{ value: null, label: 'None' }, …]` the text `'None'` is displayed instead of the `placeholder` prop (`packages/react/src/select/value/SelectValue.test.tsx:675-696`); if that null-value item's `label` is `null`, the `placeholder` is shown instead (`packages/react/src/select/value/SelectValue.test.tsx:698-719`). Object-format equivalents: a `'null'` key's label wins over placeholder (`packages/react/src/select/value/SelectValue.test.tsx:736-749`); object items without a `null` key show the placeholder (`packages/react/src/select/value/SelectValue.test.tsx:721-734`).
- Multiple mode: `value` is an array; `value={[]}` renders empty text (`packages/react/src/select/value/SelectValue.test.tsx:553-561`); a single-element array renders just that label with no separator (`packages/react/src/select/value/SelectValue.test.tsx:543-551`); with `multiple` and no `value` at all, the `children` render function receives `[]` (`packages/react/src/select/value/SelectValue.test.tsx:600-610`).
- Render precedence proven for `Select.Value` content: `children` (string or function) beats `items` (`packages/react/src/select/value/SelectValue.test.tsx:396-409`, `packages/react/src/select/value/SelectValue.test.tsx:411-424`); `children` beats `placeholder` (`packages/react/src/select/value/SelectValue.test.tsx:651-661`, `packages/react/src/select/value/SelectValue.test.tsx:663-673`); items label beats `placeholder` for the null-selection entry (`packages/react/src/select/value/SelectValue.test.tsx:675-696`); with a selected value and no matching item, the raw value is displayed (`packages/react/src/select/value/SelectValue.test.tsx:634-649`).
- Missing-value fallbacks: a `value` not present in `items` displays the raw value (`'unknown'`) for both items formats (`packages/react/src/select/value/SelectValue.test.tsx:128-141`, `packages/react/src/select/value/SelectValue.test.tsx:245-258`).
- `onValueChange={setValue}` is wired in controlled fixtures (`packages/react/src/select/value/SelectValue.test.tsx:99`, `packages/react/src/select/value/SelectValue.test.tsx:216`, `packages/react/src/select/value/SelectValue.test.tsx:295`), but no test in this batch asserts that Select itself invokes `onValueChange`; UNVERIFIED — inferred from `packages/react/src/select/value/SelectValue.test.tsx:99` fixtures, no test asserts this.

## Keyboard interactions

- Only one keyboard interaction is asserted in this batch: pressing `[Tab]` does not move focus to a disabled trigger — after `user.keyboard('[Tab]')`, `document.activeElement` is not the trigger (`packages/react/src/select/trigger/SelectTrigger.test.tsx:125-127`).
- Enter / Space / Arrow keys / Escape / typeahead on the trigger: UNVERIFIED — inferred from `packages/react/src/select/trigger/SelectTrigger.test.tsx` (absence), no test asserts these in this batch.

## Focus management

- When the popup is open and item-aligned over the trigger (`alignItemWithTrigger` active, proven via positioner `data-side="none"`), dispatching `fireEvent.focus(trigger)` closes the popup: `aria-expanded` becomes `"false"` and `onOpenChange` is called with `(false, { reason: 'none' })` (`packages/react/src/select/trigger/SelectTrigger.test.tsx:29-70`; alignment precondition `packages/react/src/select/trigger/SelectTrigger.test.tsx:58-60`; expanded assertion `packages/react/src/select/trigger/SelectTrigger.test.tsx:64-66`; callback assertion `packages/react/src/select/trigger/SelectTrigger.test.tsx:68`). The test's own comments state that focusing the trigger starts a deferred `forceMount` timer that settles after the assertions (`packages/react/src/select/trigger/SelectTrigger.test.tsx:32-33`).
- When the popup is open but not item-aligned (`alignItemWithTrigger={false}`), focus landing on the trigger keeps it open: `aria-expanded` stays `"true"` and `onOpenChange` is never called (`packages/react/src/select/trigger/SelectTrigger.test.tsx:72-102`, assertions at `packages/react/src/select/trigger/SelectTrigger.test.tsx:97-101`).
- A `disabled` trigger is not focusable via keyboard Tab (`packages/react/src/select/trigger/SelectTrigger.test.tsx:125-127`).
- Focus return, initial focus placement in the popup, and focus-trap behavior: UNVERIFIED — inferred from `packages/react/src/select/trigger/SelectTrigger.test.tsx` (absence), no test asserts these in this batch.

## Accessibility (roles, aria-*, id linking)

- The trigger is reachable via `screen.getByRole('combobox')` (`packages/react/src/select/trigger/SelectTrigger.test.tsx:332`).
- The trigger exposes `aria-expanded` reflecting popup state: `"false"` after the aligned-focus close (`packages/react/src/select/trigger/SelectTrigger.test.tsx:64-66`) and `"true"` while open (`packages/react/src/select/trigger/SelectTrigger.test.tsx:97-99`).
- `aria-required="true"` is set on the trigger when `<Select.Root required>` (`packages/react/src/select/trigger/SelectTrigger.test.tsx:344-353`).

## DOM structure & portal behavior

- Trigger renders as a native button element (ref conformance against `window.HTMLButtonElement`, `packages/react/src/select/trigger/SelectTrigger.test.tsx:10-11`); Value renders as a span element (ref conformance against `window.HTMLSpanElement`, `packages/react/src/select/value/SelectValue.test.tsx:11`).
- Popup content is rendered through `Select.Portal` → `Select.Positioner` → `Select.Popup` and remains discoverable via `screen` queries (role `listbox`) (`packages/react/src/select/trigger/SelectTrigger.test.tsx:43-50`, `packages/react/src/select/trigger/SelectTrigger.test.tsx:284`); the specific portal mount target (e.g. `document.body`) is not asserted: UNVERIFIED — inferred from `packages/react/src/select/trigger/SelectTrigger.test.tsx:43`, no test asserts this.
- `Select.Positioner` exposes a `data-side` attribute that is `'none'` while the popup is item-aligned over the trigger (`packages/react/src/select/trigger/SelectTrigger.test.tsx:57-60`, `packages/react/src/select/trigger/SelectTrigger.test.tsx:318-321`).
- `Select.Value` can render inside the trigger (`packages/react/src/select/value/SelectValue.test.tsx:22-29`), directly under Root without a trigger (`packages/react/src/select/value/SelectValue.test.tsx:47-55`, `packages/react/src/select/value/SelectValue.test.tsx:544-548`), or wrapped in an arbitrary user element such as a `<span data-testid="value">` (`packages/react/src/select/value/SelectValue.test.tsx:477-481`, `packages/react/src/select/value/SelectValue.test.tsx:495-500`).
- Item labels rendered by Value may be real element nodes (a `<span>` inside the value node, `packages/react/src/select/value/SelectValue.test.tsx:155`; a `<strong>` inside it, `packages/react/src/select/value/SelectValue.test.tsx:272`).
- Multiple selections with ReactNode labels render each node inside the single value element, comma-separated in text content (`packages/react/src/select/value/SelectValue.test.tsx:523-526`).

## Events (names, payload shape, bubbling, preventDefault semantics)

- `onOpenChange` is invoked with `(open: boolean, details)`; the only details shape asserted is `expect.objectContaining({ reason: 'none' })` alongside `false` when an item-aligned popup closes due to trigger focus (`packages/react/src/select/trigger/SelectTrigger.test.tsx:68`).
- `onOpenChange` is not called when focus lands on the trigger with a non-aligned popup open (`packages/react/src/select/trigger/SelectTrigger.test.tsx:101`) and not called when a disabled trigger is clicked (`packages/react/src/select/trigger/SelectTrigger.test.tsx:155`).
- Clicking the trigger opens the popup (listbox appears) and sets `data-popup-open` / `data-pressed` on the trigger (`packages/react/src/select/trigger/SelectTrigger.test.tsx:282-285`, `packages/react/src/select/trigger/SelectTrigger.test.tsx:334-339`); clicking `document.body` closes it and removes `data-popup-side` (`packages/react/src/select/trigger/SelectTrigger.test.tsx:287-290`).
- A click on a disabled trigger produces no popup: `queryByRole('listbox')` stays `null` and `onOpenChange` call count is 0 (`packages/react/src/select/trigger/SelectTrigger.test.tsx:150-155`).
- Event bubbling, `preventDefault` semantics, and any other detail `reason` values: UNVERIFIED — inferred from `packages/react/src/select/trigger/SelectTrigger.test.tsx:68` (only `reason: 'none'` is asserted), no test asserts these in this batch.
- In `SelectValue` tests, `fireEvent.click` on the rendered value text followed by `flushMicrotasks()` is used as setup; no open/close assertion is attached to it (`packages/react/src/select/value/SelectValue.test.tsx:40-44`, `packages/react/src/select/value/SelectValue.test.tsx:454-455`).

## Edge cases (rapid interactions, unmount, nesting)

- Stale items: when the `items` array is replaced via state while a value stays selected, the displayed label updates to the new items' label (`'a'` → `'a new'`), and selecting a newly added value (`'c'`) renders its label — Value's items lookup is not stale after an items update (`packages/react/src/select/value/SelectValue.test.tsx:275-326`).
- Unknown values fall back to the raw value string in both items formats (`packages/react/src/select/value/SelectValue.test.tsx:128-141`, `packages/react/src/select/value/SelectValue.test.tsx:245-258`).
- Null-value lookup: object items use the literal `'null'` key to map a `null` value to a label (`packages/react/src/select/value/SelectValue.test.tsx:158-172`).
- The children render function receives the raw value(s), not the item label: single mode passes `'1'` as both first and last argument (`packages/react/src/select/value/SelectValue.test.tsx:43-44`); multiple mode passes the raw array `['sans', 'serif']` even when `items` maps them to labels (`packages/react/src/select/value/SelectValue.test.tsx:581-582`); when the value is `null` the function receives a nullish value and its fallback output is rendered (`packages/react/src/select/value/SelectValue.test.tsx:437`, `packages/react/src/select/value/SelectValue.test.tsx:463-464`, `packages/react/src/select/value/SelectValue.test.tsx:663-673`).
- Empty string as `itemToStringValue` output places the trigger/value into placeholder state while still showing the item label (`packages/react/src/select/trigger/SelectTrigger.test.tsx:184-210`).
- Multiple mode with an empty array renders empty content (`packages/react/src/select/value/SelectValue.test.tsx:553-561`) and with no `value` prop the children function receives `[]` (`packages/react/src/select/value/SelectValue.test.tsx:600-610`).
- Layout-dependent assertions (alignment-based close-on-focus, `data-popup-side` values) are browser-only: they are gated with `it.skipIf(isJSDOM)` and skipped in jsdom (`packages/react/src/select/trigger/SelectTrigger.test.tsx:29`, `packages/react/src/select/trigger/SelectTrigger.test.tsx:265`, `packages/react/src/select/trigger/SelectTrigger.test.tsx:293`), where `isJSDOM` is a UA sniff (`packages/utils/src/testUtils.ts:4`, re-exported by `packages/react/test/index.ts:1`).
- Rapid repeated interactions, unmount cleanup, and Select-inside-Select nesting: N/A (no test in this batch covers them).
- Placeholder as a ReactNode renders the node itself (`<span data-testid="placeholder">` is queryable, `packages/react/src/select/value/SelectValue.test.tsx:751-762`).
