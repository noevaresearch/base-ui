## State model (controlled/uncontrolled, defaults, transitions)

Value state:

- Uncontrolled: `defaultValue="b"` marks the matching item selected (`data-selected=""` on `role="option"`) once the popup is opened — `packages/react/src/select/root/SelectRoot.test.tsx:76`, `packages/react/src/select/root/SelectRoot.test.tsx:97-100`.
- Controlled: `value="b"` selects item b identically — `packages/react/src/select/root/SelectRoot.test.tsx:107`, `packages/react/src/select/root/SelectRoot.test.tsx:128-131`.
- A controlled `value` present on initial render with `defaultOpen` selects the matching option and no other at first paint — `packages/react/src/select/root/SelectRoot.test.tsx:136`, `packages/react/src/select/root/SelectRoot.test.tsx:151-157`.
- External `value` changes while the popup is open move the selection (a→b via `setProps`) — `packages/react/src/select/root/SelectRoot.test.tsx:188-196`.
- When the controlled `value` prop does not change, clicking another item neither fires `onValueChange` (0 calls) nor changes the trigger label — the internal value is not updated — `packages/react/src/select/root/SelectRoot.test.tsx:220-228`.
- A controlled `value` change before the popup ever opens still updates the `<Select.Value />` trigger label (b→a) — `packages/react/src/select/root/SelectRoot.test.tsx:250-255`.
- `value={null}` renders the `Select.Value` fallback (render-prop child receives `null` → `'initial'`) and leaves no option selected — `packages/react/src/select/root/SelectRoot.test.tsx:3199-3205`.
- A programmatic controlled value change with the popup closed resolves the label without mounting the listbox — with or without the `items` prop — `packages/react/src/select/root/SelectRoot.test.tsx:3261-3267`.
- `onValueChange` fires exactly once per selection with the new value (`'b'`) — `packages/react/src/select/root/SelectRoot.test.tsx:494`, `packages/react/src/select/root/SelectRoot.test.tsx:529`.

Multiple mode:

- `defaultValue={[...]}` array selects all matching items — `packages/react/src/select/root/SelectRoot.test.tsx:6125-6151`.
- Each click appends to the array: first click → `['a']`, second → `['a', 'b']`; the popup stays open — `packages/react/src/select/root/SelectRoot.test.tsx:5538-5549`.
- Clicking a selected item deselects it (`['b']` after clicking a) — `packages/react/src/select/root/SelectRoot.test.tsx:5642-5647`.
- Controlled array updates while open re-render selection (`['a','b']` → `['b']`) — `packages/react/src/select/root/SelectRoot.test.tsx:5673-5679`.
- Selection persists when items are added but never rewritten when still valid — `packages/react/src/select/root/SelectRoot.test.tsx:5587-5595`.

Item-set reconciliation (dynamic items):

- If the selected item is removed, the value resets: uncontrolled falls back to `defaultValue` — `packages/react/src/select/root/SelectRoot.test.tsx:4679-4688`; controlled calls `onValueChange(null)` — `packages/react/src/select/root/SelectRoot.test.tsx:4510-4512`.
- Replacing one item (or all items) while keeping the count constant also resets the value to `null` via `onValueChange` — `packages/react/src/select/root/SelectRoot.test.tsx:4508-4514`, `packages/react/src/select/root/SelectRoot.test.tsx:4570-4572`.
- Pure reordering keeps the value and does not call `onValueChange` — `packages/react/src/select/root/SelectRoot.test.tsx:4626-4634`.
- In multiple mode, selections that no longer exist are dropped (`['a','c']` → `['a']` → `[]`) — `packages/react/src/select/root/SelectRoot.test.tsx:5424-5441`, `packages/react/src/select/root/SelectRoot.test.tsx:5489-5493`.
- When both the selected value and the initial default are removed, the value falls back to `null` and no option is selected (uncontrolled and controlled variants) — `packages/react/src/select/root/SelectRoot.test.tsx:4996-5005`, `packages/react/src/select/root/SelectRoot.test.tsx:5053-5061`.
- Selecting a removed-then-re-added item does not restore the selection — `packages/react/src/select/root/SelectRoot.test.tsx:4449-4451`.
