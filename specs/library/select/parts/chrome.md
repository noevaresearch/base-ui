# Select chrome parts — Arrow / Backdrop / Icon (behavior mined from tests)

Scope: exactly three test files — `packages/react/src/select/arrow/SelectArrow.test.tsx`, `packages/react/src/select/backdrop/SelectBackdrop.test.tsx`, `packages/react/src/select/icon/SelectIcon.test.tsx`. All three files are pure conformance suites: each mounts one part and runs the shared `describeConformance` suite; no component-specific behavioral tests exist in these files.

## Public API surface (props, parts, subcomponents)

- `Select.Arrow`, `Select.Backdrop`, and `Select.Icon` are exported as named parts of the `Select` namespace imported from `@base-ui/react/select` (`packages/react/src/select/arrow/SelectArrow.test.tsx:2`, `packages/react/src/select/backdrop/SelectBackdrop.test.tsx:2`, `packages/react/src/select/icon/SelectIcon.test.tsx:2`).
- Each part accepts a `ref` that attaches to a specific host element: `Select.Arrow` → `window.HTMLDivElement` (`packages/react/src/select/arrow/SelectArrow.test.tsx:9`), `Select.Backdrop` → `window.HTMLDivElement` (`packages/react/src/select/backdrop/SelectBackdrop.test.tsx:9`), `Select.Icon` → `window.HTMLSpanElement` (`packages/react/src/select/icon/SelectIcon.test.tsx:9`). The conformance harness clones the minimal element with a `React.createRef()` and asserts `ref.current` is an instance of the configured `refInstanceof` (`packages/react/test/conformanceTests/refForwarding.tsx:32-38`, `packages/react/test/conformanceTests/refForwarding.tsx:18-24`).
- Each part accepts a `render` prop usable in both function form and JSX-element form (proven by the render-prop conformance suite run against all three parts via `packages/react/src/select/arrow/SelectArrow.test.tsx:8`, `packages/react/src/select/backdrop/SelectBackdrop.test.tsx:8`, `packages/react/src/select/icon/SelectIcon.test.tsx:8`; assertions in `packages/react/test/conformanceTests/renderProp.tsx:41-59` and `packages/react/test/conformanceTests/renderProp.tsx:61-76`).
- Each part accepts and forwards arbitrary DOM props: `lang` and a random `data-foobar` attribute are asserted present on the rendered root element, both on the default element and on custom-rendered elements (`packages/react/test/conformanceTests/propForwarding.tsx:23-36`, `packages/react/test/conformanceTests/propForwarding.tsx:38-59`, `packages/react/test/conformanceTests/propForwarding.tsx:61-80`). The `data-testid` prop is used by the harness to locate the root (`packages/react/test/conformanceTests/propForwarding.tsx:29-33`).
- Each part accepts a `style` object, asserted to survive onto the rendered element's `style` attribute when given on the component, in the render function, or on the render element (`packages/react/test/conformanceTests/propForwarding.tsx:82-95`, `packages/react/test/conformanceTests/propForwarding.tsx:97-112`, `packages/react/test/conformanceTests/propForwarding.tsx:114-127`).
- Each part accepts `className` as a string, asserted applied to the rendered element (`packages/react/test/conformanceTests/className.tsx:20-23`), and as a function of state, asserted merged alongside a render-prop element's `className` (`packages/react/test/conformanceTests/renderProp.tsx:163-178`).
- The conformance option type also declares `nativeButton` on the tested element's props, but no test in this batch sets the `button` option, so no button-specific behavior is exercised for these parts (`packages/react/test/describeConformance.tsx:14-21`, `packages/react/test/describeConformance.tsx:36`).
- Props beyond the above (event handlers, `keepMounted`, etc.) are UNVERIFIED — no test in this batch passes or asserts them.

## DOM structure & portal behavior

- The Arrow suite mounts `<Select.Arrow />` as a child of `<Select.Positioner alignItemWithTrigger={false}>` which is itself inside `<Select.Root open>`; the conformance suite passes against that configuration, proving Arrow renders (refs, props, render prop, className all resolve) when nested under a Positioner (`packages/react/src/select/arrow/SelectArrow.test.tsx:10-16`).
- The Backdrop and Icon suites mount the part as a direct child of `<Select.Root open>` with no Positioner or other Select parts present, proving each renders standalone inside a bare open Root without throwing (`packages/react/src/select/backdrop/SelectBackdrop.test.tsx:11`, `packages/react/src/select/icon/SelectIcon.test.tsx:11`).
- Host element types as proven by ref forwarding: Arrow and Backdrop render a `div`-typed node, Icon renders a `span`-typed node (`packages/react/src/select/arrow/SelectArrow.test.tsx:9`, `packages/react/src/select/backdrop/SelectBackdrop.test.tsx:9`, `packages/react/src/select/icon/SelectIcon.test.tsx:9`, assertion mechanics in `packages/react/test/conformanceTests/refForwarding.tsx:32-38`).
- When `render` is a component that wraps the custom element in an extra `<div data-testid="base-ui-wrapper">`, the part's custom element still renders inside that wrapper and the part's `ref` points at the inner custom element (tagname `DIV`, `data-testid="wrapped"`), not the outer wrapper (`packages/react/test/conformanceTests/renderProp.tsx:27-38`, `packages/react/test/conformanceTests/renderProp.tsx:54-58`, `packages/react/test/conformanceTests/renderProp.tsx:93-113`).
- Portal behavior: nothing in this batch asserts where in the document the part is mounted (no portal-container assertions); the harness queries with `screen`/`document.querySelector` only (`packages/react/test/conformanceTests/propForwarding.tsx:33`, `packages/react/test/conformanceTests/className.tsx:22`). Portal-vs-inline mounting is UNVERIFIED — no test asserts it.
