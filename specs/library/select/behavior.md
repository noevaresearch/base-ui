## Public API surface (props, parts, subcomponents)

Part index (one paragraph per batch, depth in the linked part spec):

- **Root + store** — `specs/library/select/parts/root-store.md:5-33` for the full prop list. `Select.Root` owns both value and open state (controlled/uncontrolled for each) and exposes the compound tree; props proven: `value`/`defaultValue`/`onValueChange`, `open`/`defaultOpen`/`onOpenChange`/`onOpenChangeComplete`, `multiple`, `disabled`, `readOnly`, `modal`, `id`, `name`/`autoComplete`/`required`/`form`, the items-mapping hooks (`items`, `itemToStringLabel`, `itemToStringValue`, `isItemEqualToValue`), `highlightItemOnHover`, and `actionsRef` with `unmount()` (`specs/library/select/parts/root-store.md:13-24`). The store handed to descendants via `useSelectRootContext()` exposes `subscribe(listener)` with atomic state snapshots (e.g. `id`/`modal` published together), `context.setOpen(open, details)` callable from descendant ref callbacks, and `disabled` as live state (`specs/library/select/parts/root-store.md:90-96`).
- **Trigger + Value** — `specs/library/select/parts/trigger-value.md:7-14`. The trigger is a native button (`HTMLButtonElement`, conformance `button: true`) that throws `Base UI: SelectRootContext is missing. Select parts must be placed within <Select.Root>.` outside a Root; `Value` is a span accepting `children` (node/string/render function) and `placeholder`; `items` accepts an object map or `{ value, label }` array with ReactNode labels, and `itemToStringLabel`/`itemToStringValue` handle object-valued items (`specs/library/select/parts/trigger-value.md:9-13`).
- **Item family** — `specs/library/select/parts/items.md:7-18`. `Item` is a div (conformance `button: true`) taking `value` (including `""`), `disabled`, `onClick`, and `render`; `ItemIndicator` is a span with `keepMounted`; `ItemText` is a div that throws `Base UI: SelectItemContext is missing. SelectItem parts must be placed within <Select.Item>.` outside an Item (`specs/library/select/parts/items.md:15`).
- **Containers** — `specs/library/select/parts/containers.md:16-27`. `List`, `Popup`, `Portal`, `Positioner` all forward refs to `HTMLDivElement` and support `render`/`className`/prop spread; `Positioner` takes `align`, `side` (incl. `inline-start`), `sideOffset`/`alignOffset` (number or collision-aware callback), `alignItemWithTrigger`, `anchor`, `dir`; `Popup` takes `finalFocus` (ref, function, `false`, `() => true`, `() => null`) and throws `Base UI: SelectPositionerContext is missing. - **Scroll arrows** — `specs/library/select/parts/scroll-arrows.md:13-20`. `ScrollUpArrow`/`ScrollDownArrow` are divs with `keepMounted` and `data-testid` support; the rendered arrows contain literal `▲`/`▼` text; no callback props are asserted (`specs/library/select/parts/scroll-arrows.md:14-20`).
- **Labels** — `specs/library/select/parts/labels.md:11-15`. `Group`, `GroupLabel`, `Label` are divs supporting the full conformance surface; `GroupLabel` takes explicit `id`, `ref`, and `aria-hidden` props (`specs/library/select/parts/labels.md:19-23`).
- **Chrome (Arrow / Backdrop / Icon)** — `specs/library/select/parts/chrome.md:8-14`. All three are conformance-only in their test files: refs land on `HTMLDivElement` (Arrow, Backdrop) and `HTMLSpanElement` (Icon), with `render`, `className`, `style`, and arbitrary DOM-prop forwarding; no behavioral tests exist (`specs/library/select/parts/chrome.md:8-14`).

## State model (controlled/uncontrolled, defaults, transitions)

Cross-cutting value pipeline (root state machine ↔ items ↔ Value label):

- A commit (click or Enter) fires `onValueChange` exactly once with the new value — scalar in single mode, array in multiple — plus an opaque details object, updates the `Select.Value` label, and closes the popup in single mode while multiple mode stays open (`packages/react/src/select/item/SelectItem.test.tsx:53`, `packages/react/src/select/root/SelectRoot.test.tsx:6342-6344`, depth in `specs/library/select/parts/root-store.md:47-64`).
- An unchanged controlled `value` gates the whole pipeline: clicking another item neither fires `onValueChange` nor changes the trigger label (`packages/react/src/select/root/SelectRoot.test.tsx:220-228`).
- Item-set reconciliation is a root-level responsibility: removing/replacing the selected item resets the value to `null` via `onValueChange` (controlled) or `defaultValue` (uncontrolled), while pure reordering preserves it; in multiple mode stale selections are dropped from the array (`packages/react/src/select/root/SelectRoot.test.tsx:4510-4512`, depth in `specs/library/select/parts/root-store.md:57-64`).
- `details.cancel()` is verifiable at both ends of the pipeline: cancelling `onOpenChange` blocks the popup from ever mounting, and cancelling `onValueChange` blocks the commit (autofill case) (`packages/react/src/select/root/SelectRoot.test.tsx:648-652`, depth in `specs/library/select/parts/root-store.md:71` and `:166-167`).
- The popup mounts only after the first open; a programmatic controlled value change with the popup closed resolves the trigger label without mounting a listbox (`specs/library/select/parts/root-store.md:150-151`).
- Multiple-mode anchor/highlight follows rendered order rather than value-array order and re-elects an anchor when the anchor item's value changes or leaves the list (`specs/library/select/parts/root-store.md:98-104`).
- Part-local state is limited to DOM style hooks: `data-visible` on scroll arrows (`specs/library/select/parts/scroll-arrows.md:26-29`), `data-selected`/`data-highlighted`/`data-disabled`/`data-ending-style` on items and indicators (`specs/library/select/parts/items.md:31,39,57`), and Field-derived `data-touched`/`data-dirty`/`data-filled`/`data-focused` on the trigger (`specs/library/select/parts/root-store.md:75-83`).

## Keyboard interactions

- Trigger: ArrowDown opens the popup (including under `readOnly`); closed-trigger typeahead commits the matched value while skipping disabled items; rapid same-letter typeahead cycles enabled matches; Space during typeahead navigation completes the match instead of selecting (`specs/library/select/parts/root-store.md:106-122`).
- Popup: ArrowDown/ArrowUp move highlight and focus; Enter commits the highlighted item; Escape closes; Tab closes and moves focus to the next focusable outside (`specs/library/select/parts/root-store.md:108-120`, `specs/library/select/parts/items.md:35-39`).
- Keyboard open lands focus on the selected/default item (`packages/react/src/select/popup/SelectPopup.test.tsx:73-77`).
- The popup swallows ArrowRight so composite widgets like Toolbar do not navigate while the popup owns focus (`packages/react/src/select/popup/SelectPopup.test.tsx:80-87`, depth in `specs/library/select/parts/containers.md:42`).
- Keys not covered anywhere in the suite: Home/End/PageUp and per-key `preventDefault` semantics are UNVERIFIED — inferred from `packages/react/src/select/item/SelectItem.test.tsx:180-213`, no test asserts them.

## Focus management

- Open moves focus into the popup (first item on pointer open, selected item on keyboard open; the anchor option is focused asynchronously after mouse-open in multiple mode) (`packages/react/src/select/item/SelectItem.test.tsx:170-178`, `packages/react/src/select/popup/SelectPopup.test.tsx:73-77`, depth in `specs/library/select/parts/root-store.md:124-134`).
- Close returns focus to the trigger by default, overridable by `Popup.finalFocus` in all five proven variants (ref, function→element, `false`, `() => true`, `() => null`) (`packages/react/src/select/popup/SelectPopup.test.tsx:1694-1707`, depth in `specs/library/select/parts/containers.md:48-53`).
- Trigger focus is part of the open/close machine: when an item-aligned popup is open, focus landing on the trigger closes it with `onOpenChange(false, { reason: 'none' })`; with `alignItemWithTrigger={false}` the popup stays open (`packages/react/src/select/trigger/SelectTrigger.test.tsx:29-33`, depth in `specs/library/select/parts/trigger-value.md:36-37`).
- Label integration focuses the trigger without opening; `Field.Label` click opens and focuses the listbox; the highlighted option uses roving `tabindex` (`specs/library/select/parts/root-store.md:126-131`).
- Highlight model ties focus and hover together: `mousemove` sets `data-highlighted` by default, `highlightItemOnHover={false}` suppresses it while clicks still commit, and keyboard highlight survives mouse-out (`packages/react/src/select/root/SelectRoot.test.tsx:6522-6526`, depth in `specs/library/select/parts/items.md:80-82`).

## Accessibility (roles, aria-*, id linking)

- Trigger: `role="combobox"` with `aria-expanded`, `aria-haspopup="listbox"`, `aria-controls` (open only), `aria-required` under `required`, `aria-readonly` under `readOnly` (`packages/react/src/select/root/SelectRoot.test.tsx:1519-1521`, depth in `specs/library/select/parts/root-store.md:138-139` and `specs/library/select/parts/containers.md:58-60`).
- Dual listbox mode: without a `Select.List` the popup is the `listbox` and owns the trigger's `aria-controls` id; with a `List`, the List takes the listbox role and id linkage and the popup demotes to `role="presentation"` (`packages/react/src/select/popup/SelectPopup.test.tsx:109-116` and `:145-157`).
- Options: `role="option"`, `aria-selected` (including `"false"` after keyboard deselect), accessible name from rendered text, `data-disabled` hook (`specs/library/select/parts/items.md:53-58`).
- Groups: `role="group"` with a live `aria-labelledby` registration that tracks the newest `GroupLabel` through mount/swap/unmount, explicit and generated ids, ref churn, and StrictMode (`packages/react/src/select/group/SelectGroup.test.tsx:46-48`, depth in `specs/library/select/parts/labels.md:32-36,49-53`).
- Label/description linkage: `Select.Label` and `Field.Label` set the trigger's `aria-labelledby`; `Field.Description` appends to `aria-describedby`; SSR emits ids but defers `aria-labelledby` to hydration (`packages/react/src/select/root/SelectRoot.test.tsx:56-70`, depth in `specs/library/select/parts/root-store.md:141-143`).
- Form association: the hidden input is exposed as role `textbox`, carries `name`/`autocomplete`/derived id, and multiple mode renders one named input per selected value (`packages/react/src/select/root/SelectRoot.test.tsx:697-698`, depth in `specs/library/select/parts/root-store.md:145,157-159`).
- Scroll arrows, Arrow, Backdrop, and Icon have no asserted ARIA surface (N/A) (`specs/library/select/parts/scroll-arrows.md:41`, `specs/library/select/parts/chrome.md:31`).

## DOM structure & portal behavior

- Composition: `Root > Portal > Positioner > Popup > (List >) Item(s)`; `Positioner`/`Popup` also render inline without a Portal, and items render (and commit) under a Positioner with no Portal/Popup (`specs/library/select/parts/containers.md:68-70`, `specs/library/select/parts/items.md:67-68`).
- Item-aligned mode (default `alignItemWithTrigger`) anchors the positioner with inline `top`/`bottom`/`height` instead of `transform`, vertically centers the first selected item with the trigger, and exposes `data-side="none"`; non-aligned mode uses `translate(Xpx, Ypx)` transforms and collision-resolved `data-side`/`data.align` callback data (`specs/library/select/parts/containers.md:72-73,104`, `packages/react/src/select/root/SelectRoot.test.tsx:5926-5930`).
- After close, a kept-mounted positioner is parked `hidden`/`position: fixed` at the viewport origin with no stale `transform` (`packages/react/src/select/positioner/SelectPositioner.test.tsx:304-308`).
- `modal` renders an internal `role="presentation"` backdrop as the positioner's previous sibling; Chromium-only tests prove scroll locking for full-width touch-opened modals (`specs/library/select/parts/root-store.md:152,155`).
- Positioner CSS integration points: `--anchor-width` seeded from the `anchor` element, `--transform-origin` on the popup, and user-set `transform`/`scale`/`translate` inline styles survive measurement (`specs/library/select/parts/containers.md:75-77`).

## Events (names, payload shape, bubbling, preventDefault semantics)

- `onOpenChange(open, details)`: the only asserted details shapes are `cancel()` (`packages/react/src/select/root/SelectRoot.test.tsx:648-652`) and `{ reason: 'none' }` on the aligned-focus close (`packages/react/src/select/trigger/SelectTrigger.test.tsx:29-33`); other `reason` values are UNVERIFIED — inferred from `packages/react/src/select/trigger/SelectTrigger.test.tsx:68`, no test asserts them.
- `onValueChange(value, details)`: value is scalar/array/`null` (item-removal reset), fires once per commit, supports `cancel()` (`specs/library/select/parts/root-store.md:166-167`).
- Item `onClick` exposes `preventBaseUIHandler()`, which suppresses the selection commit and keeps the popup open while the user handler still runs (`packages/react/src/select/item/SelectItem.test.tsx:985-990`).
- Pointer event plumbing: the opening click never commits even if its mouseup lands on an item; synthetic `detail: 0` clicks don't commit unhighlighted items but full physical clicks do; drag-to-select needs real `pointerMove` traffic with `movementY` accumulation; touch releases never commit (`specs/library/select/parts/items.md:77-97`).
- Scroll arrows are driven solely by `mousemove` (`movementX/Y`; zero movement never starts) and `mouseleave`; the first step lands within 40 ms and rapid re-moves don't postpone it (`packages/react/src/select/scroll-arrow/SelectScrollArrow.test.tsx:144`, depth in `specs/library/select/parts/scroll-arrows.md:58-67`).
- Window `resize` closes an item-aligned popup because its geometry is measured once (`packages/react/src/select/popup/SelectPopup.test.tsx:1662-1672`); list/popup `scroll` events drive the aligned height-growth behavior with clamps (`specs/library/select/parts/containers.md:83-86,95-98`).
- Browser autofill is consumed as a `change` event on the hidden input, matched case-insensitively against serialized values then labels, and ignored in multiple/readOnly/disabled modes or when cancelled (`packages/react/src/select/root/SelectRoot.test.tsx:697-705`, depth in `specs/library/select/parts/root-store.md:167`).
- Escape from the select does not bubble to an enclosing popover; outside presses dismiss the popover after the select closes (`specs/library/select/parts/root-store.md:171`).

## Edge cases (rapid interactions, unmount, nesting)

- Rapid touch open→close→reopen within the close animation keeps the touch interaction type, ends unlocked, and recomputes positioning before becoming visible; highlight survives the cycle (`specs/library/select/parts/root-store.md:176`).
- Opening-delay gating for quick selection: mouseup over an item before the opening delay elapses does not commit unless real drag movement occurred; the movement threshold applies only during the delay window; movement accumulates across items (`specs/library/select/parts/items.md:88-97`).
- Item-set churn (remove/replace/reorder/re-add) all have defined value outcomes, and aligned positioning resets (scrollTop 0, first option inside the positioner) after controlled value reset plus option replacement, including with a stale controlled value (`packages/react/src/select/root/SelectRoot.test.tsx:4795-4805`, depth in `specs/library/select/parts/root-store.md:179-180`).
- Forced-open popup with a `disabled` or `readOnly` root ignores item interaction entirely (`packages/react/src/select/root/SelectRoot.test.tsx:1327-1330`, depth in `specs/library/select/parts/root-store.md:69,184`).
- Disabled/readOnly gating is unit-wide: disabled trigger is unfocusable and inert, items render `data-disabled` and ignore clicks, readOnly still opens but never commits (`packages/react/src/select/root/SelectRoot.test.tsx:2767-2769` and `:2948-2953`, depth in `specs/library/select/parts/items.md:100`).
- `actionsRef.current.unmount()` imperatively unmounts the popup after close (verified under strict and non-strict React) (`specs/library/select/parts/root-store.md:177`).
- Nesting: select inside popover — committing a non-modal select keeps the popover open until an outside press, Escape doesn't close the popover, and programmatic open returns focus to the opener; select inside Toolbar — ArrowRight swallowed by the popup (`specs/library/select/parts/root-store.md:181`, `specs/library/select/parts/containers.md:103`).
- Environment gating: layout/geometry assertions are browser-only via `isJSDOM` skips (aligned positioning, scroll locking, resize, typeahead-with-space, zoom), while stubbed-geometry tests run in both envs; animation tests flip `BASE_UI_ANIMATIONS_DISABLED` (`specs/library/select/parts/containers.md:10`, `specs/library/select/parts/scroll-arrows.md:108`, `specs/library/select/parts/root-store.md:186`).
- Fractional geometry is pinned throughout: sub-pixel scroll, browser zoom (0.9), pinch zoom (WebKit-only), 1px-off `maxScrollTop` classification, `max-height` clamps (with `0` treated as unconstrained), and non-positive-height guard (`specs/library/select/parts/containers.md:94-102`, `specs/library/select/parts/scroll-arrows.md:75-80,91`).
