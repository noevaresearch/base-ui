## State model (controlled/uncontrolled, defaults, transitions)

- Selection state lives on `Tabs.Root`. Controlled mode uses `value` (`packages/react/src/tabs/root/TabsRoot.test.tsx:235-249`); uncontrolled mode uses `defaultValue` (`:808-825`). `defaultValue={null}` selects nothing (`:827-844`); `defaultValue={undefined}` behaves as if absent (implicit default) (`:846-869`).
- Implicit default (no `value`/`defaultValue`): the tab with value `0` is selected when one exists, even if it is a later tab in DOM order — `onValueChange` fires once with that value and `reason: 'initial'` (`packages/react/src/tabs/root/TabsRoot.test.tsx:643-663`); with tabs `[0,1,2]` the first tab (value `0`) is selected (`:621-641`). If the value-`0` tab is disabled, the first enabled tab is selected instead, still with `reason: 'initial'` and `activationDirection: 'none'` (`:665-687`); if all tabs are disabled, the selection is `null` (`:750-774`). How the implicit default resolves when no tab has the value `0` at all (e.g. all-string values) is not covered — UNVERIFIED — inferred from `packages/react/src/tabs/root/TabsRoot.test.tsx:643-663`, no test asserts this.
- No `onValueChange` is emitted on initial render when an explicit `defaultValue` is provided (`packages/react/src/tabs/root/TabsRoot.test.tsx:808-825`), including `defaultValue={null}` (`:827-844`).
- An explicit `defaultValue` is honored even when it points at a disabled tab (`packages/react/src/tabs/root/TabsRoot.test.tsx:346-372`), and stays honored after the `defaultValue` prop later changes — with a dev-only warning `'Base UI: A component is changing the default value state of an uncontrolled Tabs after being initialized.'` (`:374-401`). An explicit controlled `value` pointing at a disabled tab is likewise honored (`:403-429`), and a programmatically selected disabled tab does not receive `tabindex="0"` — the previously highlighted tab keeps it (`:431-464`).
- Automatic re-selection transitions (uncontrolled roots only), each surfacing on `onValueChange`:
  - The selected tab becomes disabled → falls back to the next enabled tab with `reason: 'disabled'` and `activationDirection: 'none'` (`packages/react/src/tabs/root/TabsRoot.test.tsx:871-902`); the same transition fires for an initially-disabled explicit `defaultValue` that is enabled and disabled again (`:904-938`) and works identically with `keepMounted` panels (`:940-975`).
  - The selected tab is removed from the list → `reason: 'missing'`, selecting the next tab (`packages/react/src/tabs/root/TabsRoot.test.tsx:977-1006`); if no tabs remain, the value becomes `null` with `reason: 'missing'` (`:1008-1036`), and replacing a populated list with an empty one behaves the same (`:1038-1070`). An explicit `defaultValue` pointing at a tab that is never present also triggers the `missing` fallback to the first tab on mount (`:1072-1092`).
  - An enabled tab appearing after all tabs were disabled does NOT emit a change — the selection stays `null` (`packages/react/src/tabs/root/TabsRoot.test.tsx:776-806`).
  - Transient duplicate values during list reordering settle: the automatic fallback fires exactly once and is not re-emitted on the next pass (`packages/react/src/tabs/root/TabsRoot.test.tsx:1094-1119`).
- In a controlled root, none of these automatic transitions emit `onValueChange` or move the selection — the parent keeps full control (`packages/react/src/tabs/root/TabsRoot.test.tsx:1121-1145`, `:1147-1184`).
- All-disabled state: no tab has `aria-selected="true"` and all panels are `hidden` (`packages/react/src/tabs/root/TabsRoot.test.tsx:466-504`).
- Activation direction state: the root carries `data-activation-direction` — `'none'` initially (`packages/react/src/tabs/root/TabsRoot.test.tsx:1996`, `:2034`, `:2071`), `'right'`/`'left'` for horizontal activation (`:2002`, `:2012`), `'down'`/`'up'` for vertical (`:2040`, `:2050`). The attribute is also stamped on each tab element (`:2072`, `:2080`, `:2090`, `:2112`, `:2120`, `:2130`) and exposed to panel/tab render props as `state.tabActivationDirection` (`:1999-2001`, `:2037-2039`, `packages/react/src/tabs/tab/TabsTab.test.tsx:277-282`). Programmatic controlled `value` changes compute the direction too (`packages/react/src/tabs/root/TabsRoot.test.tsx:2053-2131`), including adding and selecting a new tab in a single update with numeric (`:2241-2290`) or out-of-order string values (`:2292-2337`). Clearing the selection (`value={null}`) resets the attribute to `'none'` and unmounts the indicator; reselecting from a cleared state is also `'none'` (`:2159-2184`). Automatic disabled fallbacks keep `'none'` (`:2133-2157`). A canceled click leaves `'none'`, and a later programmatic change still computes the correct direction (`:2186-2215`), as does a controlled parent that ignores the click (`:2217-2239`).
- Panel visibility: the selected panel lacks the `hidden` attribute while all others carry it (`packages/react/src/tabs/root/TabsRoot.test.tsx:1214-1242`); without `keepMounted`, only the selected panel is mounted and `aria-controls`/`aria-labelledby` links are re-synced on every selection change (`:137-164`).

## Keyboard interactions

All key handling is asserted on `keydown` events; after handling, the `keydown` event is `defaultPrevented` (a consumer `onKeyDown` on `Tabs.List` receives `event.defaultPrevented === true`) (`packages/react/src/tabs/root/TabsRoot.test.tsx:1318-1321`).

| Key | Behavior |
| --- | --- |
| ArrowLeft / ArrowRight (horizontal, LTR) | Move focus to previous/next tab, wrapping around by default (last→first, first→last) (`packages/react/src/tabs/root/TabsRoot.test.tsx:1290-1322`, `:1493-1525`); with `loopFocus={false}` no wrapping in either direction (`packages/react/src/tabs/list/TabsList.test.tsx:62-106`) |
| ArrowRight / ArrowLeft (horizontal, RTL via `DirectionProvider`) | Direction-swapped: ArrowRight is "previous", ArrowLeft is "next" (`packages/react/src/tabs/root/TabsRoot.test.tsx:1277-1287`) |
| ArrowUp / ArrowDown (vertical) | Move focus to previous/next tab with the same wrapping semantics (`packages/react/src/tabs/root/TabsRoot.test.tsx:1277-1287`, `:1290-1322`) |
| Home | Moves focus to the first tab regardless of orientation; activates it only when `activateOnFocus` is true (`packages/react/src/tabs/root/TabsRoot.test.tsx:1754-1810`) |
| End | Moves focus to the last tab regardless of orientation; activates it only when `activateOnFocus` is true (`packages/react/src/tabs/root/TabsRoot.test.tsx:1843-1899`) |
| Enter / Space | Activate the focused tab when `activateOnFocus` is false (the default) (`packages/react/src/tabs/tab/TabsTab.test.tsx:214-241`); also activates a focused tab inside a nested root (`packages/react/src/tabs/root/TabsRoot.test.tsx:2382-2385`) |
| Arrow keys + Shift/Control/Alt/Meta | Modifier-held arrow keys neither move focus nor activate (`packages/react/src/tabs/root/TabsRoot.test.tsx:1711-1747`) |

- `activateOnFocus = false` (default): arrow/Home/End keys move focus only and never change the selection — `onValueChange` is not called (`packages/react/src/tabs/root/TabsRoot.test.tsx:1290-1322`, `:1324-1356`, `:1493-1559`, `:1755-1781`, `:1844-1870`); activation then requires Enter/Space (`packages/react/src/tabs/tab/TabsTab.test.tsx:214-241`). The default-`false` is proven by a suite with no `activateOnFocus` prop where arrows don't select (`packages/react/src/tabs/tab/TabsTab.test.tsx:214-241`).
- `activateOnFocus = true`: moving focus to a tab with arrows/Home/End activates it in the same interaction — `onValueChange` fires with the newly focused tab's value (`packages/react/src/tabs/root/TabsRoot.test.tsx:1391-1424`, `:1426-1458`, `:1600-1669`, `:1783-1810`, `:1872-1899`); focusing an inactive tab by any means also activates it (`:575-598`).
- Disabled tabs (via the `disabled` prop) are focusable through arrow keys, Home, and End in both modes, but are never activated by the movement (`packages/react/src/tabs/root/TabsRoot.test.tsx:1358-1387`, `:1462-1488`, `:1561-1597`, `:1672-1708`, `:1812-1840`, `:1901-1929`). A natively disabled tab (rendered through `render={<button disabled />}`) is skipped in a single keypress (`packages/react/src/tabs/list/TabsList.test.tsx:132-157`).

## Focus management

- Roving tabindex: the selected tab has `tabindex="0"` and all others `-1`; changing the controlled value swaps which tab is the tab stop (`packages/react/src/tabs/root/TabsRoot.test.tsx:49-64`). With an uncontrolled default the first tab holds the tab stop (`packages/react/src/tabs/root/TabsRoot.test.tsx:1933-1947`).
- External (programmatic) value change while focus is outside the tablist: the `tabindex="0"` highlight follows the newly selected tab (`packages/react/src/tabs/root/TabsRoot.test.tsx:2534-2562`).
- External value change while focus is inside the tablist: the highlight stays on the focused tab even though `aria-selected` moves to the externally selected tab; subsequent arrow navigation continues from the highlighted (focused) tab (`packages/react/src/tabs/root/TabsRoot.test.tsx:2564-2600`).
- Controlled async activation (parent commits the value in a microtask) keeps focus and selection aligned for both `activateOnFocus` modes (`packages/react/src/tabs/root/TabsRoot.test.tsx:2484-2532`).
- Removing the highlighted tab moves the tab stop to a sensible successor: off a `hidden` successor (`packages/react/src/tabs/list/TabsList.test.tsx:160-188`), to a disabled-but-focusable tab when no enabled successor exists (`:190-211`), staying on the selected tab when focus is inside the list (`:213-238`), and it keeps tracking a successor through subsequent removals (`:240-264`). A removed controlled selection keeps the roving entry point on the first tab, which is reachable with Tab from a preceding button (`packages/react/src/tabs/root/TabsRoot.test.tsx:1147-1184`).
- Disabled tabs remain focusable (`user.focus()` lands and stays, no activation) (`packages/react/src/tabs/tab/TabsTab.test.tsx:147-162`).
- Pointer press with a secondary (non-main) button suppresses focus-activation while the button is held; activation-on-focus resumes after the press ends (`packages/react/src/tabs/tab/TabsTab.test.tsx:164-194`) or after `pointercancel` (`:196-211`).
- Composition with popups: when a `Popover` or `Dialog` containing tabs opens, the first tab receives focus and arrow keys move focus between tabs (`packages/react/src/tabs/root/TabsRoot.test.tsx:2397-2481`).

## Accessibility (roles, aria-*, id linking)

- The list exposes `role="tablist"`; `aria-orientation` is absent by default and set to `"vertical"` when `orientation="vertical"` (`packages/react/src/tabs/root/TabsRoot.test.tsx:1187-1211`). The list can be named via `aria-label` or `aria-labelledby` (`packages/react/src/tabs/list/TabsList.test.tsx:267-292`).
- Tabs expose `role="tab"` with `aria-selected="true"` on the selected tab and `"false"` on all others, updated on every selection change (`packages/react/src/tabs/list/TabsList.test.tsx:15-58`, `packages/react/src/tabs/root/TabsRoot.test.tsx:235-249`).
- Panels expose `role="tabpanel"`; hidden panels remain discoverable with `{ hidden: true }`, i.e. hiding is done via the `hidden` attribute for `keepMounted` panels (`packages/react/src/tabs/root/TabsRoot.test.tsx:66-114`).
- ID linking: each panel's `aria-labelledby` points at its tab's `id` (consumer-supplied ids are respected) and each tab's `aria-controls` points at its panel's generated id, matched by value, not DOM order (`packages/react/src/tabs/root/TabsRoot.test.tsx:66-114`). With no explicit selection the first tab/panel pair is linked in order (`:116-135`).
- `aria-controls` is only present while the panel is mounted: without `keepMounted` exactly the selected tab has it, and it is re-synced after each click (`packages/react/src/tabs/root/TabsRoot.test.tsx:137-164`); a panel with no matching selected value has neither `aria-controls` (on tabs) nor `aria-labelledby` (on the panel) (`:1038-1070`).
- Panel registration is robust under `React.StrictMode`: registrations are cleaned up and replaced when a panel is swapped, unmounted, or remounted (`packages/react/src/tabs/root/TabsRoot.test.tsx:166-231`). When two panels share one value, the last panel to register owns the link; unmounting the shadowed panel keeps the surviving registration intact (`packages/react/src/tabs/panel/TabsPanel.test.tsx:27-61`).
- Panels carry a `data-index` attribute reflecting their position (`packages/react/src/tabs/panel/TabsPanel.test.tsx:64-75`).
- Render-prop state exposes `active` and `tabActivationDirection` on tabs (`packages/react/src/tabs/tab/TabsTab.test.tsx:277-282`) and `value`/`tabActivationDirection` on panels (`packages/react/src/tabs/root/TabsRoot.test.tsx:1999-2001`).
- Indicator accessibility: when no active tab can be measured, the indicator renders with the `hidden` attribute and its state is `activeTabPosition: null` / `activeTabSize: null` (`packages/react/src/tabs/indicator/TabsIndicator.test.tsx:28-57`); with `value={null}` it is not rendered at all (`:59-70`).

## Events (names, payload shape, bubbling, preventDefault semantics)

- `onValueChange(value, eventDetails)` is the only asserted callback on the root. Payload shape proven by tests: `value` is the newly selected tab value (any supported type) or `null` (`packages/react/src/tabs/root/TabsRoot.test.tsx:539`, `:767`, `:1030`); `eventDetails.reason` is one of `'initial'` (`:636`), `'disabled'` (`:895`), `'missing'` (`:999`), or `'none'` for user-initiated changes (`:744`); `eventDetails.activationDirection` is `'none'` (`:637`), `'right'`/`'left'` (`:540`, `:2012`), or `'down'`/`'up'` (`:2040`, `:2050`); `eventDetails.event` is an `Event` instance of `type === 'base-ui'` for the initial auto-selection (`:710-711`); `eventDetails.trigger` is `undefined` for the initial auto-selection (`:712`) — other `trigger` values are not asserted (UNVERIFIED — inferred from `packages/react/src/tabs/root/TabsRoot.test.tsx:712`, no test asserts this).
- Pointer activation: with `activateOnFocus`, `onValueChange` fires on `pointerdown` (press without release), and the consumer's own `onPointerDown` on the tab still fires (`packages/react/src/tabs/root/TabsRoot.test.tsx:508-523`). Plain clicks activate with `activationDirection: 'right'` (`:525-541`). Non-main-button clicks never activate (`:543-557`), and clicking the already-active tab does not re-emit (`:559-573`, also `packages/react/src/tabs/tab/TabsTab.test.tsx:136-145`).
- Focus activation: with `activateOnFocus`, `onValueChange` fires when an inactive tab is focused (`packages/react/src/tabs/root/TabsRoot.test.tsx:575-598`); with `activateOnFocus={false}` it does not (`:600-619`).
- Cancellation semantics: `eventDetails.cancel()` on a user-initiated change (`reason: 'none'`) prevents the uncontrolled root from committing the new value (`packages/react/src/tabs/root/TabsRoot.test.tsx:720-748`) and leaves `data-activation-direction` at `'none'` (`:2186-2215`). Automatic changes (`initial`) cannot be canceled — calling `cancel()` does not stop the selection (`:689-718`).
- Keyboard events: arrow/Home/End `keydown` handling calls `preventDefault` — a consumer `onKeyDown` on `Tabs.List` observes `defaultPrevented === true` (`packages/react/src/tabs/root/TabsRoot.test.tsx:1318-1321`, `:1355`, `:1423`, `:1809`).
- Event bubbling: no test asserts anything about event bubbling for tabs interactions — N/A (UNVERIFIED, no test asserts this).

## Edge cases (rapid interactions, unmount, nesting)

- `null` children and empty children are accepted by the root (`packages/react/src/tabs/root/TabsRoot.test.tsx:31-47`).
- Tab values of heterogeneous types (number, string, object, function, `Symbol`, `RegExp`) all select correctly (`packages/react/src/tabs/root/TabsRoot.test.tsx:251-281`).
- Strict Mode double-rendering: panel registration clean-up and replacement works under `<React.StrictMode>` across replace/unmount/remount sequences (`packages/react/src/tabs/root/TabsRoot.test.tsx:166-231`).
- Dynamic lists: selected tab removed → `missing` fallback (`packages/react/src/tabs/root/TabsRoot.test.tsx:977-1006`); last tab removed → `null` selection and hidden panel (`:1008-1036`); list swapped to empty via `key` → `null` (`:1038-1070`); transient duplicate values settle without a second emission (`:1094-1119`).
- A selected tab becoming disabled mid-life retargets the selection (`packages/react/src/tabs/root/TabsRoot.test.tsx:871-902`), including the case where the explicit default was initially disabled (`:904-938`).
