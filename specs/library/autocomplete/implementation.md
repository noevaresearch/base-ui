# Autocomplete — implementation spec (Stage 2: implementation mining)

Unit: `autocomplete` (packages/react/src/autocomplete). Companion to `specs/library/autocomplete/behavior.md` (WHAT); this document is WHY/HOW. The unit's own code is small: `AutocompleteRoot` is a thin adapter over the Combobox runtime, most parts are aliases of Combobox parts, and the barrel (`index.parts.ts`, `index.ts`) re-exports them under Autocomplete names. The `TODO.md` entry `library: autocomplete` (TODO.md:311-317) has no `wraps-external:` field, so no external-package delegation applies — everything below derives from Base UI source.

## State machine / hooks used

### Unit-level hooks (in this unit's files)

- `React.useState` ×2 in `AutocompleteRoot`: `internalValue` mirrors the typed query for uncontrolled usage, and `inlineInputValue` holds the temporary inline-completion overlay text — two separate state slots, deliberately distinct so the overlay can rewrite what the input *displays* without changing what the list *filters* (packages/react/src/autocomplete/root/AutocompleteRoot.tsx:55-56). This split is the mechanism behind the behavior spec's "temporary inline-completion input value that is distinct from the filter query" (State model section).
- `React.useEffect` clears the overlay whenever the value is externally controlled or inline mode is off (packages/react/src/autocomplete/root/AutocompleteRoot.tsx:58-62); combined with `handleValueChange` clearing the overlay on every value change (packages/react/src/autocomplete/root/AutocompleteRoot.tsx:80-86), this guarantees a committed/typed value always replaces the overlay — the source of the "controlled update replaces the temporary value" and readOnly "pending inline completion is dropped, never restored" behaviors (State model / Keyboard interactions sections).
- Overlay composition is render-derived, not stored: `resolvedInputValue` prefers a non-empty `inlineInputValue`, then the controlled `value` (with `null` → `''`), then `internalValue` (packages/react/src/autocomplete/root/AutocompleteRoot.tsx:64-72). A controlled `null` therefore behaves as an empty query, matching the State model section.
- `useCoreFilter` builds the locale-aware collator filter; the resolved filter is `null` when `mode` is `inline`/`none` (`staticItems`) or `filter === null`, otherwise the custom `filter` or the collator `contains` (packages/react/src/autocomplete/root/AutocompleteRoot.tsx:74-78). `filterQuery` is pinned to the typed query only in `mode='both'` (packages/react/src/autocomplete/root/AutocompleteRoot.tsx:113-116), which is why ArrowDown can rewrite the input without disturbing filtering (State model section).
- `handleItemHighlighted` re-emits the combobox highlight callback and writes the highlighted item's label into the overlay via `stringifyAsLabel`, but only for non-pointer reasons (packages/react/src/autocomplete/root/AutocompleteRoot.tsx:88-103) — the early return on `REASONS.pointer` is what makes hover "safe" in `mode='both'` (Edge cases section).
- `AutocompleteValue` has no state machine: it reads the current input value from context and resolves `children` as render-function, static node, or raw value (packages/react/src/autocomplete/value/AutocompleteValue.tsx:14-25).
- `props.mode` maps to three independent switches: `enableInline` (overlay writes; forced off under `readOnly`, packages/react/src/autocomplete/root/AutocompleteRoot.tsx:49), `staticItems` (skip filtering, line 50), and `autoComplete={mode}` which becomes the `aria-autocomplete` value (see Context/DOM below).

### Delegated state machine (AriaCombobox — cited because it *is* the runtime)

`AutocompleteRoot` renders `<AriaCombobox selectionMode="none" fillInputOnItemPress ...>` and forwards everything else (packages/react/src/autocomplete/root/AutocompleteRoot.tsx:105-122). Inside `AriaCombobox`:

- `useControlled` ×3 backs the three externally controllable states: `selectedValue` (packages/react/src/combobox/root/AriaCombobox.tsx:293-298, inert under `selectionMode='none'`), `inputValue` (packages/react/src/combobox/root/AriaCombobox.tsx:324-329, fed by `resolvedInputValue`/`defaultValue`), and `open` (packages/react/src/combobox/root/AriaCombobox.tsx:331-336).
- The core state is a `ReactStore` (packages/react/src/combobox/root/AriaCombobox.tsx:453-542) holding `activeIndex`/`selectedIndex`, element refs, prop bags for each part, and flags (`inputInsidePopup`, `inline`, `inputOwnsFormValue`). Parts subscribe via `store.useState`; the root syncs prop-derived values in a layout effect (packages/react/src/combobox/root/AriaCombobox.tsx:1490-1501) and registers imperative callbacks into the store (packages/react/src/combobox/root/AriaCombobox.tsx:1437-1444).
- Highlight machine: `setIndices` writes `activeIndex` into the store and routes the highlighted value through `emitHighlight`, which deduplicates against `lastHighlightRef` (packages/react/src/combobox/root/AriaCombobox.tsx:600-646). Typing defers highlight updates via `pendingQueryHighlightRef` until after filtered items are derived (packages/react/src/combobox/root/AriaCombobox.tsx:680-712); the main highlight effect reconciles index vs items on every commit, handles `autoHighlight='always'` (first-item highlight), out-of-range resets, and no-highlight emission (packages/react/src/combobox/root/AriaCombobox.tsx:1050-1181). `useListNavigation` drives arrow-key movement and hover, tagging reasons `keyboard`/`pointer` and honoring `keepHighlight` via `resetOnPointerLeave` (packages/react/src/combobox/root/AriaCombobox.tsx:1355-1389). This produces the "first ArrowDown does not highlight and the second does" and highlight-persistence behaviors (Keyboard interactions / Edge cases sections).
- Open/close machine: `setOpen` fires `onOpenChange`, handles Escape propagation when the list is empty, freezes the query as `closeQuery` during exit animations (`queryChangedAfterOpen`), and commits Field touched/validation on focus-out close (packages/react/src/combobox/root/AriaCombobox.tsx:750-829); `handleInterruptedReopen` releases a frozen query when a close is interrupted (packages/react/src/combobox/root/AriaCombobox.tsx:728-748). Typing resets list scroll and manages the `aria-activedescendant`-relevant index in the same input-change path (packages/react/src/combobox/root/AriaCombobox.tsx:661-713).
- Cross-cutting hooks with call sites: `useIsoLayoutEffect` (index sync packages/react/src/combobox/root/AriaCombobox.tsx:996-1041, values registry packages/react/src/combobox/root/AriaCombobox.tsx:1043-1048, highlight reconciliation packages/react/src/combobox/root/AriaCombobox.tsx:1050-1181, Field `filled` packages/react/src/combobox/root/AriaCombobox.tsx:1183-1191, store sync packages/react/src/combobox/root/AriaCombobox.tsx:1490-1501), `useValueChanged` render-phase change detectors (packages/react/src/combobox/root/AriaCombobox.tsx:1265-1270), `useStableCallback` for every handler handed to the store or floating hooks (packages/react/src/combobox/root/AriaCombobox.tsx:555-556 and throughout), `useTransitionStatus` (packages/react/src/combobox/root/AriaCombobox.tsx:573), `useOpenInteractionType` (packages/react/src/combobox/root/AriaCombobox.tsx:574), `useLabelableId` (packages/react/src/combobox/root/AriaCombobox.tsx:158), `useRegisterFieldControl` (packages/react/src/combobox/root/AriaCombobox.tsx:578-585), `useOpenChangeComplete`/`actionsRef.unmount` (packages/react/src/combobox/root/AriaCombobox.tsx:983-994), `useRefWithInit` (packages/react/src/combobox/root/AriaCombobox.tsx:314, packages/react/src/combobox/root/AriaCombobox.tsx:453), `useMergedRefs` (packages/react/src/combobox/root/AriaCombobox.tsx:1503), `useValueAsRef` (packages/react/src/combobox/root/AriaCombobox.tsx:571), `useOnFirstRender` (packages/react/src/combobox/root/AriaCombobox.tsx:1448-1457).

## Context providers/consumers

`AriaCombobox` establishes five nested providers (packages/react/src/combobox/root/AriaCombobox.tsx:1643-1655); the Autocomplete parts read them via the shared Combobox context module (packages/react/src/combobox/root/ComboboxRootContext.tsx:17-28):

1. `ComboboxRootContext` — the `ReactStore` instance; consumed by every part (Item, Trigger, Input, List, Popup, Positioner, Portal, InputGroup, Clear, Icon, Group, …) through `useComboboxRootContext`. This is the single source of truth for open/highlight/selection/props-bags.
2. `ComboboxFloatingContext` — the `FloatingRootContext` shared by Positioner/Popup/dismiss handling.
3. `ComboboxHasItemsContext` — whether the `items` prop was provided; read by `Empty` and list rendering logic.
4. `ComboboxDerivedItemsContext` — `query`, `filteredItems`, `flatFilteredValues`; consumed by list-derived parts (List/Group/Empty/Row/Collection).
5. `ComboboxInputValueContext` — the current input value. This one is consumed *inside this unit*: `AutocompleteValue` reads it (packages/react/src/autocomplete/value/AutocompleteValue.tsx:14) to render the current text without an element (Value section of the behavior spec).

In this unit's own files, `AutocompleteItem`, `AutocompleteTrigger`, `AutocompleteInputGroup`, and `AutocompleteSeparator` are identity aliases of Combobox/Listbox parts (packages/react/src/autocomplete/item/AutocompleteItem.tsx:12, packages/react/src/autocomplete/trigger/AutocompleteTrigger.tsx:14, packages/react/src/autocomplete/input-group/AutocompleteInputGroup.tsx:14, packages/react/src/autocomplete/separator/AutocompleteSeparator.tsx:30-32), so all context consumption beyond `AutocompleteValue` happens in the delegated implementations. `Autocomplete.Root` itself is element-less and adds no provider of its own (packages/react/src/autocomplete/root/AutocompleteRoot.tsx:9-14).

Non-combobox contexts crossing the boundary (from the delegated runtime): `FieldRootContext`/`FormContext`/`DirectionContext` (packages/react/src/combobox/root/AriaCombobox.tsx:144-157) — these supply the Field state attributes, validation wiring, and RTL behavior documented in the Accessibility section of the behavior spec. Trigger/InputGroup state types explicitly extend `FieldRootState` (packages/react/src/autocomplete/trigger/AutocompleteTrigger.tsx:16, packages/react/src/autocomplete/input-group/AutocompleteInputGroup.tsx:16).

## DOM/portal strategy and why

- The unit adds **no DOM of its own**. `AutocompleteRoot`, `AutocompleteValue` render fragments; `Input`, `Portal`, `Positioner`, `Popup`, `List`, `Empty`, `Status`, `Arrow`, `Backdrop`, `Group*`, `Row`, `Collection`, `Clear`, `Icon` are Combobox parts re-exported verbatim (packages/react/src/autocomplete/index.parts.ts:4-20); `Item`, `Trigger`, `InputGroup`, `Separator` are aliases (see above). The `Portal > Positioner > Popup > List` structure of the behavior spec's DOM section is therefore Combobox's popup strategy: position against the input (or the trigger when the input lives inside the popup — the floating reference is chosen by `inputInsidePopup`, packages/react/src/combobox/root/AriaCombobox.tsx:1272-1279), with `useClick`/`useDismiss`/`useListNavigation` supplying interaction prop bags (packages/react/src/combobox/root/AriaCombobox.tsx:1323-1389).
- `inline` skips the popup entirely: the floating root is forced open (packages/react/src/combobox/root/AriaCombobox.tsx:1273), `expanded` stays true so ARIA stays consistent (packages/react/src/combobox/root/AriaCombobox.tsx:1281-1285), and the `List` renders in place — the mechanism behind the `inline` prop's no-portal behavior (DOM structure section).
- The hidden form control is the one DOM node the root runtime always renders, as a sibling after `children` (packages/react/src/combobox/root/AriaCombobox.tsx:1546-1638): it is `aria-hidden`, `tabIndex=-1`, visually hidden, carries `value` = serialized field value, autofill `onChange` handling, and focus redirection to the visible input/trigger. Naming is policy-driven: the hidden input drops `name` when the visible input owns the form value (`hiddenInputName`, packages/react/src/combobox/root/AriaCombobox.tsx:1523-1524; `inputOwnsFormValue` derived at packages/react/src/combobox/root/AriaCombobox.tsx:1498 from `selectionMode === 'none' && (inline || !inputInsidePopup)`), and SSR duplication is avoided by seeding `inputOwnsFormValue: selectionMode === 'none'` so the closed-popup default renders exactly one named control (packages/react/src/combobox/root/AriaCombobox.tsx:512-514). Under `selectionMode='none'` the visible input is the raw text, which is why submitted FormData is the typed text, not a resolved item (Events section).
- Autofill works by matching the change event's serialized value against registered item values/labels (packages/react/src/combobox/root/AriaCombobox.tsx:1561-1623) — for autocomplete (`selectionMode='none'`) it simply writes the value into the input (packages/react/src/combobox/root/AriaCombobox.tsx:1584-1587), the "hidden control change updates the visible input" behavior (Events section).

## Anything in source not explained by any test

Flagged gaps — none of these are covered by the unit's three test files (behavior.md, "Public API surface" + "Shared harness dependencies" sections):

1. **Inherited-but-undocumented props leak through the root adapter.** `AutocompleteRootProps` omits and re-does many Combobox props (packages/react/src/autocomplete/root/AutocompleteRoot.tsx:139-167) but passes `{...other}` straight to `AriaCombobox` (packages/react/src/autocomplete/root/AutocompleteRoot.tsx:107). `loopFocus`, `grid`, `virtualized`, `modal`, `limit`, `onOpenChangeComplete`, `inputRef` remain in the public type via inheritance yet have no autocomplete JSDoc and no autocomplete test. Golden fixtures must decide whether these are supported surface or accidental leakage.
2. **Grouped `items` are type-tested only.** `AutocompleteRoot.spec.tsx` asserts grouped arrays and the nested-item `itemToStringValue` typing (packages/react/src/autocomplete/root/AutocompleteRoot.spec.tsx:17-56), but no runtime test in this unit renders grouped items; the grouping/filter runtime (packages/react/src/combobox/root/AriaCombobox.tsx:371-403) is exercised only by Combobox tests.
3. **`AutocompleteSeparator` has zero coverage in this unit.** It is a cast-alias of `ListboxSeparator` (packages/react/src/autocomplete/separator/AutocompleteSeparator.tsx:30-32) with no test here; its fixture behavior must be sourced from the listbox-separator implementation, and the `orientation` prop contract (packages/react/src/autocomplete/separator/AutocompleteSeparator.tsx:6-14) is asserted nowhere at runtime.
4. **Ten barrel parts are untested under the Autocomplete name.** `Icon`, `Clear`, `Backdrop`, `Arrow`, `Status`, `Empty`, `Group`, `GroupLabel`, `Row`, `Collection` are exported (packages/react/src/autocomplete/index.parts.ts:6-20) but none appear in any autocomplete test; their contracts live in the Combobox unit. Also `Autocomplete.useFilter`/`Autocomplete.useFilteredItems` (packages/react/src/autocomplete/index.parts.ts:24-25) are untested here.
5. **Type-only contracts in `AutocompleteRoot.spec.tsx`.** `value` must be a string (packages/react/src/autocomplete/root/AutocompleteRoot.spec.tsx:82-83), collections are rejected (packages/react/src/autocomplete/root/AutocompleteRoot.spec.tsx:110-119), and `eventDetails.isItemPress` is not emitted in `mode`-based autocomplete (packages/react/src/autocomplete/root/AutocompleteRoot.spec.tsx:101-108) — compile-time guarantees with no runtime equivalent, so fixture oracles cannot assert them.
6. **`AutocompleteValue` outside a Root.** The component degrades to reading the context default `''` (packages/react/src/combobox/root/ComboboxRootContext.tsx:27-28, packages/react/src/autocomplete/value/AutocompleteValue.tsx:14) rather than throwing like other parts; untested and arguably inconsistent with the context-missing errors elsewhere (packages/react/src/combobox/root/ComboboxRootContext.tsx:30-38).
7. **`aria-activedescendant` plumbing is implicit.** The behavior spec verifies the attribute on the input (Accessibility section), but the mechanism — `useListNavigation` with `virtual: true` + the store's element/id state — lives entirely in packages/react/src/combobox/root/AriaCombobox.tsx:1355-1389 and the list/input prop bags (packages/react/src/combobox/root/AriaCombobox.tsx:1391-1424); no autocomplete test pins *how* ids are generated, only that they stay stable across filtering.
