## State model (controlled/uncontrolled, defaults, transitions)

- Text value: uncontrolled via `defaultValue` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1859`) or controlled via `value` + `onValueChange` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:979-986`); a controlled `null` value is treated as an empty query (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1322-1344`). `onValueChange` receives the typed/committed string, e.g. `'al'` on Escape dismissal (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:156`).
- Committed value becomes the query: after Enter commits `'alpha'`, the input value is `'alpha'` and reopening keeps it (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:48-49`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:113-116`).
- Popup open state: opens on typing (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:55-60`), on input click with `openOnInputClick` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:391`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1019`), and via ArrowDown (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:570-576`); closes on Enter selection (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:51-53`), Tab (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:62-66`), and Escape (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:118-119`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:151-153`). Controlled `open` and `defaultOpen` are supported (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:689`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:721`).
- Highlight state is internal: set by typing with `autoHighlight` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:45-46`), by pointer hover (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:744-749`), and by arrow keys after an initial "no highlight" step (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:639-647`); reported through `onItemHighlighted` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:426-465`).
- `mode='both'` maintains a temporary inline-completion input value that is distinct from the filter query: ArrowDown rewrites the input to `'apple'` while the option list stays filtered against the typed query (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:933-940`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1200-1206`); an external controlled update replaces the temporary value (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1009-1014`).
- `mode='list'` (default) applies no inline overlay and the root still filters supplied items by default (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:873-906`); `mode='inline'` shows the overlay but neither filters nor calls a custom filter (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1017-1053`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1209-1234`); `mode='none'` does neither (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1055-1086`).

## Keyboard interactions

- ArrowDown/ArrowUp: with `autoHighlight`, ArrowDown from a closed/open state highlights the first item and sets `aria-activedescendant` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:548-576`); without `autoHighlight`, the first ArrowDown does not highlight and the second does (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:634-647`); ArrowUp from the no-highlight state does highlight (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:542-545`); ArrowDown advances the highlight in list order (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:831-836`).
- Enter: commits the highlighted item into the input (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:48-49`), invokes that item's `onClick` (`packages/react/src/autocomplete/item/AutocompleteItem.test.tsx:66-70`), closes the popup (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:51-53`), and by default does not submit the owning form (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1348-1385`).
- Enter with `submitOnItemClick`: submits the owning form with the committed value when an item is highlighted (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1466-1511`) and also when no item is highlighted (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:2086-2128`); Enter always submits when no item is highlighted, even without `submitOnItemClick` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:2048-2084`).
- Escape: closes the popup (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:151-153`); in the popup-input composition it preserves the typed value as the value ('al' remains and `onValueChange` fired with it) and reopens filtered (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:151-163`).
- Tab: closes the popup (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:62-66`).
- `readOnly`: arrow keys still open/operate the list (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:249-252`) but item press/Enter never commits (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:254-257`), and a pending inline completion is dropped when `readOnly` turns on, never restored (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:292-321`).

## Focus management

- Popup-input composition (Input inside Popup): the popup input receives focus when the popup opens (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:100-102`); after Enter commit the popup closes and focus is restored to the trigger (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:107-110`); after Escape, focus also returns to the trigger (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:151-154`).
- Programmatic listbox focus is redirected: focusing the listbox keeps focus on the input and Enter still works (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1600-1614`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:2171-2179`).
- With `readOnly` and `mode='both'`, programmatic focus is treated as keyboard-driven highlight (highlight moves) but the input is never filled with the highlighted item (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:278-289`).
- With `autoHighlight='always'` + `keepHighlight` + `open` + `inline`, a pointer highlight survives outside pointerdown/blur (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:740-762`).

## Accessibility (roles, aria-*, id linking)

- The visible input exposes `role="combobox"` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:40`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:379`); in trigger compositions `getByRole('combobox')` resolves to the trigger that opens the popup (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1732`). The popup itself exposes `role="dialog"` when the input lives inside it (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:109`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:119`), and extra aria props pass through to it (`aria-label="Commands"` — `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:83`).
- The list exposes `role="listbox"` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:63`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:252`) and items expose `role="option"` with accessible name from their content (`packages/react/src/autocomplete/item/AutocompleteItem.test.tsx:34`, `packages/react/src/autocomplete/item/AutocompleteItem.test.tsx:98`).
- The input's `aria-activedescendant` is linked to the highlighted option's `id` while highlighted (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:491`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:575`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:601-611`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:684`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:710`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:747-757`); ids stay stable across filtering (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:607-611`); the attribute is absent when nothing is highlighted (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:524`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:637`).
- The highlighted option carries `data-highlighted` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:46`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:463`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:791`); items do NOT carry `data-selected` after a value is chosen and the popup reopens (`packages/react/src/autocomplete/item/AutocompleteItem.test.tsx:97-99`); Trigger/InputGroup never expose `data-placeholder` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:416-422`).

## DOM structure & portal behavior

- Popup content renders through `Portal > Positioner > Popup > List` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:23-35`, `packages/react/src/autocomplete/item/AutocompleteItem.test.tsx:15-27`); with the `inline` prop the `List` is rendered in place with no portal (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:721-731`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1759-1767`).
- A hidden form control participates in the DOM: it resolves as `role="textbox"` with `hidden: true` and receives change events for autofill simulation (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:191-198`). With `name` on Root, the visible input gets the `name` and `autoComplete` while the hidden input gets an `id` but no `name` and no `autocomplete` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:380-386`).
- Naming rules per composition: inline input carries the `name` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1775`) and the hidden input does not (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1777-1778`); a popup-rendered input has no `name` attribute (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1734`); server-rendered output contains exactly one `name="search"` control for both the inline (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1786-1810`) and outside-popup (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1812-1845`) compositions, while the closed-popup default value is server-rendered unnamed (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1888-1921`).
- Typing resets the list's scroll position to the top (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1092-1129`, browser-only), but inline-completion navigation in `mode='both'` must not reset scroll (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1131-1170`, browser-only).
- Autocomplete is form-association aware: `submitOnItemClick` submits the combobox input's owning form and falls back to it when another control claims the shared validation ref (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1431-1464`), and a `form="external-form"` attribute routes submission/association to an external form (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1513-1560`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1923-1947`, both browser-only).

## Events (names, payload shape, bubbling, preventDefault semantics)

- `onItemHighlighted(value, eventDetails)`: fires when the popup auto-highlights on open/type; payload is the item's string value (`'alpha'`) and `eventDetails.reason` is `'none'` in that flow (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:452-464`).
- `onValueChange(nextValue)`: fires with the current text value, e.g. the typed `'al'` when dismissed with Escape (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:123-156`), and is suppressed entirely for autofill/commit attempts while `readOnly` or `disabled` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:201-228`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:333-360`).
- `Autocomplete.Item` `onClick`: invoked on pointer click (`packages/react/src/autocomplete/item/AutocompleteItem.test.tsx:31-37`) and also when the item is selected with Enter through the root (`packages/react/src/autocomplete/item/AutocompleteItem.test.tsx:66-70`).
- Form submission: by default Enter with a highlighted item does not submit the owning form (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1348-1385`); `submitOnItemClick` makes pointer item clicks and highlighted-item Enter submit the owning form with the input value (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1387-1429`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1466-1511`); Enter with no highlighted item submits (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:2048-2084`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:2086-2128`); Enter from a focused listbox submits the highlighted item's value (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:2130-2180`).
- FormData semantics: the submitted value is the raw input text, not a resolved selection value (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:2010-2046`); the popup input's value is submitted through native FormData (via the hidden control) even though the popup input lacks `name` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1696-1745`), including a `defaultValue` before the popup ever opens (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1847-1886`); plain `Form`/`Field.Root` submission submits the typed text (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1627-1652`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1654-1694`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1747-1784`).
- Browser autofill: a `change` event on the hidden control updates the visible input (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:170-199`) and is ignored under `readOnly`/`disabled` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:201-228`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:333-360`).

## Edge cases (rapid interactions, unmount, nesting)

- Reopen after commit: the previously chosen item is not marked `data-selected` (`packages/react/src/autocomplete/item/AutocompleteItem.test.tsx:74-100`); the popup input retains the committed value and the list shows only matching options (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:113-116`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:158-163`).
- Typing then re-typing after commit reopens the popup; Tab then closes it (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:55-66`).
- `mode='both'` hover safety: hovering another option does not change the inline overlay value (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:943-974`); controlled updates from outside replace the temporary inline value (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:976-1015`).
- Highlight persistence: a trailing space in the query does not clear the highlight (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:493-497`); clearing the query retains the highlighted option (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:650-685`); `keepHighlight` keeps the highlight when the pointer leaves the list and keyboard navigation continues from it (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:765-837`).
- `autoHighlight='always'` highlights the first item immediately on `defaultOpen` with no interaction (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:687-712`); plain `autoHighlight` does not highlight on click-open or the initial arrow presses (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:500-546`).
- Item value objects: `{label}` objects filter/match by `label` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:2183-2217`), `{value}` objects by `value` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:2255-2286`), and `itemToStringValue` provides the string for objects lacking either (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:2219-2253`); `filter=null` disables default filtering entirely (async-results pattern, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1269-1318`).
- Locale-aware default filter: with `locale="tr"`, typing `'i'` matches `'İzmir'` but not `'Isparta'` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:841-871`); a custom `filter` replaces the locale-aware default (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1236-1267`).
- Items with an empty-string `value` are accepted (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:2322`).
- Portal `keepMounted` keeps the popup subtree mounted across close/open cycles; jsdom runs the unmount/remount variant while the browser runner keeps it mounted (documented test-env divergence, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:70-81`). Scroll tests and external-form tests are browser-only via `it.skipIf(isJSDOM)` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1092`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1131`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1513`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1923`); two `validationMode` tests are jsdom-only via `it.skipIf(!isJSDOM)` (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:2578`, `packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:2611`). SSR (`renderToString`) is covered for the three form-naming compositions (`packages/react/src/autocomplete/root/AutocompleteRoot.test.tsx:1786-1921`).
