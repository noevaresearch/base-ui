# PreviewCard — implementation spec (mined from source)

Unit: `packages/react/src/preview-card/`. Companion to `behavior.md` (same directory), which is ground truth for WHAT happens; this document explains WHY/HOW. The unit's TODO.md entry has no `wraps-external:` field (see `specs/library/preview-card/behavior.md:3`), so nothing here is a delegation of an external package — everything is implemented natively on the internals listed in "Dependencies on other Base UI internals".

The defining architectural fact: PreviewCard's own source contains almost no state machine. It is a thin component family over the shared popup framework in `packages/react/src/utils/popups/` plus the vendored `packages/react/src/floating-ui-react/` layer. Almost every behavior in `behavior.md` is produced by calling shared hooks with preview-card-specific parameters.

## State machine / hooks used

### The store is the state machine

All state lives in one `PreviewCardStore` instance created by the Root (see "Context providers/consumers" for how it is shared).

- `PreviewCardStore` extends `ReactStore` with state = the shared `PopupStoreState<Payload>` plus three preview-card additions: `instantType` (`'dismiss' | 'focus' | undefined`), `adaptiveOrigin` (a middleware instance or undefined), and `closeDelay` (initialized to the `CLOSE_DELAY` constant) `packages/react/src/preview-card/store/PreviewCardStore.ts:20-24`, `packages/react/src/preview-card/store/PreviewCardStore.ts:121-127`. Context adds `inlineRectCoordsRef`, the ref holding hovered-line coordinates `packages/react/src/preview-card/store/PreviewCardStore.ts:26-28`, `packages/react/src/preview-card/store/PreviewCardStore.ts:132-139`.
- Controlled/uncontrolled resolution is done by store selectors, not by a `useControlled` hook: the shared `open` selector reads `openProp ?? open` and the shared `activeTriggerId` selector reads `triggerIdProp ?? activeTriggerId` `packages/react/src/utils/popups/store.ts:140-142`. This is why `defaultOpen` is ignored under a controlled `open` (behavior.md, "State model"): `defaultOpen` only seeds internal `open`, which the selector shadows whenever `openProp` is defined. The Root mirrors the external props into the store with `store.useControlledProp('openProp', openProp)` and `store.useControlledProp('triggerIdProp', triggerIdProp)` `packages/react/src/preview-card/root/PreviewCardRoot.tsx:50-51`, and syncs the callbacks (which live in store context, not state, so identity churn is free) with `store.useContextCallback` `packages/react/src/preview-card/root/PreviewCardRoot.tsx:53-54`.
- Store creation happens exactly once via `usePopupRootStore`, which also resolves `floatingId` (via `useId`) and `nested` (via `useFloatingParentNodeId() != null`) on the first render and wires the synced `FloatingRootStore` `packages/react/src/preview-card/root/PreviewCardRoot.tsx:36-48`, `packages/react/src/utils/popups/popupStoreUtils.ts:73-96`. `useSyncedFloatingRootContext` keeps the floating layer's view in sync: the popup's *positioner element* is what Floating UI treats as the floating element (`treatPopupAsFloatingElement` defaults to false) `packages/react/src/floating-ui-react/hooks/useSyncedFloatingRootContext.ts:51-55`, `packages/react/src/floating-ui-react/hooks/useSyncedFloatingRootContext.ts:82-107`. This is the mechanical reason hover-out is observed by dispatching `mouseLeave` on the positioner (behavior.md, "Events").
- The single open/close mutation is `store.setOpen(nextOpen, eventDetails)`. It delegates to the shared `applyPopupOpenChange` sequence: notify `onOpenChange` → honor `cancel()` → run `onBeforeDispatch` → dispatch to the floating root → commit state `packages/react/src/utils/popups/popupStoreUtils.ts:241-308` (cancellation at `packages/react/src/utils/popups/popupStoreUtils.ts:270-272`; this is what implements the `eventDetails.cancel()` abort semantics in behavior.md, "Events"). The preview-card-specific `onBeforeDispatch` captures hovered inline-rect coordinates when the reason is `triggerHover` and the event carries pointer coordinates, but only when the trigger changed (`inlineRectCoordsRef.current?.element !== eventDetails.trigger`) — this is the "card stays anchored to the originally opened line" rule from behavior.md, "DOM structure & portal behavior" `packages/react/src/preview-card/store/PreviewCardStore.ts:75-96`. For hover reasons the state commit is wrapped in `ReactDOM.flushSync` so `node.getAnimations()` observes the new state synchronously (enter/exit transitions and the reopen-timing tests in behavior.md, "Edge cases") `packages/react/src/utils/popups/popupStoreUtils.ts:302-307`. The same function maps the change reason onto `instantType`: focus-open → `'focus'`, press/Escape close → `'dismiss'`, hover → `undefined` `packages/react/src/utils/popups/popupStoreUtils.ts:291-297`; that value surfaces as the `instant` state of the positioner/popup/viewport `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:88-94`, `packages/react/src/preview-card/popup/PreviewCardPopup.tsx:51-57`, `packages/react/src/preview-card/viewport/PreviewCardViewport.tsx:34-38`.
- Mount/transition lifecycle: `useOpenStateTransitions(open, store, onUnmount)` on the Root drives `mounted` and `transitionStatus` via `useTransitionStatus`, syncs them into the store, and returns `forceUnmount` (used by `actionsRef.unmount`, which also fires `onOpenChangeComplete(false)`) `packages/react/src/utils/popups/popupStoreUtils.ts:554-601`, `packages/react/src/preview-card/root/PreviewCardRoot.tsx:62-64`, `packages/react/src/preview-card/root/PreviewCardRoot.tsx:74-81`. The Root passes an `onUnmount` callback that clears `inlineRectCoordsRef` — the "hovered-line coordinates cleared after close" behavior `packages/react/src/preview-card/root/PreviewCardRoot.tsx:63`. The close-completion side of `onOpenChangeComplete` runs here (`useOpenChangeComplete` → `forceUnmount` when the exit transition finishes and unmount is not prevented) `packages/react/src/utils/popups/popupStoreUtils.ts:589-598`; the open-completion side runs in the Popup via its own `useOpenChangeComplete` that calls `onOpenChangeComplete(true)` `packages/react/src/preview-card/popup/PreviewCardPopup.tsx:37-45`. That split is why `onOpenChangeComplete` fires after each transition settles but not on a closed mount (behavior.md, "State model").
- Active-trigger reconciliation: `useImplicitActiveTrigger(store, { closeOnActiveTriggerUnmount: true })` `packages/react/src/preview-card/root/PreviewCardRoot.tsx:61`. The shared hook claims the sole registered trigger when the popup opens with no explicit trigger id, re-associates the active id when an element re-registers under a different id, and — with the option enabled — schedules a close *after a microtask* when the active trigger unmounts, so a same-tick replacement trigger with the same id can register first; the close uses `REASONS.none` and honors `cancel()`, in which case ownership is preserved `packages/react/src/utils/popups/popupStoreUtils.ts:416-537` (close path at `packages/react/src/utils/popups/popupStoreUtils.ts:506-527`). This is the cancelable unmount-close with reason `'none'` in behavior.md, "State model" and "Events".
- The `triggerHover` reopen rules (behavior.md, "Edge cases": no open delay while a hover-close transition is running, immediate switch between triggers) are decided inside the trigger-side hover hook. PreviewCard passes `isClosing: () => store.select('transitionStatus') === 'ending'` `packages/react/src/preview-card/trigger/PreviewCardTrigger.tsx:70-78`; the hook computes `shouldOpenImmediately = (isOverInactive && (isOpen || isHoverCloseTransition)) || isReenteringSameTriggerDuringCloseTransition` and opens synchronously in those cases, otherwise starting the `delay` timer `packages/react/src/floating-ui-react/hooks/useHoverReferenceInteraction.ts:260-301`. `delay: 0` therefore opens synchronously inside the hover handler (behavior.md, "State model").
- Nested-card coordination (behavior.md, "Edge cases") comes from the floating tree: popup-side `mouseleave` ignores moves into a descendant floating element, listens for tree `'floating.closed'` events from children, and closes on a zero-delay `childClosedTimeout` when the last child closed while the parent has no remaining children `packages/react/src/floating-ui-react/hooks/useHoverFloatingInteraction.ts:199-247`. The Root joins/creates the tree via `FloatingTree` (see below).
- Imperative paths: `actionsRef.close()` calls `store.setOpen(false, { reason: REASONS.imperativeAction })` `packages/react/src/preview-card/root/PreviewCardRoot.tsx:74-81`; the reason union enumerates `triggerHover | triggerFocus | triggerPress | outsidePress | escapeKey | imperativeAction | none` `packages/react/src/preview-card/root/PreviewCardRoot.tsx:188-195`, and `preventUnmountOnClose` is attached to the details object by the shared open-change sequence (`attachPreventUnmountOnClose` closure flag consumed by `createPopupOpenState`) `packages/react/src/utils/popups/popupStoreUtils.ts:190-231`. `handle.open(id)`/`handle.close()`/`isOpen` are thin wrappers over `BasePopupHandle.openByTrigger`/`closePopup`/`attachedStore.select('open')` `packages/react/src/preview-card/store/PreviewCardHandle.ts:32-50`. `openByTrigger` resolves the trigger element from the trigger registry (searching the whole attachment stack newest-first plus the fallback store, so an open-by-id in the attach commit still resolves), throws for a missing id on anchored popups, and calls the attached store's `setOpen(true, { reason: imperativeAction, trigger })` `packages/react/src/utils/popups/popupHandle.ts:215-265`. The no-root warning, the deferred multi-root overlap warning (one `AnimationFrame` later, only if still overlapping), and stack-based restore-on-detach live in `BasePopupHandle` `packages/react/src/utils/popups/popupHandle.ts:73-78`, `packages/react/src/utils/popups/popupHandle.ts:151-187`. While detached, the handle exposes an inert `NullStore` built by `createNullPreviewCardStore`, which preserves a real trigger registry so detached triggers can register before migrating to a live root store `packages/react/src/preview-card/store/PreviewCardStore.ts:105-113`, `packages/react/src/preview-card/store/PreviewCardHandle.ts:16-22`.
- Hook inventory (call sites): `useId`/`useRefWithInit`/`useSyncedFloatingRootContext` via `usePopupRootStore` `packages/react/src/preview-card/root/PreviewCardRoot.tsx:36`; `useControlledProp` ×2 `packages/react/src/preview-card/root/PreviewCardRoot.tsx:50-51`; `useContextCallback` ×2 `packages/react/src/preview-card/root/PreviewCardRoot.tsx:53-54`; `useImplicitActiveTrigger` `packages/react/src/preview-card/root/PreviewCardRoot.tsx:61`; `useOpenStateTransitions` `packages/react/src/preview-card/root/PreviewCardRoot.tsx:62`; `useIsoLayoutEffect` (payload clearing) `packages/react/src/preview-card/root/PreviewCardRoot.tsx:66-72`; `React.useImperativeHandle` `packages/react/src/preview-card/root/PreviewCardRoot.tsx:74-81`; `useDismiss` `packages/react/src/preview-card/root/PreviewCardRoot.tsx:97`; `usePopupInteractionProps` `packages/react/src/preview-card/root/PreviewCardRoot.tsx:101-105`; `useBaseUiId` `packages/react/src/preview-card/trigger/PreviewCardTrigger.tsx:49`; `useTriggerDataForwarding` `packages/react/src/preview-card/trigger/PreviewCardTrigger.tsx:60-68`; `useHoverReferenceInteraction` `packages/react/src/preview-card/trigger/PreviewCardTrigger.tsx:70-78`; `useFocus` `packages/react/src/preview-card/trigger/PreviewCardTrigger.tsx:80`; `useAnchorPositioning` `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:60-79`; `useIsoLayoutEffect` (reposition) `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:82-86`; `useFloatingNodeId` `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:50`; `useOpenChangeComplete` `packages/react/src/preview-card/popup/PreviewCardPopup.tsx:37-45`; `useHoverFloatingInteraction` `packages/react/src/preview-card/popup/PreviewCardPopup.tsx:47-49`; `usePopupViewport` `packages/react/src/preview-card/viewport/PreviewCardViewport.tsx:28-32`. Classic `React.useCallback` appears nowhere in the unit per repo convention (`useStableCallback` is used inside the shared hooks instead).

### Dismiss wiring (Escape / outside press)

`PreviewCardInteractions` is a component that renders `null` and exists only to push `useDismiss` prop bags into store state while `open || mounted` (the Root skips it entirely when fully closed) `packages/react/src/preview-card/root/PreviewCardRoot.tsx:83`, `packages/react/src/preview-card/root/PreviewCardRoot.tsx:94-108`. `activeTriggerProps = dismiss.reference`, `inactiveTriggerProps = dismiss.trigger` (same object as `reference`), `popupProps = dismiss.floating` `packages/react/src/preview-card/root/PreviewCardRoot.tsx:99-105`; `usePopupInteractionProps` syncs them into state and resets them to `EMPTY_OBJECT` on unmount `packages/react/src/utils/popups/popupStoreUtils.ts:605-624`. The Trigger spreads the active/inactive bag onto its element (so outside presses on triggers resolve correctly) and the Popup spreads `popupProps` — that bag is where the Escape keydown handler lives (`closeOnEscapeKeyDown`, honoring cancellation via `eventDetails.isCanceled`) `packages/react/src/floating-ui-react/hooks/useDismiss.ts:204-233`. Escape-while-composing, child-blocking (`hasBlockingChild`), and bubbling rules are shared logic `packages/react/src/floating-ui-react/hooks/useDismiss.ts:172-181`.

### Trigger registration and per-trigger data

A trigger contributes three things to the store: its element (registry), its `payload`, and its resolved `closeDelay` (after applying the `OPEN_DELAY`/`CLOSE_DELAY` defaults from `packages/react/src/preview-card/utils/constants.ts:1-2`, documented as 600/300 in the prop JSDoc `packages/react/src/preview-card/trigger/PreviewCardTrigger.tsx:133-142`). `useTriggerDataForwarding` returns a stable `registerTrigger` ref callback that (a) registers/unregisters the element in `PopupTriggerMap` (O(1) id map with a dev-only reverse element index that throws on duplicate claims) `packages/react/src/utils/popups/popupTriggerMap.ts:28-64`, `packages/react/src/utils/popups/popupStoreUtils.ts:144-183`, and (b) applies trigger-owned state when the registering trigger is the active one; if the popup is already open with no active trigger, the first registered trigger claims ownership `packages/react/src/utils/popups/popupStoreUtils.ts:334-358`. A layout effect re-runs registration keyed on `[store, id]` to migrate the element when the store pointer changes (the detached-handle migration path) and a second effect re-applies payload/`activeTriggerElement` whenever `isMountedByThisTrigger` or the forwarded data changes `packages/react/src/utils/popups/popupStoreUtils.ts:371-385`. The Trigger itself subscribes per-id with `store.useState('isTriggerActive', id)` and `store.useState('isOpenedByTrigger', id)`; those selectors compare against `triggerIdProp ?? activeTriggerId` and additionally require `open` `packages/react/src/preview-card/trigger/PreviewCardTrigger.tsx:50-51`, `packages/react/src/utils/popups/store.ts:183-189`. The popup reads the *active* trigger's `closeDelay` from store state for its floating-side hover close (see DOM section) — this is how per-trigger close delays work with a single shared popup.

### Payload flow

Payload never flows through React context. It is per-trigger data written into store state by the trigger (`useTriggerDataForwarding`) and read by the Root with `store.useState('payload')`, then passed as the argument of the function-children API `packages/react/src/preview-card/root/PreviewCardRoot.tsx:59`, `packages/react/src/preview-card/root/PreviewCardRoot.tsx:89`. A `useIsoLayoutEffect` clears `payload` when open with no active trigger `packages/react/src/preview-card/root/PreviewCardRoot.tsx:66-72`.

## Context providers/consumers

Three React contexts, two of which are "stable object as context value" so consumers re-render granularly via store subscriptions rather than via context value churn:

1. **`PreviewCardRootContext` — the store itself.** The context type *is* `PreviewCardStore<Payload>` (`React.createContext<PreviewCardRootContext | undefined>`) `packages/react/src/preview-card/root/PreviewCardContext.ts:5-9`. Provided by Root `packages/react/src/preview-card/root/PreviewCardRoot.tsx:86`. Consumed by Portal, Positioner, Popup, Arrow, Backdrop, Viewport (required) and by Trigger (optional) and Root itself (optional, for nesting detection) via `usePreviewCardRootContext` whose required form throws the "PreviewCardRootContext is missing" error recorded in behavior.md, "Public API surface" `packages/react/src/preview-card/root/PreviewCardContext.ts:13-22`. Crossing the boundary: store state reads (`open`, `mounted`, `transitionStatus`, `instantType`, `payload`, `popupProps`, `floatingRootContext`, …) and the `inlineRectCoordsRef` context member.
2. **`PreviewCardPositionerContext`** — a `Pick` of the anchor-positioning return value: `side`, `align`, `arrowRef`, `arrowUncentered`, `arrowStyles` `packages/react/src/preview-card/positioner/PreviewCardPositionerContext.ts:5-12`. Provided by the Positioner around its `FloatingNode` element `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:105-109`. Consumers: Popup (resolves `side`/`align` into its state attributes) `packages/react/src/preview-card/popup/PreviewCardPopup.tsx:28`, Arrow (registers itself through `arrowRef` and reads side/align/uncentered) `packages/react/src/preview-card/arrow/PreviewCardArrow.tsx:22-23`, Viewport (reads `side` for the resize axis) `packages/react/src/preview-card/viewport/PreviewCardViewport.tsx:24`. The required hook throws the "PreviewCardPositionerContext is missing" error that both Popup and Viewport produce (behavior.md, "Public API surface") `packages/react/src/preview-card/positioner/PreviewCardPositionerContext.ts:14-23`.
3. **`PreviewCardPortalContext`** — the `keepMounted` boolean `packages/react/src/preview-card/portal/PreviewCardPortalContext.ts:4`. Provided by Portal `packages/react/src/preview-card/portal/PreviewCardPortal.tsx:30`. Sole consumer: Positioner, which threads it into `useAnchorPositioning` so keep-mounted positioners skip re-mount repositioning churn and get `hidden` while closed `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:49`, `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:60-79`. The hook throws "Base UI: <PreviewCard.Portal> is missing." (behavior.md, "Public API surface") `packages/react/src/preview-card/portal/PreviewCardPortalContext.ts:6-11`.

Two boundaries are deliberately *not* React contexts:

- **Detached triggers bypass the root context entirely.** A Trigger resolves its store as `handleStore ?? rootContext` where `handleStore = usePopupHandleStore(handle)` — a `useSyncExternalStore` over the handle's store pointer (fallback store while detached, live root store after attach) `packages/react/src/preview-card/trigger/PreviewCardTrigger.tsx:40-47`, `packages/react/src/utils/popups/usePopupHandleStore.ts:17-36`. When a root attaches, `PopupHandleAttachment` (rendered by Root before children so its layout effect runs first in the commit) binds the root store onto the handle and notifies subscribers, and the trigger's registration effect migrates its element to the new store `packages/react/src/preview-card/root/PreviewCardRoot.tsx:87`, `packages/react/src/utils/popups/popupStoreUtils.ts:108-120`. This is the mechanism behind the handle handoff/overlap behaviors in behavior.md, "State model".
- **Shared interaction prop bags cross into store state**, not context (see "Dismiss wiring" above) — inactive triggers read their props through the `triggerProps` selector keyed on activeness `packages/react/src/utils/popups/store.ts:195-196`.

Public surface wiring: `index.parts.ts` aliases the parts and `createHandle`/`Handle` under the `PreviewCard` namespace, and `index.ts` re-exports the type namespaces `packages/react/src/preview-card/index.parts.ts:1-12`, `packages/react/src/preview-card/index.ts:1-10`. The `*DataAttributes.ts` files are thin aliases of the shared common attributes (e.g. open/closed/starting/ending style, side, align, anchor-hidden, popupOpen) `packages/react/src/preview-card/popup/PreviewCardPopupDataAttributes.ts:6-27`, `packages/react/src/preview-card/arrow/PreviewCardArrowDataAttributes.ts:6-24`, `packages/react/src/preview-card/backdrop/PreviewCardBackdropDataAttributes.ts:6-18`, `packages/react/src/preview-card/positioner/PreviewCardPositionerDataAttributes.ts:6-19`, `packages/react/src/preview-card/trigger/PreviewCardTriggerDataAttributes.ts:6`, `packages/react/src/preview-card/viewport/PreviewCardViewportDataAttributes.ts:4-24`.

## DOM/portal strategy and why

Composition is `Root` → (`Trigger` | detached triggers) + `Portal` → (`Backdrop`?, `Positioner` → `Popup` → (`Arrow` | `Viewport`)?), matching behavior.md, "DOM structure & portal behavior".

- **Portal**: `PreviewCardPortal` renders nothing until `mounted || keepMounted`, then provides the keepMounted flag and renders `FloatingPortalLite` into `container` (element, shadow root, ref, or default `<body>`) `packages/react/src/preview-card/portal/PreviewCardPortal.tsx:19-33`. `FloatingPortalLite` is the no-focus-management portal variant: it lacks the tabbable-logic handling of the full `FloatingPortal`, which is correct here because focus never moves into the popup (behavior.md, "Focus management") `packages/react/src/utils/FloatingPortalLite.tsx:10-13`.
- **Positioner**: a `<div role="presentation">` rendered through the shared `usePositioner` helper with `hidden: !mounted` and `inert: !open` (inline `pointer-events: none` while closed, so a closing card's positioner never swallows hover from the page) `packages/react/src/utils/usePositioner.tsx:23-44`, `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:96-103`. It is wrapped in `FloatingNode` with an id from `useFloatingNodeId` so the card is a node in the floating tree `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:105-109`. Positioning parameters default to `positionMethod: 'absolute'`, `side: 'bottom'`, `align: 'center'`, zero offsets, `collisionBoundary: 'clipping-ancestors'`, `collisionPadding/arrowPadding: 5`, and `collisionAvoidance: POPUP_COLLISION_AVOIDANCE` (`{ fallbackAxisSide: 'end' }`, the free-flipping popup preset) `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:33-43`, `packages/react/src/internals/constants.ts:22-28`. Explicit `updatePosition()` runs in a `useIsoLayoutEffect` when `open && mounted` `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:82-86`. The positioner element setter (`store.useStateSetter('positionerElement')`) is what feeds the floating layer's `floatingElement` (see "State machine"). It exposes the shared CSS vars (`--available-width/height`, `--anchor-width/height`, `--transform-origin`, `--positioner-width/height`) for consumer CSS animations `packages/react/src/preview-card/positioner/PreviewCardPositionerCssVars.ts:5-36`.
- **Multiline (inline) anchoring**: the Positioner passes `inline: createInlineMiddleware(inlineRectCoordsRef)` to `useAnchorPositioning` — Preview Card is the only consumer of this parameter in the codebase `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:78`, `packages/react/src/internals/useAnchorPositioning.ts:809-811`. The middleware recomputes the reference rect from the trigger's client-rect line boxes (grouped per line, with hit-testing of the captured pointer coordinates and side-aware fallback grouping for single-line/left-right edges) and issues a Floating UI `reset` when the rect differs `packages/react/src/utils/popups/inlineRect.ts:62-104`, `packages/react/src/utils/popups/inlineRect.ts:131-193`, `packages/react/src/utils/popups/inlineRect.ts:237-292`. Coordinates are captured in two places: in `setOpen`'s `onBeforeDispatch` on hover-open (see "State machine") and continuously by `getInlineRectTriggerProps` spread onto the trigger — `mouseenter`/`mousemove` update them only while the card is closed by this trigger, and `focus` clears them (the "focus-open anchors to the first client rect / controlled open to the last rect / cleared on close" rules in behavior.md, "DOM structure & portal behavior") `packages/react/src/utils/popups/inlineRect.ts:203-224`, `packages/react/src/preview-card/trigger/PreviewCardTrigger.tsx:85-88`.
- **Transform vs top/left positioning**: without a Viewport the positioner uses Floating UI's transform-based `floatingStyles`; when a Viewport is mounted, `usePopupViewport` installs the shared `adaptiveOrigin` middleware into store state `packages/react/src/utils/usePopupViewport.tsx:112-117`, the Positioner forwards it `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:57`, `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:77`, and `useAnchorPositioning` then switches to `{ [sideX]: x, [sideY]: y }` left/top coordinates (with `sideX/sideY` chosen by the middleware data, defaulting to `left`/`top`) so CSS transforms stay free for the popup's morph/resize animations — the `style.transform === ''` observation in behavior.md, "DOM structure & portal behavior" `packages/react/src/internals/useAnchorPositioning.ts:497-533`, `packages/react/src/utils/adaptiveOriginConstants.ts:1-4`. The same hook writes the seeded `--available-width/height` vars and computes `--transform-origin` `packages/react/src/internals/useAnchorPositioning.ts:353-359`, `packages/react/src/internals/useAnchorPositioning.ts:440-442`, `packages/react/src/internals/useAnchorPositioning.ts:526-527`.
- **Popup**: a plain `<div>` merging `FOCUSABLE_POPUP_PROPS` (`tabIndex: -1` plus the floating-layer focusable marker — programmatically focusable for touch paths without a tab stop), the store's `popupProps` (the dismiss bag; Escape lives here), and `getDisabledMountTransitionStyles(transitionStatus)` (suppresses the mount transition for `defaultOpen` popups) `packages/react/src/utils/popups/popupStoreUtils.ts:32-35`, `packages/react/src/preview-card/popup/PreviewCardPopup.tsx:59-69`. Its refs bind the forwarded ref, `store.context.popupRef` (used by all `useOpenChangeComplete`/transition listeners), and the `popupElement` setter. The popup-side hover hook (`useHoverFloatingInteraction(floatingContext, { closeDelay })` with the *active trigger's* close delay) attaches mouseenter/mouseleave to the floating (positioner) element: enter clears pending close timers, leave closes after the close delay unless the pointer moved into a trigger or a descendant floating element `packages/react/src/preview-card/popup/PreviewCardPopup.tsx:35`, `packages/react/src/preview-card/popup/PreviewCardPopup.tsx:47-49`, `packages/react/src/floating-ui-react/hooks/useHoverFloatingInteraction.ts:158-247`. State attributes (`data-open/closed/starting-style/ending-style/side/align`) come from `popupTransitionStateMapping` rather than inline conditionals `packages/react/src/preview-card/popup/PreviewCardPopup.tsx:68`.
- **Trigger**: renders an `<a>` (behavior.md, "Public API surface") via `useRenderElement('a', …)` merging, in order: hover props (native `mouseenter`/`mouseleave` listeners with the delay/safePolygon config; `move: false` disables the rest-velocity mousemove open path), focus props (`useFocus` reference handlers — focus opens with the same delay, blur closes; Escape/press dismissal blocks immediate re-open via the shared `blockedReferenceRef` mechanism), the store's trigger props bag (dismiss outside-press handling), the inline-rect props, and the id `packages/react/src/preview-card/trigger/PreviewCardTrigger.tsx:90-102`, `packages/react/src/floating-ui-react/hooks/useHoverReferenceInteraction.ts:196-414`, `packages/react/src/floating-ui-react/hooks/useFocus.ts:44-59`. Trigger state attributes use `triggerOpenStateMapping` (`data-popup-open` per behavior.md, "Accessibility") `packages/react/src/preview-card/trigger/PreviewCardTrigger.tsx:101`.
- **Backdrop**: purely presentational `<div role="presentation">` with `hidden: !mounted` and inline `pointerEvents/userSelect` (including `-webkit-user-select`) none; it never attaches listeners, consistent with hover-only dismissal semantics `packages/react/src/preview-card/backdrop/PreviewCardBackdrop.tsx:34-47`.
- **Arrow**: a `<div aria-hidden>` registered through the positioner context's `arrowRef` and styled by the positioning middleware's `arrowStyles`; state carries `open/side/align/uncentered` (`data-uncentered` when the arrow cannot center on the anchor) `packages/react/src/preview-card/arrow/PreviewCardArrow.tsx:27-39`.
- **Viewport (morphing)**: `usePopupViewport` replaces the viewport's children. Normally a single `[data-current]` container keyed by `usePopupContentKey` (a key that bumps on active-trigger change and once more if the payload arrives a render later, forcing remounts so stale DOM like `<img>` previews never flash) `packages/react/src/utils/usePopupViewport.tsx:367-395`. During a trigger switch it renders an additional `[data-previous]` container marked `inert` and absolutely positioned, filled *imperatively* with a DOM `cloneNode` snapshot of the outgoing children (clones, not React elements, because the previous subtree may be stateful), frozen with `--popup-width/height` vars and a `data-ending-style` phase toggle paired with `data-starting-style` on the current container; both are removed after animations finish via an abortable `useAnimationsFinished` watcher re-armed through `useAnimationFrame` `packages/react/src/utils/usePopupViewport.tsx:156-224`, `packages/react/src/utils/usePopupViewport.tsx:226-275`, `packages/react/src/utils/usePopupViewport.tsx:137-146`. `data-activation-direction` is a space-separated horizontal/vertical label derived from trigger-center deltas with a 5px tolerance (empty axis when within tolerance) `packages/react/src/utils/usePopupViewport.tsx:307-340` — the attribute grammar documented in `packages/react/src/preview-card/viewport/PreviewCardViewportDataAttributes.ts:10-15`. Auto-resize during morphing is delegated to `usePopupAutoResize` (measure-layout callbacks suppress animations, then restore them and freeze previous dimensions) `packages/react/src/utils/usePopupViewport.tsx:277-286`. The viewport's own CSS var aliases (`--popup-width/height`) mirror the common ones for consumers `packages/react/src/preview-card/viewport/PreviewCardViewportCssVars.ts:5-11`.
- **Root as element-less coordinator**: `PreviewCardRoot` is a `fastComponent` that wraps itself in `FloatingTree` only when no ancestor `PreviewCardRootContext` exists — the outermost card establishes the floating tree; a nested card joins the ancestor's tree so tree-based dismiss/hover coordination works across nesting levels `packages/react/src/preview-card/root/PreviewCardRoot.tsx:116-128`.

## Anything in source not explained by any test

Flagged gaps, for the golden-fixture stage and the backward-looking audit loop:

1. **Outside-press dismissal is wired but never tested.** `useDismiss` is called with defaults (`outsidePress: true`) and its reference/floating prop bags are spread onto triggers and popup `packages/react/src/preview-card/root/PreviewCardRoot.tsx:97-105`, `packages/react/src/floating-ui-react/hooks/useDismiss.ts:120-128`, yet no preview-card test asserts an outside-press close, and behavior.md ("Events") records only hover/Escape/imperative closes. Whether outside press should close a preview card is a real open question the fixtures should pin.
2. **No ARIA linkage exists in source at all.** The shared store exposes `popupId` and `triggerPopupId` selectors for popup↔trigger id wiring `packages/react/src/utils/popups/store.ts:144-147`, `packages/react/src/utils/popups/store.ts:200-201`, but no preview-card part consumes them, and the trigger's merged props contain no `aria-haspopup`/`aria-describedby`/`aria-expanded` `packages/react/src/preview-card/trigger/PreviewCardTrigger.tsx:90-102`. This upgrades behavior.md's "Accessibility" UNVERIFIED note: it's not merely untested, it's unimplemented for this unit.
3. **`closeDelay` forwarding across triggers.** The active trigger's resolved `closeDelay` is written into store state by `useTriggerDataForwarding` and read by the Popup's floating-side hover hook `packages/react/src/preview-card/trigger/PreviewCardTrigger.tsx:60-68`, `packages/react/src/preview-card/popup/PreviewCardPopup.tsx:35`, `packages/react/src/utils/popups/popupStoreUtils.ts:376-385`. Single-trigger close delay is tested (behavior.md, "State model"), but the cross-trigger case (trigger B's closeDelay being the one honored while the pointer is on the shared popup after switching) is not asserted anywhere.
4. **`instant` state / `data-instant`.** `instantType` flows into the `instant` state of positioner, popup, and viewport `packages/react/src/preview-card/positioner/PreviewCardPositioner.tsx:93`, `packages/react/src/preview-card/popup/PreviewCardPopup.tsx:55`, and the viewport documents a `data-instant` attribute `packages/react/src/preview-card/viewport/PreviewCardViewportDataAttributes.ts:20-24`.
