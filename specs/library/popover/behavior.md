## State model (controlled/uncontrolled, defaults, transitions)

- Uncontrolled: clicking the trigger toggles open→closed (a second anchor click closes it) (`packages/react/src/popover/root/PopoverRoot.test.tsx:48-62`). `defaultOpen: true` opens at mount (`packages/react/src/popover/root/PopoverRoot.test.tsx:433-437`) and the popover stays fully interactive (click closes it) (`packages/react/src/popover/root/PopoverRoot.test.tsx:451-461`).
- `defaultOpen` is ignored when `open` is controlled: `defaultOpen: true` + `open: false` stays closed (`packages/react/src/popover/root/PopoverRoot.test.tsx:439-443`); `defaultOpen: true` + `open: true` stays open (`packages/react/src/popover/root/PopoverRoot.test.tsx:445-449`).
- Controlled: `onOpenChange` fires for each change; in the recorded controlled-toggle sequence the calls are `(false)` then `(true)` for close-then-open clicks (`packages/react/src/popover/root/PopoverRoot.test.tsx:97-134`).
- `onOpenChange` eventDetails supports `cancel()` — canceling a nextOpen request blocks opening while uncontrolled (`packages/react/src/popover/root/PopoverRoot.test.tsx:593-611`) and canceling a close keeps the popover open without changing the trigger (`packages/react/src/popover/root/PopoverRoot.test.tsx:613-645`).
- `preventUnmountOnClose()` keeps the popup mounted after close (until `actionsRef.unmount()` or a later close): after a prevented close the popup remains in the DOM (`packages/react/src/popover/root/PopoverRoot.test.tsx:136-189`), and a subsequent normal close does unmount it (`packages/react/src/popover/root/PopoverRoot.test.tsx:647-687`). A `preventUnmountOnClose` does not leak into a synchronous second close request (`packages/react/src/popover/root/PopoverRoot.test.tsx:2080-2134`) nor across a root unmount/remount cycle (`packages/react/src/popover/root/PopoverRoot.test.tsx:2136-2211`).
- `actionsRef.current.close()` closes the popover imperatively (`packages/react/src/popover/root/PopoverRoot.test.tsx:1401-1412`); `actionsRef.current.unmount()` unmounts a kept-mounted popup (`packages/react/src/popover/root/PopoverRoot.test.tsx:1362-1399`).
- Active-trigger model: with `triggerId` controlled, `onOpenChange` receives `details.trigger?.id`, which the app mirrors back into `triggerId` to programmatically pick which trigger's payload shows (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:629-693`). `defaultTriggerId` selects the initially active trigger for a `defaultOpen` popover (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:820-845`, `packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:1191-1217`).
- Handle API (`Popover.createHandle()`): imperative `open(triggerId)` / `close()` open and close the popover and set `trigger.aria-expanded` accordingly (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:1345-1380`); `open(id)` sets the payload from that trigger's `payload` prop (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:1382-1423`); `handle.isOpen` reflects the open state (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:51-55`, `packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:214-215`); calls with an unregistered trigger id throw an error containing the id (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:352-372`); calls made before a root attaches or after it detaches are ignored with a "no root using this handle is mounted" warning (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:202-245`, `packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:247-322`); a handle attached to more than one mounted root triggers a "more than one mounted root" warning via a deferred check (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:374-410`).
- Hover-open state transitions: opens after the `delay` (rest-type delay by default) (`packages/react/src/popover/root/PopoverRoot.test.tsx:479-499`) and closes after `closeDelay` (`packages/react/src/popover/root/PopoverRoot.test.tsx:502-528`). A popup opened externally (not by trigger hover) does not close on hover-out of the popup (`packages/react/src/popover/root/PopoverRoot.test.tsx:191-222`) or when it was opened without trigger hover (`packages/react/src/popover/root/PopoverRoot.test.tsx:463-476`); a popup opened by its trigger's hover does close on hover-out (`packages/react/src/popover/root/PopoverRoot.test.tsx:224-251`).
- Style hooks on the trigger: `data-popup-open` + `data-pressed` when opened by click (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:209-224`); `data-popup-open` without `data-pressed` when opened by hover (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:226-244`); with `openOnHover` and `delay=0` a subsequent click adds no `data-pressed` (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:246-267`), while with a non-zero hover delay a click adds `data-pressed` (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:269-290`).
- Popup transition attributes: `data-open` while open (`packages/react/src/popover/root/PopoverRoot.test.tsx:569-572`), `data-closed` after close (`packages/react/src/popover/root/PopoverRoot.test.tsx:890-893`), `data-ending-style` during the closing transition (`packages/react/src/popover/positioner/PopoverPositioner.test.tsx:577-579`); `data-starting-style` is referenced by test CSS but never directly asserted — UNVERIFIED — inferred from `packages/react/src/popover/root/PopoverRoot.test.tsx:1783-1786`, no test asserts this attribute directly.

## Keyboard interactions

- Button trigger: Enter/Space open the popover (tests drive opening via keyboard on the focused trigger, e.g. `packages/react/src/popover/popup/PopoverPopup.test.tsx:237-243` and nested-menu tests pressing `{Enter}` on the trigger, `packages/react/src/popover/root/PopoverRoot.test.tsx:349-357`).
- Non-button trigger (`render={<div />}` + `nativeButton={false}`): Enter toggles open and closed, Space toggles open and closed, and Tab/Shift+Tab moves focus back to the trigger and closes the popover (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:462-521`, browser-only).
- Escape closes the popover (`packages/react/src/popover/root/PopoverRoot.test.tsx:79-82`, `packages/react/src/popover/popup/PopoverPopup.test.tsx:245-248`); Escape close then Enter reopen passes interaction type `'keyboard'` to `initialFocus` (`packages/react/src/popover/popup/PopoverPopup.test.tsx:215-221`).
- Tab forward from inside the popup skips any popup content and lands on the first focusable element after the trigger, and the popover closes (`packages/react/src/popover/root/PopoverRoot.test.tsx:824-847`, with focusable elements between trigger and popup `packages/react/src/popover/root/PopoverRoot.test.tsx:987-1012`, popup placed before the trigger `packages/react/src/popover/root/PopoverRoot.test.tsx:1054-1078`).
- Tab backward from inside the popup moves focus to the trigger and the popup stays visible; a subsequent Tab forward re-enters the popup (`packages/react/src/popover/root/PopoverRoot.test.tsx:949-983`, `packages/react/src/popover/root/PopoverRoot.test.tsx:1014-1050`, `packages/react/src/popover/root/PopoverRoot.test.tsx:1080-1116`).
- Tabbing out of a nested combobox popup closes the combobox and then the popover (`packages/react/src/popover/root/PopoverRoot.test.tsx:849-898`, backward `packages/react/src/popover/root/PopoverRoot.test.tsx:900-947`); tabbing out of a nested menu moves focus to the element after the menu, closes the menu, and keeps the popover open (`packages/react/src/popover/root/PopoverRoot.test.tsx:1272-1319`).
- Composite keys (e.g. ArrowRight) pressed inside the popup are NOT relayed to an enclosing Toolbar composite handler (`packages/react/src/popover/popup/PopoverPopup.test.tsx:677-705`), while native key behavior (caret movement in an input) keeps working inside the popup (`packages/react/src/popover/popup/PopoverPopup.test.tsx:709-730`).

## Focus management

- `initialFocus` default: the first focusable element inside the popup receives focus on click-open (`packages/react/src/popover/popup/PopoverPopup.test.tsx:73-101`).
- `initialFocus` accepts a ref (`packages/react/src/popover/popup/PopoverPopup.test.tsx:103-138`) or a function returning an element (`packages/react/src/popover/popup/PopoverPopup.test.tsx:140-176`); a function receives the latest interaction type — `'keyboard'` when opened via keyboard and `'touch'` when opened via touch pointerdown, updated on each reopen (`packages/react/src/popover/popup/PopoverPopup.test.tsx:223-256`); element-returning functions and no-op returns (`false`/`undefined`) are both supported (`packages/react/src/popover/popup/PopoverPopup.test.tsx:178-221`); `initialFocus={false}` does not move focus (trigger keeps it) (`packages/react/src/popover/popup/PopoverPopup.test.tsx:258-282`); returning `true` (`packages/react/src/popover/popup/PopoverPopup.test.tsx:284-307`) or `null` (`packages/react/src/popover/popup/PopoverPopup.test.tsx:309-332`) falls back to the default first-focusable behavior.
- Browser-only: if the focused element inside the popup becomes `display: none`, focus moves to the popup element itself (`packages/react/src/popover/popup/PopoverPopup.test.tsx:335-371`).
- `finalFocus` default: the trigger is focused when the popover closes (`packages/react/src/popover/popup/PopoverPopup.test.tsx:415-446`); accepts a ref (`packages/react/src/popover/popup/PopoverPopup.test.tsx:448-488`) or function (`packages/react/src/popover/popup/PopoverPopup.test.tsx:490-522`); `finalFocus={false}` does not move focus (`packages/react/src/popover/popup/PopoverPopup.test.tsx:524-551`); `() => true` moves focus to the trigger (`packages/react/src/popover/popup/PopoverPopup.test.tsx:553-580`); a function receives the close type — pointer close falls back to the default (trigger), keyboard close targets the returned element (`packages/react/src/popover/popup/PopoverPopup.test.tsx:582-627`); returning `null` uses the default (`packages/react/src/popover/popup/PopoverPopup.test.tsx:629-654`).
- Closing a keepMounted popover (not unmounted) restores focus to the trigger (`packages/react/src/popover/root/PopoverRoot.test.tsx:691-718`).
- Hover-open does not move focus into the popup (`packages/react/src/popover/root/PopoverRoot.test.tsx:755-774`), and hover open+close leaves the user's focus where it was (`packages/react/src/popover/root/PopoverRoot.test.tsx:776-821`); if the popover was click-opened before the hover delay completed, focus still returns to the trigger on close (`packages/react/src/popover/popup/PopoverPopup.test.tsx:373-412`).
- Modal focus containment: with `modal=true` or `modal='trap-focus'` (and a Close part rendered), elements outside the popover become inert (`aria-hidden="true"`, `inert`, or `data-base-ui-inert` on the element or an ancestor) (`packages/react/src/popover/close/PopoverClose.test.tsx:184-226`).
- Modal focus guards: `modal=true` without a Close part places `data-base-ui-focus-guard` elements immediately before and after the trigger (`packages/react/src/popover/root/PopoverRoot.test.tsx:1466-1492`); when a Close part is rendered the guards are instead rendered only inside the popup (two `[data-base-ui-focus-guard][data-type="inside"]` elements, none around the trigger) (`packages/react/src/popover/root/PopoverRoot.test.tsx:1437-1464`). For detached triggers, focus guards appear around the active trigger while open and are removed on close (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:1181-1188`).
- Reopening a keepMounted popover after tabbing out restores focus into the popup (temporarily disabled/inert focus is re-enabled) (`packages/react/src/popover/root/PopoverRoot.test.tsx:720-753`).
- Non-modal popups close as soon as focus leaves the popup via pointer-down outside (`packages/react/src/popover/root/PopoverRoot.test.tsx:1239-1270`).
- `modal='trap-focus'`: when the focused popup child is removed on pointerdown, focus moves to the popup element and outside-press dismissal still works (`packages/react/src/popover/root/PopoverRoot.test.tsx:1322-1358`).
- Programmatic close returns focus to the active trigger even when the popover was opened without any focus (from body focus) (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:695-763`); when the active trigger unmounts while open, focus returns to the element focused before the popover opened (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:765-818`).
- Nested popovers restore focus through the close order: closing the child returns focus to the element that opened it, then closing the parent returns focus to the parent trigger (`packages/react/src/popover/root/PopoverRoot.test.tsx:1832-1901`).

## Accessibility (roles, aria-*, id linking)

- The popup has `role="dialog"` (`packages/react/src/popover/root/PopoverRoot.test.tsx:20-34` with harness assertion `packages/react/test/popupConformanceTests.tsx:71-76`).
- The trigger has `aria-expanded="false"` initially and `"true"` when open (`packages/react/test/popupConformanceTests.tsx:87-105`), `aria-controls` set to the popup's id when open (`packages/react/test/popupConformanceTests.tsx:80-85`), and `aria-haspopup="dialog"` (the suite's `expectedAriaHasPopupValue` defaults to the popup role, `packages/react/test/popupConformanceTests.tsx:12`, asserted at `packages/react/test/popupConformanceTests.tsx:107-113`); a custom popup `id` is honored in the `aria-controls` link (`packages/react/test/popupConformanceTests.tsx:115-120`).
- Multiple triggers: only the active trigger gets `aria-expanded="true"` and `aria-controls=<popup id>`; the others get `aria-expanded="false"` and no `aria-controls` (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:552-574`); a single trigger without an explicit `triggerId` still gets a synced `aria-controls` (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:576-595`).
- `Popover.Title` links itself to the popup via `aria-labelledby=<title id>` on the dialog (`packages/react/src/popover/title/PopoverTitle.test.tsx:25-41`); `Popover.Description` links via `aria-describedby=<description id>` (`packages/react/src/popover/description/PopoverDescription.test.tsx:25-41`).
- Disabled trigger: native button gets the `disabled` attribute plus `data-disabled`, cannot open the popover on click, and is skipped by Tab (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:48-69`); a custom (non-native) element gets `data-disabled` and `aria-disabled="true"` instead, and likewise cannot be clicked or tabbed into (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:71-93`).
- Positioner exposes `data-side` (e.g. flips to `top`) (`packages/react/src/popover/positioner/PopoverPositioner.test.tsx:356-358`) and `data-align` (e.g. `end` after alignment flip) (`packages/react/src/popover/positioner/PopoverPositioner.test.tsx:855-858`).
- `Popover.Viewport` morphing containers expose `data-previous` (rendered `inert` with the outgoing content) and `data-current` containers inside a `[data-transitioning]` wrapper, cleaned up after the animation (`packages/react/src/popover/viewport/PopoverViewport.test.tsx:289-309`), plus a `data-activation-direction` attribute on the viewport with space-separated direction tokens (`right`/`left`/`up`/`down`, omitted tokens when the movement is within tolerance) (`packages/react/src/popover/viewport/PopoverViewport.test.tsx:587-595`).
- `Popover.Backdrop` sets `pointer-events: none` when the popover was opened by hover (`packages/react/src/popover/backdrop/PopoverBackdrop.test.tsx:16-34`) and not when opened by click (`packages/react/src/popover/backdrop/PopoverBackdrop.test.tsx:36-54`).
- `modal=true` renders an internal backdrop element with `role="presentation"` as the positioner's previous sibling (`packages/react/src/popover/root/PopoverRoot.test.tsx:1416-1435`); `modal=false` renders none (`packages/react/src/popover/root/PopoverRoot.test.tsx:1494-1513`); with hover-open the internal backdrop only appears after the impatient click promotes the hover-open to a click-open (`packages/react/src/popover/root/PopoverRoot.test.tsx:1518-1543`).

## DOM structure & portal behavior

- Popup renders its children (`packages/react/src/popover/popup/PopoverPopup.test.tsx:57-70`).
- The Portal renders content outside the React tree into `container` (an element or ShadowRoot) (`packages/react/src/popover/root/PopoverRoot.test.tsx:1166-1235`); `keepMounted` keeps the positioner/popup mounted while closed, and in both modes the popup stays anchored when the trigger moves (`packages/react/src/popover/positioner/PopoverPositioner.test.tsx:369-429`).
- Switching triggers reuses the same popup and positioner DOM nodes instead of remounting them (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:597-627`, `packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:1056-1091`); after a trigger switch with a Viewport, the popup carries no inline `scale` style that would fight CSS transitions (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:1219-1271`).
- Positioning without a Viewport is transform-based on the positioner (`packages/react/src/popover/positioner/PopoverPositioner.test.tsx:587-604`); with a `Popover.Viewport` the positioner switches to `top`/`left` positioning (`packages/react/src/popover/positioner/PopoverPositioner.test.tsx:606-624`).
- `sideOffset`/`alignOffset` accept numbers or data-reading functions; the offset function can read the resolved (post-flip) `side`/`align`, including logical sides (`inline-start` resolves to `inline-end` in the flipped position, and stays `inline-start` under RTL) (`packages/react/src/popover/positioner/PopoverPositioner.test.tsx:62-314`).

## Edge cases (rapid interactions, unmount, nesting)

- Impatient vs patient clicks with `openOnHover`: a click within `PATIENT_CLICK_THRESHOLD` of hover-open does not close the popover (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:298-319`); a click after the threshold closes it (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:321-342`); an impatient click makes the popover "stick" so a subsequent mouse-leave doesn't close it (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:344-370`, also before the hover delay completes `packages/react/src/popover/trigger/PopoverTrigger.test.tsx:396-425`); a patient click does not stick (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:372-394`); re-hovering and clicking within the threshold keeps the popover open (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:427-459`).
- Touch vs hover ownership: after a touch tap opens the popover, hovering a sibling trigger does not steal ownership (content stays on the tapped trigger) (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:171-186`); when opened by mouse, hovering a sibling trigger does hand ownership over (`packages/react/src/popover/trigger/PopoverTrigger.test.tsx:190-205`).
- Touch-opened modal popovers scroll-lock the document only when the popup covers (nearly) the viewport width (`packages/react/src/popover/root/PopoverRoot.test.tsx:1588-1620`); a narrower popup does not scroll-lock (`packages/react/src/popover/root/PopoverRoot.test.tsx:1622-1655`).
- Rapid viewport morphing: clicking triggers in quick succession (trigger1→2→3→1) still settles on the correct content (`packages/react/src/popover/viewport/PopoverViewport.test.tsx:403-466`); morph containers (`data-previous` inert showing old content + `data-current` showing new) are created during transitions and cleaned up after the animation (`packages/react/src/popover/viewport/PopoverViewport.test.tsx:214-311`), including after a kept-mounted popup closes and reopens (`packages/react/src/popover/viewport/PopoverViewport.test.tsx:313-401`); the activation direction is computed with a ~5px tolerance (differences within tolerance produce no direction token) (`packages/react/src/popover/viewport/PopoverViewport.test.tsx:468-596`).
- Detached-trigger robustness: hover handoff between triggers works even when the rendered component retains a stale ref (trigger registration migrates stores; popup shows the newly hovered trigger's payload) (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:58-104`); re-hosting a trigger node (key swap) re-registers on the attached store so `open('id')` anchors to the live element (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:106-162`); attaching a handle to a root does not churn the consumer's ref with spurious `null` calls (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:164-197`); a trigger declared after the root still registers and opens (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:324-350`); during a transient multi-root overlap, `open('id')` resolves a trigger still registered to the outgoing root without throwing and keeps the popup open after the handoff (`packages/react/src/popover/root/PopoverRoot.detached-triggers.test.tsx:412-475`).
