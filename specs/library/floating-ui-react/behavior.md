## State model (controlled/uncontrolled, defaults, transitions)

- Open state is owned by consumers everywhere; the group only mediates delays (instant member-to-member switch, `timeoutMs` re-open window, `isInstantPhase` marker, unmount-safe group timeout). FocusManager holds no open state; it tracks close modality (keyboard vs pointer) per session, `disabled` flip grabs focus, keep-mounted sessions reset stale state — detailed in `specs/library/floating-ui-react/parts/components.md:38-61`.
- `useDismiss` normalizes `bubbles`/`capture` (default `{ escapeKey: false, outsidePress: true }`); dismissals funnel through `onOpenChange(false, details)` and can be vetoed via `details.cancel()`. `useFloating({ rootContext })` syncs refs into an external `FloatingRootStore` (elements, `positionReference`/virtual elements, `dataRef`, `events`, `floatingId`) — detailed in `specs/library/floating-ui-react/parts/hooks-interaction.md:65-101`.
- `useListNavigation`/`useTypeahead` keep `activeIndex` fully consumer-controlled via `onNavigate`/`onMatch`; the internal pointer resets on close; `allowEscape`/pointer-leave deliver `null`; typeahead uses a 750 ms typing/buffer-reset window — detailed in `specs/library/floating-ui-react/parts/hooks-navigation.md:39-60`.
- utils are stateless pure functions, except `safePolygon` factories hold per-invocation traversal state (fresh handler = reset traversal) and `markOthers` keeps reference-counted attribute ownership across concurrent calls — detailed in `specs/library/floating-ui-react/parts/safePolygon-utils.md:37-51`.

## Keyboard interactions

- FocusManager: modal Tab trap with wrap-around, non-modal Tab-out close (+focus-out close), Escape dismiss returning focus with `focusVisible`, `initialFocus={false}` keeps focus on the reference, trapped-on-empty-content behavior — detailed in `specs/library/floating-ui-react/parts/components.md:63-79`.
- `useDismiss`: Escape dismisses by default (disabled via `escapeKey: false`), IME-composition guard, `bubbles.escapeKey`/`capture.escapeKey` cascade semantics across `FloatingTree` — detailed in `specs/library/floating-ui-react/parts/hooks-interaction.md:103-134`.
- `useListNavigation`: ArrowDown/Up (vertical), ArrowRight/Left (horizontal, rtl-flipped) open + navigate, clamping vs `loopFocus` wrap vs `allowEscape` exit-to-`null`, `openOnArrowKeyDown`, disabled/hidden skipping, full grid matrix (row-locked columns, virtualized partial rows, preferred-candidate fallback), nested menus/submenus, Home/End intentionally ignored; `useTypeahead`: printable-character matching, same-letter cycling with doubled-letter bail-out, 750 ms full-string reset — detailed in `specs/library/floating-ui-react/parts/hooks-navigation.md:61-125`.
- safePolygon + utils: N/A (`specs/library/floating-ui-react/parts/safePolygon-utils.md:53-55`).

## Focus management

- FocusManager: initial focus (first tabbable, checked radio, ref, `autoFocus` precedence, wrapper-element targeting), return focus (default reference, ref/function forms, non-focusable reference → first focusable descendant, fallback tabbable insertion after reference removal, hover-open floats don't return focus on unhover), `restoreFocus` on element removal/hidden, iframe support, managed `tabindex` (`0`↔`-1` with `data-tabindex` mirror, listbox exemption) — detailed in `specs/library/floating-ui-react/parts/components.md:81-112`.
- Interaction hooks: `useClientPoint` restores the DOM reference rect on focus-reason opens; `useFocus` guards against reopen after window blur; FocusManager wrapping changes outside-press classification — detailed in `specs/library/floating-ui-react/parts/hooks-interaction.md:136-166`.
- `useListNavigation`: real DOM focus vs `virtual` index-only mode, rAF-deferred cancelable item focus, pointer-leave clearing with clipped-container coordinate checks, `selectedIndex` scroll-into-view without focus steal; WebKit variant ignores stationary pointer events (scroll-under-pointer) — detailed in `specs/library/floating-ui-react/parts/hooks-navigation.md:127-155`.
- `utils/tabbable` defines the focusability rules FocusManager relies on (buttons/inputs/iframes/slotted light DOM/`<details>`/radio groups in; hidden, disabled, unslotted, `content-visibility`-hidden, inert-subtree content out) — detailed in `specs/library/floating-ui-react/parts/safePolygon-utils.md:57-91`.

## Accessibility (roles, aria-*, id linking)

- FocusManager: modal hides outside content with `aria-hidden` (reference included, live regions preserved, `getInsideElements` opt-out); non-modal applies `data-base-ui-inert` markers to top-level outside ancestors; portal `aria-owns` owner element with configurable `portalOwnerRole`; roles/aria attributes otherwise come from consumers, not the manager — detailed in `specs/library/floating-ui-react/parts/components.md:114-134`.
- Interaction hooks emit no aria wiring themselves; `context.floatingId` is the id-linking primitive consumers wire (`aria-controls`, `id`) at fixture level — detailed in `specs/library/floating-ui-react/parts/hooks-interaction.md:168-196`.
- `useListNavigation` injects no ARIA (no `aria-orientation`, no `aria-activedescendant` — fixtures wire `aria-selected`/`aria-haspopup`/`aria-controls`); it does honor `aria-disabled` for initial navigation — detailed in `specs/library/floating-ui-react/parts/hooks-navigation.md:157-169`.
- `markOthers` implements the aria-hidden/inert marking semantics (control attributes, `data-base-ui-inert` marker, `mark: false` opt-out, externally-owned attributes preserved, shadow-DOM scope); `composite`/`tabbable` treat `aria-disabled` as focusable-but-semantically-disabled — detailed in `specs/library/floating-ui-react/parts/safePolygon-utils.md:93-110`.

## DOM structure & portal behavior

- FocusManager renders no wrapper DOM (attribute manipulation + temporary fallback tabbable insertion); FloatingPortal creates a `data-base-ui-portal` host under `document.body` by default, accepts element/ref/lazy containers, re-parents on container switch, and feeds the `aria-owns` owner — detailed in `specs/library/floating-ui-react/parts/components.md:136-152`.
- Portaled children still count as "inside" for dismissal; portal containers can be shadow roots; nested floats may use different containers; `useClientPoint` repositions via virtual reference rects rather than DOM moves — detailed in `specs/library/floating-ui-react/parts/hooks-interaction.md:198-228`.
- Navigation/typeahead hooks are headless: items register into `listRef`, virtualized grids navigate a logical list longer than the rendered DOM, keydowns are handled from reference/floating/document targets — detailed in `specs/library/floating-ui-react/parts/hooks-navigation.md:171-183`.
- `markOthers` scopes document-wide marking with shadow-host awareness; `nodes` is a logical (non-DOM) flat tree — detailed in `specs/library/floating-ui-react/parts/safePolygon-utils.md:112-129`.

## Events (names, payload shape, bubbling, preventDefault semantics)

- FocusManager emits no custom events; observable surface is `onOpenChange` (setTimeout-wrapped focus-out close), `returnFocus` callback receiving `'keyboard'` vs `''` close modality, `focus({ preventScroll, focusVisible })` restore calls, and native `focusout` handling — detailed in `specs/library/floating-ui-react/parts/components.md:154-169`.
- Interaction hooks share the `onOpenChange(nextOpen, details)` contract with `details.reason` (`REASONS.escapeKey`/`outsidePress`/`triggerPress`/`triggerHover`/`inputPress`, overridable via `useClick`'s `reason`); a dismissing Escape is default-prevented unless vetoed via `details.cancel()`; `useDismiss` registers document-level keydown/pointer/touch listeners with `bubbles`/`capture` cascade control; `useClientPoint` uses window-level mousemove while open; `useHover` resolves targets via native event paths, not React's synthetic target — detailed in `specs/library/floating-ui-react/parts/hooks-interaction.md:230-271`.
- Navigation hooks: `onNavigate(index | null)` (synchronous, no asserted second-argument payload), `onMatch(index)`, `onTyping(boolean)`; no bubbling/preventDefault assertions — detailed in `specs/library/floating-ui-react/parts/hooks-navigation.md:185-199`.
- safePolygon consumes mousemove-shaped objects (`clientX`/`clientY`, `composedPath`) and its only observable output is `onClose`; the other utils exercise no events — detailed in `specs/library/floating-ui-react/parts/safePolygon-utils.md:131-140`.

## Edge cases (rapid interactions, unmount, nesting)

- Strict Mode safety (group instant phase, dismiss marker cleanup), rapid member hovering, member unmount preserving group timeout, rapid reopen preserving close modality, keep-mounted session resets, nested floats (one-level-per-press dismissal, mixed modal/non-modal, replacement chains), iframe traversal — detailed in `specs/library/floating-ui-react/parts/components.md:171-194`.
- `outsidePressEvent: 'intentional'` press-observation model (drag suppression, compat-event dedup, keyboard `detail: 0` clicks, session-leak guards, non-primary/cancelled presses), IME Escape, touch open delay, rapid re-hover during close transition, virtual positionReference cleanup on unmount — detailed in `specs/library/floating-ui-react/parts/hooks-interaction.md:273-319`.
- Rapid multi-press grid chains, disabled/hidden fallback in virtualized partial rows, filtered-list consistency and remount recovery, clipped-container pointer-leave, keepMounted nested submenus, known in-test rAF flakiness note; typeahead StrictMode safety — detailed in `specs/library/floating-ui-react/parts/hooks-navigation.md:201-219`.
- safePolygon geometry per placement (leave/trough/outside points, open-child suppression incl. contextless intermediaries, 50 ms intent window, handler re-invocation resets), markOthers out-of-order/concurrent cleanup, `onlyOpenChildren` not pruning closed-intermediary descendants — detailed in `specs/library/floating-ui-react/parts/safePolygon-utils.md:142-177`.

## Cross-cutting behavior (whole-unit)

- **Shared open/close contract:** every interaction hook funnels state changes through `useFloating`'s controlled `open` + `onOpenChange(nextOpen, details)` with a `details.reason` drawn from `REASONS`, and supports veto via `details.cancel()` — the same contract the components consume (`specs/library/floating-ui-react/parts/hooks-interaction.md:230-271`, proven at `packages/react/src/floating-ui-react/hooks/useDismiss.test.tsx:44-54`, `packages/react/src/floating-ui-react/hooks/useHover.test.tsx:249-276`, `packages/react/src/floating-ui-react/hooks/useClick.test.tsx:226-237`).
- **Root store coordination:** `useFloating({ rootContext })` / `useBaseUIFloating` bind hooks to an external `FloatingRootStore`; `context.rootStore`/`dataRef`/`events` are identity-shared, elements sync from refs, and hover shared state (`handleCloseOptions`) propagates synchronously through the store — the whole-unit state backbone (`specs/library/floating-ui-react/parts/hooks-interaction.md:65-101`, proven at `packages/react/src/floating-ui-react/hooks/useFloating.test.tsx:79-102`).
- **Logical floating tree:** `FloatingTree`/`FloatingNode` + `utils/nodes` provide the flat `{ id, parentId, context }` tree that three consumers rely on: `useDismiss` bubble/capture cascades, `safePolygon`'s open-child close suppression, and FocusManager nested focus return (`specs/library/floating-ui-react/parts/safePolygon-utils.md:127-129` + `specs/library/floating-ui-react/parts/hooks-interaction.md:273-296`, proven at `packages/react/src/floating-ui-react/hooks/useDismiss.test.tsx:649-848`, `packages/react/src/floating-ui-react/safePolygon.test.ts:168-194`).
- **FocusManager ⇄ utils pipeline:** `utils/tabbable` classification feeds FocusManager initial focus/tab-trap/tabindex decisions, while `utils/markOthers` (reference-counted `aria-hidden`/`inert` marking) implements its modal AT-hiding — the utils and the manager are one pipeline, not independent features (`specs/library/floating-ui-react/parts/components.md:81-134` + `specs/library/floating-ui-react/parts/safePolygon-utils.md:93-118`, proven at `packages/react/src/floating-ui-react/components/FloatingFocusManager.test.tsx:1139-1185`, `packages/react/src/floating-ui-react/utils/markOthers.test.ts:116-167`).
- **Hover corridor chain:** `safePolygon()` is the `handleClose` factory consumed by `useHover`/`useHoverReferenceInteraction`; its geometry keeps hover popups reachable and its `blockPointerEvents` state must be cleaned up on trigger change (`specs/library/floating-ui-react/parts/safePolygon-utils.md:7-13` + `specs/library/floating-ui-react/parts/hooks-interaction.md:306-319`, proven at `packages/react/src/floating-ui-react/hooks/useHover.test.tsx:322-368`).
