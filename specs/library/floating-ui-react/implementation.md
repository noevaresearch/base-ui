# floating-ui-react — implementation spec

WHY/HOW companion to `specs/library/floating-ui-react/behavior.md` (that file is ground truth for WHAT happens; its section names are cited below without re-description). All citations point at the unit's non-test source files unless marked otherwise.

The unit's spine is a **store, not React state**: a single `FloatingRootStore` (a `ReactStore` subclass) is handed around by reference, interaction hooks subscribe to it with `useState` selectors, and cross-hook coordination happens through (a) store selectors, (b) an `openchange` event bus, and (c) a mutable `dataRef`. React context is used only for three narrow concerns (floating tree, delay group, portal guards).

## State machine / hooks used

### Store backbone

- `FloatingRootStore extends ReactStore` from `@base-ui/utils/store` with selectors `open`, `transitionStatus`, `domReferenceElement`, `referenceElement` (coalesced as `positionReference ?? referenceElement`), `floatingElement`, `floatingId` — `packages/react/src/floating-ui-react/components/FloatingRootStore.ts:33-63`. This coalescing selector is how virtual-element positioning (`useClientPoint`, `useFloating.setPositionReference`) stays invisible to consumers.
- Store context holds non-reactive identity objects created once in the constructor: `dataRef: { current: {} }`, `events: createEventEmitter()`, `nested`, `triggerElements` — `packages/react/src/floating-ui-react/components/FloatingRootStore.ts:66-86`.
- The open/close "state machine" is two methods: `syncOpenEvent` (writes `dataRef.current.openEvent`, but a pending hover-open never overwrites a click-like open event while a click may upgrade a hover-open — `packages/react/src/floating-ui-react/components/FloatingRootStore.ts:91-101`), `dispatchOpenChange` (emits `'openchange'` with a `FloatingUIOpenChangeDetails` payload — `packages/react/src/floating-ui-react/components/FloatingRootStore.ts:106-118`), and `setOpen` which fans out to both — unless `syncOnly` is set, in which case it only forwards to `context.onOpenChange` (`packages/react/src/floating-ui-react/components/FloatingRootStore.ts:126-135`). `syncOnly` is the mode used by popup components (Menu/Select/etc.) whose popup store owns the real state; the standalone `useFloating` path uses `syncOnly: false` (`packages/react/src/floating-ui-react/hooks/useFloatingRootContext.ts:43-56` vs `packages/react/src/floating-ui-react/hooks/useSyncedFloatingRootContext.ts:63-76`).
- Two construction paths feed the same store class: `useFloatingRootContext` (public `useFloating` path; syncs props into the store in `useIsoLayoutEffect`, then patches `context.onOpenChange`/`context.nested` on every render — `packages/react/src/floating-ui-react/hooks/useFloatingRootContext.ts:58-77`) and `useSyncedFloatingRootContext` (popup-store adapter; reads `open`/`activeTriggerElement`/`positionerElement|popupElement` from the popup store and mirrors them into the floating store, including a one-time `positionReference = referenceElement` mirroring that stops mirroring once they diverge — `packages/react/src/floating-ui-react/hooks/useSyncedFloatingRootContext.ts:51-107`).
- `useFloating` is a thin composition: internal store from `useFloatingRootContext`, overridden by `options.rootContext`; `useBaseUIFloating` requires the store and skips the internal hook entirely — `packages/react/src/floating-ui-react/hooks/useFloating.ts:21-36`. It delegates all positioning to `@floating-ui/react-dom`'s `useFloating` (renamed `usePosition`) at `packages/react/src/floating-ui-react/hooks/useFloating.ts:71-77` and layers on top: extended `refs` (`setReference` with virtual-element backward compatibility at `packages/react/src/floating-ui-react/hooks/useFloating.ts:110-131`, `setFloating` at `:133-139`, `setPositionReference` which wraps a real element into a `VirtualElement` shim at `:93-108`) and a `FloatingContext` memo whose `onOpenChange` is literally `store.setOpen` (`packages/react/src/floating-ui-react/hooks/useFloating.ts:160-174`). A dependency-free `useIsoLayoutEffect` re-attaches `context` into `dataRef.current.floatingContext` and into the matching tree node every render (`packages/react/src/floating-ui-react/hooks/useFloating.ts:182-189`) — this is how late-mounted hooks always see the freshest context without re-render churn.

### Cross-hook communication pattern

Every interaction hook follows the same composition recipe (visible identically in `useClick`, `useDismiss`, `useFocus`, `useHover*`, `useListNavigation`, `useTypeahead`, `useClientPoint`):

1. Normalize `context` to the store: `const store = 'rootStore' in context ? context.rootStore : context` (e.g. `packages/react/src/floating-ui-react/hooks/useHover.ts:65`, `packages/react/src/floating-ui-react/hooks/useClick.ts:73`) — so hooks accept either a `FloatingRootStore` or the richer `FloatingContext`.
2. Subscribe to reactive slices with `store.useState(...)` only where a re-render is genuinely needed (e.g. `open`, `floatingElement`); use `store.select(...)` inside event handlers for fresh values without re-subscribing (e.g. `packages/react/src/floating-ui-react/hooks/useHover.ts:210,216,424`).
3. Register an `events.on('openchange')` listener for reactions to open/close transitions that must not depend on render timing (cancel pending hover timeouts on close: `packages/react/src/floating-ui-react/hooks/useHover.ts:113-127`; record close modality in FocusManager: `packages/react/src/floating-ui-react/components/FloatingFocusManager.tsx:763-807`; end dismiss press sessions: `packages/react/src/floating-ui-react/hooks/useDismiss.ts:279-292`; block focus reopen after press/Escape: `packages/react/src/floating-ui-react/hooks/useFocus.ts:100-119`).
4. Stash per-session mutable state in refs and in `dataRef.current` (`insideReactTree`, `openEvent`, `__escapeKeyBubbles`/`__outsidePressBubbles`, `hoverInteractionState`, `floatingContext`, `orientation`) rather than in React state — e.g. `packages/react/src/floating-ui-react/hooks/useDismiss.ts:304-305`, `packages/react/src/floating-ui-react/hooks/useHoverInteractionSharedState.ts:118-131`.

### Notable per-hook state machines

- **Hover (3 implementations, one shared instance).** `useHover` keeps its state local (refs `pointerTypeRef`, `interactedInsideRef`, `blockMouseMoveRef`, `performedPointerEventsMutationRef`, `restTimeoutPendingRef` — `packages/react/src/floating-ui-react/hooks/useHover.ts:79-85`), while the split pair `useHoverReferenceInteraction`/`useHoverFloatingInteraction` share a single mutable `HoverInteraction` instance stashed on `dataRef.current.hoverInteractionState` so reference-side and floating-side handlers agree on pointer type, rest state, and safePolygon handler without a shared React provider (`packages/react/src/floating-ui-react/hooks/useHoverInteractionSharedState.ts:11-52,114-131`). `useHoverReferenceInteraction` adds trigger-mapping logic absent from `useHover`: delegated/wrapper trigger resolution from the event target (`packages/react/src/floating-ui-react/hooks/useHoverReferenceInteraction.ts:236-254`), immediate open when moving between triggers or re-entering during a hover close transition (`:261-285`), a `shouldOpen` veto, and a Chrome `mouseleave`-dropped backup via `mouseout` (`guardStaleOpen`, `:365-376`). The rest-ms engine (tremor guard `movementX² + movementY² < 2`, `restTimeoutPending`, touch → immediate) is duplicated in both reference hooks (`packages/react/src/floating-ui-react/hooks/useHover.ts:428-461`, `packages/react/src/floating-ui-react/hooks/useHoverReferenceInteraction.ts:455-498`).
- **safePolygon.** The factory closes over one `Timeout` shared across invocations; each invocation of the returned `HandleClose` creates fresh traversal state (`hasLanded`, `lastX/lastY/lastCursorTime`) — so a fresh handler always means a fresh corridor (`packages/react/src/floating-ui-react/safePolygon.ts:90-129`). Its per-move pipeline is ordered short-circuit checks (over floating/reference → related-target bail → open-child suppression → opposite-side → trough rect → `hasLanded` miss → slow-cursor miss → quadrilateral test → 40 ms intent timer), `packages/react/src/floating-ui-react/safePolygon.ts:129-441`.
- **Dismiss press model.** Outside-press classification is a capture-phase state machine on the document: `pointerdown`/`mousedown` capture marks `sawPressWhileOpenRef` and records pointer type (`packages/react/src/floating-ui-react/hooks/useDismiss.ts:579-607`), press-end capture converts an inside press into one-shot suppression of the trailing outside click (`:609-655`), and the actual dismissal runs in `closeOnPressOutside` with ordered guards (press-type filtering → `insideReactTree` → trigger-map → inert-marker provenance walk → scrollbar hit-test → floating-tree membership → intentional-mode `detail: 0`/virtual/saw-press checks → user `outsidePress` fn → blocking child) before `setOpen(false, ...)` (`:380-513`). Document listeners are registered once per open session with `capture: true`, and the touch path re-targets listeners onto the actual touch target "once" (`:558-572,711-739`).
- **List navigation.** `indexRef` is the internal truth mirror; the consumer's `activeIndex` is reconciled into it by `useIsoLayoutEffect`, and `onNavigate` is a `useStableCallback` wrapper that always reports `indexRef` (`packages/react/src/floating-ui-react/hooks/useListNavigation.ts:292-298,390-470`). Focus application is a scheduler: `enqueueFocus` (rAF, cancelable) for real focus, `tree.events.emit('virtualfocus', ...)` for virtual mode, plus a bounded microtask→rAF retry while the list is still empty (`:314-358,416-448`). Grid navigation is opt-in via the injected `grid` function so non-grid consumers tree-shake the helpers (`:591-612`); `gridNavigation` itself is a positional-arg shim over `getGridNavigatedIndex` pinned to a uniform 1×1 grid (`packages/react/src/floating-ui-react/hooks/gridNavigation.ts:8-49`), with the row-structure inference and virtualized-gap logic living in `utils/composite` (`packages/react/src/floating-ui-react/utils/composite.ts:101-283`).
- **Typeahead.** A string buffer + `prevIndexRef`/`matchIndexRef` cycle with a 750 ms reset; "same letter twice" rapid cycling is allowed only when no list item starts with a doubled letter, and unavailable (hidden/native-disabled) items are excluded from that check (`packages/react/src/floating-ui-react/hooks/useTypeahead.ts:92-206`); the same props are attached to both reference and floating (`:241-245`).
- **FocusManager.** Holds no open state; its "sessions" are effect lifetimes. Close modality is inferred by `getEventType` (KeyboardEvent → FocusEvent-with-last-pointer → pointerType → touch → MouseEvent `detail`) and recorded from the `openchange` event (`packages/react/src/floating-ui-react/components/FloatingFocusManager.tsx:49-70,763-766`). Return-focus targets are computed in the unmount/cleanup path (`getReturnElement`, `:809-844`) with `queueMicrotask` ordering so focus restoration wins races against removal (`:864-889`). A module-level `WeakRef` LRU (20 entries) of previously focused elements backs the "return to last focused before body" fallback (`:72-94`).
- **DelayGroup.** All shared group state lives in refs inside context (`delayRef`, `currentIdRef`, `currentContextRef`, a shared `Timeout`) so membership changes never re-render other members; only `isInstantPhase` is component-local React state (`packages/react/src/floating-ui-react/components/FloatingDelayGroup.tsx:14-35,161`). Taking ownership on open zeroes the open delay and — if a previous member was active — flips instant phase on both members and force-closes the previous one with `REASONS.none` (`:219-254`); on close, `timeoutMs` schedules the group reset that is skipped if another member took over (`:181-204`); unmount cleanup clears ownership without leaking the group timeout (`:256-270`).
- **Portal.** `useFloatingPortalNode` is a small state machine: `containerProp === null` waits; otherwise resolve `containerProp (node or ref) → parentPortalNode → document.body`; any change to the resolved container tears the portal node down and rebuilds (`packages/react/src/floating-ui-react/components/FloatingPortal.tsx:95-125`), with the ref callback deliberately ignoring `null` so the effect remains the sole owner of node lifetime (`:84-91`).

## Context providers/consumers

- **FloatingTree / FloatingNode** (`packages/react/src/floating-ui-react/components/FloatingTree.tsx`): `FloatingTreeContext` carries a `FloatingTreeStore` (`nodesRef` array + its own event emitter — `packages/react/src/floating-ui-react/components/FloatingTreeStore.ts:8-22`); `FloatingNodeContext` carries `{ id, parentId }`. `FloatingTree` creates (or accepts an `externalTree`) once via `useRefWithInit` (`packages/react/src/floating-ui-react/components/FloatingTree.tsx:90-95`); `FloatingNode` re-publishes the parent chain (`:62-72`); `useFloatingNodeId` registers/unregisters the node in `useIsoLayoutEffect` (`:32-50`). Consumers crossing this boundary: `useDismiss` (bubble/capture cascades and blocking-child checks read `nodesRef` + `dataRef.__*Bubbles` — `packages/react/src/floating-ui-react/hooks/useDismiss.ts:172-181,369-378`), `safePolygon` (open-child suppression — `packages/react/src/floating-ui-react/safePolygon.ts:167-180`), `FloatingFocusManager` (nested focus return scans children/ancestors — `packages/react/src/floating-ui-react/components/FloatingFocusManager.tsx:460-484,615-618,849-857`), `useHoverFloatingInteraction` (parent-children close chain via `tree.events.on('floating.closed')` — `packages/react/src/floating-ui-react/hooks/useHoverFloatingInteraction.ts:163-247`), and `useListNavigation` (parent orientation lookup + refocus parent on child close + virtualfocus broadcast — `packages/react/src/floating-ui-react/hooks/useListNavigation.ts:474-492,520-526,317`).
- **PortalContext** (`packages/react/src/floating-ui-react/components/FloatingPortal.tsx:40-49`): provides `portalNode`, four focus-guard refs, and `setFocusManagerState`. Consumed by `FloatingFocusManager` (renders inside/outside guards through the portal's merged refs, pushes its modal/open/closeOnFocusOut state up so the portal can render its own outside guards and the hidden `aria-owns` owner — `packages/react/src/floating-ui-react/components/FloatingFocusManager.tsx:922-940,953-1003`) and by nested `useFloatingPortalNode` calls (a nested portal renders into the parent portal node — `packages/react/src/floating-ui-react/components/FloatingPortal.tsx:78,108`).
- **FloatingDelayGroupContext** (`packages/react/src/floating-ui-react/components/FloatingDelayGroup.tsx:27-35`): provider is `FloatingDelayGroup`; consumer is `useDelayGroup` (used by Tooltip's provider/trigger pair outside this unit). It deliberately exposes refs (not values) so delay changes don't re-render unrelated members.
- **Not React context:** the `FloatingRootStore` itself is passed by reference — as the `context` argument to hooks or the `rootContext`/`context` prop of FocusManager — and identity is what matters (`packages/react/src/floating-ui-react/types.ts:122,124-137`). Consumers outside a real popup get a throwaway store from `getEmptyRootContext` (`packages/react/src/floating-ui-react/utils/getEmptyRootContext.ts:5-17`, used by navigation-menu and the test fixtures).
- **`usePortalContext`** is exported for sibling components (`packages/react/src/floating-ui-react/components/FloatingPortal.tsx:49`) and is part of the FocusManager⇄Portal contract described in behavior.md's "Accessibility" section.

## DOM/portal strategy and why

- **Two-level portal.** `useFloatingPortalNode` renders a host `div` (id + `data-base-ui-portal`) into the resolved container via `createPortal(portalElement, containerElement)` (`packages/react/src/floating-ui-react/components/FloatingPortal.tsx:127-143`); `FloatingPortal` then portals its children into that host (`:272`). The indirection exists so the host is addressable (forwarded ref, `aria-owns`, nested-portals-as-parent) independently of the children.
- **Container precedence** is explicit node/ref → parent portal node → `document.body` (`packages/react/src/floating-ui-react/components/FloatingPortal.tsx:106-109`); note the `document.body` fallback uses the global `document` rather than `ownerDocument`, which is fine for the default case but assumes the main document (shadow roots are supported only via an explicit `container`).
- **Accessibility wiring of the portal:** a visually-hidden owner `<span role={portalOwnerRole} aria-owns={portalNodeId}>` is rendered in the React tree so `aria-owns` points at a real, stable id even though the content is portaled (`packages/react/src/floating-ui-react/components/FloatingPortal.tsx:270`); the id is read back from the rendered element's props so consumer `id` overrides stay truthful (`:145-153`).
- **Non-modal tabbability guards:** when a FocusManager runs non-modal inside the portal, the portal listens `focusin/focusout` (capture) and swaps tabbability of portal content via `disableFocusInside`/`enableFocusInside` (a `data-tabindex` mirror) so Tab cycles through outside content until focus deliberately enters the portal (`packages/react/src/floating-ui-react/components/FloatingPortal.tsx:198-236`, `packages/react/src/floating-ui-react/utils/tabbable.ts:262-282`). Outside `FocusGuard` spans route Tab back inside or to the next/previous document tabbable (`packages/react/src/floating-ui-react/components/FloatingPortal.tsx:254-293`).
- **FocusManager renders no DOM of its own** beyond optional `FocusGuard` spans; everything else is attribute surgery (`tabindex`/`data-tabindex` on the floating focus element — `packages/react/src/floating-ui-react/components/FloatingFocusManager.tsx:108-145`) plus `markOthers`-driven `aria-hidden`/`data-base-ui-inert` marking with reference-counted cleanup and `aria-live` preservation (`packages/react/src/floating-ui-react/utils/markOthers.ts:102-213`).
- **Native listeners over React synthetic props for hover:** enter/leave/move handlers are attached with `addEventListener` directly to the trigger/floating/document elements (`packages/react/src/floating-ui-react/hooks/useHover.ts:313-327`, `packages/react/src/floating-ui-react/hooks/useHoverReferenceInteraction.ts:378-391`) — per the in-source comment, React's delegation system misses `mouseenter` when entering over a disabled child; `{ once: true }` `mousemove` additionally re-arms the enter path. Dismiss goes further and owns document-level capture-phase listeners for press lifecycle (`packages/react/src/floating-ui-react/hooks/useDismiss.ts:711-739`), and `useClientPoint` uses a window-level `mousemove` while open (`packages/react/src/floating-ui-react/hooks/useClientPoint.ts:204-210`).
- **Pointer-events manipulation is owned, scoped, and single-writer:** `applySafePolygonPointerEventsMutation` sets `pointer-events: none` on a scope element (body, parent floating, or `closest('[data-rootownerid]')` fallback) with `auto` on reference+floating, tracks exactly which elements it touched, and registers the owner in a module-level `WeakMap` so a second claimant clears the first (`packages/react/src/floating-ui-react/hooks/useHoverInteractionSharedState.ts:62-112`; scope fallback chain in `packages/react/src/floating-ui-react/hooks/useHoverFloatingInteraction.ts:122-138`; legacy body-mutation variant in `packages/react/src/floating-ui-react/hooks/useHover.ts:353-384`).
- **Shadow-DOM/iframe safety** is delegated to `@base-ui/utils/shadowDom` (`activeElement`/`contains`/`getTarget`, re-exported at `packages/react/src/floating-ui-react/utils/element.ts:3-8`) plus `getRootNode`/`isShadowRoot` handling in dismissal marker walks (`packages/react/src/floating-ui-react/hooks/useDismiss.ts:397-405`), `markOthers` host unwrapping (`packages/react/src/floating-ui-react/utils/markOthers.ts:33-56`), tabbable slot/shadow traversal (`packages/react/src/floating-ui-react/utils/tabbable.ts:11-27,146-159`), and `isEventTargetWithin`'s `composedPath` preference (`packages/react/src/floating-ui-react/utils/element.ts:33-45`).
- **Virtual elements instead of DOM moves:** `useClientPoint` repositions by installing a `VirtualElement` on `positionReference` whose `getBoundingClientRect` folds the cursor in per-axis, locks the initial offset on first call, and freezes the rect during `autoUpdate` passes unless the open event was hover/move (`packages/react/src/floating-ui-react/hooks/useClientPoint.ts:10-82`); `useFloating.setPositionReference` builds the equivalent shim for real elements (`packages/react/src/floating-ui-react/hooks/useFloating.ts:93-108`).
