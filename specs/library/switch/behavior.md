## State model (controlled/uncontrolled, defaults, transitions)

- Default (uncontrolled) state is unchecked: the root initially renders `aria-checked="false"` `packages/react/src/switch/root/SwitchRoot.test.tsx:40`, `packages/react/src/switch/root/SwitchRoot.test.tsx:110`.
- Clicking the root toggles uncontrolled state false → true `packages/react/src/switch/root/SwitchRoot.test.tsx:36-47`.
- Controlled mode: state is fully driven by the `checked` prop; toggling the prop from outside flips the rendered `aria-checked` both directions `packages/react/src/switch/root/SwitchRoot.test.tsx:49-76`.
- The hidden native checkbox input participates in state: clicking the input updates the switch's rendered state `packages/react/src/switch/root/SwitchRoot.test.tsx:78-88`.
- A change canceled via `onCheckedChange`'s `eventDetails.cancel()` leaves the switch unchecked, keeps the hidden input unchecked, and suppresses `data-dirty`/`data-filled`, whether the click originated on the root `packages/react/src/switch/root/SwitchRoot.test.tsx:203-222` or on the hidden input `packages/react/src/switch/root/SwitchRoot.test.tsx:224-243`.
- `disabled` blocks state changes on click `packages/react/src/switch/root/SwitchRoot.test.tsx:332-343`; `readOnly` blocks state changes on click `packages/react/src/switch/root/SwitchRoot.test.tsx:357-368` and on label clicks `packages/react/src/switch/root/SwitchRoot.test.tsx:370-388`.
- A native form reset does not change the React-managed switch state — it stays checked after reset `packages/react/src/switch/root/SwitchRoot.test.tsx:579-586`.
- Field state-hook transitions on the root: `data-touched` is added after focus then blur `packages/react/src/switch/root/SwitchRoot.test.tsx:928-941`; `data-dirty` is added after the first successful user change `packages/react/src/switch/root/SwitchRoot.test.tsx:943-957`; `data-filled` is added when checked after being initially unchecked and removed when unchecked again `packages/react/src/switch/root/SwitchRoot.test.tsx:960-978`, is present initially when `defaultChecked` and removed when unchecked `packages/react/src/switch/root/SwitchRoot.test.tsx:1007-1021`, and is cleared when a controlled switch remounts unchecked (new `key`) `packages/react/src/switch/root/SwitchRoot.test.tsx:980-1005`.
- `data-focused` tracks focus/blur `packages/react/src/switch/root/SwitchRoot.test.tsx:1024-1042`; `data-disabled` is applied when `Field.Root disabled` is inherited `packages/react/src/switch/root/SwitchRoot.test.tsx:906-915`.
- Without a `value` prop the hidden input has no `value` attribute `packages/react/src/switch/root/SwitchRoot.test.tsx:452-458`.

## Accessibility (roles, aria-*, id linking)

- The root exposes `role="switch"` (all tests query `getByRole('switch')`, e.g. `packages/react/src/switch/root/SwitchRoot.test.tsx:38`); a consumer-supplied `role` prop overrides the built-in role `packages/react/src/switch/root/SwitchRoot.test.tsx:122-125`.
- `aria-checked` mirrors the on/off state `packages/react/src/switch/root/SwitchRoot.test.tsx:40-46`, `packages/react/src/switch/root/SwitchRoot.test.tsx:110-116`.
- `disabled` is expressed as `aria-disabled="true"` instead of the HTML `disabled` attribute `packages/react/src/switch/root/SwitchRoot.test.tsx:321-325`; no `disabled` attribute is present when the prop is unset `packages/react/src/switch/root/SwitchRoot.test.tsx:327-330`.
- `readOnly` sets `aria-readonly="true"` `packages/react/src/switch/root/SwitchRoot.test.tsx:347-350`, absent when unset `packages/react/src/switch/root/SwitchRoot.test.tsx:352-355`; `required` sets `aria-required="true"` `packages/react/src/switch/root/SwitchRoot.test.tsx:391-394`, absent when unset `packages/react/src/switch/root/SwitchRoot.test.tsx:396-399`.
- Label linking through the hidden input: a sibling `<label htmlFor>` matching the Root's `id` produces a fallback `aria-labelledby` on the switch pointing to the label's generated id `packages/react/src/switch/root/SwitchRoot.test.tsx:127-138`; the fallback updates when the hidden input's id changes `packages/react/src/switch/root/SwitchRoot.test.tsx:140-173`.
- With `nativeButton`, the user's `id` is placed on the visible switch element and not on the hidden input `packages/react/src/switch/root/SwitchRoot.test.tsx:504-524`.
- `Field.Label` associations: an implicit label gets `for` equal to the hidden input's generated id and the switch's `aria-labelledby` equals the label's id `packages/react/src/switch/root/SwitchRoot.test.tsx:1180-1203`; an explicit sibling `Field.Label` associates the same way `packages/react/src/switch/root/SwitchRoot.test.tsx:1206-1228`; association works when rendering a non-native button (`nativeButton={false}`) `packages/react/src/switch/root/SwitchRoot.test.tsx:1230-1244`; a non-native label (`nativeLabel={false}`, rendered as `<span>`) has no `for`, links via `aria-labelledby` only, and clicking it does not toggle the switch `packages/react/src/switch/root/SwitchRoot.test.tsx:1246-1267`.
- `aria-describedby` on the root preserves an externally supplied id and appends the `Field.Description` id `packages/react/src/switch/root/SwitchRoot.test.tsx:1271-1287` (also asserted around a canceled change and reset, `packages/react/src/switch/root/SwitchRoot.test.tsx:559-562`, `packages/react/src/switch/root/SwitchRoot.test.tsx:583-586`).

## Events (names, payload shape, bubbling, preventDefault semantics)

- `onCheckedChange(checked, eventDetails)` fires once per activating click with the new boolean value (`true` on activation) `packages/react/src/switch/root/SwitchRoot.test.tsx:177-188`.
- `eventDetails` exposes the underlying event; keyboard modifiers are observable, e.g. `eventDetails.event.shiftKey === true` when Shift is held during the click `packages/react/src/switch/root/SwitchRoot.test.tsx:190-201`.
- `eventDetails.cancel()` cancels the pending state change (root click and hidden-input click) `packages/react/src/switch/root/SwitchRoot.test.tsx:203-243`.
- The user's `onClick` is invoked once per click `packages/react/src/switch/root/SwitchRoot.test.tsx:247-257`; each user click propagates exactly one click event to ancestors, in both span (non-native) mode `packages/react/src/switch/root/SwitchRoot.test.tsx:259-271` and native-button mode `packages/react/src/switch/root/SwitchRoot.test.tsx:287-299`; calling `stopPropagation()` in the consumer's `onClick` suppresses ancestor handlers while the switch still toggles, in both modes `packages/react/src/switch/root/SwitchRoot.test.tsx:273-285`, `packages/react/src/switch/root/SwitchRoot.test.tsx:301-317`.
- A hidden-input click that was canceled (preventDefault called before React handles the event) is ignored entirely: `onCheckedChange` is not called and state does not change `packages/react/src/switch/root/SwitchRoot.test.tsx:90-103`.
- Form submission payload (FormData semantics, browser-only — these tests are `it.skipIf(isJSDOM)`): an unchecked switch submits no value by default (FormData `get` → `null`), a checked switch submits `'on'` `packages/react/src/switch/root/SwitchRoot.test.tsx:591-623`; this matches native checkbox behavior side-by-side `packages/react/src/switch/root/SwitchRoot.test.tsx:690-746`; `value` and `uncheckedValue` customize the on/off payloads across an off/on/off cycle `packages/react/src/switch/root/SwitchRoot.test.tsx:819-854` (`packages/react/src/switch/root/SwitchRoot.test.tsx:748-786`, `packages/react/src/switch/root/SwitchRoot.test.tsx:788-817`); `uncheckedValue` is not submitted when the switch is `disabled` `packages/react/src/switch/root/SwitchRoot.test.tsx:670-688`; `form="external-form-id"` submits into an external form `packages/react/src/switch/root/SwitchRoot.test.tsx:625-646`, `packages/react/src/switch/root/SwitchRoot.test.tsx:648-668`.

## Edge cases (rapid interactions, unmount, nesting)

- Imperative interaction inside the ref callback (`focus`, `blur`, `click` called on the element before the hidden input mounts) is tolerated without crashing and leaves the switch unchecked `packages/react/src/switch/root/SwitchRoot.test.tsx:20-34`.
- Field validation props survive a canceled change, a failed submit (valueMissing error), a successful change, and a reset in one flow `packages/react/src/switch/root/SwitchRoot.test.tsx:528-588`.
- External (programmatic) controlled changes re-run Field validation `packages/react/src/switch/root/SwitchRoot.test.tsx:1122-1153`, and a user change validates exactly once `packages/react/src/switch/root/SwitchRoot.test.tsx:1107-1120`.
- Remounting a controlled switch with a new `key` clears the field's `data-filled` state `packages/react/src/switch/root/SwitchRoot.test.tsx:980-1005`.
- Repeated toggle cycles (off → on → off) are exercised through the form-submission tests without state corruption `packages/react/src/switch/root/SwitchRoot.test.tsx:748-786`, `packages/react/src/switch/root/SwitchRoot.test.tsx:819-854`.
