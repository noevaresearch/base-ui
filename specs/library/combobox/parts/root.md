## State model (controlled/uncontrolled, defaults, transitions)

- Open: uncontrolled via `defaultOpen` (still closable by interaction) or controlled via `open` — controlled open ignores close requests (`click` on body does not close) and `open={false}` overrides `defaultOpen` (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:9664-9698`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:9888-9970`). An attempted open can be canceled with `onOpenChange` `details.cancel()` (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:12800-12821`); an attempted close can likewise be canceled, keeping the popup open and the pending selection committed (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:362-405`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:6884-6925`).
- Value: single mode `value: string|object|null`, multiple mode `value: string[]`; `onValueChange` receives cumulative arrays in multiple mode (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:2502-2527`). Controlled `value={null}` is normalized in multiple mode (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:12873-12887`). A controlled consumer that never applies the change (declines without cancel) still clears the query and keeps highlight on the pressed item, but the item stays unselected (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:2665-2722`); `cancel()` on `onValueChange` prevents commit and keeps the popup open in single mode (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:6775-6802`).
- inputValue: derived from `defaultValue`/`value` on first mount; overridden by `defaultInputValue`/`inputValue`; empty in `multiple` mode and in the input-inside-popup composition (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:5304-5389`). Controlled `inputValue` blocks clears until the consumer commits (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:1460-1512`); re-derived on external value/items/label changes and reported exactly once per change via `onInputValueChange` (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:5393-5614`).
- Open/close selection transition: uncontrolled open auto-closes after single selection; controlled open does not (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:981-1062`). Closing without a selection resets the input to the selected value (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:1131-1173`); closing without any selection clears typed query text with reason `'input-clear'` (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:7753-7857`).
- selectedIndex/activeIndex store state: `selectedIndex` registers on open/keepMounted mount, clears when the value is cleared/unmatched externally while closed, re-syncs on external controlled updates at close time, and is `null` when the selected item is outside `limit` (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:2203-2423`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:3243-3299`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:9973-10006`). Navigation/anchor semantics for `activeIndex` are under Keyboard.
- Filtering: internal collator-based filter shows all items for an empty query, rejects nullish items, and bypasses filtering when the query exactly matches the selected label (single mode) (`packages/react/src/combobox/root/utils/index.test.ts:20-53`); `useComboboxFilter` default `contains` filters selected items in single but not multiple mode (`packages/react/src/combobox/root/utils/useFilter.test.tsx:20-40`). Custom `filter` fn `(item, query)` narrows results; `filter={null}` disables filtering (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:7860-7893`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:12478-12550`). With `limit`, filtering stops (and the filter fn is no longer invoked) once the limit is reached; `limit` only applies with the `items` prop; `-1` is the default; `0` shows none (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:10008-10345`). Groups with no matching items are omitted (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:12961-12990`).

## Keyboard interactions

- ArrowDown opens the popup and highlights the first item; ArrowUp opens and highlights the last item (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:3414-3454`).
- Enter selects the highlighted item (works with manual `index` props) and closes in single mode, writing the item into the input (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:3456-3527`). Enter with nothing highlighted keeps the typed value and does not commit (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:3629-3654`); in a form it does not preventDefault when nothing is highlighted, and prevents submit when an item is highlighted (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:11150-11228`).
- Escape: closes the popup without committing when nothing is highlighted (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:3570-3593`); with a query, discards the uncommitted query and preserves the selection (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:314-360`). Escape bubbles to outer handlers when rendered inline or when the list is empty with a CSS-hidden popup, but not when `<Combobox.Empty>` is present (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:3595-3735`).
- Grid mode: arrows navigate rows/columns; ArrowLeft/Right move the input caret when nothing is highlighted and the caret is not at the boundary; horizontal arrows are mirrored in RTL; uneven rows clamp and remember the column; typeahead continues across Space without selecting (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:6361-6691`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:8811-8847`).
- Looping: by default ArrowDown past the last item clears the highlight (back to the input) then wraps to the first item, and ArrowUp symmetrically; `loopFocus={false}` clamps at the ends (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:12615-12797`).
- Multiple selection via keyboard: ArrowDown+Enter toggles selection, keeps the popup open, keeps the input focused, clears the query, and continues arrow navigation from the toggled item (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:2773-2803`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:7385-7435`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:9161-9222`).
- readOnly still allows opening and arrow-key browsing with keyboard-reason highlight events, but typing, item clicks, and Enter commit are blocked (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:4932-5171`).
- Programmatic `change` events do not open the popup; paste (`insertFromPaste`) does (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:4674-4724`).

## Focus management

- Opening from a trigger click (input inside popup) focuses the popup input; closing via trigger click returns focus to the trigger, not the input (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:229-264`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:291-295`). Keyboard selection in multiple mode keeps the input focused; Escape moves focus to the trigger (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:7385-7435`).
- Clicking the listbox or portalled content inside the popup does not move focus away or dismiss; clicking a plain wrapper around the input does dismiss (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:3529-3568`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:603-624`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:572-601`).
- `modal`: Tab cycles among popup controls and wraps back to the input; outside content becomes inert; internal hidden "Dismiss" buttons are placed before the input and after the popup (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:689-716`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:748-896`).
- Highlight is expressed with `aria-activedescendant` on the input (focus stays on the input at all times) (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:3844-3885`).
- The hidden form control redirects focus: to the visible input, else to the trigger, else body; when the input is inside the popup, hidden-control focus moves to the trigger (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:13010-13084`).
- Field blur semantics: blurring into the popup does not mark touched or validate; blurring the popup to the outside validates once (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:11755-11844`). In the dialog pattern, highlight clears when the input loses focus and is restored when it regains focus (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:10637-10671`).
- A pending dialog initial-focus rAF cannot steal focus from a just-opened combobox (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:10467-10505`).

## Accessibility (roles, aria-*, id linking)

- The combobox input carries `role="combobox"`, `aria-expanded`, `aria-autocomplete="list"` (`"none"` when readOnly), `aria-haspopup="listbox"` (`"dialog"` on the trigger when the input is inside the popup; `"grid"` in grid mode), `aria-controls` pointing at the listbox/dialog while open, and `aria-activedescendant` pointing at the highlighted option id (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:176-209`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:3739-3814`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:3844-3885`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:4922-4930`).
- Options are `role="option"` with `aria-selected`; highlighted items get `data-highlighted`; the list is `role="listbox"` (never `aria-orientation`); grid mode uses `role="grid"`, `role="row"`, `role="gridcell"`, and Groups render as `role="rowgroup"` with accessible names (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:154-173`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:3844-3885`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:6315-6327`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:6329-6359`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:6717-6743`).
- The trigger (as combobox in the popup composition) links `aria-controls` to the popup id, supports custom popup ids (prop or render prop), and gets `aria-labelledby` from `Field.Label`/`Combobox.Label` when the input is inside the popup and the trigger has an explicit id; the linkage updates when the root `id` changes (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:3887-3965`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:11290-11399`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:12163-12189`). `Combobox.Label` labels the Trigger only and warns otherwise (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:12124-12146`).
- Hidden form input: `type` input with `name` (from prop or Field), `autocomplete` from the `autoComplete` prop, `required` (multiple: only when no selection), `disabled`/`readonly` mirroring root state; the visible input gets `autocomplete="off"` and no name (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:3301-3338`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:4571-4596`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:4861-4905`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:5020-5038`).
- Field data attributes `data-touched`, `data-dirty`, `data-filled`, `data-focused`, `data-invalid`, `data-valid` are mirrored on input and trigger, except the popup input in the input-inside-popup composition carries none of them (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:11324-11367`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:11426-11911`). `aria-labelledby` is not set as a fallback when no label is rendered (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:12148-12161`).
- Chip/ChipRemove get `aria-disabled` when disabled and `aria-readonly` when readOnly (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:3340-3409`).

## DOM structure & portal behavior

- Popup content renders through `Combobox.Portal` > `Positioner` > `Popup` > `List`; closed popups are absent from the DOM unless the portal is `keepMounted` (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:2321-2349`, harness `packages/react/test/popupConformanceTests.tsx:134-153`). Portals can target a custom container (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:8623-8662`).
- The input may live outside the popup (classic combobox) or inside it (dialog-like composition); the composition changes which element is the combobox role holder and where the root `id` lands (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:176-209`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:4726-4773`).
- Input-outside-popup open state applies `aria-hidden`/`inert` to outside content including the trigger, and renders internal start/end Dismiss buttons (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:748-896`).
- Filtered DOM structure: list is the scroll container or a scrollable wrapper; query changes reset scroll to the top of the nearest scrollable wrapper without touching enclosing dialogs (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:8313-8662`).
- `<Combobox.Empty>` renders a `role="status"` region for "No matches" (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:535`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:7497`).
- Scroll-into-view of highlighted items uses `{block:'nearest', inline:'nearest'}` (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:1207-1245`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:1716-1769`).

## Events (names, payload shape, bubbling, preventDefault semantics)

- `onOpenChange(open, {reason, event, cancel()})`: fires once per open and once per close; reasons include `'item-press'` with the originating MouseEvent/KeyboardEvent (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:900-979`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:9852-9885`). Cancel semantics: `cancel()` blocks the transition (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:12800-12821`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:362-405`).
- `onValueChange(value, details)`: item value(s) plus details; `cancel()` reverts/ignores; not fired under readOnly, disabled, or canceled autofill (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:6775-6802`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:5040-5066`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:4489-4530`).
- `onInputValueChange(value, details)`: fires for user typing, programmatic sync (reason `'none'`), autofill, selection-time clears (reason `'input-clear'` with `event` = the click or the originating keydown, `isItemPress: true`), and close-path clears; the clear emitted by reopen cleanup carries a synthetic placeholder event of type `'base-ui'` and no `isItemPress` (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:7088-7163`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:7204-7287`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:3993-3994`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:6927-6970`).
- `onItemHighlighted(value | undefined, {reason, index})`: `'keyboard'` on arrow navigation, `'none'` for programmatic/restore highlights (with correct index), a single clearing call with `undefined` on Enter selection, and `undefined`+correct index on mount for virtualized lists (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:9472-9508`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:2009-2054`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:9426-9469`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:1681-1714`).
- `onOpenChangeComplete(open)`: fires after the transition (including when `actionsRef.unmount()` forces close) (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:12992-13008`).
- Escape bubbling rules as under Keyboard (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:3595-3735`); Enter submit prevention as under Keyboard/Form (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:11150-11228`).

## Edge cases (rapid interactions, unmount, nesting)

- Reopening during the close animation is fully supported: single-select query clears and the selection restores; a typed keystroke during the animation reopens and keeps the query; multiple-mode pending filters are cleared with reason `'input-clear'`; controlled-input clears are not double-emitted; frozen queries are released on controlled reopen (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:407-538`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:5695-6313`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:7204-7346`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:7666-7751`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:6019-6116`).
- Rapid item interactions: drag-select (mousedown elsewhere, mouseup on item) commits with `isItemPress`; hover highlight does not clobber a pending programmatic highlight; deselect/filter-out clears highlight appropriately (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:7165-7202`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:1595-1679`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:3008-3029`).
- External/controlled churn: value cleared or set to unmatched while closed clears `selectedIndex`; items becoming `undefined` does not loop; items identity changes preserve the typed filter; async items load restores derived input and never calls the comparator with null/undefined (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:2203-2349`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:718-746`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:5778-5841`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:5675-5692`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:12404-12476`).
- Nesting: nested Popover inside the popup does not dismiss the combobox; portalled content inside the popup does not dismiss or navigate; combobox composes inside Dialog (focus guards, close-on-select) and inside a Composite root for roving-tabindex navigation (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:655-687`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:603-653`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:10348-10672`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:13187-13209`).
- Unmount: `actionsRef.current.unmount()` completes cleanup and fires `onOpenChangeComplete(false)`; hidden-control focus falls back to the trigger after the input unmounts (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:12992-13008`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:13037-13056`).
- Autofill: browser autofill through the hidden input selects matching items (by serialized value, label, case-insensitively), does not force-mount the list, is ignored under readOnly/disabled, in multiple mode for scalar values, and for unmatched values (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:3968-4570`, `packages/react/src/combobox/root/ComboboxRoot.test.tsx:13086-13116`).
- Touch scroll lock with `modal` applies only when the touch-opened popup spans the viewport width (`packages/react/src/combobox/root/ComboboxRoot.test.tsx:4598-4672`).
