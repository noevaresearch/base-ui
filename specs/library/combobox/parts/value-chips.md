# Combobox — value & chips parts (behavior spec)

Scope: `Combobox.Value`, `Combobox.Chips`, `Combobox.Chip`, `Combobox.ChipRemove`, `Combobox.Clear`, mined from their test files only.

## Public API surface (props, parts, subcomponents)

- `Combobox.Value` accepts `children` as a render function `(value) => ReactNode`; the current selected value is passed as the argument (a single string, object, or `null` when nothing is selected) `packages/react/src/combobox/value/ComboboxValue.test.tsx:11-50`.
- `Combobox.Value` also accepts static ReactNode `children`, which overrides the automatic value display entirely (arbitrary nested JSX renders verbatim) `packages/react/src/combobox/value/ComboboxValue.test.tsx:75-117`.
- `Combobox.Value` accepts a `placeholder` prop (string or ReactNode) shown when no value is selected `packages/react/src/combobox/value/ComboboxValue.test.tsx:718-737`, `packages/react/src/combobox/value/ComboboxValue.test.tsx:858-877`.
- `Combobox.Chips` renders a `div` (conformance asserts the ref is `HTMLDivElement`) and accepts `onMouseDown`/`onContextMenu`-style native handlers; it is placed inside `Combobox.Root` and typically wraps `Combobox.Chip` and `Combobox.Input` siblings `packages/react/src/combobox/chips/ComboboxChips.test.tsx:10-15`, `packages/react/src/combobox/chips/ComboboxChips.test.tsx:41-49`.
- `Combobox.Chip` renders a `div` (ref is `HTMLDivElement`), wraps chip content plus an optional `Combobox.ChipRemove`, and forwards native handlers such as `onClick`, `onKeyDown`, `onMouseDown`, `onContextMenu` `packages/react/src/combobox/chip/ComboboxChip.test.tsx:11-20`, `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:283-305`, `packages/react/src/combobox/chips/ComboboxChips.test.tsx:105-164`.
- `Combobox.ChipRemove` renders a native `button` (conformance: `refInstanceof: window.HTMLButtonElement`, `button: true`) and supports `render`/`nativeButton={false}` to render a non-button element `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:9-21`, `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:337-367`.
- `Combobox.ChipRemove` must be rendered inside `Combobox.Chip`; otherwise it throws `Base UI: ComboboxChipContext is missing. ComboboxChip parts must be placed within <Combobox.Chip>.` `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:23-41`.
- `Combobox.Clear` renders a native `button` (ref is `HTMLButtonElement`, `button: true`) and supports `keepMounted` plus a `className` callback receiving state (e.g. `state.visible`) `packages/react/src/combobox/clear/ComboboxClear.test.tsx:10-21`, `packages/react/src/combobox/clear/ComboboxClear.test.tsx:209-253`.
- Root props exercised by these tests: `value`/`defaultValue` (primitive, object, array), `onValueChange`, `items` (flat and grouped), `multiple`, `disabled`, `readOnly`, and `itemToStringLabel` `packages/react/src/combobox/value/ComboboxValue.test.tsx:52-73`, `packages/react/src/combobox/value/ComboboxValue.test.tsx:443-522`, `packages/react/src/combobox/value/ComboboxValue.test.tsx:685-715`, `packages/react/src/combobox/chip/ComboboxChip.test.tsx:22-124`, `packages/react/src/combobox/clear/ComboboxClear.test.tsx:180-207`.

## State model (controlled/uncontrolled, defaults, transitions)

- Uncontrolled usage: `defaultValue` seeds the value; `Combobox.Value` reflects it immediately for strings `packages/react/src/combobox/value/ComboboxValue.test.tsx:620-639`, numbers `packages/react/src/combobox/value/ComboboxValue.test.tsx:641-660`, booleans `packages/react/src/combobox/value/ComboboxValue.test.tsx:662-683`, and arbitrary objects `packages/react/src/combobox/value/ComboboxValue.test.tsx:52-73`.
- Controlled usage: `value` + `onValueChange` drive the displayed label; changing the controlled value externally (including to `null`) updates `Combobox.Value` on the next render (empty text for `null` in this items-based test) `packages/react/src/combobox/value/ComboboxValue.test.tsx:283-329`.
- Multiple mode holds an array value: `defaultValue={[...]}` with `multiple` renders all selected labels; without `items`, raw member values are shown `packages/react/src/combobox/value/ComboboxValue.test.tsx:525-557`, `packages/react/src/combobox/value/ComboboxValue.test.tsx:594-616`.
- In multiple mode an empty array is treated as "no value": the placeholder is displayed `packages/react/src/combobox/value/ComboboxValue.test.tsx:879-898`.
- `onValueChange` receives the new value as the first argument (the array with the removed member) and an event-details object as the second `packages/react/src/combobox/chip/ComboboxChip.test.tsx:494-520`, `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:151-179`.
- Chip removal transitions: Backspace or Delete on a focused chip removes that chip's value from the array `packages/react/src/combobox/chip/ComboboxChip.test.tsx:494-520`, `packages/react/src/combobox/chip/ComboboxChip.test.tsx:388-408`; clicking `ChipRemove` removes its chip's value `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:151-179`; Enter or Space on a focused `ChipRemove` removes it `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:491-519`, `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:369-394`.
- Clear transitions: clicking `Clear` in single mode removes the selected value and the button unmounts (until a value exists again) `packages/react/src/combobox/clear/ComboboxClear.test.tsx:83-105`; in multiple mode it removes all chips at once `packages/react/src/combobox/clear/ComboboxClear.test.tsx:61-81`.
- With `keepMounted`, `Clear` stays in the DOM and toggles visibility state instead of unmounting (`className` callback flips `visible`/`hidden`, `data-visible` attribute added/removed) `packages/react/src/combobox/clear/ComboboxClear.test.tsx:209-253`.
- Disabled and readOnly roots block all removal/clear transitions: `onValueChange` is never called and the DOM keeps the chips/value `packages/react/src/combobox/chip/ComboboxChip.test.tsx:61-90`, `packages/react/src/combobox/chip/ComboboxChip.test.tsx:140-169`, `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:60-89`, `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:93-122`, `packages/react/src/combobox/clear/ComboboxClear.test.tsx:180-207`.
- Display precedence for `Combobox.Value`: `children` (node or function) wins over `placeholder` `packages/react/src/combobox/value/ComboboxValue.test.tsx:760-802`; an items-array label wins over `placeholder` `packages/react/src/combobox/value/ComboboxValue.test.tsx:804-829`; `placeholder` is shown only when the resolved display is empty (e.g. item has `value: null` and `label: null`) `packages/react/src/combobox/value/ComboboxValue.test.tsx:831-856`.
- The value display is re-derived when the `items` array changes, so labels are not stale after items update (mutated label of a stable selected object is reflected; a newly added item can be selected) `packages/react/src/combobox/value/ComboboxValue.test.tsx:387-440`.

## Keyboard interactions

- ArrowRight on a focused chip moves focus to the next chip; ArrowRight on the last chip moves focus to the input `packages/react/src/combobox/chip/ComboboxChip.test.tsx:299-308`.
- ArrowLeft on the first chip moves focus to the input `packages/react/src/combobox/chip/ComboboxChip.test.tsx:310-315`; from the input with the caret at position 0, ArrowLeft moves focus to the last rendered chip `packages/react/src/combobox/chip/ComboboxChip.test.tsx:475-481`, `packages/react/src/combobox/chips/ComboboxChips.test.tsx:296-308`.
- Navigation walks only chips that are actually rendered (a `Combobox.Value` render function can render a subset of the value array; arrow navigation stops at the rendered boundary instead of failing) `packages/react/src/combobox/chip/ComboboxChip.test.tsx:452-492`.
- RTL mirrors arrow semantics: from the input, ArrowRight moves to the last chip then leftward across chips and back to the input; from the leftmost-rendered chip ArrowLeft steps back toward the input `packages/react/src/combobox/chip/ComboboxChip.test.tsx:410-450`.
- Activation and list-opening keys on a focused chip hand focus back to the input: Enter, Space, ArrowDown (which opens the popup), ArrowUp (opens popup), and plain printable characters (text entry) `packages/react/src/combobox/chip/ComboboxChip.test.tsx:318-363`.
- Modified printable keys (Ctrl/Meta/Alt + letter) intentionally leave focus on the chip `packages/react/src/combobox/chip/ComboboxChip.test.tsx:365-386`.
- Backspace on a focused chip deletes it `packages/react/src/combobox/chip/ComboboxChip.test.tsx:494-520`; Delete is also a removal key `packages/react/src/combobox/chip/ComboboxChip.test.tsx:388-408`.
- Disabled roots block chip keyboard navigation and deletion (focus stays on the chip, `onValueChange` not called) `packages/react/src/combobox/chip/ComboboxChip.test.tsx:36-59`, `packages/react/src/combobox/chip/ComboboxChip.test.tsx:61-90`; readOnly blocks navigation and Delete `packages/react/src/combobox/chip/ComboboxChip.test.tsx:171-196`.
- `ChipRemove` keyboard: Enter activates removal `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:491-519`; Space activates removal while unrelated keys (e.g. ArrowDown) are ignored `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:369-394`; under readOnly, activation does nothing `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:124-147`.
- No keyboard interactions are asserted for `Combobox.Clear` in these tests; UNVERIFIED — inferred from `packages/react/src/combobox/clear/ComboboxClear.test.tsx:1-357`, no test asserts this.

## Focus management

- Pressing (mouse down) anywhere in the `Chips` area focuses the input — including pressing on a chip — in the default enabled state `packages/react/src/combobox/chips/ComboboxChips.test.tsx:41-65`, `packages/react/src/combobox/chip/ComboboxChip.test.tsx:522-537`.
- Calling `event.preventBaseUIHandler()` inside `Chips` `onMouseDown` — or inside a nested `Chip` `onMouseDown` — suppresses both the built-in input focus and the popup open `packages/react/src/combobox/chips/ComboboxChips.test.tsx:67-140`.
- A mouse down on `ChipRemove` is not treated as a chips-area press: it neither focuses the input nor opens the popup `packages/react/src/combobox/chips/ComboboxChips.test.tsx:166-191`.
- When the root is disabled via `Field.Root disabled`, chips-area presses neither focus the input nor open the popup `packages/react/src/combobox/chips/ComboboxChips.test.tsx:193-219`; under root `readOnly`, presses still focus the input and open the popup `packages/react/src/combobox/chips/ComboboxChips.test.tsx:221-245`.
- With the input rendered inside the popup, pressing the chips area opens the popup and focuses that popup input `packages/react/src/combobox/chips/ComboboxChips.test.tsx:247-275`.
- A chip receiving focus closes the popup `packages/react/src/combobox/chip/ComboboxChip.test.tsx:243-274`; conversely, when the popup opens again (ArrowDown from the input) the highlighted chip state is cleared and the chip is not focused `packages/react/src/combobox/chips/ComboboxChips.test.tsx:277-309`.
- Removing a chip (click) focuses the input afterward `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:181-200`; if a popup is open it stays open `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:202-233`, and a popup-rendered input keeps focus even when the chips (and the removed chip) live outside the popup `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:235-281`.
- Clicking `Clear` focuses the input, both in the plain (input outside popup) setup `packages/react/src/combobox/clear/ComboboxClear.test.tsx:83-105` and when the input is rendered inside the popup `packages/react/src/combobox/clear/ComboboxClear.test.tsx:146-178`, `packages/react/src/combobox/clear/ComboboxClear.test.tsx:243-253`.
- Chips and Clear clicks count as "inside" for outside-press purposes: clicking a chip `packages/react/src/combobox/chip/ComboboxChip.test.tsx:215-241` or the clear button `packages/react/src/combobox/clear/ComboboxClear.test.tsx:121-144` does not dismiss an open popup.

## Accessibility (roles, aria-*, id linking)

- `Chips` has no `role` attribute when it contains no chips, and gets `role="toolbar"` when at least one chip is rendered `packages/react/src/combobox/chips/ComboboxChips.test.tsx:17-39`.
- `Chip` exposes `aria-disabled="true"` when the root is disabled `packages/react/src/combobox/chip/ComboboxChip.test.tsx:23-34` and `aria-readonly="true"` when the root is readOnly `packages/react/src/combobox/chip/ComboboxChip.test.tsx:127-138`.
- `ChipRemove` exposes `aria-disabled="true"` when the root is disabled `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:44-58` and carries `tabindex="-1"` (removed from tab order; focus is managed via chips navigation/input) `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:521-535`.
- When `ChipRemove` is rendered as a non-native button (`nativeButton={false}` + `render={<div/>}`), disabled and readOnly roots ignore both dispatched click and synthetic Enter keydown (no removal) `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:337-367`.
- `Clear` renders the native `disabled` attribute when the root is disabled (click is a no-op) `packages/react/src/combobox/clear/ComboboxClear.test.tsx:180-193`; under readOnly, clicks are no-ops but no disabled attribute is asserted UNVERIFIED — inferred from `packages/react/src/combobox/clear/ComboboxClear.test.tsx:195-207`, no test asserts this.
- Removing a chip or clearing the value updates the corresponding popup option to `aria-selected="false"` `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:277-281`, `packages/react/src/combobox/clear/ComboboxClear.test.tsx:177`, `packages/react/src/combobox/clear/ComboboxClear.test.tsx:252`.
- `Clear` visibility is exposed via a `data-visible` attribute and a state-driven `className` callback (`state.visible`) for styling the appear/disappear transition `packages/react/src/combobox/clear/ComboboxClear.test.tsx:235-247`.
- `Clear` enter/exit transitions use `data-starting-style` and `data-ending-style` (animation hooks verified in a browser-only suite) `packages/react/src/combobox/clear/ComboboxClear.test.tsx:255-355`.
- No aria-label/id-linking (e.g. `aria-labelledby` between chips and input) is asserted for these parts UNVERIFIED — inferred from `packages/react/src/combobox/chips/ComboboxChips.test.tsx:17-39`, no test asserts this.

## DOM structure & portal behavior

- `Chips` is a plain container div rendered in the inline (non-portal) tree, holding `Chip` and `Input` as siblings; it participates in layout without any popup machinery of its own `packages/react/src/combobox/chips/ComboboxChips.test.tsx:41-49`.
- `Chip` renders a div that can contain text and a nested `ChipRemove` button `packages/react/src/combobox/chip/ComboboxChip.test.tsx:11-20`, `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:151-179`.
- `Value` can render inside the `Trigger`, inside `Chips` (as a render function producing chips), or produce arbitrary markup; it is a pass-through rendering part without its own host element expectations in these tests `packages/react/src/combobox/value/ComboboxValue.test.tsx:126-141`, `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:238-249`, `packages/react/src/combobox/clear/ComboboxClear.test.tsx:64-68`.
- Chips rendered via a `Value` render function are keyed per value and unmount on removal (`remove-apple` disappears from the DOM after its click) `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:238-281`.
- `Clear` mounts only when a value exists by default and unmounts when the value is cleared `packages/react/src/combobox/clear/ComboboxClear.test.tsx:33-42`, `packages/react/src/combobox/clear/ComboboxClear.test.tsx:83-105`; with `keepMounted` it remains mounted and toggles visibility state instead `packages/react/src/combobox/clear/ComboboxClear.test.tsx:209-253`.
- Although chips and clear buttons are rendered outside the `Combobox.Portal` subtree, presses on them do not count as outside presses: the popup remains open `packages/react/src/combobox/chip/ComboboxChip.test.tsx:215-241`, `packages/react/src/combobox/clear/ComboboxClear.test.tsx:121-144`.
- Chip removal while a popup is open leaves the popup (dialog) mounted `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:268-276`.

## Events (names, payload shape, bubbling, preventDefault semantics)

- Root `onValueChange` fires with `(newValue, eventDetails)`; these tests assert the first argument equals the post-change array and the second is "anything" (details object) for Backspace `packages/react/src/combobox/chip/ComboboxChip.test.tsx:494-520`, Delete `packages/react/src/combobox/chip/ComboboxChip.test.tsx:388-408`, `ChipRemove` click `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:151-179`, Enter `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:491-519`, and Space `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:369-394`.
- The change-event details expose `allowPropagation()`; by default a `ChipRemove`-triggered value change blocks propagation of the originating click/keydown to the parent `Chip`, and calling `allowPropagation` in `onValueChange` lets the chip's `onClick`/`onKeyDown` handlers receive the event `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:307-335`, `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:283-305`.
- The change details are typed as `Combobox.Root.ChangeEventDetails` and are delivered to user `onValueChange` handlers `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:310-315`.
- Mouse-press events: `Chips`/`Chip` `onMouseDown` are user handlers that run before the built-in behavior; `event.preventBaseUIHandler()` cancels the built-in input focus + popup open, while the user handler itself still runs exactly once `packages/react/src/combobox/chips/ComboboxChips.test.tsx:67-140`.
- `Chip` `onContextMenu` is a supported handler; `event.preventBaseUIHandler()` within it does not throw `packages/react/src/combobox/chips/ComboboxChips.test.tsx:142-164`.
- Native event props are forwarded: a click on `ChipRemove` fires the remove button's own `onClick` but not the wrapping `Chip`'s `onClick` (by default) `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:283-305`.
- `Clear` click triggers the value-clear transition but does not dismiss the popup; no separate `onClear`-style callback is asserted in these tests UNVERIFIED — inferred from `packages/react/src/combobox/clear/ComboboxClear.test.tsx:121-144`, no test asserts this.

## Edge cases (rapid interactions, unmount, nesting)

- Duplicate values in the `items` array resolve to the first match's label `packages/react/src/combobox/value/ComboboxValue.test.tsx:358-385`.
- Items mutating after mount (label mutation with stable object identity, plus newly appended items) do not leave the value display stale, and new items are selectable immediately `packages/react/src/combobox/value/ComboboxValue.test.tsx:387-440`.
- Null-valued items (`{ value: null, label }`) render their label as the display value both flat and inside grouped item structures `packages/react/src/combobox/value/ComboboxValue.test.tsx:196-221`, `packages/react/src/combobox/value/ComboboxValue.test.tsx:489-521`; a selected value object with `label: null` falls back to raw stringification `packages/react/src/combobox/value/ComboboxValue.test.tsx:170-192`.
- Grouped `items` (nested `items` arrays via `Combobox.Group`) participate in value-label resolution `packages/react/src/combobox/value/ComboboxValue.test.tsx:443-487`.
- Multiple-selection display joins labels with a comma (`"Sans-serif, Serif"`) and supports ReactNode labels rendered side by side `packages/react/src/combobox/value/ComboboxValue.test.tsx:525-592`.
- Arrow navigation is bounded by rendered chips: with only a subset rendered through `Value`, navigation never targets unmounted chips and falls back to the input at boundaries `packages/react/src/combobox/chip/ComboboxChip.test.tsx:452-492`.
- Chip removal while an option is hovered: a different hovered option keeps its highlight `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:396-429`; removing a chip whose option is filtered out of the list does not clear the visible highlight `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:431-460`; a pointer-originated removal clears the highlighted item `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:462-489`.
- Clearing right after pointer movement (pointer interaction marks keyboard navigation inactive) still removes the value and unmounts the clear button `packages/react/src/combobox/clear/ComboboxClear.test.tsx:107-119`.
- Animation edge cases (enter via `data-starting-style` on mount-after-selection; exit via `data-ending-style` before unmount after clearing) are exercised only in a real browser (`describe.skipIf(isJSDOM)`) `packages/react/src/combobox/clear/ComboboxClear.test.tsx:255-356`.
- Disabled `ChipRemove` ignores even programmatically dispatched (non-trusted) click/keydown events `packages/react/src/combobox/chip-remove/ComboboxChipRemove.test.tsx:337-367`.
- The same `Combobox.Clear` part is shared with the `Autocomplete` component: it clears a typed (no-selection) value and focuses the input `packages/react/src/combobox/clear/ComboboxClear.test.tsx:44-59`.
