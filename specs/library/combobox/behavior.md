# Combobox — behavior spec (unit index)

Behavior mined from test files only (`packages/react/src/combobox/**\/*.test.{ts,tsx}`), batched by subdirectory into `parts/*.md`. This file is the index and whole-unit synthesis; the parts files carry the depth. Combobox is first-party (its `TODO.md` entry has no `wraps-external:` field), so nothing is delegated to an external package.

## Public API surface (props, parts, subcomponents)

Combobox exposes ~20 composable parts co-tested with the root: `Root`, `Input`, `Trigger`, `Value`, `Label`, `Portal`, `Positioner`, `Popup`, `List`, `Item`, `ItemIndicator`, `Group`, `GroupLabel`, `Collection`, `Row`, `Empty`, `Chips`, `Chip`, `ChipRemove`, `Clear`, `InputGroup`, plus `createItems` and the hooks `useFilteredItems`/`useFilter`/`useComboboxRootContext` (`specs/library/combobox/parts/root.md:5-15`, `specs/library/combobox/parts/items-item.md:5-21`). Root props cover open/value/inputValue control (each with default + change callback), `multiple`, `items`/`filteredItems`/`filter`/`limit`, `grid`, `inline`, `modal`, `virtualized`, `autoHighlight`, `highlightItemOnHover`, `loopFocus`, `openOnInputClick`, `itemToStringLabel`/`itemToStringValue`/`isItemEqualToValue`, `onItemHighlighted`, and form props (`name`, `autoComplete`, `required`, `form`, `id`) (`specs/library/combobox/parts/root.md:7-11`). Input/Trigger/InputGroup, overlay parts, value/chips parts, and list/group parts each pass the shared conformance suites (ref forwarding, prop spread, render prop, className) (`specs/library/combobox/parts/input-trigger.md:5-16`, `specs/library/combobox/parts/overlay-parts.md:5-14`, `specs/library/combobox/parts/value-chips.md:5-15`, `specs/library/combobox/parts/list-groups-a11y.md:5-18`). Misuse errors are asserted: context hooks throw when used outside their part (`specs/library/combobox/parts/items-item.md:63`, `specs/library/combobox/parts/value-chips.md:13`, `specs/library/combobox/parts/overlay-parts.md:13`, `specs/library/combobox/parts/list-groups-a11y.md:74`).

## State model (controlled/uncontrolled, defaults, transitions)

Open, value, and inputValue are each independently controllable with `default*` fallbacks; controlled open ignores interaction closes, and every change callback receives a details object with `cancel()` (`specs/library/combobox/parts/root.md:19-22`). inputValue is a synchronized mirror of the resolved selection with a freeze/frozen-query mechanism around close animations (`specs/library/combobox/parts/root.md:21`, `specs/library/combobox/parts/root.md:76`). The `Autocomplete`-tested store carries at least `inline`, `inputOwnsFormValue`, `inputInsidePopup`, `selectedIndex`, `activeIndex`, and `openOnInputClick`; prop-to-store transitions publish atomically (no intermediate snapshot observed) (`specs/library/combobox/parts/store-utils.md:16-34`). Items derive a primitive selection value via `createItems({getValue, getLabel})`; labels resolve live from collection data with per-value degradation to the raw value, never cached at selection time (`specs/library/combobox/parts/items-item.md:22-36`, `specs/library/combobox/parts/value-chips.md:29`). Multiple mode holds an array where `[]` means "no value" (placeholder shown); single mode holds a primitive or object (`specs/library/combobox/parts/value-chips.md:21-22`). Disabled resolution flows local part → Root → Field (`specs/library/combobox/parts/input-trigger.md:27`).

## Keyboard interactions

Root keyboard: ArrowDown/ArrowUp open and highlight first/last, Enter commits (preventDefault only when an item is highlighted), Escape closes without committing or discards an uncommitted query, grid mode adds row/column navigation with RTL mirroring, and looping clears-then-wraps by default (`specs/library/combobox/parts/root.md:26-35`). Input keyboard: typing opens, readOnly blocks typing but not navigation, IME `keyCode` 229 Enter never selects, Home/End handle caret (inverted in Gecko RTL), and an empty-input Backspace removes the last rendered chip (`specs/library/combobox/parts/input-trigger.md:31-48`). Trigger keyboard: closed-state typeahead cycles like a native select and ArrowDown/Up open with focus moved to the combobox (`specs/library/combobox/parts/input-trigger.md:49-56`). Chip keyboard: Arrow navigation is bounded by *rendered* chips (not the value array), Backspace/Delete remove, and activation keys hand focus back to the input (`specs/library/combobox/parts/input-trigger.md:41-43`, `specs/library/combobox/parts/value-chips.md:31-41`). List-level Enter respects highlighted-item/disabled/readOnly gating (`specs/library/combobox/parts/list-groups-a11y.md:29-33`).

## Focus management

Focus stays on the input at all times while the list is open; highlight is expressed via `aria-activedescendant`, and the popup's touch-open path focuses the popup element instead of the input (`specs/library/combobox/parts/root.md:42`, `specs/library/combobox/parts/overlay-parts.md:29-34`). Opening/closing moves focus between trigger and input depending on composition; removal and clear actions return focus to the input even across portal boundaries (`specs/library/combobox/parts/root.md:39`, `specs/library/combobox/parts/value-chips.md:52-53`). Chip highlight navigation is stateful across focus returns, and chip focus vs popup open are mutually exclusive (`specs/library/combobox/parts/input-trigger.md:63`, `specs/library/combobox/parts/value-chips.md:51`). Modal mode cycles Tab inside the popup, makes outside content inert, and injects hidden Dismiss buttons; the hidden form control redirects focus (input → trigger → body) (`specs/library/combobox/parts/root.md:41,43`). `initialFocus={false}` and `finalFocus` are honored by the popup (`specs/library/combobox/parts/overlay-parts.md:11,31-33`).

## Accessibility (roles, aria-*, id linking)

The active element carries `role="combobox"` with `aria-expanded`/`aria-controls`/`aria-haspopup`/`aria-activedescendant`; which element that is depends on composition — input-outside-popup demotes the Trigger to a plain `tabindex="-1"` button, while input-inside-popup promotes the Trigger to the combobox and the popup to `role="dialog"` (otherwise `presentation`) (`specs/library/combobox/parts/root.md:49-51`, `specs/library/combobox/parts/input-trigger.md:71-77`, `specs/library/combobox/parts/overlay-parts.md:38`). Options are `role="option"` with `aria-selected` and `data-highlighted`; grid mode uses grid/row/gridcell roles; the listbox gets `aria-multiselectable` and `aria-readonly` (moved to the input in grid mode) (`specs/library/combobox/parts/root.md:50`, `specs/library/combobox/parts/items-item.md:56-64`, `specs/library/combobox/parts/list-groups-a11y.md:42-44`). Groups are `role="group"` + `aria-labelledby` pointing at an `aria-hidden` GroupLabel id with newest-label-wins race safety (`specs/library/combobox/parts/list-groups-a11y.md:45-47`). `Combobox.Label` labels the Trigger only and warns in dev otherwise; no `htmlFor` wiring is proven (`specs/library/combobox/parts/list-groups-a11y.md:50-52`). Form-value ownership is a two-sided invariant — exactly one named control exists (hidden control vs the input itself) — surviving SSR/hydration and StrictMode (`specs/library/combobox/parts/store-utils.md:49-50,57`, `specs/library/combobox/parts/root.md:52`).

## DOM structure & portal behavior

Structure is `Portal → Positioner → Popup → List` (+ `Empty`/`Group`/`Item` inside); closed popups are unmounted unless `keepMounted`, portals accept a custom container, and `inline` renders the list without a portal (`specs/library/combobox/parts/root.md:58`, `specs/library/combobox/parts/overlay-parts.md:43-51`, `specs/library/combobox/parts/input-trigger.md:81-89`). The Positioner anchors to the InputGroup when present, else the Input (never the Trigger), exposes `data-side` and a `--available-height` CSS var that must be seeded before sizing to avoid erroneous flips (`specs/library/combobox/parts/overlay-parts.md:49-50`). Items register into the root's `listRef` at filtered indexes, leaving empty slots under virtualization; highlight/Enter resolution uses filtered indexes, not DOM order (`specs/library/combobox/parts/items-item.md:71,100`). Chips/Clear render inline (outside the portal) yet count as "inside" for dismissal; `Clear` mounts only when a value exists (`specs/library/combobox/parts/value-chips.md:74-75`). Scroll-into-view uses `{block:'nearest', inline:'nearest'}` and query changes reset list scroll (`specs/library/combobox/parts/root.md:61,63`).

## Events (names, payload shape, bubbling, preventDefault semantics)

Three change callbacks share one details-object contract — `onOpenChange(open, {reason, event, cancel()})`, `onValueChange(value, details)`, `onInputValueChange(value, details)` — with observed reason strings `'item-press'`, `'input-press'`, `'trigger-press'`, `'cancel-open'`, `'input-clear'`, `'keyboard'`, `'none'` (`specs/library/combobox/parts/root.md:9,67-72`, `specs/library/combobox/parts/input-trigger.md:92-94`). `cancel()` vetoes open/close/value transitions; `preventBaseUIHandler()` on item/chip handlers vetoes the built-in select/close or focus/open pipeline; `details.allowPropagation()` re-enables the originating event reaching the parent Chip (`specs/library/combobox/parts/root.md:67-69`, `specs/library/combobox/parts/items-item.md:79`, `specs/library/combobox/parts/value-chips.md:80-83`). `onItemHighlighted(value, {reason, index})` distinguishes `'keyboard'` from programmatic/restore highlights (`specs/library/combobox/parts/root.md:70`). Escape propagation is conditional on actual mutation; Enter only preventDefaults form submit when an item is highlighted; item mousedown is default-prevented so selection never steals focus (`specs/library/combobox/parts/input-trigger.md:95`, `specs/library/combobox/parts/root.md:29`, `specs/library/combobox/parts/items-item.md:48`).

## Edge cases (rapid interactions, unmount, nesting)

Reopening during the close animation is fully supported with query freeze/restore semantics; stale pointer state across close/reopen must not poison the next drag-select; multi-touch must not double-commit (`specs/library/combobox/parts/root.md:76`, `specs/library/combobox/parts/input-trigger.md:103-105`). Controlled churn is guarded: external value clears resync `selectedIndex`, async items restore derived labels, `items` identity changes preserve the typed filter, and duplicate derived values warn and resolve first-match (`specs/library/combobox/parts/root.md:78`, `specs/library/combobox/parts/items-item.md:89,93`). Unmount paths are covered: pending mouseup after trigger unmount fires nothing, `actionsRef.unmount()` completes cleanup with `onOpenChangeComplete(false)`, live-region markers are restored before detach, and the store ownership invariant survives input remount replay and StrictMode (`specs/library/combobox/parts/input-trigger.md:103`, `specs/library/combobox/parts/root.md:80`, `specs/library/combobox/parts/list-groups-a11y.md:73`, `specs/library/combobox/parts/store-utils.md:72-73`). Nesting is safe: nested Popover/portalled content inside the popup never dismisses, and combobox composes inside Dialog (focus guards, close-on-select) and Composite roots (`specs/library/combobox/parts/root.md:79`). Browser autofill through the hidden control selects matching items with case-insensitive value/label matching, gated by readOnly/disabled (`specs/library/combobox/parts/root.md:81`).

## Whole-unit cross-cutting behavior

- **One store drives all parts.** Root exposes the store to every descendant; `activeIndex`/`selectedIndex` are single sources of truth viewed as the input's `aria-activedescendant` and the item's `data-highlighted`, and items register into `context.listRef` so keyboard selection can synthesize a click through `selectionEventRef` (`specs/library/combobox/parts/root.md:11`, `specs/library/combobox/parts/items-item.md:71`, `specs/library/combobox/parts/store-utils.md:65`).
- **Two structural compositions reassign identity.** Input-outside-popup (classic) vs input-inside-popup (dialog-like) deterministically decide the combobox role holder, anchor element, popup role, `id`/label linkage, Field data attributes, and form-value ownership (`specs/library/combobox/parts/root.md:59`, `specs/library/combobox/parts/input-trigger.md:76,88`, `specs/library/combobox/parts/overlay-parts.md:38`).
- **Derived-value pipeline.** `createItems` → lazy `getValue`/`getLabel` accessors → locale-aware collator filter (bypassed when the query equals the selected label; short-circuited by `limit`) → custom `filter`/`filteredItems` windows → label resolution cache with raw-value degradation → form serialization (`specs/library/combobox/parts/items-item.md:24-33,96-99`, `specs/library/combobox/parts/root.md:24`).
- **Value lifecycle converges on `onValueChange`.** Item click/Enter, trigger typeahead, drag-select, chip Backspace/ChipRemove, and Clear all funnel into the same callback with cumulative arrays in multiple mode and a shared details contract (`specs/library/combobox/parts/value-chips.md:80`, `specs/library/combobox/parts/root.md:20`).
- **Shared live-region protocol.** `Empty` and `Status` use `role="status"` with a WORD JOINER (`\u2060`) initial-announcement marker removed after a reset delay, skipped on iOS — implemented via the shared `useInitialLiveRegionTextMutation` hook (`specs/library/combobox/parts/list-groups-a11y.md:24-27`, `specs/library/combobox/parts/store-utils.md:51`).
- **`readOnly` suppresses mutation, never navigation.** Across input, trigger, chips, and list: typing/commit/removal blocked; opening, arrow browsing, and focus movement preserved (`specs/library/combobox/parts/root.md:34`, `specs/library/combobox/parts/input-trigger.md:36,52`, `specs/library/combobox/parts/value-chips.md:40,49`).
