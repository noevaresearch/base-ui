## State model (controlled/uncontrolled, defaults, transitions)

- Uncontrolled `defaultValue={1}` renders input text `'1'`; no props renders empty text. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:51-62`
- Controlled `value` accepts a number (updates when rerendered: 1 → 2), `undefined` (empty), and `null` (empty). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:65-84`
- Value contract is `number | null`: whitespace-only text reports `null` (input "empty but not trimmed"). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:86-92`
- `onValueChange` fires once per transition `null → number` (value `5`) and `number → null` (value `null`) when driven by a controlled state. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:192-232`
- Two-callback commit model: `onValueChange` fires for every parseable change while typing; `onValueCommitted` fires only on blur or on discrete actions (keyboard step, buttons, wheel). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:331-355`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:789-832`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1496-1526`
- `step` defaults to `1` (increment from 5 → 6 with no props). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1204-1210`
- `snapOnStep` snaps to the nearest multiple of `step` when incrementing (5 + step 2 → 6) or decrementing (5 − step 2 → 4); without it, value moves by raw `step` (4 + 2 → 6). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1212-1238`
- `largeStep` defaults to 10 (applied with Shift held on stepper pointer-down: 5 → 15); `smallStep` defaults to 0.1 (applied with Alt held: 5 → 5.1). Modifier flags reset when the key is released. Browser-only (`describe.skipIf(isJSDOM)`). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1241-1307`
- Clamping while typing: with `min={5}` and typed text `'4'`, the visible input keeps `'4'` but `onValueChange` receives the clamped `5`; symmetric behavior for `max={5}` with typed `'6'`. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1003-1028`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1056-1081`
- `allowOutOfRange` disables that clamp for typed input (raw value reaches the hidden input and native `rangeOverflow` validity), while stepper/wheel interactions still clamp to range even when `allowOutOfRange` is true; `allowOutOfRange={false}` clamps typed values as usual. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1110-1201`
- Blur commits the clamped/canonical value and rewrites the visible text: typing `1000` with `max={10}` commits `10` and displays `'10'`; typing `-50` with `min={0}` commits `0` and displays `'0'`. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:761-787`
- `onValueCommitted` is not fired for a focus→blur cycle on an untouched empty field. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:848-857`
- `onValueCommitted` is not fired for keyboard steps that don't change the value (ArrowUp/End at `max`). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:859-874`
- Default `inputmode` attribute is `numeric`. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:2385-2391`
- iOS-gated (platform mocked in `NumberFieldRoot.iOS.test.tsx`): `inputmode` is widened to `decimal` when negatives are impossible (`min={0}`), and to `text` when negatives are possible (`min={-5}`) or no `min` is set — because the iOS numeric keyboard lacks decimal/minus keys. `packages/react/src/number-field/root/NumberFieldRoot.iOS.test.tsx:6-17`, `packages/react/src/number-field/root/NumberFieldRoot.iOS.test.tsx:24-52`

## Keyboard interactions

- `ArrowUp` / `ArrowDown` on the focused input step the value by `step` and fire `onValueCommitted` per press (0 → 1 → 0 with `min={-10} max={10}`). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:789-813`
- `Home` jumps to `min` (-10) and `End` jumps to `max` (10), each committing. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:806-812`
- Without `min`/`max`, `Home`/`End` are NOT preventDefault-ed (native caret movement preserved). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:2843-2853`
- Navigation/editing keys `Backspace`, `Delete`, `ArrowLeft`, `ArrowRight`, `Tab`, `Enter` are never preventDefault-ed. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:2829-2841`
- Non-handled non-printing keys (`PageUp`, `PageDown`, `Insert`, `F5`) are not swallowed (no preventDefault). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:2855-2865`
- With `allowOutOfRange` and `min={0}`, the `-` key is not blocked (no preventDefault) so native underflow validation is reachable, and typing `-1` is accepted. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1111-1123`
- IME composition keydown (`which: 229`) is not preventDefault-ed. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:2723-2735`
- A canceled keyboard step (calling `details.cancel()` in `onValueChange`) leaves the input value unchanged and skips the commit. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:889-906`
- Keyboard `Backspace` is allowed to delete a trailing currency symbol that follows a locale literal; the value contract stays unchanged. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:683-718`
- A `.` keypress replacing a selection (e.g. replacing the decimal region of `12.3`) is not blocked. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:413-429`

## Focus management

- Focusing the hidden native input forwards focus to the visible textbox. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:2404-2410`
- On forwarded focus the caret is placed at the end of the visible input (`selectionStart === selectionEnd === value.length`), unless the consumer's own `onFocus` changes the selection (e.g. `event.currentTarget.select()` is preserved). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:2412-2439`
- `data-focused` attribute is set on the input on focus and removed on blur, repeatedly (verified across two focus cycles and on a `readOnly` field). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1964-2005`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:943-958`
- When a Base UI `Form` reports server errors, the input receives focus and gets `aria-invalid="true"`. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1699-1728`
- Wheel scrubbing requires focus: with `allowWheelScrub` and an unfocused input, no change occurs. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1403-1410`

## Events (names, payload shape, bubbling, preventDefault semantics)

- `onValueChange(value: number | null, details)` fires on parseable typing, paste, blur-commit transitions, stepper presses, keyboard steps, and wheel scrub. Payload details include `reason`. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:170-328`
- Reason strings asserted: `'input-change'` (typing, via `REASONS.inputChange`), `'input-clear'` (clearing), `'keyboard'` (ArrowUp), `'increment-press'` / `'decrement-press'` (stepper clicks, also asserted on `onValueCommitted` details), `'wheel'`, `'input-paste'` (pasted exotic numerals). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:234-328`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:834-846`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1515`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:2516`
- `details.cancel()` on `onValueChange` vetoes the change: input text stays at the old value, `onValueCommitted` is skipped (keyboard step and clear-on-blur cases). Validation still runs on a canceled autofill change (`validate` receives the parsed value even though the input stays empty). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:889-925`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:2461-2474`
- `onValueCommitted(value, details)` fires on blur (canonical/clamped value), on each keyboard step, on stepper clicks, and on each wheel tick; blur after wheel commits does NOT commit again. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:733-787`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:789-832`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1496-1526`
- Wheel preventDefault semantics (observed via `fireEvent.wheel` return value, `false` = canceled): a vertical-dominant wheel over a focused input IS canceled and scrubs (deltaY > 0 decrements, deltaY < 0 increments); a horizontal-dominant wheel (including sub-pixel cross-axis noise and zero movement) is NOT canceled and does not scrub; `ctrlKey` (pinch-zoom) wheel does not scrub. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1373-1391`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1393-1401`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1412-1455`
- Shift+wheel applies `largeStep`, including Chromium's axis swap where the horizontal delta carries direction (dominant axis wins over noise). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1457-1494`

## Edge cases (rapid interactions, unmount, nesting)

- Stepper press-and-hold: value steps on `pointerDown` alone (no pointerUp needed); one press-release fires exactly one commit even when `mouseleave`/`mouseenter` fire during the hold. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1241-1272`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:876-887`
- Rapid wheel at a boundary: a no-op step (already at `max`) fires neither `onValueChange` nor `onValueCommitted`. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1528-1548`
- Wheel after paste: the visible input syncs with the value contract (paste `20`, wheel → `21`). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1550-1569`
- Typing model edge cases: `onValueChange` fires for each parseable change (`'1'`, `'12'`, `'12.'` → 12) and not for non-parseable intermediates (`'12.a'`, `'-'`, `'.'`); group separators parse progressively; `de-DE` comma decimals; percent style parses `12`/`12%` → 0.12 and interleaved `1%2` reformats to `12%` → 0.12 on blur; currency/unit/scientific symbols and bidi control chars (U+200E) don't block parsing; multi-character currency symbols (`R$`) and unit symbols (`km/h`) don't block trailing-digit entry; `1.5E3` parses to 1500. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:331-355`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:384-411`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:431-487`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:489-538`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:540-652`
- IME: no `onValueChange` during composition (`compositionStart`/changes/`compositionEnd` with non-numeric text); a parseable Han numeral afterwards fires with value 1; commit happens on blur. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:357-382`
- Invalid partial input (e.g. `'.'`) stays visible but does not commit on blur. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:720-730`
- Exotic numeral systems: Persian digits typed (`۱۲۳` → 123); pasted Persian / Arabic-Indic / fullwidth / Han numerals parse with reason `input-paste` while the raw text stays visible; Persian digits with Arabic group/decimal separators (`۱۲٬۳۴۵٫۶۷` → 12345.67); fullwidth punctuation (`１，２３４．５６` → 1234.56); percent/permille signs in percent format (`١٢٪` → 0.12, `12؉` → 0.012) but ignored outside percent format; trailing unicode minus (`1234−` → -1234); accounting-style parentheses `(1,234.5)` rejected; extra dots from mixed locales collapse (`1.234.567.89` → 1234567.89). `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:2477-2721`
- Pasting: valid paste replaces the selection; invalid paste (`'abc'`) is ignored without changing value or firing callbacks; paste is blocked on `readOnly`; pasted text inserts at the caret rather than replacing the whole value (`123|` + `5` → `1235`), replaces a selected range (`1[2]3` + `9` → `193`), and leaves the caret just after the pasted text. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:2738-2763`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:2766-2826`
- Autofill: changing the hidden input fires `onValueChange` with the parsed number and updates the visible input; validation receives the parsed number; hidden-input autofill changes are ignored when the field is `readOnly` or `disabled`, both inside and outside a Base UI `Field`. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1784-1825`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1827-1883`
- Form integration: submitted FormData carries the raw unformatted value (`'50'`, `'54.5'` despite `de-DE` EUR formatting); native `<form>` and external `form` id both work; `step` mismatch (`step={0.1}` with `0.11`, or default `step` with `0.11`) blocks submission via native `validity.stepMismatch`; `step="any"` never mismatches; `allowOutOfRange` exposes `rangeOverflow` instead of clamping. `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:95-168`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1125-1150`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:1572-1674`, `packages/react/src/number-field/root/NumberFieldRoot.test.tsx:2173-2241`
