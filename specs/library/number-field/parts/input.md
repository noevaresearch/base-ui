## State model (controlled/uncontrolled, defaults, transitions)

- Uncontrolled usage: `defaultValue` seeds the value (e.g. `defaultValue={0}` yields input text `"1"` after ArrowUp, `"-1"` after ArrowDown). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:92-114`
- Controlled usage: `value` + `onValueChange`; `value` may be `null` initially, and a mirrored `setState` in `onValueChange` is the pattern used throughout the controlled tests. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:157-171`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:559-567`
- While focused, typing numeric text fires `onValueChange` with the parsed number immediately on each change event (e.g. typing `1.5` with a stale controlled `value={0}` still reports `1.5`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:258-278`
- Display text is NOT formatted while focused: typing `1234` keeps the input value `"1234"`; the formatted rendering `(1234).toLocaleString()` only appears on blur. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:486-498`
- Blur commits the validated number: with `min={0}` a typed `-1` becomes `"0"` on blur; with `max={0}` a typed `1` becomes `"0"`. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:500-526`
- Blur does NOT snap to `step` even when `snapOnStep` is set: `1.5` typed with `step={0.5} snapOnStep` stays `1.5` (locale-formatted) on blur. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:528-540`
- With `min={2} step={2}`, a typed `3` (already on-step and in-range) stays `3` on blur. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:542-554`
- Dirty-input authority: when the controlled `value` is never mirrored back (parent ignores `onValueChange`), keyboard stepping and Increment-button clicks step from the dirty typed text (`1.5` → `2.5`), not from the stale numeric state (`0` → `1`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:258-278`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:347-366`
- A non-mutating key (`ArrowLeft`) does not clear dirty authority: after typing `1.5` and pressing ArrowLeft, the next keyboard step still uses `2.5`, and blur still commits the typed `5` rather than reverting to the stale state. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:324-345`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:368-390`
- Cancellation: `onValueChange` receives a details object with `cancel()`; a canceled keyboard step does not fire `onValueCommitted` and does not commit a previously-stored value (count stays at 1 after an external change + canceled step). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:280-322`
- A canceled blur change (`details.cancel()` called in `onValueChange`) means `onValueCommitted` never fires and the input keeps the raw text `"1.239"`. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1218-1245`
- No-edit focus/blur cycles are no-ops numerically: after an external `setProps({ value: 1.23456 })`, focus+blur does not re-fire `onValueChange` (0 calls) and the display stays locale-formatted. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:556-585`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:732-769`
- Typing remains possible after a formatted blur: clear + type `1.234567` shows the raw text, and blur reformats. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:661-698`
- External value changes always update the visible input text with default formatting: clicking `NumberField.Increment` shows `"1"`, then an external `setValue(1.23456)` shows `(1.23456).toLocaleString()`; same for Decrement followed by external `2.98765`. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:587-659`
- An external value change during typing replaces the dirty text: typing `2.7`, then clicking a "set pi" button that sets `3.14159265`, shows the formatted pi; blur keeps it. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:803-838`
- With explicit `format.maximumFractionDigits: 2`, blur rounds the value AND fires `onValueChange` once with the rounded number (`1.23456` → `1.23`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:840-872`
- Without explicit precision options, the committed numeric value keeps full precision (`1.23456` committed as-is) while the displayed text uses the Intl default formatting; the same holds for values with more than 15 significant digits (`1.234567890123456`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1247-1286`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1288-1325`
- Typing a numerically-equal but textually-different value (`1.50` for stored `1.5`) still commits and reformats on blur (input matches `/^1[.,]5/`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:771-801`

## Keyboard interactions

- `ArrowUp` / `ArrowDown` on the focused input increment/decrement by the default step (`0` → `"1"` / `"-1"`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:92-114`
- `Home` sets the value to `min` (`"‑10"` with `min={-10}`); `End` sets it to `max` (`"10"` with `max={10}`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:116-138`
- Holding `Alt` with `ArrowUp`/`ArrowDown` steps by `smallStep` and snaps when `snapOnStep` is set (`0.15` with `smallStep={0.1}` → `0.3` then `0.2`, locale-formatted). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:140-152`
- A `smallStep` finer than 3 fraction digits works: `smallStep={0.0001}` reports `0.0001` to `onValueChange` even though the visible display rounds to `"0"`. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:154-182`
- Keyboard stepping uses the full-precision numeric state, not the rounded display text: from `defaultValue={1.23456}` (display shows the rounded `toLocaleString`), ArrowUp yields `2.23456` and ArrowDown yields `0.23456` to `onValueChange`. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:184-224`
- Stepping from numeric state survives a no-edit blur cycle: type `1.23456`, blur (display formats), re-focus, ArrowUp → `2.23456`. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:226-256`
- A keyboard step fires `onValueCommitted` immediately with the stepped value (`1` after ArrowUp from 0). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:309-311`
- Typing non-numeric characters is blocked both via change events (`abc` leaves value `""`) and via keydown (`a` leaves value `""`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:56-78`
- Numeric characters are accepted via change events (`123` shows as `"123"` while focused). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:80-90`
- When formatted as percent, keydown accepts unicode minus sign (U+2212), fullwidth plus sign (U+FF0B), permille `‰`, and fullwidth digit `１` (dispatched keydown events are NOT default-prevented — dispatch returns `true`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:392-411`
- When NOT formatted as percent, `%` and `‰` keydowns ARE default-prevented (dispatch returns `false`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:413-430`
- Locale-aware key gating (de-DE, decimal `,` group `.`): the first `,` is allowed; a second `,` is default-prevented; the grouping `.` is allowed multiple times; change keeps locale-typed text like `"1,"`. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:432-461`
- Locale space grouping (pl-PL): plain space keydown is allowed and a change to `"1 234"` is preserved verbatim. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:463-484`
- Single sign character: with value `-5`, pressing `-` is blocked (default-prevented) when the caret is not on the existing sign; allowed when the existing `-` is selected; allowed when the whole value is selected. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1482-1521`

## Events (names, payload shape, bubbling, preventDefault semantics)

- `onValueChange(nextValue, details)`: fires on typing changes (parsed number), on keyboard/button steps, and even when a paste produces an unchanged value (reason-tagged direct-entry changes always report). Details include `cancel()` and `reason`. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:258-278`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1457-1480`
- `details.reason` identifies the source; a paste-triggered change carries `REASONS.inputPaste` (`'input-paste'`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1479`
- `onValueCommitted(value)`: fires once per committed transition — on keyboard step (`1` after ArrowUp), and on blur after typing (`1.5` for roundingIncrement commit, `12300` for significant-digit rounding, `1.239` for roundingMode commit, `0.0000012` for tiny percent, `0.0046` for percent boundary). It does NOT fire for no-edit focus/blur cycles. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:309-311`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:959-1011`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1013-1028`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1367`
- `details.cancel()` semantics: canceling `onValueChange` suppresses `onValueCommitted` for that transition (keyboard step and blur both covered). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:280-322`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1218-1245`
- Native `change` on the input: if the consumer prevents the change event's default (Input `onChange` → `event.preventDefault()`), the change is ignored entirely — the display reverts to `"5"` and `onValueChange` is not called. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1578-1593`
- Native `keydown`: if the consumer prevents the keydown default (Input `onKeyDown` → `event.preventDefault()`), stepping does not happen (`ArrowUp` leaves `"5"`, `onValueChange` not called). Similarly, the component itself calls `preventDefault` on blocked character keys (`%`, `‰`, duplicate `-`, second de-DE `,`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1595-1610`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:413-430`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1504-1508`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:449-455`
- Native `focus`/`blur`: preventing their defaults gates focus-state marking and all blur commit/reformat/touch behavior respectively. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1543-1576`
- `paste` event: handled natively on the input. If clipboard text cannot be read, the component logs a console warning starting with "Base UI: <NumberField.Input> could not read clipboard text during paste handling." (once, deduped by message), does NOT prevent the paste (`pasteEvent.defaultPrevented === false`), and leaves the value unchanged (`"12"`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1398-1422`
- The paste warning message has no owner-stack suffix when React's `captureOwnerStack` is unavailable (exact message ends with a trailing space); this variant is skipped on React < 19.1. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1424-1455`
- A paste event with `clipboardData === null` splices an empty string (text unchanged), still marks the input dirty, and emits exactly ONE `onValueChange` with the current value `12` and reason `input-paste`. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1457-1480`
- Bubbling: dispatched keydown/paste events in tests are created with `bubbles: true`; no assertion in this file pins bubbling behavior of component-emitted events — UNVERIFIED — inferred from `packages/react/src/number-field/input/NumberFieldInput.test.tsx:14-26`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:402-405`.

## Edge cases (rapid interactions, unmount, nesting)

- Rapid/interleaved external changes: increment-button click followed immediately by an external controlled `setValue(1.23456)` correctly refreshes the display to the formatted external value (and the decrement analog with `2.98765`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:587-659`
- External change DURING active typing replaces dirty text with the formatted external value and survives blur. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:803-838`
- Canceled keyboard step after an external change must not commit the stale earlier value: ArrowUp (commit 1) → external set to 10 → canceled ArrowUp keeps `onValueCommitted` count at 1. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:280-322`
- Repeated no-edit focus/blur cycles (2+ cycles) keep the full-precision numeric value and fire `onValueChange`/`onValueCommitted` zero additional times. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:732-769`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1361-1367`
- Stepping after blur cycles uses the full-precision numeric value (`2.23456` from `1.23456`), not the rounded display (`2.235`). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1369-1372`
- Parsing overflow: a formatted `Number.MAX_VALUE` (percent style) typed in and blurred does NOT commit — neither `onValueChange` nor `onValueCommitted` fires, and the raw text stays. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1185-1216`
- Rounding on blur can cross a max boundary: with `max={0.01235}`, typing `1.236%` (percent, `maximumFractionDigits: 2`) commits the clamped `0.01235`. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1149-1166`
- Locale-typed decimals normalize on blur: fr-FR `"1234,5"` fires exactly one `onValueChange(1234.5)` and the display becomes `(1234.5).toLocaleString('fr-FR')`; ar-EG accepts Arabic-Indic digit input `١٫٢٣٩` and commits `1.23`. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1375-1396`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:911-931`
- Intl rounding options are honored on blur commit: `roundingMode: 'floor'` with `maximumFractionDigits: 2` (`1.239` → `1.23`), `roundingIncrement: 5` with min/max fraction digits 1 (`1.26` → `1.5`, no throw on blur), `maximumSignificantDigits: 3` (`12345` → `12300`), tiny percents (`0.0001234%` → `0.0000012`), and roundingMode without explicit precision (`1.2399` → `1.239`). Percent styles (incl. `unit: 'percent'`) round WITHOUT percent scaling errors and display `"1.23%"`; tr-TR prefix-percent formatted strings parse back to `0.0123`. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:911-931`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:933-977`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:979-1028`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1054-1111`, `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1113-1147`
- Currency rounding happens without percent scaling (`1.239` → `1.23` USD). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1168-1183`
- Controlled values rendered with rounding options format correctly after external `setProps` (`1.2399` displayed via the configured formatter). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1030-1052`
- A focus+blur cycle with no edits after an external `setProps` never re-parses the rounded display text into the numeric value (no `onValueChange` calls). `packages/react/src/number-field/input/NumberFieldInput.test.tsx:556-585`
- Unmount behavior: N/A — no unmount assertions in this file.
- Nesting: the Input is tested nested inside `Field.Root` (focus/touch attribute suppression); no deeper nesting is tested. `packages/react/src/number-field/input/NumberFieldInput.test.tsx:1543-1576`
