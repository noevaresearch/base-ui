# NumberField scrub parts — implementation spec (WHY/HOW)

Explains how the source in this batch produces the behavior documented in `specs/library/number-field/parts/scrub.md` (cited below as "behavior: <section name>"). Batch files: `packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx`, `packages/react/src/number-field/scrub-area/NumberFieldScrubAreaContext.ts`, `packages/react/src/number-field/scrub-area/NumberFieldScrubAreaDataAttributes.ts`, `packages/react/src/number-field/scrub-area-cursor/NumberFieldScrubAreaCursor.tsx`, `packages/react/src/number-field/scrub-area-cursor/NumberFieldScrubAreaCursorDataAttributes.ts`. Scope note per the unit's `TODO.md` entry: it has no `wraps-external:` field (`TODO.md:440-447`), so nothing is delegated to a third-party package — all Pointer Lock API work is native browser API called directly from the component.

## State machine / hooks used

`NumberFieldScrubArea` owns a pointer-driven state machine; `NumberFieldScrubAreaCursor` is stateless relative to it — a conditional renderer.

**States.** The machine has three coarse states with split bookkeeping: React state (`isScrubbing`, `isTouchInput`, `isPointerLockDenied` — `packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:71-73`) drives rendering/listener attachment, while refs (`isScrubbingRef`, `didMoveRef`, `pointerDownTargetRef`, `virtualCursorCoords` — `packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:63-67`) hold the synchronous truth. The ref/state split is deliberate: the refs survive the `<Activity>` teardown/re-attach cycle where effects are destroyed and re-created without unmounting, and `handleScrubPointerMove` checks `isScrubbingRef.current` first for exactly that reason (comment at `packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:199-204`).

**Transitions:**

1. **Idle → PointerDown** (`async onPointerDown`, `packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:302-339`). Guards in order: `event.defaultPrevented || readOnly || event.button || disabled` (non-primary buttons are truthy `button`, so they no-op — behavior: Events) at `packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:303`. Touch state is recorded first (`pointerType === 'touch'` → `setIsTouchInput`, `packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:307-308`). Mouse presses `preventDefault()` then call root's `focusInput()` (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:310-313`) — the preventDefault is what suppresses the browser's native click generation and text-selection drag, which is *why* the synthetic-click compensation of transition 4 exists. `isScrubbingRef.current = true` and `didMoveRef.current = false` reset the ref truth (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:315-316`), the original event target is captured shadow-DOM-safely via `getTarget` (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:317`), and `onScrubbingChange(true, …)` flips the visible state.
2. **PointerDown → PointerLock resolution** (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:320-338`). Non-touch, non-WebKit presses await `ownerDocument(...).body.requestPointerLock()`; resolution sets `isPointerLockDenied` accordingly, and the `finally` block re-emits `onScrubbingChange(true, …)` if still scrubbing (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:330-337`). The re-emit is required because the cursor's render gate reads `isPointerLockDenied` (`packages/react/src/number-field/scrub-area-cursor/NumberFieldScrubAreaCursor.tsx:41-42`): without a second state emission after the promise settles, the cursor would never mount when the lock is granted asynchronously (the "pointer lock resolves late" scenario, behavior: DOM structure & portal behavior). WebKit is excluded entirely (`platform.engine.webkit` gate) because the pointer-lock notification causes layout shift there (JSDoc at `packages/react/src/number-field/scrub-area-cursor/NumberFieldScrubAreaCursor.tsx:24-25`).
3. **Scrubbing** — the `React.useEffect` at `packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:148-261` attaches window-level capture listeners only while `inputRef.current && !disabled && !readOnly && isScrubbing` (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:151`), so an unrelated window `pointerup` can never commit (behavior: DOM structure & portal behavior). `pointermove` handler (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:198-231`): bails when the ref says no pointer is down, `preventDefault()`s to block text selection, moves the virtual cursor (`onScrub`), and accumulates `movementX`/`movementY` into `cumulativeDelta` selected by `direction` (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:213`). When `|cumulativeDelta| >= pixelSensitivity` the accumulator resets, `didMoveRef` marks real movement, and the value mutates through the root's shared step pipeline: `incrementValue(Math.abs(rawAmount), { direction, event, reason: REASONS.scrub })` (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:215-229`) — feeding behavior: State model and the one-pipeline cross-cutting rule (behavior: Whole-unit cross-cutting behavior). Two subtleties: the vertical axis uses `-movementY` so upward movement increases (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:218`), and the `rawAmount !== 0` guard (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:222`) is what keeps a zero-distance move from firing a step (behavior: Edge cases). `allowInputSyncRef.current = true` before stepping (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:223`) re-arms the root's input-sync flag so the visible text follows scrubbed values (the precondition for the scrub-after-paste continuity, behavior: State model).
4. **Scrubbing → Ended** — window capture `pointerup` handler (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:157-196`). It exits pointer lock (try/catch-swallowed), clears `isScrubbingRef`, emits `onScrubbingChange(false, …)` (which unmounts the cursor and clears root `data-scrubbing`), then commits exactly once: `onValueCommitted(lastChangedValueRef.current ?? valueRef.current, …)` (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:164-169`) — the discrete endpoint of the two-callback model (behavior: State model); the `?? valueRef.current` fallback covers a press that never changed the value. If no movement occurred, a synthetic bubbling `MouseEvent('click')` is dispatched on the captured pointerdown target (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:171-182`), built from `ownerWindow(input).MouseEvent` so the constructor comes from the element's realm. Refs reset (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:184-185`). Gecko gets the same handler deferred 20ms via `useTimeout` (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:189-195`) because Firefox will not release the lock on a synchronous exit after a soft click — the mechanism behind the gecko commit/`data-scrubbing` deferral (behavior: Events). The timeout is cleared in the effect's teardown (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:240`).

**Hooks composition.** `useStableCallback` (`packages/utils/src/useStableCallback.ts:35`) wraps `onScrub` and `onScrubbingChange` (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:82,125`) so the listener effect can depend on them without re-subscribing per render. `useTimeout` (`packages/utils/src/useTimeout.ts:46`) provides the Gecko-deferral timer with automatic unmount disposal. Three plain `React.useEffect`s: the window-listener effect, the unmount-mid-scrub safety net, and the touch-prevent effect. The unmount effect (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:265-278`) checks `isScrubbingRef` and, without committing (there is no pointer release), clears root scrubbing state and exits pointer lock — so an unmount or `<Activity>` hide mid-drag cannot leave the document pointer-locked or the root stuck with `data-scrubbing` (behavior: State model and Edge cases). The touch-prevent effect (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:281-297`) cancels `touchstart` only when `event.touches.length === 1`, matching the single-finger-cancel/two-finger-pass behavior (behavior: Events); combined with the static `touchAction: 'none'` style (see DOM section) it makes single-finger drags scrub instead of scroll.

**Cursor side.** `NumberFieldScrubAreaCursor` uses one local `useState` purely to observe its own DOM node (`domElement`, `packages/react/src/number-field/scrub-area-cursor/NumberFieldScrubAreaCursor.tsx:39`) and otherwise renders through `useRenderElement` with `enabled: shouldRender` (`packages/react/src/number-field/scrub-area-cursor/NumberFieldScrubAreaCursor.tsx:44-56`); when disabled the hook returns `null` (`packages/react/src/internals/useRenderElement.tsx:40-42`), and the `element &&` guard at `packages/react/src/number-field/scrub-area-cursor/NumberFieldScrubAreaCursor.tsx:58` makes the whole component render nothing. The four-condition gate (`isScrubbing && !platform.engine.webkit && !isTouchInput && !isPointerLockDenied`, `packages/react/src/number-field/scrub-area-cursor/NumberFieldScrubAreaCursor.tsx:41-42`) encodes behavior: DOM structure & portal behavior — mouse-only, granted-lock-only, non-WebKit-only rendering.

**Value mutation direction.** ScrubArea never computes a new value itself; it only produces `(amount, direction, reason)` calls into root's `incrementValue` and a single commit call. All parsing/validation/formatting lives in the root unit and is deliberately not re-derived here.

## DOM/portal strategy and why

- **ScrubArea renders inline.** A plain `<span role="presentation">` with hard-coded `SCRUB_AREA_STYLE` — `touchAction: 'none'`, `userSelect: 'none'`, `WebkitUserSelect: 'none'` (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:21-25`, applied at `:301`) — so pointer drags are never hijacked by scrolling or text selection at the style layer. It must stay in the layout flow because it is the interactive hit area users press on (behavior: DOM structure & portal behavior; accessibility rationale in behavior: Accessibility).
- **Cursor renders through a portal to `document.body`.** `ReactDOM.createPortal(element, ownerDocument(domElement).body)` (`packages/react/src/number-field/scrub-area-cursor/NumberFieldScrubAreaCursor.tsx:58`). The virtual cursor is `position: fixed` (`CURSOR_STYLE`, `packages/react/src/number-field/scrub-area-cursor/NumberFieldScrubAreaCursor.tsx:13-18`) and is transformed to follow the OS pointer; portal-ing to the body of the cursor's own owner document keeps it out of any ancestor `overflow`/`transform`/`filter` context that would otherwise clip or distort a fixed-position child (the scrub area routinely lives inside styled demo containers). `ownerDocument(domElement)` rather than the global `document` is the realm/shadow-safe lookup (`packages/utils/src/owner.ts:3-4`). `domElement` is captured by putting the state setter in the cursor's ref list (`packages/react/src/number-field/scrub-area-cursor/NumberFieldScrubAreaCursor.tsx:46`), so the portal container is derived from the actual mounted node rather than assumed. No test asserts portal behavior for either part (behavior: DOM structure & portal behavior, UNVERIFIED note).
- **Cursor positioning is imperative, not layout.** Coordinates are kept in `virtualCursorCoords` and applied as `translate3d(x,y,0) scale(1 / visualViewport.scale)` (`updateCursorTransform`, `packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:75-80`) — inverting the visual-viewport scale so the virtual cursor matches the OS cursor, which does not grow under pinch-zoom (behavior: DOM structure & portal behavior). `pointerEvents: 'none'` on the cursor guarantees the moving virtual cursor never becomes the `pointermove`/click target, which would break the window-level listeners' movement math and the synthetic-click dispatch. The initial position centers the cursor on the pointer (`clientX - offsetWidth/2`, `packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:137-144`), applied inside the flushSync'd `onScrubbingChange` so the cursor is placed before any `pointermove` can arrive.
- **Teleport wrapping.** `onScrub` wraps coordinates at the bounds returned by `getViewportRect(teleportDistance, scrubAreaEl)` (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:90,94-118`): with `teleportDistance` the bounds are the scrub-area rect inflated by half the distance (`packages/react/src/number-field/utils/getViewportRect.ts:7-15`); without it, the visual-viewport offsets or the document element size (`packages/react/src/number-field/utils/getViewportRect.ts:17-33`). The wrap math is half-cursor-size-aware (`offsetWidth/2`, `packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:95-118`) so the cursor's center, not its edge, triggers the teleport (behavior: DOM structure & portal behavior).
- **Listener topology.** Scrub events are attached to `window` with `capture: true` via the typed `addEventListener` (`packages/utils/src/addEventListener.ts:37-62`) and combined with `mergeCleanups` (`packages/utils/src/mergeCleanups.ts:6-15`) so both unsubscribe in one teardown (`packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:233-242`); capture phase ensures the handlers run even if some inner node stops propagation. The touch listener, by contrast, attaches directly to the scrub-area element (non-capture, `packages/react/src/number-field/scrub-area/NumberFieldScrubArea.tsx:294`) because it only cares about touches that begin on the area itself. Clicks are never intercepted — child clicks bubble naturally to ScrubArea's `onClick` (behavior: Events).
