# NumberField steppers (`Increment` / `Decrement`) and `Group` — mined behavior

Behavior proven by `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx` (994 lines), `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx` (572 lines), and `packages/react/src/number-field/group/NumberFieldGroup.test.tsx` (24 lines). All three render parts inside `<NumberField.Root>` and use the shared `#test-utils` harness.

## Public API surface (props, parts, subcomponents)

- `<NumberField.Increment />` and `<NumberField.Decrement />` are native-button parts: conformance is configured with `refInstanceof: window.HTMLButtonElement` and `testComponentPropWith: 'button'`, and the parts are mounted inside `<NumberField.Root>` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:11-18`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:11-18`.
- `<NumberField.Group />` is a `<div>` part: conformance asserts `refInstanceof: window.HTMLDivElement`, also mounted inside `<NumberField.Root>` `packages/react/src/number-field/group/NumberFieldGroup.test.tsx:9-14`.
- Both steppers accept a `disabled` prop that renders the native `disabled` attribute on the button and makes stepping a no-op `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:950-966`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:528-544`.
- Both steppers accept `className` as a function; the render-state object passed to it has a `disabled` boolean that is `true` when either the root or the button itself is disabled `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:968-992`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:546-570`.
- The conformance run for each part executes the four shared suites — prop forwarding, ref forwarding, `render` prop, and string `className` — against that part `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:11-18`, `packages/react/src/number-field/group/NumberFieldGroup.test.tsx:9-14`; the suite keys are defined in the harness `packages/react/test/describeConformance.tsx:44-49` and dispatched per key `packages/react/test/describeConformance.tsx:64-67`.
- Prop forwarding is proven generically for these parts: arbitrary props (`lang`, `data-*`, `style`) reach the default element and elements rendered via function or JSX `render` props `packages/react/test/conformanceTests/propForwarding.tsx:23-36`, `packages/react/test/conformanceTests/propForwarding.tsx:61-80`, `packages/react/test/conformanceTests/propForwarding.tsx:82-95`.
- The `render` prop supports function, JSX element, ref passing, and ref/className merging with the custom element `packages/react/test/conformanceTests/renderProp.tsx:41-59`, `packages/react/test/conformanceTests/renderProp.tsx:93-113`, `packages/react/test/conformanceTests/renderProp.tsx:115-144`, `packages/react/test/conformanceTests/renderProp.tsx:146-161`.
- No `data-*`-specific or style-specific part props are asserted beyond the generic forwarding above (no dedicated tests in these files).

## State model (controlled/uncontrolled, defaults, transitions)

- Empty uncontrolled field: a first click on Increment renders `'0'` in the input `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:29-40`; a first click on Decrement on an empty field also renders `'0'` (the seed step does not additionally move) `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:29-40`.
- With `defaultValue={0}` a click steps to `'1'` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:42-53` or `'-1'` `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:42-53`.
- Empty field in a fully negative range (`min={-10} max={-5}`): the first increment seeds the in-range value nearest 0 (the max, `-5`), not 0 `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:55-65`; with `step={2} snapOnStep` the seed is still `-5`, not the directionally-snapped `-6` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:881-893`.
- Uncontrolled stepping uses numeric state, not rounded display text: `defaultValue={1.23456}` displays `(1.23456).toLocaleString()` and one click emits `onValueChange(2.23456)` and displays `(2.23456).toLocaleString()` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:90-108`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:78-96`.
- Typed precision is kept after blur formatting: type `1.23456`, blur (display becomes localized), then successive clicks emit `2.23456` then `3.23456` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:110-135`.
- Controlled value updated externally mid-flight: after `setValue(1.23456)` from outside, the next click steps from it (`2.23456` / `0.23456`) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:67-88`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:55-76`.
- `onValueChange` is called exactly once per click `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:258-274`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:142-158`.
- Precision guarantees: a `step` of `0.0001` emits `0.0001` then `0.0002` even though the input displays the rounded `'0'` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:137-169`; `0.7 + 0.1` commits exactly `0.8` (binary floating-point noise cleaned) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:171-185`; large fractional values are preserved when stepping (`100000000000000.1 + 0.1` emitted exactly) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:187-212`.
- `snapOnStep={false}` steps by the exact step without rounding: `2.7` with `step={2}` → `4.7` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:843-855`, `0.7` `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:447-459`.
- `snapOnStep` (explicitly `true`): an increment from an off-grid value lands on the next step-grid multiple above the current value — `1.3 → 2`, dirty `1.9 → 2`, dirty `-0.2 → 0` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:857-879`; the mirror decrement lands on the next grid multiple below — `1.3 → 1`, dirty `1.9 → 1`, dirty `-0.2 → -1` `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:461-483`.
- Grid is anchored at `min` when stepping with `snapOnStep`: `min={1} step={2}` increment `1 → 3 → 5`, dirty `1.112 → 3`, dirty `0.999 → 1` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:895-919`; decrement from `8`: `8 → 7 → 5`, dirty `9.112 → 9`, dirty `1.112 → 1` `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:485-509`.
- Committing dirty text before a step is never itself snapped: with `step={2} snapOnStep` and dirty text `'7'`, no intermediate `6` is emitted and the result is `'8'` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:821-841`.
- Whether `snapOnStep` defaults to true or false is not proven by these files.
- readOnly root: clicks on either stepper change nothing and the input stays `''` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:628-639`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:348-359`.
- Disabled root: clicks are no-ops with zero `onValueChange` calls `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:935-948`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:513-526`; a disabled stepper button blocks even `pointerdown` starting a hold `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:950-966`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:528-544`.
- Commit model: a click commits immediately (`onValueCommitted` called once with the stepped value, e.g. `1` / `-1`) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:243-245`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:127-129`; during a hold nothing commits until release — `onValueCommitted` fires once on `pointerup` with the final boundary value `10` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:427-451`.

## Keyboard interactions

- No test in these three files fires real key events (no `keydown`, no Space/Enter simulation) on the steppers or the Group.
- The keyboard/AT activation path is only modeled indirectly: a `click` that arrives without a preceding `pointerdown` (the comment says "A keyboard/AT activation reaches `onClick` without a preceding `pointerdown`") still triggers the dirty-input sync + step pipeline `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:703-732`, with the modeling note at `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:723-724`.
- Space/Enter native button activation semantics are UNVERIFIED — inferred from `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:11-18` (ref is a native `HTMLButtonElement`), no test asserts key-based activation in these files.
- Arrow-key stepping on the input is not covered here (that scope lives in the Root/Input tests, outside this batch).

## Focus management

- A mouse `pointerdown` (primary button) on Increment moves focus to the input and places the caret at the end: `document.activeElement` is the input and `selectionStart`/`selectionEnd` equal `value.length` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:734-750`.
- A `pen` pointerdown does not focus the input ("treats pen pointer as touch-like": `document.activeElement` is not the input) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:752-766`.
- Stepping while the input is focused but dirty commits the dirty text as part of the step: type `'100'` without blurring, then click or `pointerdown` on Increment → `'101'` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:641-675`; on Decrement → `'99'` `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:361-395`.
- Disabling mid-hold and re-enabling does not restore focus or resume stepping; the value stays frozen `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:318-344`.
- No tests assert focus restoration to the stepper button after release, focus trapping, or blur-on-disable.

## Events (names, payload shape, bubbling, preventDefault semantics)

- `click`: steps exactly once per click and calls `onValueChange` once `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:258-274`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:142-158`; it also commits (`onValueCommitted` once with the stepped value) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:243-245`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:127-129`.
- `pointerdown` (primary button): performs the first step immediately and starts hold auto-repeat — value `1` on press, then one step per tick after the `START_AUTO_CHANGE_DELAY` warm-up, with each tick spaced by `CHANGE_VALUE_TICK_DELAY` (both constants imported into the tests) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:288-316`, `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:6`; mirrored for Decrement (`-1` → `-4`) `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:163-191`. The press-and-hold suites run under fake timers (`clock.withFakeTimers()`) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:277`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:161`.
- Non-primary pointer buttons are ignored entirely: a middle-button (`button: 1`) `pointerdown` neither syncs dirty input text nor starts a hold (`onValueChange` not called, display keeps `'100'`) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:677-701`.
- `pointerup`: stops auto-repeat (a trailing tick after release does not change the value) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:311-315`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:186-190`, and triggers the single commit after a hold `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:427-451`.
- `mouseleave` while the pointer is still held pauses auto-repeat `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:519-547`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:239-267`; a subsequent `mouseenter` resumes it (value continues to `5` / `-5`) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:549-583`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:269-303`; after `pointerup`, `mouseleave`/`mouseenter` no longer resume stepping `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:585-625`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:305-345`.
- Touch: the quick-tap sequence `touchStart` → (`mouseEnter`) → `pointerDown(touch)` → `click(detail: 1)` → `touchEnd` always steps exactly once, including a second tap with no `mouseenter` (test title: "touchend that occurs before TOUCH_TIMEOUT") `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:768-794`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:397-423`.
- Soft tap on touch (Chromium-only, `it.skipIf(isJSDOM)`): `touchStart`/`pointerDown(touch)`/`touchEnd`/`mouseEnter`/`click(detail: 1)` fires `onValueCommitted` exactly once with `1` (Increment) or `-1` (Decrement) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:796-818`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:425-444`.
- `onValueChange` payload: `(nextValue: number, details)` where `details.cancel()` vetoes the change `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:221-237`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:105-121`.
- Veto semantics: a canceled synced step still runs the step from the previously stored value and reports it — with dirty text `'100'` and an always-canceling `onValueChange`, the recorded calls are `[100, 100, 1]`, the typed display `'100'` is left untouched, and `onValueCommitted` is never called `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:703-732`.
- No bubbling, `stopPropagation`, or `preventDefault` assertions exist in these files.

## Edge cases (rapid interactions, unmount, nesting)

- Rapid double-fire guard: `pointerdown` + `pointerup` + `click(detail: 1)` steps the value exactly once (`'1'` / `'-1'`), not twice `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:501-517`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:221-237`.
- Unmount during an active hold removes the window-level `pointerup` release listener `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:366-397`.
- Disabling mid-hold cancels the active repeat: after `setProps({ disabled: true })`, ticks leave the value at `'1'`, and re-enabling plus `mouseleave`/`mouseenter` does not resume it `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:318-344`.
- Disabling between a touch press and release cancels the compatibility click: after disable/enable, `pointerup`/`touchEnd`/`mouseEnter`/`click(detail: 1)` leaves the value `'0'` `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:346-364`.
- Boundary clamping during hold: from `defaultValue={9} max={10}`, the press steps to `'10'` once and further ticks emit no more `onValueChange` calls (Increment) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:399-425`; mirrored at `min` for Decrement (`defaultValue={-9} min={-10}` → `'-10'`, one call) `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:193-219`; the pending commit still fires on release with the boundary value `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:427-451`.
- Stale-commit prevention: after a committed step populates the internal last-changed value (`1` / `-1`) and the controlled value changes externally to `10`, canceling the next step must not commit the stale earlier value — `onValueCommitted` call count stays at 1 `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:214-256`, `packages/react/src/number-field/decrement/NumberFieldDecrement.test.tsx:98-140`; the hold variant with dirty input (`'-'` typed) commits `10`, not the dirty/step value `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:453-499`.
- Numeric edge cases: sub-0.001 step precision `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:137-169`, floating-point noise cleanup (`0.7 + 0.1 → 0.8`) `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:171-185`, and preservation of large fractional values `packages/react/src/number-field/increment/NumberFieldIncrement.test.tsx:187-212` are all increment-file-only (no decrement equivalents).
- Nesting: no nesting tests exist in these files; the only composition tested is the conformance render-prop wrapping via the harness `packages/react/test/conformanceTests/renderProp.tsx:27-38`.
