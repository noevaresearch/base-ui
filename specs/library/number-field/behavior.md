# NumberField — behavior spec (unit index)

Behavior mined from test files only (`packages/react/src/number-field/**/*.test.{ts,tsx}`), batched by subdirectory into `parts/*.md`. This file is the index and whole-unit synthesis; the parts files carry the depth. NumberField is first-party (its `TODO.md` entry has no `wraps-external:` field), so nothing is delegated to an external package.

Batches: `parts/root.md` (Root + iOS-gated tests), `parts/input.md` (Input), `parts/stepper-group.md` (Increment/Decrement/Group), `parts/scrub.md` (ScrubArea/ScrubAreaCursor incl. Gecko variant), `parts/utils.md` (parse/validate/getViewportRect).

## Public API surface (props, parts, subcomponents)

`NumberField.Root` renders a `div` and composes `Group` (a `div` with `role="group"`), `Input` (native `<input>`, role `textbox`), `Increment`/`Decrement` (native `<button>`s named "Increase"/"Decrease"), and `ScrubArea` (a `span` with `role="presentation"`, hosting a `ScrubAreaCursor` `span`) (`specs/library/number-field/parts/root.md:5-14`, `specs/library/number-field/parts/stepper-group.md:5-14`, `specs/library/number-field/parts/scrub.md:5-12`). Root props exercised by tests: `defaultValue`/`value`/`onValueChange`/`onValueCommitted`, `disabled`, `readOnly`, `required`, `name`, `min`, `max`, `allowOutOfRange`, `step`, `snapOnStep`, `largeStep` (default 10), `smallStep` (default 0.1), `format` (`Intl.NumberFormatOptions`), `locale`, `inputMode`, `allowWheelScrub`, `form`, `render`, `className` (`specs/library/number-field/parts/root.md:9-14`, `specs/library/number-field/parts/root.md:25`). ScrubArea adds `pixelSensitivity`, `teleportDistance`, and `direction` (`specs/library/number-field/parts/scrub.md:9`); steppers take `disabled` and a className render-state with `disabled` (`specs/library/number-field/parts/stepper-group.md:9-10`). Context misuse errors are asserted: `Input` outside `Root` and `ScrubAreaCursor` outside `ScrubArea` both throw (`specs/library/number-field/parts/input.md:7`, `specs/library/number-field/parts/scrub.md:12`). Every part passes the shared conformance suites (prop spread, ref forwarding, `render` prop, className); the private utils `parseNumber`/`getNumberLocaleDetails`/`isNumeralChar`/`removeFloatingPointErrors`/`toValidatedNumber`/`getViewportRect` have pinned signatures (`specs/library/number-field/parts/utils.md:5-14`).

## State model (controlled/uncontrolled, defaults, transitions)

The value contract is `number | null`; `value`/`defaultValue` work controlled and uncontrolled, whitespace-only text reports `null`, and controlled transitions fire `onValueChange` once per `null → number` / `number → null` (`specs/library/number-field/parts/root.md:18-21`). A two-callback commit model runs everywhere: `onValueChange` fires for every parseable change while typing (and per scrub/hold/wheel tick); `onValueCommitted` fires only at discrete endpoints — blur, each keyboard step, stepper click, hold release, each wheel tick, scrub pointerup (`specs/library/number-field/parts/root.md:22`, `specs/library/number-field/parts/input.md:24-25`, `specs/library/number-field/parts/stepper-group.md:33`, `specs/library/number-field/parts/scrub.md:17`). Clamping is split-phase: while typing, the visible text keeps the raw input but the value contract reports the clamped number, and blur commits the clamped value and rewrites the text (`specs/library/number-field/parts/root.md:26-28`). `allowOutOfRange` trades typing-clamp for native `rangeOverflow` form validation, while steppers/wheel still clamp (`specs/library/number-field/parts/root.md:27`). `snapOnStep` snaps step travel to the step grid (min-anchored, direction-relative) but never applies to blur commits or dirty-text commits (`specs/library/number-field/parts/root.md:24`, `specs/library/number-field/parts/input.md:20`, `specs/library/number-field/parts/stepper-group.md:27-29`). The numeric state keeps full precision independent of the rounded display text (`specs/library/number-field/parts/input.md:40-41`, `specs/library/number-field/parts/stepper-group.md:21`). The validation pipeline ordering proven by the utils is: snap to step → floating-point cleanup → format-aware rounding (percent at display scale, honoring `roundingMode`/`roundingIncrement`/significant digits) → clamp, with a clamp pass *before* rounding for non-integer bounds and clamping *after* snapping so non-step-aligned min/max are reachable; `clamp: false` keeps values out of range on purpose (`specs/library/number-field/parts/utils.md:16-27`). Scrub state lives on the Root as `data-scrubbing`, cleared on pointerup, mid-scrub unmount, and Activity hide (`specs/library/number-field/parts/scrub.md:16-22`).

## Keyboard interactions

On the input: ArrowUp/ArrowDown step by `step` and commit per press; Alt applies `smallStep` (with `snapOnStep` snapping); Home/End jump to `min`/`max` and commit, but are NOT preventDefault-ed (native caret movement preserved) when `min`/`max` are absent; Backspace/Delete/ArrowLeft/ArrowRight/Tab/Enter and IME composition (keyCode 229) are never preventDefault-ed (`specs/library/number-field/parts/root.md:36-42`, `specs/library/number-field/parts/input.md:36-40`). Character gating is locale/format-aware: `%`/`‰` are default-prevented outside percent format; de-DE allows one `,` (a second is blocked) and repeated grouping `.`; pl-PL space grouping is preserved verbatim; a duplicate sign is blocked unless the existing sign or the whole value is selected; unicode minus/plus/permille/fullwidth digits are accepted in percent mode (`specs/library/number-field/parts/input.md:45-49`). Steppers have no direct keyboard tests — the keyboard/AT path is modeled only as a `click` without a preceding `pointerdown`, which still runs the full step pipeline; native Space/Enter activation is UNVERIFIED (`specs/library/number-field/parts/stepper-group.md:35-40`). Utils: N/A (`specs/library/number-field/parts/utils.md:29-31`).

## Focus management

Focus funnels to the visible input: focusing the hidden native input forwards focus to the visible textbox with the caret at the end (a consumer `onFocus` selection such as `.select()` is preserved); a primary-button `pointerdown` on a stepper focuses the input (pen does not); a mouse `pointerdown` on ScrubArea focuses the input (selection preserved); wheel scrubbing requires focus (`specs/library/number-field/parts/root.md:49-53`, `specs/library/number-field/parts/stepper-group.md:44-45`, `specs/library/number-field/parts/scrub.md:30`). `data-focused` tracks focus cycles including readOnly (`specs/library/number-field/parts/root.md:51`), and Base UI Form server errors focus the input and set `aria-invalid` (`specs/library/number-field/parts/root.md:52`). Preventing the native `focus`/`blur` default suppresses Field focus/touched marking and the entire blur commit/reformat path (`specs/library/number-field/parts/input.md:55-56`). Select-on-focus forcing: UNVERIFIED — the only selection test proves the browser-set selection is preserved (`specs/library/number-field/parts/input.md:57`).

## Accessibility (roles, aria-*, id linking)

The editable input is role `textbox`; a hidden `input[type=number][aria-hidden]` mirrors the value for forms and autofill (`specs/library/number-field/parts/root.md:57-58`). Steppers are `button`s named "Increase"/"Decrease" with `aria-controls` linking to the input id; under readOnly they get `aria-disabled="true"` but never `aria-readonly` (invalid on button role) (`specs/library/number-field/parts/root.md:59-60`, `specs/library/number-field/parts/stepper-group.md:52-53`). `Group` renders `role="group"`; `ScrubArea` is `role="presentation"` (the cursor's own role: UNVERIFIED) (`specs/library/number-field/parts/stepper-group.md:55`, `specs/library/number-field/parts/scrub.md:34-35`). Validation surfaces as `aria-invalid="true"` (native submit, Form server errors, Field validate/revalidate); Field integration links `Field.Label` via `for` and appends `Field.Description` to `aria-describedby` (`specs/library/number-field/parts/root.md:63-64`). Field state attributes (`data-touched`, `data-dirty`, `data-filled`, `data-focused`, `data-invalid`/`data-valid`) are asserted on Root/Input (`specs/library/number-field/parts/root.md:65`). `inputmode` is `numeric` by default; on iOS it widens to `decimal` when negatives are impossible and `text` otherwise (`specs/library/number-field/parts/root.md:31-32`). No `aria-valuenow`/`aria-valuemin`/`aria-valuemax` or spinbutton-role assertions exist anywhere (Input aria: UNVERIFIED beyond the above) (`specs/library/number-field/parts/input.md:63`).

## DOM structure & portal behavior

Composition is `Root` (div) > `Group` (div) > `Input` + `Increment`/`Decrement` (buttons) + `ScrubArea` (span); the hidden `input[type=number]` carries `name` (and `readonly` under readOnly) and is reachable from `document`, though its exact position relative to the Root is not asserted (`specs/library/number-field/parts/root.md:70-71`, `specs/library/number-field/parts/stepper-group.md:60`). Portal behavior: N/A — no portal assertions in any batch; all parts render inline (`specs/library/number-field/parts/root.md:73`, `specs/library/number-field/parts/input.md:69`, `specs/library/number-field/parts/scrub.md:53`). During a scrub, `pointermove`/`pointerup` listeners attach to `window` with capture and are removed on scrub end; during a stepper hold a `{ once: true }` window `pointerup` listener is registered and removed on unmount (`specs/library/number-field/parts/scrub.md:63`, `specs/library/number-field/parts/stepper-group.md:61`). The cursor element exists only while scrubbing with a mouse after granted pointer lock, is unmounted on pointerup, and is positioned via `style.transform` that compensates `visualViewport.scale` and wraps within `getViewportRect` teleport bounds (`specs/library/number-field/parts/scrub.md:41-52`, `specs/library/number-field/parts/utils.md:45-49`).

## Events (names, payload shape, bubbling, preventDefault semantics)

`onValueChange(value, details)` and `onValueCommitted(value, details)` carry a `reason` string; asserted reasons are `'input-change'`, `'input-clear'`, `'keyboard'`, `'increment-press'`, `'decrement-press'`, `'wheel'`, `'input-paste'` (`specs/library/number-field/parts/root.md:77-78`, `specs/library/number-field/parts/input.md:74`). `details.cancel()` vetoes the change (text stays at the old value) and suppresses the paired `onValueCommitted`, for keyboard steps, blur commits, and synced stepper steps alike; validation still runs on a canceled autofill (`specs/library/number-field/parts/root.md:79`, `specs/library/number-field/parts/input.md:76`, `specs/library/number-field/parts/stepper-group.md:73-74`). Wheel semantics: a vertical-dominant wheel over a focused input is canceled and scrubs (deltaY > 0 decrements), horizontal-dominant/zero/`ctrlKey` (pinch) wheels pass through un-canceled, Shift applies `largeStep` including Chromium axis-swap noise handling (`specs/library/number-field/parts/root.md:81-82`). Stepper pointer model: `pointerdown` (primary only) steps immediately and starts hold auto-repeat (`START_AUTO_CHANGE_DELAY` warm-up, `CHANGE_VALUE_TICK_DELAY` ticks); `pointerup` stops and commits once; `mouseleave`/`mouseenter` pause/resume an active hold but never after `pointerup`; `pointerdown`+`click` double-fires are guarded to one step; touch taps step exactly once (`specs/library/number-field/parts/stepper-group.md:66-72`). Scrub pointer model: non-primary buttons ignored; single-touch `touchstart` is canceled, two-finger gestures are not; movement after `pointerup` is ignored (except Gecko, which defers the pointer-lock release ~20ms so commit/`data-scrubbing` clear only after a 20ms tick); child clicks bubble to ScrubArea's `onClick` (`specs/library/number-field/parts/scrub.md:58-66`). Consumer-side `preventDefault` on Input `focus`/`blur`/`change`/`keydown` gates focus marking, blur commit/reformat/touch, change processing, and stepping respectively; an unreadable clipboard warns once ("Base UI: <NumberField.Input> could not read clipboard text…") without preventing the paste (`specs/library/number-field/parts/input.md:77-82`). Bubbling of component-emitted events: no assertions (UNVERIFIED) (`specs/library/number-field/parts/input.md:83`).

## Edge cases (rapid interactions, unmount, nesting)

Typing/parsing is tolerant of exotic locales while the raw text stays visible: Persian/Arabic-Indic/fullwidth/Han numerals (typed and pasted, reason `'input-paste'`), trailing unicode minus, collapsed extra dots, multi-char currency/unit symbols, bidi control chars, scientific `1.5E3`; accounting parentheses are rejected (`specs/library/number-field/parts/root.md:90-94`, `specs/library/number-field/parts/utils.md:59-99`). Paste replaces the selection and inserts at the caret with the caret left after the pasted text; invalid paste is ignored without firing callbacks; paste is blocked under readOnly (`specs/library/number-field/parts/root.md:94`). Autofill flows through the hidden input (applied or cleared), ignored when readOnly/disabled (`specs/library/number-field/parts/root.md:72,95`). Form integration: FormData carries the raw unformatted value, `step` mismatches block submission via native `stepMismatch`, `step="any"` never mismatches, and `allowOutOfRange` exposes `rangeOverflow`; Form/Field validation lifecycle (submit/onChange/onBlur modes, clamped blur values, error clearing on change) is covered (`specs/library/number-field/parts/root.md:96-97`). Rapid/interleaved interactions: external value changes during typing replace dirty text; canceled steps after external changes never commit stale values; no-op steps at boundaries fire no callbacks; hold commits exactly once even with mouseleave/mouseenter during the hold (`specs/library/number-field/parts/root.md:87-89`, `specs/library/number-field/parts/input.md:87-91`, `specs/library/number-field/parts/stepper-group.md:79-84`). Scrub accumulation handles direction reversals, sub-threshold `pixelSensitivity` accumulation, `teleportDistance` cursor wrap, and per-direction axis gating; unmount mid-scrub and Activity hide/show clear scrub state; headless pointer lock is stubbed in tests (`specs/library/number-field/parts/scrub.md:68-78`). Unmount during a stepper hold removes the window listener; disabling mid-hold cancels repeat permanently and cancels the touch compatibility click (`specs/library/number-field/parts/stepper-group.md:80-82`). NumberField-in-NumberField nesting: no tests (N/A) (`specs/library/number-field/parts/root.md:101`). Utils edge cases include the floating-point delta cap (a single ULP above ~2^19 exceeds it, so large magnitudes are left un-cleaned), Infinity-like inputs parsing to null, and `MAX_VALUE` percent overflow guards (`specs/library/number-field/parts/utils.md:98-110,128`).

## Whole-unit cross-cutting behavior

- **One validation pipeline feeds every mutation source.** Typing, paste, stepper click/hold, keyboard steps, wheel scrub, drag scrub, and hidden-input autofill all converge on parse → validate (snap → round → clamp, with clamp passes on both sides of rounding) → format; `parts/utils.md` pins the ordering and each parts file pins its source-specific entry point (`specs/library/number-field/parts/utils.md:21-27`, `specs/library/number-field/parts/root.md:22-28`, `specs/library/number-field/parts/stepper-group.md:18-33`, `specs/library/number-field/parts/scrub.md:14-22`).
- **Two-callback commit model with a cancel veto.** Continuous mutations emit `onValueChange`; discrete endpoints emit `onValueCommitted`; `details.cancel()` on `onValueChange` reverts/skips and suppresses the paired commit everywhere it is tested (`specs/library/number-field/parts/root.md:22,79`, `specs/library/number-field/parts/input.md:24-25,76`, `specs/library/number-field/parts/stepper-group.md:74`).
- **Dirty-input authority vs full-precision numeric state.** Typed text outranks stale numeric state for step travel and blur commit; stepping math uses full-precision numeric state, never the rounded display text (`specs/library/number-field/parts/input.md:22-23,40-41`, `specs/library/number-field/parts/stepper-group.md:46`).
- **`snapOnStep` is travel-only.** It snaps step travel (buttons, keyboard, scrub) directionally onto the min-anchored step grid, but never snaps dirty-text commits or blur (`specs/library/number-field/parts/stepper-group.md:27-29`, `specs/library/number-field/parts/input.md:20`, `specs/library/number-field/parts/utils.md:135-143`).
- **`readOnly` suppresses mutation, never focus.** Input gets `readonly`, stepper clicks/wheel/scrub/autofill/paste are no-ops, yet focus and `data-focused` tracking continue; `disabled` additionally blocks pointerdown holds and propagates from `Field.Root` (`specs/library/number-field/parts/root.md:60,99`, `specs/library/number-field/parts/stepper-group.md:31-32`, `specs/library/number-field/parts/scrub.md:18`).
- **Focus routing converges on the visible input.** Hidden-input focus forwarding, stepper mouse press, and scrub pointerdown all move focus to the input (caret at end, consumer selection preserved); wheel requires focus (`specs/library/number-field/parts/root.md:49-53`, `specs/library/number-field/parts/stepper-group.md:44`, `specs/library/number-field/parts/scrub.md:30`).
- **Display vs value locale split.** Visible text is locale-formatted only on blur/commit (never while focused); the numeric contract keeps full precision; percent style scales (parse ÷100, round at display scale) while unit-percent and currency do not (`specs/library/number-field/parts/input.md:18,31,94-95`, `specs/library/number-field/parts/utils.md:62-69,122-129`).
- **Explicit platform gating.** iOS widens `inputmode` (decimal vs text), Gecko defers scrub commit by a 20ms pointer-lock release tick, and pointer-lock mechanics are skipped in jsdom/WebKit with stubs in Chromium (`specs/library/number-field/parts/root.md:32,66`, `specs/library/number-field/parts/scrub.md:66,80-84`).
