## State model (controlled/uncontrolled, defaults, transitions)

- `Toolbar.Root` carries no value-like controlled/uncontrolled state in the tested surface; `orientation` is a plain prop relayed through context — a consumer inside `<Toolbar.Root orientation="vertical">` reads `'vertical'` (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:35-42`).
- Disabled state cascades from the root through context: with `<Toolbar.Root disabled>`, every button and input (including ones nested in a `Toolbar.Group`) gets `aria-disabled="true"` and `data-disabled`; the group element itself gets `data-disabled`; links get neither attribute (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:141-153`).
- `Toolbar.Group disabled` cascades the same way to items inside the group only (`packages/react/src/toolbar/group/ToolbarGroup.test.tsx:61-67`).
- Disabled presentation is non-native by default: a disabled `Toolbar.Button` has NO native `disabled` attribute but has `data-disabled` + `aria-disabled="true"` (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:149-151`); same for inputs (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:318-320`).
- `focusableWhenDisabled={false}` switches to the native `disabled` attribute and drops `aria-disabled` (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:171-173`).
- Disabled-ness is reactive across renders: `setProps({ disabled: false })` flips a `Toolbar.Input` from click-blocking to click-focusable (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:65-77`) and from click-default-preventing to checking a checkbox (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:89-97`).
- Roving tabindex state lives at the composite level: exactly one item holds `tabindex="0"` at a time and the stop migrates with arrow navigation; a natively disabled first item cannot hold the single tab stop, which moves to the next item (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:198`, `packages/react/src/toolbar/root/ToolbarRoot.test.tsx:262-264`).
- State of components rendered via `render` is that component's own: a rendered `Toggle`'s `aria-pressed` flips per activation, a `ToggleGroup` supports uncontrolled (`defaultValue`) and controlled (`value` + `onValueChange`) value state, and its default (non-`multiple`) selection is exclusive — selecting another value replaces the previous one (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:1043-1083`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:1114-1142`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:1144-1169`).

## Keyboard interactions

- Arrow keys move focus through ALL toolbar items in flat DOM order (button → link → group children → input), skipping nothing focusable by default. Direction/orientation matrix proven for: LTR+horizontal (`ArrowRight` next / `ArrowLeft` prev), LTR+vertical (`ArrowDown`/`ArrowUp`), RTL+horizontal (`ArrowLeft` next / `ArrowRight` prev), RTL+vertical (`ArrowDown`/`ArrowUp` — vertical navigation is not direction-flipped) (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:46-100`).
- `Tab` enters the toolbar focusing the first item (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:74-75`).
- Wrapping: navigation loops by default — the next key after the last item returns focus to the first, and the previous key from the first item lands on the last (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:89-97`). With `loopFocus={false}`, focus stops at both ends instead of wrapping (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:102-123`).
- Text-input caret handling in horizontal toolbars: arrow keys first move the caret/selection inside the input; focus only leaves the input when the caret is at the corresponding text boundary — the "next" key at the trailing boundary (value end for LTR-`ArrowRight` / RTL-`ArrowLeft`), the "previous" key at the leading boundary. `Shift`+arrow while a selection is active does NOT move focus (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:101-147`).
- Vertical orientation: `ArrowDown`/`ArrowUp` move focus in/out of the input while `ArrowLeft`/`ArrowRight` stay inside it (caret movement); arrowing into the input selects its whole value (`selectionStart` 0, `selectionEnd` 4 for value `"abcd"`) (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:169-190`, `packages/react/src/toolbar/input/ToolbarInput.test.tsx:176-177`).
- `Enter` and `Space` activate a `Toolbar.Button`, dispatching real click events (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:86-92`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:119-125`).
- Composite popups opened from a `Toolbar.Button` handle their own keys while open: Menu — `Enter` opens, `ArrowDown`/`ArrowUp` move items, `Escape` closes (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:376-408`); Select — `ArrowDown` opens and focuses the selected option, `Enter` commits and closes (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:509-533`); Dialog/AlertDialog/Popover — `Enter` opens, `Escape` closes (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:628-644`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:749-765`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:869-883`).
- Toolbar arrow navigation does not steal composite keydowns while focus is inside a nested composite popup: pressing `ArrowRight` while a Dialog/AlertDialog popup (opened from a `Toolbar.Button` trigger) holds focus does not move toolbar focus to the next item (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:681-708`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:802-829`).
- `Tab` from a disabled input exits the toolbar entirely instead of being trapped on it (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:219-224`).
- `ArrowUp`/`ArrowDown` on a rendered `NumberField.Input` increment/decrement the value (5 → 6 → 5) rather than navigating the horizontal toolbar (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:293-299`).

## Focus management

- Roving tabindex across all items with a single tab stop; initially the first item (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:74-75`).
- Disabled items remain keyboard-focusable by default (root-level default `focusableWhenDisabled` is true): disabled buttons and a disabled input are all reachable via arrow navigation and receive focus (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:184-204`).
- A natively disabled first item cannot hold the roving tab stop — the stop lands on the next enabled item, and looping back around skips the disabled item (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:251-275`).
- Individually setting `focusableWhenDisabled={false}` makes that item natively disabled and it is skipped during arrow navigation, whether it is a button (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:207-249`) or an input (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:299-317`).
- An ENABLED item with `focusableWhenDisabled={false}` stays fully navigable — the prop only changes disabled-state handling (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:277-297`).
- Pointer focus: clicking a disabled input does not steal focus from the current item; clicking the enabled input focuses it (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:65-77`).
- Closing a Menu, Select, Dialog, AlertDialog, or Popover that was opened from a `Toolbar.Button` returns focus to the trigger (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:410-412`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:528-530`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:642-644`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:763-765`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:881-883`).
- In a vertical toolbar, arrow navigation still moves focus past a disabled input in both directions (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:243-254`).

## Accessibility (roles, aria-*, id linking)

- `Toolbar.Root` has `role="toolbar"` (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:18-22`).
- `Toolbar.Group` exposes `role="group"` (`packages/react/src/toolbar/group/ToolbarGroup.test.tsx:45`) and is marked `data-disabled` when disabled (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:148`).
- Disabled-state ARIA convention: `aria-disabled="true"` + `data-disabled` (no native `disabled`) for buttons (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:149-151`), inputs (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:319-320`), group items (`packages/react/src/toolbar/group/ToolbarGroup.test.tsx:61-64`), and rendered Switch/Menu/Select/Dialog/Popover triggers (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:305-307`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:441-443`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:563-565`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:666-668`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:787-789`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:904-906`).
- Links are exempt from toolbar disabling: no `aria-disabled`, no `data-disabled` (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:150-153`, `packages/react/src/toolbar/group/ToolbarGroup.test.tsx:66-67`).
- `aria-haspopup` comes from the rendered trigger component through `Toolbar.Button`: `'menu'` for `Menu.Trigger` (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:345`), `'listbox'` for `Select.Trigger` (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:481`), `'dialog'` for `Popover.Trigger` (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:848`).
- `aria-pressed` is present on `Toggle`-rendered buttons and mirrors toggle state (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:933-935`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:962-982`).
- `Toolbar.Input` rendering `NumberField.Input` carries `aria-roledescription="Number field"` (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:270`).
- `Toolbar.Separator` has role `separator` with `aria-orientation` perpendicular to the toolbar's orientation by default: horizontal toolbar → `aria-orientation="vertical"`, vertical toolbar → `"horizontal"` (`packages/react/src/toolbar/separator/ToolbarSeparator.test.tsx:14-31`).
- Dev-only semantic warnings: rendering a non-`<button>` (e.g. `Switch.Root`) via `render` while `nativeButton` is true logs the "A component that acts as a button expected a native <button>…" error; rendering a `<button>` while `nativeButton` is false logs the inverse error (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:215-223`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:580-586`).
- No `id` linking, `aria-controls`, or `aria-orientation` on the root itself is asserted anywhere in the suite.

## DOM structure & portal behavior

- `Toolbar.Root` renders a `div` (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:13`); `Toolbar.Group` renders a `div` that wraps its children in normal DOM order (`packages/react/src/toolbar/group/ToolbarGroup.test.tsx:25`, `packages/react/src/toolbar/root/ToolbarRoot.test.tsx:62-65`).
- `Toolbar.Button` renders a native `<button>` by default (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:34`); with `nativeButton={false}` and `render={<span/>}` it renders the span but keeps button semantics (found via `getByRole('button', { name: 'Save' })`) (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:72`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:81`).
- `Toolbar.Input` renders an `<input>` (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:29`); `Toolbar.Link` renders an `<a>` (`packages/react/src/toolbar/link/ToolbarLink.test.tsx:25`); `Toolbar.Separator` renders a `div` with `role="separator"` (`packages/react/src/toolbar/separator/ToolbarSeparator.test.tsx:10`, `packages/react/src/toolbar/separator/ToolbarSeparator.test.tsx:26-29`).
- N/A — portal behavior: popups opened from toolbar items (`Menu.Portal`, `Select.Portal`, `Dialog.Portal`, `Popover.Portal`) render through those components' own portals, and the toolbar has no portal-related behavior of its own asserted anywhere (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:332-341`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:467-475`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:596-602`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:838-843`).

## Events (names, payload shape, bubbling, preventDefault semantics)

- `Toolbar.Root` and `Toolbar.Group` expose no event callbacks in the tested surface; all events are per-item DOM handlers plus the rendered components' own callbacks.
- A disabled `Toolbar.Button` never fires `onClick`, `onMouseDown`, `onPointerDown`, or `onKeyDown` — zero calls across click, `Space`, and `Enter` (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:153-159`) — while hover handlers (`onMouseMove`) still fire on it (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:192-198`).
- With `nativeButton={false}`, `Space`/`Enter` activation synthesizes a real click that runs the custom element's capture and bubble handlers AND bubbles to an ancestor `<div onClick>` — one call each (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:88-91`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:121-124`).
- A `Switch.Root` rendered via `Toolbar.Button` fires its `onCheckedChange` and the button's `onClick` once per activating interaction — click, `Enter`, and `Space` each toggle it (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:260-273`); when disabled, none fire (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:313-322`).
- A `Menu.Trigger` rendered via `Toolbar.Button` fires `onClick` and `onOpenChange(true)` on `Enter`, and `onOpenChange(false)` on `Escape` (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:379-408`).
- A `Select.Trigger` rendered via `Toolbar.Button` fires `onValueChange` once per commit with the picked value as first arg — `('b', <event-like>)` (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:512-533`).
- `Dialog`/`AlertDialog`/`Popover` triggers fire `onOpenChange(true, event)` on open and `onOpenChange(false, event)` on `Escape` close (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:632-640`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:753-761`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:873-880`).
- A `Toggle` rendered via `Toolbar.Button` fires `onPressedChange` once per `Enter`/`Space`/click activation (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:962-981`); disabled ones never fire (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:1018-1040`).
- A direct `ToggleGroup` inside `Toolbar.Root` fires `onValueChange` with the full value array: exclusive mode REPLACES the previous value (`['one']` → `['three']`), `multiple` mode appends (`['one', 'two']`) (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:1077-1082`, `packages/react/src/toolbar/button/ToolbarButton.test.tsx:1138-1141`).
- A disabled `Toolbar.Input` prevents the click's default action: a `type="checkbox"` input stays unchecked after click while disabled, then checks normally when enabled (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:80-98`).
- A rendered `NumberField.Input` fires `onValueChange(6)` then `onValueChange(5)` for `ArrowUp`/`ArrowDown` (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:293-299`); disabled, it fires nothing (`packages/react/src/toolbar/input/ToolbarInput.test.tsx:326-328`).
- No bubbling/preventDefault semantics are asserted for any toolbar-owned custom event — the toolbar defines none; every event above belongs to the items or their rendered components.

## Edge cases (rapid interactions, unmount, nesting)

- Repeated rapid arrow navigation is exercised as back-to-back key sequences including wrap-around in both directions (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:77-97`).
- Runtime mutation: a direct `ToggleGroup` child that becomes disabled between renders (`setProps({ twoDisabled: true })`) is skipped by subsequent arrow navigation (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:1208-1237`); statically disabled direct `ToggleGroup > Toggle` children are natively disabled and skipped too (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:1085-1112`).
- Nesting — `Toolbar.Group` inside `Toolbar.Root`: group children participate in the same flat roving-tabindex order as the root's direct items (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:62-65`, `packages/react/src/toolbar/root/ToolbarRoot.test.tsx:80-87`); a `ToggleGroup` nested inside a disabled `Toolbar.Group` has its toggles natively disabled and removed from navigation (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:1171-1206`).
- Nesting — composite popups (Menu/Select/Dialog/AlertDialog/Popover) inside `Toolbar.Root` via `render`: focus hands off to the popup and returns to the trigger on close (see Focus management); toolbar navigation does not fight the popup's own composite keydowns (`packages/react/src/toolbar/button/ToolbarButton.test.tsx:681-708`).
- A `Toolbar.Separator` rendered outside `Toolbar.Root` throws `'Base UI: ToolbarRootContext is missing. Toolbar parts must be placed within <Toolbar.Root>.'` (`packages/react/src/toolbar/separator/ToolbarSeparator.test.tsx:43-53`).
- Context is optional-consumable: `useToolbarRootContext(true)` returns `undefined`/nullish outside the toolbar and works inside both plain and vertical toolbars (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:26-43`).
- RTL: direction comes from `DirectionProvider` + the root `dir` prop and only affects horizontal arrow-key mapping (`packages/react/src/toolbar/root/ToolbarRoot.test.tsx:57-59`, `packages/react/src/toolbar/input/ToolbarInput.test.tsx:108-115`).
- Unmount: N/A — no test unmounts toolbar parts mid-interaction; any unmount/cleanup behavior is UNVERIFIED — inferred from `packages/react/src/toolbar/root/ToolbarRoot.test.tsx:102-123` (state lives in the composite layer), no test asserts this.
