## State machine / hooks used

The unit is one shared interaction state machine split across `SliderRoot` (value + session bookkeeping) and `SliderControl` (pointer/touch session), with `SliderThumb` running a keyboard machine and inset-measurement effects against the same refs.

### SliderRoot — value gate and session bookkeeping

- `useControlled` holds the raw (possibly unsorted, to support frozen arrays) `valueUnwrapped` with `defaultValue ?? min` as the uncontrolled seed `packages/react/src/slider/root/SliderRoot.tsx:116-122`. The displayed/derived `values` are a memo that clamps each entry to `[min, max]` and sorts ascending when ranged `packages/react/src/slider/root/SliderRoot.tsx:165-172` — the sorting/clamping layer that behavior.md's "State model" clamping bullets observe.
- The change gate `setValue` `packages/react/src/slider/root/SliderRoot.tsx:193-226` rejects NaN and values equal to the raw current value (`areValuesEqual` handles scalar and array equality, `packages/react/src/slider/root/SliderRoot.tsx:39-47`), then clones the native event and redefines `target` as `{ value: newValue, name }` for form-library integration `packages/react/src/slider/root/SliderRoot.tsx:199-212`, forwards `onValueChange`, and aborts via `details.isCanceled` before committing `packages/react/src/slider/root/SliderRoot.tsx:216-222`. It records the applied reason into `lastChangeReasonRef` `packages/react/src/slider/root/SliderRoot.tsx:220` (initial value `REASONS.none`, `packages/react/src/slider/root/SliderRoot.tsx:135`) and returns whether the change was applied — the boolean every caller uses to decide follow-ups.
- `handleInputChange` `packages/react/src/slider/root/SliderRoot.tsx:228-247` is the *immediate-commit* path (keyboard and native input `change`): `getSliderValue` clamps/bounds, `validateMinimumDistance` rejects, the reason is picked by event shape (`'key' in event` → `REASONS.keyboard`, else `REASONS.inputChange`), and `onValueCommitted` fires synchronously when applied — explaining behavior.md's "Events" reasons and the keyboard/input commit semantics.
- Interaction-session state lives in refs: `controlRef`, `thumbRefs`, `pressedThumbCenterOffsetRef` (grab offset), `pressedThumbIndexRef`, `pressedValuesRef` (baseline values at press), `lastChangeReasonRef` `packages/react/src/slider/root/SliderRoot.tsx:124-135`. React state is `active`/`lastUsedThumbIndex` (focus tracking; `setActive` folds both `packages/react/src/slider/root/SliderRoot.tsx:140-157`), `dragging`, `thumbMap` (registered thumbs from `CompositeList`), and `indicatorPosition` `packages/react/src/slider/root/SliderRoot.tsx:140-149`. The comment at `packages/react/src/slider/root/SliderRoot.tsx:128-131` explains why press uses a ref while active uses state (refs update at pointerdown, state when the nested input focuses).
- `useIsoLayoutEffect` blurs the focused element and resets `active` when `disabled` becomes truthy `packages/react/src/slider/root/SliderRoot.tsx:256-272` — behavior.md's "Setting disabled on the root explicitly blurs" bullet.
- Field integration: `useRegisterFieldControl` registers `validation.inputRef` + id + `fieldValue` + name `packages/react/src/slider/root/SliderRoot.tsx:176`, and `useValueChanged(fieldValue, …)` (`packages/react/src/internals/useValueChanged.ts:6-17` — a layout-effect diff) drives `clearErrors`, `validation.change`, and `setDirty` on every value change `packages/react/src/slider/root/SliderRoot.tsx:178-191` — the machinery behind behavior.md's "Accessibility" Field-validation bullets.
- Dev-only `warn` when `min >= max` `packages/react/src/slider/root/SliderRoot.tsx:249-254` (behavior.md's "Edge cases" max/min warning).
- The `state` object merges `fieldState` with slider state `packages/react/src/slider/root/SliderRoot.tsx:274-299`; `sliderStateAttributesMapping` nulls out `activeThumbIndex`/`max`/`min`/`minStepsBetweenValues`/`step`/`values` so only `disabled`/`dragging`/`orientation`/validity become `data-*` attributes `packages/react/src/slider/root/stateAttributesMapping.ts:5-14`. Render goes through `useRenderElement('div', …)` with `role: 'group'`, `aria-labelledby`, and validation props `packages/react/src/slider/root/SliderRoot.tsx:374-387`.

### SliderControl — pointer/touch drag session

Session lifecycle: `idle → pressing (startPressing) → moving (handleTouchMove) → end (handleTouchEnd)`, entered through two modality paths that share the same move/end handlers:

- **Pointer path**: the element's `onPointerDown` `packages/react/src/slider/control/SliderControl.tsx:458-515` ignores right-clicks (`event.button !== 0`), disabled targets, and disabled thumbs (`isTargetDisabledThumb`, `packages/react/src/slider/control/SliderControl.tsx:154-166`), calls `startPressing`, focuses the pressed thumb's input (deferred one frame via `useAnimationFrame` → `focusFrame.request`, `packages/react/src/slider/control/SliderControl.tsx:426, 495-498`; `preventDefault` only when pressing the already-focused thumb, `packages/react/src/slider/control/SliderControl.tsx:487-498`), sets `dragging` immediately `packages/react/src/slider/control/SliderControl.tsx:500`, applies the track-press value only when the press was *not* on a thumb `packages/react/src/slider/control/SliderControl.tsx:502-505`, captures the pointer `packages/react/src/slider/control/SliderControl.tsx:507-509`, and attaches document-level `pointermove`/`pointerup`-once listeners `packages/react/src/slider/control/SliderControl.tsx:511-514`.
- **Touch path**: `touchstart` handler `packages/react/src/slider/control/SliderControl.tsx:381-414` latches `touchIdRef` to the starting touch identifier, presses, focuses, applies with `REASONS.trackPress`, and attaches document-level `touchmove`/`touchend` listeners. `getFingerCoords` filters later events to the latched identifier `packages/react/src/slider/control/SliderControl.tsx:52-77` — behavior.md's "Touch semantics" single-touchpoint rule.
- `startPressing` `packages/react/src/slider/control/SliderControl.tsx:221-272` snapshots `pressedValuesRef`, resets the interaction value, chooses the pressed thumb: keep a thumb press, else pick the closest *enabled* thumb by `getMidpoint` distance (ties go to the later index via `<=`, `packages/react/src/slider/control/SliderControl.tsx:246-257`), with a stacked-at-max walk backwards to the leftmost max-valued thumb `packages/react/src/slider/control/SliderControl.tsx:229-238` (behavior.md's stacked-thumbs-at-max edge case). For inset alignment it measures the thumb size into `insetThumbOffsetRef` `packages/react/src/slider/control/SliderControl.tsx:264-271`.
- `getFingerState` `packages/react/src/slider/control/SliderControl.tsx:168-219` is the coordinate→value mapping: control rect, border+padding offsets (`getControlOffset`, `packages/react/src/slider/control/SliderControl.tsx:30-50`), inset thumb offset, finger position minus the grab offset, rescaled to `[0, 1]`, then `(max - min) * rescaled + min` → `roundValueToStep` → `clamp` `packages/react/src/slider/control/SliderControl.tsx:183-197`. For ranges it delegates to `resolveThumbCollision` `packages/react/src/slider/control/SliderControl.tsx:207-218`.
- `handleTouchMove` `packages/react/src/slider/control/SliderControl.tsx:315-344` hedges a dropped mouseup (`pointermove` with `buttons === 0` → `handleTouchEnd`, `packages/react/src/slider/control/SliderControl.tsx:324-329` — behavior.md's dropped-mouseup bullet), flips `dragging` on only after `moveCountRef` exceeds `INTENTIONAL_DRAG_COUNT_THRESHOLD = 2` `packages/react/src/slider/control/SliderControl.tsx:28, 337-343` (behavior.md's `data-dragging` "added after several moves"), and applies with `REASONS.drag`. It returns early — without applying — when `getFingerState` is null, and null also clears `currentInteractionValueRef` when the value array shrank past the pressed index `packages/react/src/slider/control/SliderControl.tsx:172-177` (behavior.md's mid-drag-shrink no-op).
- `setValueFromPointer` `packages/react/src/slider/control/SliderControl.tsx:288-313` records the applied value into `currentInteractionValueRef` and `latestValuesRef` (a `useValueAsRef` mirror of `values` to dodge stale closures, `packages/react/src/slider/control/SliderControl.tsx:136`), and performs swap bookkeeping (`updatePressedThumb` + `focusThumb`) *only when the change was applied* so a canceled swap cannot leak the new index `packages/react/src/slider/control/SliderControl.tsx:304-309` (behavior.md's canceled-swap bullet).
- `handleTouchEnd` `packages/react/src/slider/control/SliderControl.tsx:346-379` resets `active`/`dragging`, clears the grab offset, drops a stale interaction array whose length no longer matches `values` `packages/react/src/slider/control/SliderControl.tsx:355-358`, commits `currentInteractionValueRef` via `onValueCommitted` using `lastChangeReasonRef` as the reason `packages/react/src/slider/control/SliderControl.tsx:360-366` (why the commit reason matches the last move, not the release), releases pointer capture with the original id `packages/react/src/slider/control/SliderControl.tsx:368-373`, and clears all session refs via `stopListening` `packages/react/src/slider/control/SliderControl.tsx:416-424`.
- A mount effect attaches the `touchstart` listener and cancels `focusFrame`/listeners on unmount `packages/react/src/slider/control/SliderControl.tsx:428-444`; `disabled` transitions call `stopListening` `packages/react/src/slider/control/SliderControl.tsx:446-450`. `stylesRef` captures computed style once for the border/padding offsets `packages/react/src/slider/control/SliderControl.tsx:121-126`.

### SliderThumb — keyboard machine and inset measurement

- Registration: `useCompositeListItem<ThumbMetadata>({ metadata: { inputId } })` `packages/react/src/slider/thumb/SliderThumb.tsx:179-188` returns the composite mount-order `index`; `index = !range ? 0 : (indexProp ?? compositeIndex)` `packages/react/src/slider/thumb/SliderThumb.tsx:190` — the `index` prop overrides for SSR (behavior.md's "Public API surface" index bullet and "Accessibility" SSR bullet).
- Keyboard: `onKeyDown` on the input `packages/react/src/slider/thumb/SliderThumb.tsx:363-438` respects `event.defaultPrevented` (user veto, behavior.md's preventDefault bullet), stops propagation for composite keys `packages/react/src/slider/thumb/SliderThumb.tsx:372-374`, computes `increment = shiftKey ? largeStep : step` with `PAGE_UP/PAGE_DOWN` forcing `largeStep`, flips `ARROW_RIGHT/ARROW_LEFT` direction under RTL, and resolves `HOME`/`END` to neighbor-aware bounds (`neighbor ± step * minStepsBetweenValues`, else `min`/`max`) `packages/react/src/slider/thumb/SliderThumb.tsx:380-415` — behavior.md's entire "Keyboard interactions" section. `getNewValue` rounds to the max decimal precision of value/increment/min before clamping `packages/react/src/slider/thumb/SliderThumb.tsx:62-80`. Before applying, a non-focus-visible input is blurred and refocused with `focusVisible: true` (tracked by `restoringFocusVisibleRef` `packages/react/src/slider/thumb/SliderThumb.tsx:156, 424-433`), and the internal handlers suppress the user's `onFocus`/`onBlur` props during that synthetic cycle `packages/react/src/slider/thumb/SliderThumb.tsx:161-173, 332-345` — behavior.md's focus-visible-with-no-extra-events bullet. The input's `onChange` routes `valueAsNumber` through the root's `handleInputChange` `packages/react/src/slider/thumb/SliderThumb.tsx:329-331`.
- Blur suppression: `onBlur` skips `setTouched`/validation when `event.relatedTarget` is inside another thumb `packages/react/src/slider/thumb/SliderThumb.tsx:352-361` — behavior.md's "moving focus between range thumbs does not trigger validation".
- Inset positioning: `getInsetPosition` computes the thumb-center percentage accounting for thumb size, writes local `positionPercent` state, and reports index-0/last positions up to root `setIndicatorPosition` `packages/react/src/slider/thumb/SliderThumb.tsx:201-229`. It runs in three `useIsoLayoutEffect`s (microtask after mount, sync on value change, and a `ResizeObserver` on control+thumb, `packages/react/src/slider/thumb/SliderThumb.tsx:231-268`) — behavior.md's `thumbAlignment="edge"` recompute bullet.
- Render styles: `thumbStyle` positions absolutely at `insetInlineStart`/`bottom` with a translate to center on the coordinate, writes `--position` when inset, hides while hydrating or unmeasured, and falls back to `visuallyHidden` for non-finite percentages `packages/react/src/slider/thumb/SliderThumb.tsx:270-302`. Range `zIndex` is 2 for the active thumb, 1 for the last-used thumb (single-thumb active = 1) `packages/react/src/slider/thumb/SliderThumb.tsx:273-282` — behavior.md's stacking-order bullet.
- The nested `<input type="range">` gets `mergeProps`'d input props `packages/react/src/slider/thumb/SliderThumb.tsx:312-453` (aria-valuenow/-valuetext with `getAriaValueText` > explicit prop > `getDefaultAriaValueText`'s `"start range"`/`"end range"` suffixing, `packages/react/src/slider/thumb/SliderThumb.tsx:45-60, 315-322`), merged refs `useMergedRefs(inputRef, validation.inputRef, inputRefProp)` `packages/react/src/slider/thumb/SliderThumb.tsx:455`, and `onPointerDown` records `pressedThumbIndexRef` + the grab offset from the thumb midpoint `packages/react/src/slider/thumb/SliderThumb.tsx:474-484` (behavior.md's vertical grab-offset bullet).

## DOM/portal strategy and why

No portals anywhere in the unit (behavior.md's "Portal behavior: N/A") — every part renders in place, which is what lets `Control` resolve thumbs via `thumbRefs` + `contains` and lets `SliderLabel`'s fallback query the control subtree `packages/react/src/slider/label/SliderLabel.tsx:38-42`.

- Composition: Root `div[role="group"]` → Control `div` → Track `div[style*="position: relative"]` → Indicator `div` + Thumb `div`s. The thumb wrapper is absolutely positioned and centers itself on the value coordinate with `translate`, while the nested `<input type="range">` is stretched to 100% of the wrapper under `visuallyHidden` styling `packages/react/src/slider/thumb/SliderThumb.tsx:440-446`. This is the central DOM decision: the *native input* is the focusable/AT surface (implicit `role="slider"`, native min/max/step/valuenow semantics, native `change` events, form submission), and the wrapper is the visual/positioning surface — behavior.md's "Accessibility" and "DOM structure" sections all fall out of this split.
- Document-level listeners + pointer capture: drags continue outside the control because `pointermove`/`touchmove` listeners attach to `ownerDocument(control)`, with `setPointerCapture`/`releasePointerCapture` bracketing the pointer session `packages/react/src/slider/control/SliderControl.tsx:411-413, 507-509, 368-373`.
- Geometry as inline styles/CSS custom properties rather than classes: values are continuous, so thumb `--position`/percent insets and indicator `--start-position`/`--relative-size` are computed per render `packages/react/src/slider/thumb/SliderThumb.tsx:284-302`, `packages/react/src/slider/indicator/SliderIndicator.tsx:11-45`.
- SSR/pre-hydration: for `thumbAlignment="edge"` only, the last thumb renders a `PrehydrationScript` `packages/react/src/slider/thumb/SliderThumb.tsx:468-470` (a CSP-nonce-aware inline `<script>` that renders only while hydrating, `packages/react/src/internals/PrehydrationScript.tsx:32-48`), whose body `packages/react/src/slider/thumb/prehydrationScript.min.ts:5` walks the control's `input[type="range"]` value attributes and writes `--position`/`--start-position`/`--relative-size` before React hydrates — anchoring itself via the `data-base-ui-slider-control`/`data-base-ui-slider-indicator` marker attributes emitted at `packages/react/src/slider/control/SliderControl.tsx:457` and `packages/react/src/slider/indicator/SliderIndicator.tsx:81`, and resolving the script body through the `#prehydration/slider/thumb` import alias `packages/react/package.json:116-118`. `useIsHydrating` (`packages/react/src/utils/useIsHydrating.ts:16-22`) keeps inset thumbs/indicator hidden during hydration so React doesn't fight the already-correct script output.
