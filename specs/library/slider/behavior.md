## State model (controlled/uncontrolled, defaults, transitions)

- Uncontrolled state via `defaultValue` (number or number[]); controlled via `value` + `onValueChange`. Range sliders are created by passing an array value and one `Slider.Thumb` per entry (`packages/react/src/slider/root/SliderRoot.test.tsx:44-73`); three-thumb sliders work the same way (`packages/react/src/slider/root/SliderRoot.test.tsx:59-73`).
- Default `step` is `1` — the native input gets `step="1"` when unspecified (`packages/react/src/slider/root/SliderRoot.test.tsx:170`). Default `orientation` is horizontal (`aria-orientation="horizontal"` and `data-orientation="horizontal"` without the prop) (`packages/react/src/slider/root/SliderRoot.test.tsx:167-168`, `packages/react/src/slider/root/SliderRoot.test.tsx:474-479`). A default `largeStep` or `minStepsBetweenValues` value is UNVERIFIED — inferred from `packages/react/src/slider/root/SliderRoot.test.tsx:2257-2288`, no test asserts this.
- Initial out-of-range values are clamped at render: range `[19, 41]` with `min={20} max={40}` renders `aria-valuenow` 20/40 (`packages/react/src/slider/root/SliderRoot.test.tsx:752-758`); an out-of-range initial value does not break touch interaction (`packages/react/src/slider/root/SliderRoot.test.tsx:123-144`); a controlled out-of-bounds value clamps the thumb position to 0%/100% (`packages/react/src/slider/thumb/SliderThumb.test.tsx:1134-1168`).
- Controlled value changes reposition thumbs (single and multi) (`packages/react/src/slider/thumb/SliderThumb.test.tsx:1062-1131`).
- `onValueChange` fires only when the value actually changes — duplicate pointer moves at the same position do not re-fire (`packages/react/src/slider/root/SliderRoot.test.tsx:1972-1998`). Exception: for a range slider whose array is unsorted/reversed, it is called even if the sorted value is unchanged, and the delivered value is the sorted array (`packages/react/src/slider/root/SliderRoot.test.tsx:2000-2041`).
- `onValueChange` details expose `cancel()`; a canceled change leaves the rendered value untouched and skips `onValueCommitted` (`packages/react/src/slider/root/SliderRoot.test.tsx:888-914`). When a drag move is canceled after earlier accepted moves, commit uses the last applied value (`packages/react/src/slider/root/SliderRoot.test.tsx:1105-1202`).
- No commit when a keyboard/pointer interaction leaves the value unchanged (single or range) (`packages/react/src/slider/root/SliderRoot.test.tsx:916-967`, `packages/react/src/slider/root/SliderRoot.test.tsx:969-1007`).
- Dragging state machine: the control carries `data-dragging` only for the drag modality (repeated moves), not for click modality; it is added after several moves and removed on touch end (`packages/react/src/slider/root/SliderRoot.test.tsx:1609-1660`).
- Disabled state: root `disabled` propagates `data-disabled` to Root, Value, Control, Track, Indicator, and Thumb (`packages/react/src/slider/root/SliderRoot.test.tsx:232-256`); per-thumb `disabled` disables only that thumb's input and blocks dragging it (`packages/react/src/slider/root/SliderRoot.test.tsx:336-426`); track press never selects a disabled thumb (`packages/react/src/slider/root/SliderRoot.test.tsx:429-460`).

## Keyboard interactions

- Keys: `ArrowRight`/`ArrowUp` increment by `step`, `ArrowLeft`/`ArrowDown` decrement by `step` in LTR for both orientations (20 → 21 / 20 → 19) (`packages/react/src/slider/root/SliderRoot.test.tsx:2225-2255`, table at `packages/react/src/slider/root/SliderRoot.test.tsx:2208-2213`). In RTL the increment/decrement keys swap: `ArrowRight`/`ArrowDown` decrement, `ArrowLeft`/`ArrowUp` increment, for horizontal and vertical alike (`packages/react/src/slider/root/SliderRoot.test.tsx:2210-2213`).
- `Shift` + arrow keys move by `largeStep` (tests use 10), clamped to `min`/`max` (`packages/react/src/slider/root/SliderRoot.test.tsx:2257-2322`, `packages/react/src/slider/root/SliderRoot.test.tsx:2393-2458`).
- `PageUp` increments by `largeStep`, `PageDown` decrements by `largeStep`, both clamped (`packages/react/src/slider/root/SliderRoot.test.tsx:2606-2776`). PageUp preserves the largeStep grid even when `step` uses a different grid (step 2 + largeStep 5: 20 → 25) (`packages/react/src/slider/root/SliderRoot.test.tsx:2640-2672`).
- `End` sets the value to `max`; `Home` sets it to `min` (`packages/react/src/slider/root/SliderRoot.test.tsx:2461-2493`, `packages/react/src/slider/root/SliderRoot.test.tsx:2533-2565`). In a range slider, `End` on thumb 0 drives it to thumb 1's value ([20,50] max 77 → [50,50], no second call), `End` on thumb 1 → [50,77]; `Home` on thumb 1 → [20,20], `Home` on thumb 0 with min 7 → [7,20] (`packages/react/src/slider/root/SliderRoot.test.tsx:2495-2530`, `packages/react/src/slider/root/SliderRoot.test.tsx:2567-2603`).
- Keyboard increments round fractional values to the configured `step` grid (0.2 + 1 step → 0.3) (`packages/react/src/slider/root/SliderRoot.test.tsx:2358-2391`), and keypresses correct out-of-grid controlled values (5.4698 with step 1 → 6) (`packages/react/src/slider/root/SliderRoot.test.tsx:2780-2803`).
- Range thumb independence: `minStepsBetweenValues` is enforced while moving thumbs by keyboard — a move that would violate it is rejected (no second `onValueChange`) (`packages/react/src/slider/root/SliderRoot.test.tsx:761-792`).
- `Slider.Thumb` `onKeyDown` receives all key events, including ones the slider handles internally (`Enter`, `ArrowRight`, `PageUp`); calling `event.preventDefault()` in the user handler blocks the internal value change (`packages/react/src/slider/thumb/SliderThumb.test.tsx:89-150`).
- Keyboard handling works inside a shadow root (`packages/react/src/slider/root/SliderRoot.test.tsx:2128-2163`).
- Rendering more thumbs than values: keyboard changes on the extra thumb commit nothing (no NaN) (`packages/react/src/slider/thumb/SliderThumb.test.tsx:152-178`).

## Focus management

- The only focusable elements are the native `input[type="range"]` inputs nested in thumbs; Tab reaches them and blur/focus follow the inputs (deliberate AT/TalkBack support, per test comment) (`packages/react/src/slider/thumb/SliderThumb.test.tsx:188-216`, multiple thumbs `packages/react/src/slider/thumb/SliderThumb.test.tsx:218-252`).
- Touch on the control focuses the slider input (`packages/react/src/slider/root/SliderRoot.test.tsx:1502-1515`); pointer down on a thumb focuses it (`packages/react/src/slider/root/SliderRoot.test.tsx:1517-1533`).
- Thumb `onFocus`/`onBlur` fire on the input, with `event.currentTarget` being the input element (`packages/react/src/slider/thumb/SliderThumb.test.tsx:295-316`).
- `:focus-visible` after a pointer press is false; a following keyboard interaction turns it on with no extra focus/blur events in between (`packages/react/src/slider/root/SliderRoot.test.tsx:1746-1779`, `packages/react/src/slider/thumb/SliderThumb.test.tsx:254-293`).
- Setting `disabled` on the root explicitly blurs the focused thumb (`packages/react/src/slider/root/SliderRoot.test.tsx:258-271`).
- Stacking order: before any interaction thumbs have no inline z-index; the focused/active thumb gets `z-index: 2`, and after focus leaves it is demoted to `z-index: 1` while others revert (`packages/react/src/slider/thumb/SliderThumb.test.tsx:605-645`).
- Field validation on blur: moving focus between range thumbs does not trigger validation; moving to an arbitrary Control child or outside does (`packages/react/src/slider/thumb/SliderThumb.test.tsx:318-390`).
- Invalid form submit moves focus to the native input (the registered field control) rather than the non-focusable wrapper (`packages/react/src/slider/root/SliderRoot.test.tsx:3212-3234`).
- `Slider.Label` click focuses the registered thumb — specifically the labeled one, not an unrelated native input inside the control (`packages/react/src/slider/root/SliderRoot.test.tsx:3453-3466`, `packages/react/src/slider/label/SliderLabel.test.tsx:24-41`); for range sliders label click focuses no thumb (`packages/react/src/slider/root/SliderRoot.test.tsx:3468-3486`); a label with no thumb to focus is a no-op (`packages/react/src/slider/label/SliderLabel.test.tsx:43-56`).

## Accessibility (roles, aria-*, id linking)

- Each thumb renders a native `input[type="range"]` carrying implicit `role="slider"` semantics (`packages/react/src/slider/root/SliderRoot.test.tsx:163`, `packages/react/src/slider/thumb/SliderThumb.test.tsx:200-202`).
- The input reflects `aria-valuenow` (updates on change events and keyboard interaction) (`packages/react/src/slider/root/SliderRoot.test.tsx:173-186`), `aria-orientation` (`packages/react/src/slider/root/SliderRoot.test.tsx:167-168`, vertical at `packages/react/src/slider/root/SliderRoot.test.tsx:464-469`), `min`/`max`/`step` attributes (`packages/react/src/slider/root/SliderRoot.test.tsx:660-663`, `packages/react/src/slider/root/SliderRoot.test.tsx:724-727`, `packages/react/src/slider/root/SliderRoot.test.tsx:170`), and keeps full float precision in `aria-valuenow` (e.g. `5e-8`) (`packages/react/src/slider/root/SliderRoot.test.tsx:533-546`).
- `aria-valuetext`: range thumbs default to `"44 start range"` / `"50 end range"` (`packages/react/src/slider/root/SliderRoot.test.tsx:188-195`); with `format`, values are Intl-formatted and suffixed the same way (`packages/react/src/slider/root/SliderRoot.test.tsx:2836-2848`); Thumb-level `getAriaValueText` takes precedence over a direct `aria-valuetext` prop (`packages/react/src/slider/thumb/SliderThumb.test.tsx:74-86`).
- Label linking: explicit root `aria-labelledby` is forwarded to root and input (`packages/react/src/slider/root/SliderRoot.test.tsx:165-169`); `Slider.Label` and `Field.Label` link the input via `aria-labelledby` with the label's id (`packages/react/src/slider/root/SliderRoot.test.tsx:3437-3451`, `packages/react/src/slider/root/SliderRoot.test.tsx:3419-3435`); when root `id` changes, the label id becomes `<id>-label` and both `aria-labelledby` attributes update (`packages/react/src/slider/root/SliderRoot.test.tsx:3522-3547`); `Field.Description` appends its id to the root's `aria-describedby` (`packages/react/src/slider/root/SliderRoot.test.tsx:3549-3563`).
- `getAriaLabel` on a thumb sets `aria-label` and suppresses `aria-labelledby` (`packages/react/src/slider/root/SliderRoot.test.tsx:3488-3506`); with no label rendered there is no fallback `aria-labelledby` (`packages/react/src/slider/root/SliderRoot.test.tsx:3508-3520`).
- SSR: label and root ids exist but no `aria-labelledby` link is rendered before hydration (`packages/react/src/slider/root/SliderRoot.test.tsx:99-121`).
- State attributes: `data-orientation` on root/control/value (`packages/react/src/slider/root/SliderRoot.test.tsx:471-480`); `data-disabled` on all subcomponents when root is disabled (`packages/react/src/slider/root/SliderRoot.test.tsx:232-256`); Field integration sets `data-touched` on blur, `data-dirty` on change (back to clean when the value returns to the original), `data-focused` on focus (`packages/react/src/slider/root/SliderRoot.test.tsx:3071-3161`), and `data-invalid`/`data-valid` on root and thumb per validation (`packages/react/src/slider/root/SliderRoot.test.tsx:3163-3210`).
- Field validation receives the slider value: number for single thumbs, array for range, on submit/blur/onChange per `validationMode`, exactly once per user change, and revalidates on external controlled-value changes (`packages/react/src/slider/root/SliderRoot.test.tsx:3163-3416`); external Form `errors` are cleared on the next change (`packages/react/src/slider/root/SliderRoot.test.tsx:2882-2908`).
- Vertical sliders do not use `webkitAppearance: slider-vertical` (`packages/react/src/slider/root/SliderRoot.test.tsx:482-495`).

## DOM structure & portal behavior

- Composition: `Slider.Root` (div) wraps everything; `Slider.Control` (div) holds `Slider.Track` (div) which holds `Slider.Indicator` (div) and `Slider.Thumb` elements; `Slider.Value` is an `<output>`; `Slider.Label` is a div (`packages/react/src/slider/root/SliderRoot.test.tsx:30-73`, `packages/react/src/slider/value/SliderValue.test.tsx:9-14`, `packages/react/src/slider/label/SliderLabel.test.tsx:10-22`).
- Thumb DOM: a div that renders the nested `input[type="range"]` as a sibling to its children, in default, short-form render, and long-form render modes (`packages/react/src/slider/thumb/SliderThumb.test.tsx:499-547`); thumbs expose `data-index` (`packages/react/src/slider/thumb/SliderThumb.test.tsx:32-42`).
- Positioning: thumb position is driven by inline CSS custom property `--position` and `insetInlineStart` (e.g. `30%` at value 30 in RTL) (`packages/react/src/slider/root/SliderRoot.test.tsx:212`, `packages/react/src/slider/thumb/SliderThumb.test.tsx:679-693`); computed `left` tracks values (100px-wide slider: value 40 → `40px`) (`packages/react/src/slider/thumb/SliderThumb.test.tsx:1088-1091`).
- `thumbAlignment="edge"` keeps thumbs/indicator hidden (`visibility: hidden`, `--position: 0%`) until the slider is visible/measurable, then recomputes insets and `--start-position`/`--relative-size` (`packages/react/src/slider/thumb/SliderThumb.test.tsx:648-763`). Indicator parity across horizontal/vertical × LTR/RTL × center/edge × single/range asserts `insetInlineStart`/`bottom`, `width`/`height`, and the `--start-position`/`--relative-size` vars (`packages/react/src/slider/indicator/SliderIndicator.test.tsx:18-88`).
- SSR: thumbs get inline `left` (e.g. `30px` for value 30 at width 100) without JS (`packages/react/src/slider/thumb/SliderThumb.test.tsx:1172-1265`); with `thumbAlignment="edge"` an inline pre-hydration script is rendered — exactly one script, placed inside the last thumb so preceding thumbs are already in the DOM (`packages/react/src/slider/thumb/SliderThumb.test.tsx:1193-1241`).
- `Slider.Value` associates with every thumb input via the `for` attribute containing all thumb input ids (unique, non-empty) (`packages/react/src/slider/value/SliderValue.test.tsx:40-56`); renders single values, ranges (`"40 – 65"`), and N-thumb lists (`"40 – 60 – 80 – 95"`) (`packages/react/src/slider/value/SliderValue.test.tsx:16-68`), and recomputes when `format` changes (`packages/react/src/slider/value/SliderValue.test.tsx:70-88`).
- Portal behavior: N/A — no test exercises a portal for any slider part; all parts render in place within `Slider.Root` (see conformance renders at `packages/react/src/slider/root/SliderRoot.test.tsx:86-89`, `packages/react/src/slider/control/SliderControl.test.tsx:11-16`).

## Events (names, payload shape, bubbling, preventDefault semantics)

- `onValueChange(value, eventDetails)`: `value` is a number (single) or number[] (range/multi). `eventDetails` carries `reason`, `activeThumbIndex`, the underlying `event` (its `target` has `name` and `value`), and `cancel()` (`packages/react/src/slider/root/SliderRoot.test.tsx:1206-1248`, `packages/react/src/slider/root/SliderRoot.test.tsx:2043-2069`, `packages/react/src/slider/root/SliderRoot.test.tsx:888-914`).
- Reasons: `'trackPress'` (pointer down/up on track), `'drag'` (pointer drag end), `'inputChange'` (native change on input), `'keyboard'` (arrow keys) — imported `REASONS` constants are asserted alongside raw `'keyboard'` (`packages/react/src/slider/root/SliderRoot.test.tsx:815-835`, `packages/react/src/slider/root/SliderRoot.test.tsx:859-886`, `packages/react/src/slider/root/SliderRoot.test.tsx:1728-1744`, `packages/react/src/slider/root/SliderRoot.test.tsx:1781-1805`).
- `onValueCommitted(value, eventDetails)` fires once per interaction end with the same reason values; it is not called during dragging (`packages/react/src/slider/root/SliderRoot.test.tsx:859-886`); when `pointerup` lands elsewhere than the last move, it commits the last applied change value (`packages/react/src/slider/root/SliderRoot.test.tsx:2165-2205`).
- Pointer semantics: track `pointerdown` immediately applies the pressed value and calls `onValueChange` (`packages/react/src/slider/root/SliderRoot.test.tsx:1663-1677`); `pointerdown` on the thumb itself does not change the value (`packages/react/src/slider/root/SliderRoot.test.tsx:1679-1694`); right-click (`button: 2`) is ignored (`packages/react/src/slider/root/SliderRoot.test.tsx:1696-1710`); moving with `buttons: 0` (hedging a dropped mouseup) ends the drag session (`packages/react/src/slider/root/SliderRoot.test.tsx:1471-1500`).
- Touch semantics: `touchstart` on the control applies the value; only the touchpoint identifier that started the interaction drives moves/commit (`packages/react/src/slider/root/SliderRoot.test.tsx:1314-1370`); the document `touchend` listener added for the interaction is removed afterwards (`packages/react/src/slider/root/SliderRoot.test.tsx:1414-1469`); tapping outside after a touch interaction does not re-commit (`packages/react/src/slider/root/SliderRoot.test.tsx:1372-1412`).
- Event identity: the slider does not override `event.target` on touch or mouse events (document-level listeners still see the real target) (`packages/react/src/slider/root/SliderRoot.test.tsx:1535-1606`).
- Pointer capture: `releasePointerCapture` is called with the original pointer id when the interaction ends (`packages/react/src/slider/control/SliderControl.test.tsx:172-205`).
- Native `change` events on the input (AT-driven) update the value and are clamped to min/max; a change to the already-clamped value does not re-fire `onValueChange` (`packages/react/src/slider/thumb/SliderThumb.test.tsx:393-465`).
- `preventDefault` semantics: `preventDefault()` in a Thumb `onKeyDown` cancels the internal keyboard handling (`packages/react/src/slider/thumb/SliderThumb.test.tsx:129-150`); there is no test asserting `preventDefault` on pointer events — UNVERIFIED, inferred from `packages/react/src/slider/control/SliderControl.test.tsx:172-205`.
- Collision behavior during drags: `'none'` clamps the dragging thumb at its neighbour ([40, 40]) (`packages/react/src/slider/thumb/SliderThumb.test.tsx:885-924`); `'push'` shoves the neighbour along ([65, 65]) (`packages/react/src/slider/thumb/SliderThumb.test.tsx:926-965`); `'swap'` exchanges logical thumb indices ([40, 70]) and respects `minStepsBetweenValues` while swapping ([30, 50, 80]) (`packages/react/src/slider/thumb/SliderThumb.test.tsx:967-1057`). After a swap, DOM focus and `activeThumbIndex` follow the logical thumb (`packages/react/src/slider/root/SliderRoot.test.tsx:1856-1916`); a canceled swap keeps the originally pressed thumb for subsequent moves (`packages/react/src/slider/root/SliderRoot.test.tsx:1918-1970`).

## Edge cases (rapid interactions, unmount, nesting)

- Rapid/repeated identical pointer moves are de-duplicated (no extra `onValueChange`) (`packages/react/src/slider/root/SliderRoot.test.tsx:1972-1998`).
- Dropped-mouseup hedge: a move with `buttons: 0` terminates the drag (`packages/react/src/slider/root/SliderRoot.test.tsx:1471-1500`).
- Unmount/ref loss mid-interaction: a control rendered with a render function that drops the ref makes track presses no-ops without crashing (`packages/react/src/slider/control/SliderControl.test.tsx:207-225`); a thumb whose merged host ref is recreated every render still settles and mounts the input (`packages/react/src/slider/thumb/SliderThumb.test.tsx:44-54`).
- Controlled range length changes mid-drag: shrinking so the pressed index disappears makes later moves/commits no-ops (`packages/react/src/slider/control/SliderControl.test.tsx:280-343`); shrinking with the pressed index still valid but a stale longer cached array does not commit (`packages/react/src/slider/control/SliderControl.test.tsx:345-404`); growing mid-drag clears cached interaction state so no stale commit fires and a fresh drag works (`packages/react/src/slider/control/SliderControl.test.tsx:406-469`).
- Touch starting on a text node inside the control is handled (`packages/react/src/slider/control/SliderControl.test.tsx:227-252`); touch interactions are ignored when no thumbs are composed (`packages/react/src/slider/control/SliderControl.test.tsx:254-278`).
- Stacked thumbs at max: dragging the last of `[100, 100, 100]` moves the first thumb ([50, 100, 100], `activeThumbIndex: 0`) (`packages/react/src/slider/control/SliderControl.test.tsx:42-67`).
- Swap targeting an unrendered thumb clears the grabbed offset and re-targets the logical index (`packages/react/src/slider/control/SliderControl.test.tsx:69-97`); a drag is ignored when the collision behavior cannot satisfy `minStepsBetweenValues` (`packages/react/src/slider/control/SliderControl.test.tsx:99-125`).
- Inset control press accounts for thumb size so the value maps to 0 at the edge (horizontal and vertical, `thumbAlignment="edge-client-only"`) (`packages/react/src/slider/control/SliderControl.test.tsx:127-170`).
